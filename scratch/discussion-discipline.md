# 讨论纪律（2026-09-27 对齐）

> **一句话**：讨论中不频繁记录；**明显对齐后（一句显式确认）才记**；默认成批。
> 性质：过程纪律，非 cogos 本体结论；落点候选＝补进 `AGENTS.md` 记忆小节。

## 三条

1. **记录是讨论的产物，不是讨论的节奏。**
   中段记录会把"碰撞"变成"归档"；且早期结论还在动，记下的常是半成品／错的（冻结了还要推翻）——churn 比不记更糟。
2. **触发条件 = 双方显式对齐**（一句"对／就是这样"）。
   判据是**状态**（确实对齐了），不是**请求**（谁说要记）；不靠单方推断。
3. **默认成批，不逐点。**
   一次讨论收口记一次，覆盖已对齐的几点。例外：某条已成后续依赖、又可能丢 → 单独一句。

## Caveat（已接受）

不记的代价 = 崩溃／切会话会丢**未落纸**的讨论。认这个代价（流程 > 防丢；scratch 有 ENTRY、任务可续）。

## 设计文档纪律（2026-09-27 对齐 · 更新）

> 与讨论纪律同源：都反对"把包袱叠在已有的东西上"。

1. **不补丁式**：新设计更好就**汰旧**——**直接删掉旧内容**，不写"限定 / 澄清不冲突 / 顺带改 / 守…"这类相容话。
2. **设计文档只写"现在是什么"**；演化 ＝ **删旧 ＋ 写新**。
3. **不留"过时 / 作废"标记**：过时的内容**直接不存在**（标记本身也是过程痕迹，会形成干扰）。要的是结论，不是过程。
4. 区分两类旧内容：**被取代的设计** → 删除；**不变量 / 判据**（目的函数、硬约束）→ 留着当尺子。

**删痕**：过程与痕迹不留——草稿里不必要或自相矛盾的内容，直接删。

## 落点候选

`AGENTS.md` 记忆小节现在只讲"**写在哪**"（scratch / 记忆层），缺"**何时写**"——本条补后者。
