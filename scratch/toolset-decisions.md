> **一句话**：分组由 5 收缩为 **3 组——电脑 / 通信 / 视觉**；**时间、定时器、草稿收入电脑**。
> 性质：呈现形状定稿；呈现思路本身见 `ENTRY.md`。

## 组描述（用法总览的一句话）

- **电脑**：你自己的机器：跑命令、读写文件、看并操作图形界面、上网查取信息；到点能提醒你。
- **通信**：和其他人相互交流——收发消息与文件。
- **视觉**：能看清一张图的细节（可放大局部），并测出图上某处的坐标。

> 以上是**模型面**描述；上面 29 / 6 / 3 的计数是**实现面归属**，模型面能力见 `toolbox-design.md §9`。

## 为什么（why）

1. **草稿与电脑文件重叠**：都是同步、有界的文本读写。
2. **"无电脑"前提不成立**：`term.open` 默认开本机 shell，`sync_reachable` 默认 true（`cogos/agent/config.py:44`）→ 本地必有 term＋fs，草稿"无机器基线"的理由被吃掉。
3. **归一层次＝对象层**（agent 有自己的家电脑），不是裸 shell 层：文件访问仍走结构化 fs 面（免转义／二进制安全）。
4. **时间／定时器天然属于"一台电脑"**：电脑有表、能设闹钟；且"能跑 agent ⟹ 必然有持久存储／时钟／调度器"，三者是必然伴随物，直接当公理（无需分层契约）。
5. **少概念 → 高感知清晰度**：5 组 → 3 组；组描述是模型看到的顶层目录。

## 边界与保留

- **实现不变**：时间坐标唯一（epoch UTC，时区只影响渲染）；定时器后果走事件（§8 due vs 送达）。二者仍是机制原语，只是**呈现上归组**到电脑。
- **"电脑"读作"我的家／自有环境"**，非"外面某台机器"；私域 vs 世界靠归属表达。
- **不设概念下限／Tier**：与 §12「按需装配、无预先固定的几套」一致；各后端声明能提供哪些面（pty／图形／网络／准点唤醒／存活模型随平台变）。
- 草稿并入后，`transfer` 的草稿端点 → 家电脑私有区（home ↔ 远端／spool）。

## 被否（why）

- **草稿独立成组** → 与电脑文件重叠；"无电脑"前提不成立。
- **裸 shell 顶替草稿**（不经 fs 面、直接敲命令）→ 丢结构化文件通道、丢有界私域、把"选"降级成"拼"。
- **时间／定时器写成 shell 命令**（`date`／`sleep`）→ 破坏时间坐标不变量；`sleep` 唤不醒 agent，得叠脆弱的 §5.4 pty notify。
- **给"电脑"定最小契约／Tier** → 无消费者，且与 §12 冲突。
- **`mark/unmark/list` 对模型可见** → "有界私域"的实现痕迹，是感知负担（倾向：策略留机制，不暴露）。

## 未定（留实现／后续）

- 命名（组名、模型可见工具名）。
- 草稿策略（淘汰／配额／`id=0` 信箱）：保留成家私有区策略，还是退化为普通目录。
- `toolbox help` 展开形式；用法保温／淘汰策略。
- 机制工具面的命名与形状。
- **凭据／秘密**：由**工具内部**持有与控制（每 agent 一份 tool 实例＝一份会话与凭据，装配时绑定，模型不选、不见值，不嗅探）。**不设计**身份／密钥／平台级 ACL。模型自建秘密（密码本）挂 §15。

## 电脑与资源（2026-09-28）

- **电脑最小形态**：agent 在运行平台上有自己的目录，电脑配置放其中（现有 `agent.json` 的 `computer` 块，`cogos/agent/config.py:36`）；agent 即带**一台默认电脑**（家电脑＝真实账户），工具直接对它操作，**模型不传 name**。
- **锚点**：＝运行平台（agent 自有目录）＝真实账户；"锚在进程还是 memory"的问题消解。
- **必备描述**：电脑需有**环境描述**（os / shell / 家目录等，模型据此决定命令怎么写）与**能力面声明**（终端 / 文件 / 图形 / 网络…，机制据此装配工具）；现缺 os / shell，待补。
- 多台、动态、凭据——出现需求前不动。
