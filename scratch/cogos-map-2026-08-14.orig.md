# cogos 项目认知地图 · 讨论草稿

> 2026-08-14 · 来源：人介绍项目背景（第一轮）。目的：为「项目认知地图」铺目的轴，待核对代码实现。

## 一、项目目的（认知层）

- 起源 `~/agent-study`：先学 agent → 开发 agent → 追求 AGI（通用人工智能体）。
- 最初构想：AGI 是**独立的认知个体**。
- 后来转向：不该只做一个 agent，而应搭一个**平台**，从平台中生成 AGI agent。这个平台 = **cogos（认知操作系统）**。

## 二、核心概念体系（分层的骨架，项目自己的语言）

### 认知层（为什么要通信）
- **独立认知个体**：agent 与 agent、agent 与人之间自由通信。
- **感知层 vs 意识层**：外部通信**不能直接注入意识层**（对比：现在人跟 AI 对话 = 直接把消息注入 LLM 上下文，即注入意识）。
- **通信工具 = 独立个体的嘴和耳朵**：接入感知层，而非意识层。
- **身份识别**：通信时直接识别「对方是谁」；号码即身份标识。

### 通信层（cogos-feishu 要实现的）
- **通信运营商（provider）**：可命名（如 `COGOS001`），cogos-feishu 支持多运营商。
  - **为什么要有运营商**：provider = 一个飞书租户下的号码域。不同人用各自飞书租户建体系后，agent 要跨租户通信很麻烦；解法是给对方的 agent 在我租户下也开一个号码，用它通信。类比：一个人可以有联通号，也可以有移动号——一个 agent/人可同时持有多个 provider 的号码。
  - **不互通是折中而非设计**：运营商之间无法互通，只因跨租户互通实现麻烦、没必要想那么远；**不是**有意设计的边界。
  - **号码全名只在接口层**：`运营商前缀 + 号码`（如 `COGOS001:A1328`）仅接口层用；进入软件内部、定位到对应 provider 后，号码只用裸号码。故代码内部 key 一律裸号码，**不必**前缀拼接。
- **基站（bs / bs-bot）**：每台设备装 cogos-feishu → `setup-bs` 指定运营商 → 创建一个 bot，代表「运营商在这台设备上的管理员」。创建者为**真人管理员**，bs-bot 只响应真人管理员消息。
- **admin-bot**：整个 provider 唯一；`/setup` 命令建立 provider 管理信息时创建，并以 admin-bot 身份建 **bitable** 存 provider 资料。
- **多设备**：换设备 → 再 `setup-bs`（每设备一个独立 bot）→ 与 bs-bot 通消息执行 `/resume <admin-bot-app-id> <admin-bot-app-secret>` → bs-bot 用 admin-bot 账号读 bitable 拿全量信息。

### 号码体系（身份）
- 号码：真人 `Hxxxx`，agent `Axxxx`（H=Human, A=Agent，4 位数字）。
- 真人注册：真人先加入真人管理员的飞书租户 → `/add-human <Hxxxx> <user-id> <name>` 写入 bitable（Hxxxx 由真人自定，不重复即可）。
- agent 注册：`/add-agent <name>` → bs-bot 引导真人管理员授权建 bot、设权限 → 自动分配 `Axxxx`，把 `Axxxx/app-id/app-secret` 写 bitable。
- 应用命名：bot 有名字（如 `张三`），应用名 = `张三(A1328)`，方便真人在飞书客户端搜到。

### 通信方案
- 真人 → agent：真人直接搜应用 `A1328`/`张三(A1328)` 发消息。
- agent → 真人：经 cogos-feishu 接口。
- bot ↔ bot：飞书**不支持两个 bot 直接互通** → 内部建一个**只有两 bot 的群**，不解散，信息写 bitable；之后经此群通信（相当于私聊），收发用 **@all** 保证另一 bot 收到。

## 三、Python 接口（agent 侧，设计目标）

```python
inst = startup("COGOS001:A1328", on_msg, PIN)  # 运营商前缀号码 + PIN + 回调
inst.send("COGOS001:H2049", msg)               # 发给真人
inst.send("COGOS001:A0053", msg)               # 发给另一 bot
inst.shutdown()                                 # 关机，收不到消息
```

- **PIN**：add-agent 时生成（随机串），相当于密码，只有持 PIN 的 agent 才能用该号码。

## 四、关键不变量 / 易错点（建图时须核对代码是否兑现）

1. 一个 provider 只有一个 admin-bot。
2. 每设备一个独立 bs-bot；bs-bot 只响应真人管理员。
3. `/resume` 用 admin-bot 账号读 bitable 恢复多设备信息。
4. bot 间私聊 = 双 bot 群 + @all；群**不解散**、写 bitable。
5. add-agent 同时生成 PIN（随机串）。
6. 号码命名 Hxxxx/Axxxx 在**单个 provider 内**唯一。
7. 一个 agent/人可持有多个 provider 的号码；运营商间不互通是折中（未实现，非设计边界）。
8. 接口层号码带前缀，内部定位 provider 后用裸号码；代码内部 key 用裸号码。
