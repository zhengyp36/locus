# 工具分层

1. toolbox 不必改名, 因为它代表自驱 agent 的对外工具的全集
2. catalog 应该改名为 toolbox_catalog, 它代表了 toolbox 的工具分类与用法
3. body 是自驱 agent 对外工具的"精简+熟练"版, 把高频常用工具放在里面, 并且封装得易用
4. **对外工具设计3条思想: 1. 简单; 2. 全面; 3. 手艺**
5. 目前只有**图形界面的操作需要手艺**, 图形界面为人类使用而设计, 而 **LLM 对图形的理解和响应速度无法跟上**, 因此在操作图形界面时显得笨拙, 因为是需要练手艺的
6. 为什么自驱 agent 通常不需要手艺呢? 因为真正的价值在2点: 1. 思维能力, 2. 创造工具的能力; 基于这两点, 对外工具只要不制约"创造工具"这个条件, 那么通常就足够了; 造工具的成败关键不在造的速度是不是快, 而在于造出的工具质量是不是高, 这需要的是思维能力, 而不是动手方面的速度, 因此简单全面的对外工具就足够了.

# 对外工具的通用形态/本质

## 对外工具3态

1. 事件通知, 感知变化
   行动方式: 被动感知, 后续是否响应为主动判断与决定, 可再次主动获取完整信息
   信息方向: 输入型
   信息组成: 源+内容(内容可配为不带或带)

2. 读取内容, 形成认知
   行动方式: 主动获取
   信息方向: 输入型
   信息组成: 源+内容

3. 对外输出, 观察影响
   行动方式: 主动行动
   信息方向: 输出型
   信息组成: 对象+内容

## IO模型

被动感知: 输入型, 源+内容, 内容可配为不带或带
主动获取: 输入型, 源+内容
主动行动: 输出型, 对象+内容

## 补充说明

形成认知: 结合自己的记忆, 对"源+内容"的解读
行动闭环: 观察影响=主动获取=>"源+内容"=>形成认知 (不必纠结"闭环"是主动获取还是被动等响应)

## 附件/投影思路

- 无论输入型还是输出型工具，原始内容只在当轮有效，过时即丢；但元信息（来源/作用对象+位置+数据量）不丢。
- 模型至少有两种处理方式：一是通过复述记住内容，二是通过重新读原文件拿到内容。但我们不能给模型指路。
