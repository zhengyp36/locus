## 定位与目标

- **这一步 ＝ 把工具做成可用**：让模型看得见、选得到、调得起来；为此可补齐能力、重塑呈现。
- **目的函数 ＝ 感知清晰度**（低认知负荷 → 推理质量）；**token 次要**。
- **总目的 ＝ 把模型的工具从"散"变"可用"**，然后推进**外圈 / 内圈**。
- **"可用"判据（2026-09-28 定）**：
  1. 模型看到的是 **3 组用法总览 ＋ 单一 `toolbox`**，不是散工具；
  2. 不查文档也能选到能力并调起来（`help` / `call`）；
  3. **一次真实操作端到端跑通**（如：给一台电脑 → 开终端、跑命令、拿结果）。

## 尺子（公理）

1. **目的函数 ＝ 感知清晰度**。
2. **上下文即记忆**（"模型无记忆"不成立）：模型记得上下文里的一切，机制是真相源；不在上下文里的，模型就不知道。
3. **缓存**：tool-schema 保持不变 → 命中；内容的一切变化走**追加消息**。

## 工具呈现长什么样

1. **三个载体**：`system` / `message` / `tool-schema`。
2. **`tool-schema` 里只有一个元工具 `toolbox`**（省掉快捷直达）。它有两个命令：`help`（查用法）/ `call`（用）。schema 里只写"怎么用这个元工具"的**元规则**，**不含工具清单** → 因此**不随视角变**。
3. **一份常驻的「用法总览」**：模型据它知道**有哪些能力**；用 **`system-reminder` 包裹的消息**承载，会话开始时出现在 `system` 之后。
4. **具体用法逐级展开**：需要时 `toolbox help` 取——**精确路径前缀**：`help`（空）＝三组总览；`help computer`＝面清单；`help computer.command`＝能力清单；`help computer.command.run`＝单能力详情。不做自然语言匹配（展开只让模型选，不猜）。
5. **用法进入上下文后不立即淘汰**（保温）→ **热路径不必每次重载用法**。
6. **视角 ＝ 用法的契约**：切换视角 ＝ **就近追加**一份新的用法总览，**以最近的为准**（追加式覆盖，不改历史）→ 换工具集。**始终是同一个 `toolbox`**。
7. **事件 / 推送走消息**，不经过 `toolbox`——否则模型"听不见"来信、到点、任务完成。
8. **原则**：展开**只让模型选**（给候选，不猜）；**执行只认模型明确写出的调用**。

## 用法总览的内容（能力目录）

- 每组一句，写**"这组能为你做什么"**；不写使用建议、不写排除句；齐平、可预测。
- **泄漏判据**：不得用动作名 / 虚概念顶替"想要的东西"（模型要拿到的东西该留）。
- **随角色走**：角色相关词只在对应视角成立。

| 组（标识） | 总览 |
|---|---|
| 电脑 `computer` | 你自己的机器：跑命令、读写文件、看并操作图形界面、上网查取信息；到点能提醒你。 |
| 通信 `communication` | 和其他人相互交流——收发消息与文件。 |
| 视觉 `vision` | 能看清一张图的细节（可放大局部），并测出图上某处的坐标。 |

- **标识＝英文路径**（`computer` / `communication` / `vision`）：`help` / `call` 一律用标识寻址，中文仅作解释（消除"看中文、敲英文"的翻译步）。
- **描述只列模型面能力**（据 `toolbox-design.md §9`）；非模型面能力不进描述。

## 分组（能力目录的结构）

| 组 | 面 | 成员 |
|---|---|---|
| 电脑 | 终端 · 文件 · 图形 · 网络 · 时间 · 定时 · 私域 | `terminal` 8 · `fs` 3 · `screen` 3 · `web` 3 · `time` 2 · `timer` 3 · `draft` 6 ＋ `transfer` 1 |
| 通信 | | `phone` 6 |
| 视觉 | | `see` `mark` `coord` |

- **成员列＝实现面归属**（供装配）；模型面按用途组织，形状见 `toolbox-design.md §9`（数量不同：实现 38 → 模型面 ~21）。
- **网络并入电脑**（保住"查外网"意图）；网络面与图形面邻近（取外网两条腿：api 先、browser 后）。
- **时间 / 定时 / 草稿并入电脑**（2026-09-28，详见 `toolset-decisions.md`）：草稿＝家电脑私有区，`transfer` 归电脑；**"工作台"退休**。
- 这是**动作面**分组；感知由各工具的**事件面**承担。
- **后期候选**：裁"对象 vs 意图"分组轴（如把取信息的两条腿合成意图组）。

## 角色相对（主体 / 机制）

- **至少两个视角**；各有自己的**用法总览与工具集**；**同一个 `toolbox`**。
- **命名**：同一能力、两个角色名；按**该角色下的用途**命名，与实现名解耦，跨角色不算撞车。
- 机制侧的"草稿"＝组织记忆类能力，主体侧不暴露；按用途命名，**不叫"草稿"**。

## 原则（方法论）

- 工具**按角色要做的事设计**（先问需求，再定形状）。
- **模型可见名 vs 实现名分离**。
- 展开只让模型选；执行只认明确调用；机制离场**擦除**其痕迹。

## 已否（why，仍适用）

- **完全按需（连名字都藏）** → 把负荷从"选择"移到"发现"，违清晰 → **总览必须常驻**。
- **组描述写使用建议 / 排除句** → 属更深层；组描述只写"能为你做什么"。
- **按工具实现列清单** → 会把跨面用途切碎、看不出用途 → 按用途组织。
- **用意图翻译去藏工具 / 独立意图匹配器** → 见 `checkpoint-18 §5`；意图 / 模糊只用在"发现与绑定"，**执行保持精确**。
- **用 `[来源:]` 承载视角或说明** → `[来源:]` 是**世界数据（非指令）**专属；说明 / 视角用归属头 / 独立标记。
- **缓存不作约束** → 修订为：**tool-schema 恒定即命中**。
