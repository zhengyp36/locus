# Checkpoint 规则（递进式清理历史）

## 目的

节省 token：会话过长时，YZ 用 `/undo` 回退多轮消息释放上下文，改由 AI 把关键上下文蒸馏进 scratch 草稿。下次重读草稿即可无痛恢复，不必重新全量加载。

## 触发

- 仅在 YZ 明确指示时执行（如"记录到 scratch""整理 checkpoint""写草稿"）。不主动写。
- YZ 说"读 scratch/xxx.md"时，读该文件并按其内容恢复上下文。

## 文件位置

- `scratch/<日期>-<主题>.md`，例：`scratch/260818-issues.md`。
- 整个会话记录一个文件, 问题依次编号

## 写作内容（按此结构，缺哪块写哪块）

1. **当前问题**：一句话说清在做什么。
2. **已做修改**：`文件:行` + 改了什么（改点，非 diff 原文）。
3. **已读代码要点**：`文件:行` + 关键逻辑一句话，够我重读时定位即可。
4. **关键结论 / 决策**：讨论定下来的东西，含 YZ 拍板的方向。
5. **遗留 / 坑**：报错要点、未解决项、下一步候选（可记，草稿允许存待办）。

## 写作要求

- **凝练可恢复**，不搬运原文。结论 + 锚点（文件:行）优先，细节能靠锚点重新 `read`/`grep` 找回。
- 代码/路径/变量/文件名用英文；讨论结论可用中文。
- 只记"重读后能继续干活"所需的最小集合，宁可少不可冗。

## 重读后的行为

- 读完直接进入状态，缺的细节再按锚点 `read`/`grep` 局部补，不重复全量加载、不复述草稿。

## 与 locus 记忆的关系

- scratch 是**会话内临时 checkpoint**，不进 AGENTS.md，不定稿。
- 一个主题收口后，值得长期留的结论由 YZ 决定是否并入 `projects/<工程>/current.md` 或 `entries/`，届时草稿可删。
