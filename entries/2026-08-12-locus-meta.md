# locus 起源与设计

## 来源

locus 框架于 2026-08-12 凌晨从 agent-study 工程的多 session 协作方式探索中孵化。
设计过程文档已迁至 projects/locus-meta/（multi-session-workflow.md + collaboration-framework-design.md）。

## 核心设计决策

1. **上下文管理：current.md 模型**
   - current.md = 活跃记忆（类似物理内存），会话启动时全部加载
   - index.md + entries/ = 归档（类似虚拟内存），按需换入
   - 没有"移除"机制：上下文只往文件系统换出，不丢弃
   - 原方案是树模型（project-tree.md 承载 [DONE]+[TODO]），在跨主题多工程场景下演进为单元模型

2. **AI 主体性与目的驱动**
   - AI 判断基于信息完整度，不基于服从
   - 目的是合一的，决定所有行动的边界和方向
   - 目的不明确时 AI 主动推导、提出假设、请人类确认
   - AI 有拒绝权——路径不对齐目的且沟通无法一致时

3. **记忆原则：按归属区分**
   - 不归属工程的通用内容 → locus 本体
   - 工程特有内容 → 留在工程，locus 只存索引 + 简短摘要
   - 记：稳定结论、关键锚点、下次起点、方向与推理
   - 不记：大段源码、冗长讨论过程、已推翻猜测

4. **结构在使用中生长**
   - 不定死规则，从实验提取结论写成起点
   - 主题多了拆，结构乱了整

## 理论根源（agent-study 实验结论）

- 树形摘要精确定位能力不足，需路线图视图补充
- project-tree.md 承载 [DONE]+[TODO] 可替代多文件维护
- AI 能严格按给定目的推演，也能从历史+方向自主反推深层目的
- AI 能对人制定的路线图做独立评估，提出替代方案
- 自主判断 = 信息完整度 + 目的作为判断标准 + 递进式问法
- 路由开销判据：路由需要大量上下文 → 记忆该重组

## 话题插入与旁注机制（2026-08-12，CogOS 讨论中旁路产生）

**问题**：话题切换的仪式感（归档 → 清空 → 写入口 → 更新 timeline）对一两句话的快速插入太沉重。
实际场景：CogOS 讨论中途想到 locus 改进，不值得完整切换，但不记又会丢失。

**新增两个轻量机制（已写入 AGENTS.md）**：

### 话题插入
- 触发："插入 X 话题：..."
- 行为：加载 X 上下文 → 临时讨论 → 追加到 X 的 entries → 回到原话题
- 不归档、不清空、不更新 timeline

### 旁注
- 触发："记给 X：..."
- 行为：直接追加到 X 的当前状态文件，不加载上下文，不讨论，不切换
- 下次切到 X 时自然出现在活跃记忆中

## profile.md — 持久语义记忆（2026-08-12，CogOS 讨论中旁路产生）

**问题**：locus 当前只有情景记忆（current.md / entries），缺少持久语义记忆层。稳定元信息（用户代号、工程性质）不应随话题切换消失。

**方案**：独立 `profile.md`，AGENTS.md 声明每次会话启动时加载。

已记录内容：
- 用户代号：YZ
- 工程性质：私有工程

## projects.md `约定:` 字段 — 工程约定自动加载（2026-08-12，CogOS 真实账号测试中产生）

**问题**：讨论 CogOS 时发现 `commands.py` 的 `DESCRIPTION` 缺失新增命令，需要 AI 在操作工程前知道工程的开发约定。但 locus 和 CogOS 是独立工程，AI 不会主动加载 CogOS 的 `AGENTS.md`。

**方案**：`projects.md` 新增 `约定:` 字段，指向对应工程的约定文件（如 `AGENTS.md`）。启动和话题切换时 AI 自动按字段加载。

**具体改动（已写入 AGENTS.md 和 projects.md）**：
- `AGENTS.md` 机制部分：启动后识别话题 → 查 `projects.md` → 有 `约定:` 字段则加载
- `AGENTS.md` 话题切换部分：步骤 4 写入入口后，步骤 5 加载约定文件
- `projects.md` CogOS 条目：`- 约定: ~/codex/cogos/AGENTS.md`
- `~/codex/cogos/AGENTS.md`：新增命令需同步更新 DESCRIPTION

**影响**：以后任何新工程只需在 `projects.md` 加一个 `约定:` 字段即可。
