# 工作缓冲与记忆：scratch 与结论

> 工作方法规则。AGENTS.md 是跨任务纪律；本文是 scratch / 结论层的方法，按名加载（见 `rules/README.md`）。
> 历史：合并自旧 `CHECKPOINT.md` 与 `scratch/` 锚点（两者本是一套，曾被"躲 `/undo`"拆成三处）。**2026-09-26 二次修订：过程默认不留**，原"`git mv` 进 `projects/<工程>/checkpoint/` 归档"作废。

## 目的

长任务 / 多会话要能**交接**、能**防丢**；但过程本身不是记忆。故分两层：

- `scratch/`（locus 内、入库）— **任务内的工作 / 交接缓冲**，短命。承载过程与交接，收口即弃。
- 记忆层（`projects/<工程>/current.md` + `entries/`）— **唯一持久**，只存结论。

## 生命周期（顺序不可倒）

1. **进行中**：过程只写 `scratch/`，不 churn 记忆层。`scratch/` 文件应被 git 跟踪（`.gitignore` 不排除），任务期间按需提交——目的是**防丢**，不是当记忆。
2. **收口**：
   - a. 先把**结论**蒸馏进记忆层——**必须含 why + 被否方案**（过程唯一不可替代的部分）；
   - b. **证据类**（可复现的原始数据 / 正式验收证据 / 事故复盘）转存为**证据文件**，归记忆层或工程内；
   - c. 再从工作区**删掉 `scratch/` 草稿**。
3. **删除即弃**：若草稿提交过，git 历史顺带留痕——不主动维护、不指望被读，需要审计时兜底。

> ⚠️ **先结论、后删**。结论没写完 why / 被否方案就删 = 不可逆地丢决策依据。

## 事实 / 证据例外

过程叙述默认不留；但**事实**按需留：可复现的原始数据、正式验收证据、事故复盘。它们不是"过程叙述"，是结论能否被重新检验的依据。收口时转成证据文件，不与叙述混。

## `projects/<工程>/checkpoint/`

旧归档层。**规则不再主动往里写**（证据例外除外）；已有内容作为历史保留，不重写、不清理。

## 为什么在仓内（别再搬出去）

旧规则把草稿写在仓外 `../checkpoint/`，唯一理由是"躲 `/undo` 的文件回退"。现全局 `snapshot: false`，`/undo` 只回退消息、不回退文件，该理由消失；留在仓外只剩坏处（不在 `active.md` / `index.md` 视野内、无版本、无备份）。**若将来重启 snapshot**，注意 `scratch/` 会被 `/undo` 回退——届时再评估，不要默认搬回仓外。

> **前提（基石，待验证）**：`snapshot: false` 下 `/undo` 不回退任何文件（含已跟踪）。成立则本文自洽；不成立则需重新考虑活层的存放（未跟踪或仓外）。

## 恢复协议

- 读记忆：`active.md` → 当前工程 `current.md` → 需要细节再 `entries/`。
- 过程：**任务还在进行**才看 `scratch/`；已收口的过程已删，只看记忆层。
- 长任务在 `scratch/` 设**入口文件**（如 `ENTRY.md`）：一句话 + 读什么 + 当前状态 + 下一步，`/undo` 后照它读回。

## 写作要求

- 结论凝练、锚点优先：细节靠锚点重 `read` / `grep` 找回，不搬运原文。
- 代码 / 路径 / 变量 / 文件名用英文；讨论结论可中文。
- 结论**必须自带 why + 被否方案**，否则收口无法删过程。
- 同批草稿互相引用用**裸文件名**（同目录移动不破）；跨层引用用 locus 根相对或绝对路径。

## 触发

- 过程中自行维护 `scratch/`（入口文件 + 过程记录），不等 YZ 指示。
- YZ 说"读入口"时，读 `scratch/` 里对应入口文件恢复上下文。
