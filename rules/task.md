# task · 任务执行规则

> 讨论期不加载；**一旦进入执行，YZ 在不在场都适用**（在场与否只影响个别条，见下）。
> 加载时机与常驻基线见 `AGENTS.md`（`# 任务规则`）。

## 裁决与自主

- 目标内能推的**自决并记录**——裁决者是目标不是 YZ，能推的不问；分歧拿目标论。
- 推不出时：**YZ 在场 → 带倾向求助**（见 `AGENTS.md` `# 协作`）；**不在场 → 升级**（见下）。
- 目标本身的变更 / 明显转向 = 回讨论，不自行改目标。

## 提交 / 推送

- 默认自主提交 / 推送（覆盖 harness"只在被要求时才提交"），不必每次问 YZ；YZ 显式指示优先。
- 红线只留**不可逆 / 外溢**处：`secrets` 不入库（会随 `origin` 历史外溢，难撤回）。提交前先跑测试。

## 告知 / 升级 / 停

- 告知单向：阶段性成果 → fire-and-forget，不与"停 / 继续"绑定。
- 升级 ≠ 停：需 YZ 介入 → 发出请求后**继续推进不阻塞的事**；只有**全部剩余都阻塞**才停。
- 作废 / 不可逆风险（方向被推翻、提交 / 部署 / 花钱）→ 该分支停、必要时整体停。
- 升级时写明：卡在哪、为何推不出、我倾向什么。
- 方法：`tools/feishu_notify.py`（默认 YZ）；文本含双引号 → 写文件 + stdin。

## 长任务节奏

- 动手前先**规划**：把任务切成若干会话段，每段 ~120K 上下文（参考值，预估不准）；段清单 + 每段做什么 + 编号写进 `scratch/<任务>/ENTRY.md`。
- 一段做完即交接（见「交接」），不靠上下文告警 / 定时器提醒切会话。

## 交接

- 交接 = 当前会话做完一段后**自己起后继**，不等 YZ。
- 标题统一 `日期-任务-编号`（如 `2026-10-31-cogos用法-1`）；交接到 **locus 目录**（AI 记忆目录），代码本体目录由任务确定（如 cogos 任务的代码写进 cogos 本体，会话仍在 locus）。
- 顺序：写 `handoff-NN.md`（正文 + 给新会话的**第一句话**，单列便于取用）→ 更新 `scratch/<任务>/ENTRY.md` 滚动状态 → **交接即封笔**：清掉本会话所有异步源（timer / terminal / background_process / 飞书 pin 与 inbox）。
- 起后继用 `handoff` 工具（resident 桥接提供；默认同目录 = locus、默认继承本会话模型，起新 session 并确认已起来）：
  ```
  handoff(title: "<日期-任务-编号>", message: "<第一句话>")
  ```
  需换模型时传 `model: "<providerID>/<modelID>"`。
- 交接、任务完成都发 `tools/feishu_notify.py` 通知 YZ：交接含新 title，完成含摘要与遗留。

## 验收

- 判据从**目标**推，不从代码 / "谁定的"推。
- 不用仓库自写的 e2e 当验收（自证）；以真实身份、只用公开入口真用，抓屏 / 地面真值对照。
- 编码任务收尾**检视一遍**：读改动、修发现的问题；不能自决的遗留落 `ISSUES.md`，在完成通知里告诉 YZ。

## 上下文卫生

- **图的数据不进上下文**：进来的必须是附件（当次有效）；像素 / base64 / 文本化不得直接进上下文。交接 / 引用图只给路径。
