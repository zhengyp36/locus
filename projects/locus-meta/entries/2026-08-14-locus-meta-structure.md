# 结构整理与两层模型（2026-08-14）

本会话把 locus 目录结构定稿，并确立"工程管理 vs 记忆"两层模型。

## 两层模型

- 工程管理层（大写、确定、追加、不重写）：README（工程是什么/本体路径）、CHANGELOG（阶段/变更）、ROADMAP（可选，下一阶段方向）、ISSUES（可选，遗留问题）。
- 记忆层（小写、重写、可乱）：current（当前印象）、index（索引）、entries（细节）。
- 核心：工程管理是确定的锚，记忆是类人印象，可乱可模糊；乱了从锚拉回（事件溯源）。
- 命名约定（子工程内）：大写=管理/确定，小写=记忆/模糊；顶层指针/草稿（active/timeline/scratch）不套此约定。

## CHANGELOG

- 触发：人显式指出、人机共同维护，一个阶段完成时更新；不绑定"更新记忆"。
- 前期历史已补入：08-11 agent-study 原理探索 → 08-12 搭建 → 08-13 复盘（locus-original）→ 08-13 重新整理（locus-v1）。

## ROADMAP（计划）

- 管理层的"未来向"孪生，按需生长；本次已建：核实对照前期原理探索，确认已实现/缺失，时间待定。

## ISSUES（遗留问题）

- 管理层的"问题账本"：记录发现过、未闭合的欠账，与 ROADMAP（将来做）不同层。本次已建：过度思考、重复性工作、agent 模式 system-prompt 三条。

## docs/ = 本体

- 非管理非记忆，是本体文档（locus-meta 无外部仓库，本体落在 locus 内）；可选。

## 顶层 README

- 给人看（是什么/为什么），AGENTS.md 给 AI 看（怎么做），互指不复制。

## 草稿机制

- scratch/ 临时承载"不必频繁更新记忆"；结论落定后基于草稿更新记忆，再删草稿。
