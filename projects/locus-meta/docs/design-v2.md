# 工程化记忆方案 v2

> 日期 2026-08-13。基于 locus_original 机制研究与多轮讨论收敛，作为 collaboration-framework-design.md 的演进。

## 定位：印象层

locus 存的是对每个工程的"印象"——讨论、临时结论、未成形想法。
工程本体（代码、正式文档、规范）留在工程自己的仓库，成形后才外溢写入正式文档。

## 结构

- projects/ 下按工程分目录，每工程：README + 各自的 current/index/entries。
- 不区分内部/外部工程类型；README 保留"本体路径"可选字段（无本体工程留空）。
- 全局 active.md 指针文件（内容 = 工程名）做焦点切换；写记忆永远写工程目录下的 current.md。
- timeline.md 只记最近几个工程。

## 关键决策

1. 统一印象层（消掉内/外类型标签，结构无差异）。
2. 焦点切换 = active.md 指针文件（替代软链接，避开 symlink 工具行为不一致的坑）。
3. 外溢不做规则：成形后由人判断是否写入正式文档；外溢后 locus 侧保留摘要、不删，靠"记忆=索引/归属"原则。

## 与原理的一致性

- projects 分层 + 每工程树 = 构想3（双层树形结构）
- active.md 指针 = 构想6（树上切换焦点）的最简实现
- 印象层 = "记忆=索引/归属"原则的推进

## 相对 locus_original 的演进

- 软链接 → 指针文件：避开 symlink 工具行为不一致
- 内/外类型 → 统一印象层 + 本体路径字段
- 触发短语 → 保留"生长触发"，不预先设计目录结构
- 外溢触发条件 → 不写规则，人判断 + AI 依原则自行判断
