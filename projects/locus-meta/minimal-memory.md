# 极简记忆

> 日期 2026-08-13。人与 AI 协作中，locus 记忆机制的精简方案。

## 定位：记忆是印象

记忆回答的是："当前会话讨论过什么、经历了什么、重要内容是什么"——像人对信息的**印象**：大方向对即可，不求精确。

真正的内容（细节）放在索引指向的地方，记忆只存**摘要 + 索引**。细节不是过程和流水账，而是真正有用的信息（讨论的问题、要点）。

## 指令

只有两条指令，都作用于 `active.md` 指针指向的当前工程：

- **更新记忆**：把当前会话的印象写进记忆。
- **切换话题**：切换指针（高频动作，值得用固定指令）。

其余动作用自然语言表达，不设指令。例如加载记忆说"把 cogos 这个工程最近讨论的内容加载进来"。

## AGENTS.md 只需 4 点

1. 进入时加载最新记忆（当前已可做到）。
2. 用户说"更新记忆"时更新当前记忆。
3. 用户说"切换话题"时切换指针。
4. 加载记忆用自然语言描述，不用指令。

## 切换话题 vs 加载记忆

- 切换话题 = 改指针，高频、动作精确，设固定指令。
- 加载记忆 = 一次性读取，低频、天然带"哪个工程"参数，用自然语言。
- 边界：**加载不改指针**；只有"切换话题"才改指针。加载后说"更新记忆"，仍写指针指向的当前工程，不是被加载的工程。

## 更新记忆 = 摘要 + 索引

更新是**重写**，不是追加：

1. 把重要内容写入 `entries/`（细节层）。
2. 在印象（`current.md`）存摘要 + 索引，索引指向 entries/ 下的内容。
3. 重写时先看记忆里有什么：相似的合并，没有的写在后面，可能重排主次。

为什么重写：追加必然导致重复冗余、膨胀成流水账；重写天然去重、合并、重排，正是"印象"的维护方式。丢掉的只是旧表述，内容仍可通过索引找回。

### entries/ 与外溢的区分

- **entries/ = 记忆的细节层**，在 locus 内部，属于"更新记忆"。
- **"写个文档" = 外溢到工程本体**（正式文档），另一回事，由人判断。

## 什么算多 / 如何拆分

两个判据，够用，不用字数：

1. **条数**：印象里的记录条数（≈索引条数）≥ 3-4 条 → 该整理。
2. **细节**：印象里出现细节（非摘要/索引）→ 本身就"多了"，该下沉到 entries/。

拆分方法：达到阈值时**拒绝更新记忆**，说明内容过多需拆分，由用户和 AI 一起讨论完成；不做自动化，用户更有把控。
