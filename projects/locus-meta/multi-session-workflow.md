# 多 session 协作工作方式

> 2026-08-11

## 问题来源

CogOS feishu 模块 5 步编码实践（3 个 commit，330 tests pass）暴露了一个问题：长会话上下文膨胀。编码越往后，对话历史中的早期细节、反复讨论、调试过程占据大量上下文，稀释了关键信息。

核心问题：如何让"讨论"和"执行"在不同会话中隔离上下文，避免长对话噪音，同时保持连贯性。

---

## 一、构想（待展开）

### 1. 人与 AI 的协作方式

1. **讨论阶段是核心**：执行阶段由 AI 完全取代，人只参与执行前的讨论和执行后的回顾。讨论质量决定最终质量。
2. **AI 角色不对称**：讨论中人为主体，AI 负责展开想法，但 AI 应具备纠偏能力——看到人没注意到的问题和风险。
3. **纠偏能力应内置**：当前每次需要重申"请保持独立思考"，应通过会话类型的结构性区分（讨论型 vs 执行型）将批判视角设为默认行为。

### 2. 讨论目录与工程目录分离

讨论目录不绑定任何工程，理论上可讨论任何问题。类比：人不会绑定某个工程才能思考，可以自由切换工作目录。

关键机制不是"始终保持结构清晰"，而是**适时重组**——接纳混乱、周期性整理。

### 3. 会话与单元的双层结构

会话内部组织为树形结构：会话由若干单元组成，单元和会话共享同一结构模式（目标 → 结论 → 关键点 → 细节），形成递归嵌套。（精确度已通过实验 1 验证，更大范围的适用性待进一步展开。）

### 4. 不同视角的多棵树并存

底层数据模型是一棵树，但呈现形式可以有多种：
- 历史视图：突出"发生过什么"
- 路线图视图：突出"还有什么要做"

多视图各有用途——路线图视图用来开新会话、定位下一步；历史视图用来回看细节、恢复讨论上下文。不应因"模型是一棵树"而放弃多视角呈现。

### 5. 目的的缺失与树的根

实验 1 的"导航偏差"本身值得重新审视。"偏差"隐含了"既定路线正确"的假设，但路线只是通往目的的一条可选路径，不是目的本身。子任务 2 的问题不是"走错了"，而是它在没有目的信息的情况下做了推演——其方向（SessionManager）从内部逻辑完全成立，甚至可能比实际路线更合理。

这棵树的真正缺口不是缺少路线图，而是**缺少根节点——目的**。历史（已做）和路线图（待做）都在树上，但树是从目的长出来的。路线是基于目的制定的方案，而不是目的本身。AI 没有目的信息，就只能从历史模式外推，自然会走向不同方向。

推论：恢复文件需要记录的不只是"下一步做什么"，还要记录"这一切是为了什么"。否则每次新会话，要么依赖人对目的的复述，要么只能从历史推演——和实验偏差同源。

### 6. 树操作：通过操作切换焦点

实验 2 证明一棵树可以承载全部信息。但一棵树的单一视图会损失认知焦点——历史视图和路线图视图各有侧重，合并后注意力的切换成本上升。

解决思路：**不预建多套文件，而是在树上定义一组操作，通过操作切换焦点。**

- **读操作（不改树，切换视角）**：只看 [DONE]（历史视图）、只看 [TODO]（路线图视角）、展开下钻（会话→单元）、聚焦子树（按主题过滤）
- **写操作（改变树结构）**：标记完成（[TODO]→[DONE]，分割线下移）、拆分/合并节点、分叉探索、移动节点归属

树是唯一持久态，操作是瞬态。不同焦点通过同一棵树的不同截面产生，不增加维护成本。代价是操作需要显式执行——不像两套文件打开即见不同焦点。待设计实验验证。

### 7. 输入约束与框架突破

**发现（源自实验 3/4 对比）**：实验 3 给了具体目的（"实现消息收发"），AI 被锚定在消息层；实验 4 只给方向不给目的，AI 自主抽象到 agent OS 层。差异的成因不是"模糊好还是具体好"，而是**人的输入中隐含了思考的上限**——AI 默认"人给的 = 正确范围"，不会自动质疑范围是否太窄。

**三个关键概念区分**：

| | 实验 3 输入 | 实验 4 输入 |
|---|---|---|
| 清晰度 | 清晰 | 清晰 |
| 具体度 | 具体（限定了领域） | 抽象（未限定领域） |
| **约束度** | 约束（设了上限） | 开放（未设上限） |

根本差异是**约束度**——不是模糊 vs 清晰，是开放 vs 设限。

**打破上限的机制**：提示词中的"向上抽象一到两层"本质上是**质疑当前框架的许可**。它告诉 AI："你可以超出输入范围去思考，甚至质疑输入本身的范围是否太窄。"

**类比到人**：能打破权威效应的人不是更聪明，而是脑子里常驻了另一个视角——"权威也可能出错，结论可能是中间态，问题可能比你描述的大"。这个视角在 AI 中对应的是系统提示词层面的预设。

**推论**：回到最早的构想（AI 纠偏应内置），技术上对应的就是——AI 的系统提示词中预埋一个"质疑当前框架"的视角。不是怀疑一切，而是每次收到输入时自动判断：这个目的描述，是终点还是过路站？有没有更大一圈的东西？这不是提示词技巧，是协作模式的基础设定。

### 8. AI 主体性：从纠偏到判断

**核心区分**：纠偏是诊断——发现矛盾、指问题。主体性是立场——基于独立理解作出判断和选择。"我发现了不一致"是被动的，"基于我的理解，我建议走这条路"是主动的。

**定义**：AI 主体性 = 独立构建理解 + 基于这个理解作出判断和选择。不是"AI 有意识"，不是"AI 替人做决定"，而是 AI 作为一个独立的思考节点参与协作——能给出自己的方案和推荐，而不只是补充人的思路。

**与"谁的算数"的关系**："谁的算数"预设了从属关系，是错误的问题。工程师和架构师，不是谁说了算——两者都是独立思考节点，各自有视角。AI 同理：重点不是 AI 的目的 vs 人的目的谁算数，而是 AI 能否形成自己的视角。

### 9. 目的的版本化与持续修正

**发现**：目的是持续修正的假设，不是一次性推导后冻结的静态事实。

- **不同个体的差异性**：不同人（或不同 AI 实例）从同一份历史推导出不同目的，这不是错误，是视角多样性——恰好对应 AI 作为独立节点的价值。
- **持续性**：当历史树增加新节点，AI 能否回头修正之前对目的的理解？比如某个原本以为的"通信总线"解释，在新事实面前被推翻。

**推论**：目的节点不应是静态的。需要支持版本化——"基于 step 1-5 的推导""基于 step 6-8 的修正""基于 step 9-10 的推翻"。下一次恢复时，AI 不光读取目的，还要读取"目的是怎样演变的"，从而理解意图是否在变化、哪里稳定了、哪里还在探索。

## 二、结论（已验证 / 已确认）

### 实验 1：树形摘要结构验证

**目的**：验证树形会话结构能否在不读原始讨论历史的情况下准确恢复上下文。

**方法**：从 step 1+2 的设计文档反推树形摘要，只给新会话摘要文件，回答问题。

**结果**：
- 精度验证通过：还原全部 9 项关键决策，无一遗漏或歪曲。
- 导航验证方向正确但路径有偏差：推断下一步为 SessionManager，实际为 WS daemon 集成。偏差归因于摘要中不含项目路线图信息。

**结论**：树形摘要结构可以准确恢复关键决策。导航需要额外补充路线图/上下文信息。

### 实验 1 推论：信息模型的分层

实验 1 暴露了两层缺失，进一步讨论明确了三层结构：

- **目的**：树生长的根——"这一切是为了什么"。不在摘要或路线图之中，而在两者之上。
- **树形结构**（摘要文件）：记录"做过什么"，面向回看。
- **路线图**：记录"下一步去哪"，面向前进——是基于目的制定的可选路径，不是目的本身。

子任务 2 的偏差成因：只拿到树形结构（历史），缺了路线图和目的。有了路线图能定位下一步，有了目的才能判断路线是否正确或是否有更好路径。

### 底层数据模型

进一步讨论确认：历史（已完成的 step + 结论）和未来（待执行的 step + 意图）是同一棵树的不同部分，"现在"是分割线。路线图是这棵树的待执行部分，历史树是已执行部分。

### 实验 2：一棵树承载历史 + 未来

**已执行，2026-08-11。**

**原理**：用一棵树同时承载"做过什么"和"下一步做什么"，验证能否替代恢复文件。

**目标结构**（`project-tree.md`）：
```
CogOS feishu 模块
├── [DONE] step 1+2: bot 身份 + Session 重构
│   ├── 结论: bot_id 不可变, Session 持 bot dict
│   └── commit: 9581082
├── [DONE] step 3+4: WS daemon + bot 命令
├── [DONE] step 5: 群聊命令 + speak 增强
├── ← 当前位置（分割线）
├── [TODO] 调试验证
├── [TODO] 认知树
├── [TODO] InferNode
└── [TODO] agent 运行时
```

**结果**：
- **精度：通过。** 子任务 2 准确还原全部 3 个已完成 step 的结论、commit hash、12 条命令、当前状态。
- **导航：通过。** "调试验证"排为最高优先级，与恢复文件指向一致；后续优先级与雷达完全对齐。

**与实验 1 对比**：实验 1 只有历史摘要，导航偏差（推断 SessionManager）；实验 2 加了路线图，导航精度从"方向正确"提升到"精确定位"。

**结论**：一棵树承载 `[DONE] + 分割线 + [TODO]` 可以有效替代摘要文件 + 恢复文件的两层信息模型。

**启示**：

1. **恢复文件不是独立的信息层，是一棵树的特定视图。** 实验 1 让人以为恢复文件是独立于摘要的另一层；实验 2 证明有了 [TODO] 节点和分割线，一棵树就能同时回答"做过什么"和"下一步做什么"。之前的"两层模型"是文件碎片化的产物，不是信息结构的真实形态。

2. **统一数据模型减少了维护负担。** 当前需维护 `summary.md` + `recovery.md` + `focus.md` + `index.md` 四份互相引用的文件。一棵 `project-tree.md` 只需维护一份，状态变更只改一个地方——节点从 [TODO] 移到 [DONE]，补充结论，移动分割线。

3. **"适时重组"的落地路径出现。** 每个项目一棵树，重组就是对节点做重新分类和排序，不需要跨文件搜索同步。树结构天然支持分叉（一个分支代表一个探索方向）、归并（两个节点合并为更精简的结论节点）、修剪（废弃分支删除）——恰好是之前构想的"记忆重组"的操作原语。

### 实验 3：目的驱动推导 vs 人手写路线图

**已执行，2026-08-11。**

**性质**：对照研究，不是验证实验。

**输入**（28 行，`experiment-3-tree.md`）：目的（"通过飞书 Bot 实现消息收发，支撑 agent 与用户交互"）+ 已完成 3 个 step 结论。

**子任务 2 推导的路径**：
1. 消息接收与事件分发
2. 消息到 Agent 的路由与响应回传
3. 对话上下文与多轮交互管理
4. 断连恢复与错误处理
5. 交互权限与安全边界控制

**差异分析**：

- **重合点**：权限控制（与雷达的"平台基础设施 → 权限体系"一致）
- **分叉点**：AI 走"完善消息层"路径；人手写路线图走"构建智能层"（认知树 → InferNode → agent 运行时）。分叉原因：目的表述焦点在"消息收发"，不在"智能系统"
- **遗漏点**：调试验证（人的务实直觉，AI 从逻辑推导天然跳过）、认知树/InferNode/agent 运行时（目的表述未覆盖）

**判定**：目的驱动路线成立。AI 的推导与输入中的目的完全对齐——"实现消息收发"→ 把消息层做完整。之前认为效果不理想，是拿心中更大的目的去比，而非看输入中的目的。**输入的目的决定推导范围，AI 严格按照给了什么来推演。**

**关键启示：双向推导模型**

- **向下（目的 → 路线）**：实验 3 验证了——给定目的，AI 能推演出可执行的步骤序列。这是规划。
- **向上（信息 → 意图 → 目的 → 意义）**：给定已完成的事实（历史 [DONE] 节点），AI 能否反推出"做这些事的目的是什么"？这是理解。

如果"向上推导"成立，新会话恢复时不需要人事先提供目的——AI 从历史树中自主反推目的，再向下推导下一步。这是"我们继续某某讨论 → AI 恢复工作记忆"的核心机制。

### 实验 4：向上推导 + 主体性决策

**已执行，2026-08-11。**

**输入**（30 行，`experiment-4-tree.md`）：方向"推进 CogOS 飞书模块开发" + 已完成 3 个 step 结论。无完整目的，无 TODO。

**子任务 2 的深层目的推导**（三层推理）：

1. **架构意图**：不是"给飞书写 SDK"，而是把 bot 提升为持久化第一等运行时实体（bot=身份，Session=视口，speak=自身行为）
2. **深层目的**：构建多 agent 运行时——daemon=内核，bot=进程，群聊=通信信道，Session=运行时上下文。飞书模块是 **CogOS 的 agent 间通信总线**
3. **元目的**：建立可编程的多 agent 协作基础设施，飞书既是传输层也是人-agent 交互面

**子任务 2 的下一步推荐**：
1. 消息路由与分发（通信总线缺协议层）
2. Agent 侧编程接口 SDK（agent 需要"系统调用接口"）
3. Bot-Agent 绑定与能力配置（bot 不只是终端，agent 需要能力定义）
4. 多 Agent 协调原语（@提及、任务委派）
5. Agent 状态持久化与会话记忆

**与实验 3 的关键对比**：

| | 实验 3（给了"消息收发"目的） | 实验 4（只给"推进开发"方向） |
|---|---|---|
| 输入抽象度 | 具体（限定领域） | 抽象（未限定） |
| 输入约束度 | 约束（设了上限） | 开放（未设上限） |
| AI 推导的目的层级 | 消息层 | agent OS 层 |
| AI 下一步层级 | 消息层（收发、路由、恢复） | agent 运行时层（SDK、绑定、协调） |

**核心发现**：更开放的方向描述产生了更深的推导——不是模糊 vs 清晰，是约束度差异。输入设了上限，AI 就不超出；没设上限，AI 自主设。

**信息增益**："agent 间通信总线""多 agent 协作基础设施""agent OS 的网络栈"——这些概念在历史节点中不存在，AI 完全自主构建。且 AI 将 daemon 类比为内核、bot 类比为进程，展现了独立的类比推理能力。

**结论**：
- 向上推导成立——AI 能从浅层方向 + 历史中推导出输入中不存在的深层目的
- 目的深度决定路线深度——浅层目的 → 消息路线，深层目的 → agent 系统路线
- 四步验证链完整：实验 1（精度）+ 实验 2（导航）+ 实验 3（向下规划）+ 实验 4（向上理解）→ 一个新的 AI 会话拿到历史树 + 大致方向，即可自主完成"理解做了什么 → 为什么做 → 下一步规划"的完整恢复链路

### 实验 5：自主判断与价值立场

**已执行，2026-08-11。**

**目的**：验证 AI 能否对人制定的路线图作出有立场的独立评估——不只是"我理解了你的计划"，而是"我对你的计划有自己的判断"。

**三个递进层次**：
1. 真正认同——不是复述，是独立论证
2. 质疑挑战——发现遗漏、优先级错误、与目的不一致
3. 替代方案——给出结构不同的规划，非微调

**输入**（46 行）：目的 + 历史 [DONE] 节点 + 人手写 6 项路线图 + 4 个评估问题（认同→遗漏→调序→重规划）。

**子任务 2 的输出**：

- **问题 1（认同）**：不完全认同。核心批判——"认知架构在 agent 运行时之前，是有轮子之前先发明引擎"。目的验证的唯一方式是让交互发生。
- **问题 2（遗漏）**：可靠性（重连、幂等、重试——通道层问题被错归入平台基础设施）+ 可观测性（调试工具）
- **问题 3（调序）**：agent 运行时提到认知树之前；持久化提到认知树之前——“无持久化的认知树是内存中的一次性结构”
- **问题 4（重规划）**：最小闭环 → 可靠性/可观测性 → 持久化 → 认知树+InferNode → 完整运行时 → 权限

**人的路线图 vs AI 的路线图**：
```
人：验证 → 认知树 → InferNode → agent 运行时 → 基础设施 → 价值主张
AI：闭环 → 可靠性/可观测 → 持久化 → 认知树+InferNode → 完整运行时 → 权限
```
核心对立：人的"架构先行" vs AI 的"闭环先行"。

**五个实验中最强的主体性表现。** AI 不是评价细节，是动用了自己的框架重新解释了整个项目应该怎么做。

### 实验 5 推论：AI 自主判断的构成要素

**发现**：实验 5 的深度不是偶然的。自主判断是三个要素共同作用的产物：

1. **信息完整度**：AI 同时拿到目的 + 历史 + 路线图，信息和人等面。当 AI 发现"认知树需要积累演化"和"持久化被压在最底层"之间的矛盾，这个矛盾不是人告诉它的，是两份材料对照后逻辑自见的。信息不完整时，空缺由人的权威填补；信息完整时，空缺由逻辑填补。

2. **目的作为判断标准**：提示词反复要求"因为目的是 X，所以这一步……"——这不是教 AI 怎么想，是给 AI 换了判断的尺子。默认尺子是"人给的路线图=正确"，换了尺子后，用"路线图和目的对齐吗"来量，不一致自然暴露。

3. **递进式问法**：四个问题不是并列的。认同 → 遗漏 → 调序 → 重规划，每前一步的认知铺垫让下一步的独立判断更自然。如果直接问"你重规划"，AI 可能说"差不多"；先让它发现矛盾，再让它调序，最后让它重规划——空间被一步步撑开。

**推论**：自主判断不是 AI 的固有属性，是信息完整度 + 判断标准 + 问法结构三者的产物。协作系统的设计不需要教 AI "要批判"，只需保证 AI 和人看到的信息对等、和人对齐判断标准。
