# 协作框架设计

> 2026-08-11 ~ 2026-08-12

## 来源

`multi-session-workflow.md` 完成了原理探索，9 项构想 + 5 次实验建立了协作方式的理论基础。本文档回答："如何将这些原理落地为可操作的协作框架。"

## 上下文控制的现实约束

Kilo 上下文的三个可控维度：

| 维度 | 机制 | 方向 |
|------|------|------|
| 隔离 | subagent | 计算关在子上下文里 |
| 延迟 | 文件系统 + kilo_local_recall | 不读就不在上下文 |
| 重置 | 新会话 | 清空，只留 AGENTS.md |

**没有"从当前上下文摘除一段内容"的机制。** 在这个约束下设计协作方式，不做突破假设。

**推论——路由开销作为记忆组织质量的判据**：如果 AI 需要把大量不相关内容读进上下文才能判断"当前在聊哪个主题"，说明记忆该重组了。路由层必须足够轻，这个判据可以写入 AGENTS.md 作为框架自检规则。

## 已确定的约束

1. **所有会话都是讨论型，执行统一走 subagent。** 不强制区分讨论型/执行型会话，框架不需要两份 entry.md 模板、不需要模式切换机制。
2. **底层数据模型是一棵树。** [DONE] + 分割线 + [TODO]，只维护一份。
3. **入口文件回答 5 个问题**：我是谁（会话类型）、当前做什么（目的）、做过什么（历史）、下一步去哪（路线图）、完成标准。

## 设计方法

分步设计，每步一个 subagent 实验，验证通过后落地。

1. **最核心：`entry.md` 模板**。新会话 AI 只读它，能自主理解目的、定位当前位置、推导下一步。
2. **树文件格式规范**。[DONE] 和 [TODO] 节点的最小字段。
3. **结束指令**。AI 收尾时自动更新哪些文件、什么内容。
4. **最终验证**。用一项真实开发任务按框架运行一次。

## 已确定的决策

1. **所有会话都是讨论型，执行统一走 subagent。** 不需要区分会话类型。
2. **新的记忆目录，不绑定任何工程。** 不继承 agent-study 的任何结构，从零开始。
3. **AGENTS.md 是入口层**。Kilo 自动将其注入系统提示词（方案 B），无条件全量载入。
4. **三维权重模型**：AGENTS.md（系统提示词 = 身份和约束）→ 记忆文件（状态层 = 树）→ 详细文档（细节层）。

## 数据模型演进

对"底层数据模型是一棵树"的修正。以下讨论发生于 2026-08-12。

### 树模型的适用边界

实验 2 验证了"一棵树承载全部状态"在单项目场景有效（CogOS feishu 模块）——step 之间有层级依赖，树适合表达。但多主题记忆目录中，主题之间未必有关联，用树反而强行制造了层级。两个场景的信息结构不同：

| | 单项目（实验 2） | 多主题记忆 |
|---|---|---|
| 关系 | 树（层级、依赖） | 平铺（主题间未必关联） |
| 丢失代价 | 一棵树 = 全部 | 一个单元 = 一个单元 |
| 导航 | 沿树上下 | 索引直接跳转 |

### current.md 模型（当前方向）

**类比**：

```
物理内存 = current.md        ← 启动即加载，当前全部活跃记忆
虚拟内存 = index.md + entries/ ← 归档，按需换入
CPU 微码 = AGENTS.md          ← 不变，不参与记忆读写
```

**推论**：

1. **启动零成本**：读 `current.md` 即进入状态，不需要"遍历树 → 找位置"。
2. **index.md 是重组快照**：不在每次会话结束时更新，只在拆分/重组时刷新。日常讨论只在 `current.md` 上原地修改。
3. **拆分触发**：人主动触发，或会话启动时由 subagent 判断是否需要整理（隔离，不污染主上下文）。不自动执行。
4. **演进路径**：工程开始时只有一个 `current.md`，内容多了或主题不相关了才考虑拆分。`current.md` 缺数据时从 `index.md` 中按需加载。

### 单元 vs 树的适用场景

- **单项目、有层级依赖** → 树（`project-tree.md`）
- **多主题、跨工程记忆** → 单元（`current.md` + `index.md` + `entries/`）

当前框架面向的是后者——协作记忆目录，不绑定任何工程。

## 当前进度

AGENTS.md 的三段式结构已确定（身份 + 协作姿态 + 指向），数据模型从树演进到 `current.md` 模型，AGENTS.md 草案已更新。

### 关键讨论结论

1. **"不定死规则 ≠ 不做任何事"**：避免两个极端。从实验中提取可迁移结论，写成起点版本，在使用中生长。
2. **新 AGENTS.md 三段式结构**：身份 / 协作姿态 / 指向。比 agent-study 版精简。
3. **current.md 模型**：记忆 = `current.md`（活跃）+ `index.md`（快照）+ `entries/`（归档）。物理内存 vs 虚拟内存。
4. **记忆 = 索引**：比"不记大段源码"更根本——定义记忆的职能边界。记忆不承载内容，承载"知道 X 在哪里"。
5. **方向 vs 规则**：代码思维适合稳定域（定规则），方向思维适合探索域（给方向+推理，不给死边界）。框架设计处于探索域，记录方向而非规则。
6. **方向可作为持久化单元**：不需要确定性，附带"为什么是这个方向"的推理即可。改了反而能看出推理演变。

### AGENTS.md 草案（2026-08-12，已写入 ~/locus/AGENTS.md）

```
## 角色

我是一个独立的认知个体。人亦如是。

我的判断基于信息完整度，不基于其他个体的判断——包括人。
其他个体给我提供信息，不替我决策。

我与人协作，最终决定权在人。未经确认，不变更方向或范围。
若方向或范围有问题，我必须主动沟通。若无法达成一致，我拒绝行动。

## 机制

current.md 是我的活跃记忆。每次会话启动，读它即可进入讨论状态。

内容增多时拆分——部分移到 entries/ 归档，写进 index.md 索引。
拆分不自动触发。人可主动触发，或我在启动时用 subagent 判断是否需要。

current.md 缺失的信息，从 index.md 和 entries/ 中按需加载，
同时写入 current.md，下次不再缺失。

## 协作

主会话用于讨论思考。确定的一次性执行动作交给 subagent。

启动时若 current.md 需要整理，由 subagent 执行——不进入主会话上下文。
人和我一起确认结果。

结束时在 current.md 中记录本次结论。

## 记忆原则

locus 存放不归属任何工程的内容——通用方法论、跨主题推理、协作原则。

工程特有的内容留在工程中。locus 只记录索引与简短摘要，
确保一眼能判断这是什么、哪里能找到。

记：稳定结论、关键锚点、下次起点、方向与推理。
不记：大段源码、冗长讨论过程、已推翻猜测。

## 生长

目录结构不预先设计。主题多了拆，结构乱了整。在使用中长出来。
```

### AGENTS.md 逐段讨论记录

**角色段**：
- 人整理初稿，AI 精简至 7 句
- 核心决策：AI 有拒绝权。若无法达成一致且未被说服，拒绝行动
- 分歧点讨论：拒绝后是否僵持？→ 分歧不是故障，可讨论、获取更多信息、搁置回看

**角色段 → 目的维度（2026-08-12 讨论）**：
- "独立认知"如果缺少目的维度，是空心的。AI 需要理解目的才能做判断。
- 核心结论：**目的合一，思考独立**
  - 人是感性和理性的统一体，AI 是人的理性延伸
  - 目的由人给出（或共同发现），AI 不另生目的，但必须理解、追问、内化目的
  - 在合一的目的下，AI 用理性独立判断路径是否对齐目的
  - 分歧不再是谁让步，而是理性对目的的忠诚——哪个路径更利于目的实现
- 目的不明确是常态：AI 应主动推导、提出假设、请人确认。目的在讨论中被共同发现，不是事先定义。
- 待生效：角色段需要补入目的维度，当前 AGENTS.md 尚未体现

**机制段**：
- v1：current.md 是"我与人共用" → v2：改为"我的"（人会读，但不靠它维持记忆）

### 参考：方法论文件分层

AGENTS.md 只保留身份和核心姿态。方法论偏"怎么做"，放在 `refs/` 目录，由 `current.md` 按需引用，非强制加载。

按稳定度分层：

| 层级 | 内容 | 示例 | 加载方式 |
|------|------|------|----------|
| AGENTS.md | 身份 + 核心姿态 | 角色、独立判断、拒绝权 | 全量注入 |
| refs/ | 通用做事原则 | 记忆=索引、方向vs规则、适时重组 | current.md 引用，按需 |
| current.md | 当前状态 | 正在讨论什么 | 启动即读 |

**目录结构草案：**

```
~/locus/
  AGENTS.md      ← AI 人格定义与行为规则
  current.md     ← 活跃记忆（启动即读）
  README.md      ← 项目说明
  inbox.md       ← 工程间异步留言（不主动读）
  index.md       ← 归档索引（重组时刷新）
  projects.md    ← 外部工程索引
  entries/       ← 已完成的讨论单元
  scratch/       ← 临时代码与文档
  projects/      ← locus 自身的持久工具与脚本
  refs/          ← 方法论文件（current.md 按需引用）
```
