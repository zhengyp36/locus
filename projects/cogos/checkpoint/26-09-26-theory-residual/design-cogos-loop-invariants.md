# design｜环与不变量的重解

> **上接**：`design-cogos-minimal-agent.md`。本文件记录该草稿之后的讨论，两件事：
> **（一）三条不变量的重解**（两条被改写，一条被深化）——**部分内容推翻了总纲和 `handoff-cogos-scaffold.md` 的旧说法**；
> **（二）环的形态**（唤醒 / 念 / 真空 / cu / 打断重组）。
> 需要同步修的旧表述见 §三。

## 一、三条不变量的重解

### 1. "过去可寻址" → 改名"**时间线可寻址**"

**YZ**：时间线索就是过去可寻址。**agent 活在当下，不活在时间线里**；但 agent 可以把时间线的内容纳入当下——**过去的经历、未来的规划，都可以纳入现在**。

修正：

- 名字要改：范围不止过去，**还包括未来规划**（未闭合项、预约事件）。
- 我此前"槽持有时间线"的措辞要改：**时间线是资源，不是栖居地**；槽只是**有访问权**。

### 2. "后果绑定" → 后果是**权重**，不是经历的构成要件

**YZ 的质疑**：为什么经历要与后果绑定？后果应该是**经历上的权重**——后果明显 → 权重更高 → 更容易记住、不容易淘汰；后果不明显 → 权重较低。

**YZ 对"后果是什么"的定义**：后果 ＝ **关注点**，来源四类——

```
兴趣点          （内部，和我有关）
任务 / 目标     （内部，和我要做的事有关）
惩罚 / 付出代价  （外部，世界给的）
好处 / 奖励     （外部，世界给的）
```

**接受。这比"有/无后果"的判据好三点：**

1. **连续而非二值**——"算不算经历"要定阈值，权重不要阈值；
2. **与 `runtime-flows` §21 的权重合成了一个东西**（那节列的五个权重来源，主源其实就是后果）；
3. **最小 agent 更小**——不再需要"要不要记"的判据：**什么都记，权重决定留存**。

两点附带：

- **外部锚没丢**：惩罚/奖励是世界给的，Zenil 那条仍成立；不变量②不推翻，只是机制角色从"准入"变成"权重"。
- **"兴趣点"形成环**：兴趣 ← 自我 ← 权重沉淀 ← 兴趣。这是 §21 那条正反馈，所以**衰减 + 归一化是必须的，不是可选的**。

**保留一处修正**：**内容与权重是两栏**。只留标量权重会丢掉"到底发生了什么"，而这个"什么"至少三处要用——**意外**（预测≠实际，主动思考的主燃料）、**取回判相关性**、**学习**。所以：

```
(时间戳, 处境, 选择, 发生了什么, 权重, 闭合位)
                              ↑ 由后果（关注点）算出
```

**权重是后果在机制里的角色，内容是后果的实体。**

### 3. "单一归属" → **共切面**，且"我"不需要常驻

**YZ**：时间线似乎只是**一个维度**（过去/现在/未来），可能还有其他维度——**我的动机 / 目标 / 兴趣点**。而这些其他维度**都在"现在"这个时间点上**，像一份**快照**，是从过去积累/变迁成为现在。这些共同构成"单一归属"，即那个**"我"**。

**一个小纠正**：时间线是**轴**不是维度。维度是**切面上的坐标**（动机/目标/兴趣/权重，它们同时成立于"现在"）；轴是**串起切面的那条**。

```
纵轴：时间线（过去 / 现在 / 未来，有序，可寻址）
          ↓ 在某个时刻取一刀
横切面：当下的量（动机 / 目标 / 兴趣 / 权重 …）
"我"  ＝ 这个切面
```

- **横切面不是独立的东西，是纵轴的结果**：那些"当下的量"就是经历被压缩后剩下的高层节点（`runtime-flows` §20/§21）。所以两头是一件事：**时间线 = 积累过程，切面上的量 = 积累结果**。
- **"活在当下"在这里落地**：只有切面"活着"；时间线是可访问的资源；但切面上每一个量都是纵轴给的。

**精确含义：共切面。** 不是"只有一份数据"那么弱，而是**所有维度必须取同一个 now、同一份积累、同一套权重**。反例最清楚：动机取去年的截面、权重取今天的 → 那就不是一个人了。**多自我 ＝ 各自切各自的刀。**

**实用推论（意外收获）："我"不需要常驻。** 最小 agent 每次醒都**重建** material；靠什么保持是同一个我？**只要来源唯一**——同一份时间线、同一套权重——重建出来的就是同一个我。

> **单一归属不是要一个常驻的"自我对象"，而是要"来源唯一"。**

**可操作的检验**：换一条流 / 换一次醒，**权重与偏好必须读写同一份**；若另起一套 → 破了。把切面重建一次，若动机/兴趣和上次对不上（又没有新后果支撑）→ 破了。

## 二、环的形态

### 1. 环 ＝ 一次唤醒的弧

**YZ**：那个环像是一个**运行态**。什么是唤醒？外部事件会唤醒，内部生念也是唤醒。念与念之间有歇。**agent 不是连续的，是离散的，靠那一念一念串起来。**一个长任务可能是连续的，但长任务不会中断那个念——那个念可能与当前长任务相关（变成**回看**），可能不是回看而**产生新方向**，也可能与任务无关、是**另一个未闭环任务的张力**。agent 会处理某种**真空状态**（念与念之间）。环＝**唤醒触发的一次流动**，可长可短。

**用"主槽"给三个词下机械定义**：

```
唤醒 = 主槽装载一次内容      （来源：外部事件 / 生念 / 预约事件）
真空 = 主槽只剩锚            （没有当前内容）
发呆 = 真空 + tick 判"无内容"（不调 LLM，§12）
```

于是"运行态"＝ 环在跑；"念之间的歇"＝ 真空。**环是 agent 的原子，不是它的循环。**

### 2. 念 ＝ 点火，流 ＝ 燃烧，基调 ＝ 易燃度

YZ 早先既说"念是起跳动作"，又说"念像基调"。两句可并存：

```
念   = 点火（一次起跳）      ← 不是时长，是起点
流   = 烧起来的那段（＝一次环，可长可短）
基调 = 未闭合张力给的【易燃度】，提高点火概率
```

长任务就是那一次点火烧出来的长流。长流内部还能嵌念：回看（嵌套子）/ 新方向（分叉）/ 别的任务（张力穿透）——对应 `runtime-flows` §19 的三种拓扑。

### 3. "方向"不是环里的一项

```
唤醒 → 取 → 选择 → 世界 → 后果 → 存 → 沉淀
  ↑                                      │
  └────────────── 方向 ←─────────────────┘
```

**方向没有存在任何地方**——它是**沉淀改变了下一圈的"取"**。所以环不是相位序列，是**自指的弧**：产出即输入。**沉淀是闭合的那一环**；没它，下一圈与这一圈一模一样，环退化成重复。

### 4. cu 实现

**YZ**：loop 可以用 cog-unit 实现。cu 是一个起跳，然后**直接没有工具调用就结束**；有些是任务，可以调一个 `finish` 表示结束。因为**一旦一轮结束，重复喂给 LLM 就是空转**，所以它天然应该停下来。cu 前需要**装载**（这不是 cu），cu 后需要**沉淀**（这可能是另一个 cu，或需做成 cog-func / cog-object）。

**cu 天然就是那条弧**：模型不再调工具时结束（`runtime.py:103` → `_finish`），空转天然没有。而且 cu 内部的 `material.append`（`runtime.py:134-142`）是对的——**弧内 append 没问题，只有跨环 append 才是病**。

**环 ＝ 机制的三段夹一个 cu**：

```
唤醒 = 装载（机制） → cu（模型） → 沉淀（机制 + 可能的模型）
```

装载/沉淀不能在 cu 内：装载定义弧的 `material`（必须在弧前，且不能做成弧的子 cu）；沉淀需要弧的产物（必须在弧后）。两者都不需要完整模型弧。

**代码接缝已经对上**：

| 环里的位置 | 现成钩子 |
|---|---|
| 后果采集 | `on_tool_call`（`runtime.py:113`） |
| 沉淀点 | `on_done`（`runtime.py:164`） |
| 装载补齐 | `on_ready`（`runtime.py:156`） |
| 嵌套 | `parent` / `children`（`runtime.py:37,172`） |

**嵌套的对应**（`_all_children_done` 会卡住父 cu，`runtime.py:68`）：

```
回看 → child cu      父等它 → 插入型 ✓
迸发 → 独立 root cu  不阻塞父 → 旁路型，产出投递给主槽 ✓
```

**要改一处**：`MAX_TOOL_ROUNDS = 10`（`consciousness.py:14`）是硬常数；弧长应由**预算 / 回看判停 / 中断**决定。

**`finish` 的定位（修正）**：不需要它来结束——不调工具就结束了。它的价值是**显式产出"这次弧的结果是什么"**，而这正是**"预测"的载体**：

```
cu 结束：finish(声称的结果)   ← 预测
世界/验收：实际后果           ← 实际
两者比较 → 意外 → 权重 + 主动思考的燃料
```

模型自述不能当验收（`handoff-cogos-scaffold.md` §7.6），但**能当预测**。所以 `finish` 不是终结器，是**预测器**。

**cog-func / cog-object：按两轴分，不必新造运行时**

```
            无状态            有状态
无模型      cog-func          cog-object
有模型      （少见）           cu
```

- **cog-object** ＝ 有状态、无模型：`Store`（经历轴）、`Anchor`（锚）、`Weights`（权重/偏好）
- **cog-func** ＝ 无状态纯函数：`assemble`（装载）、`cut`（切分）、`distance`（距离）
- **cu** ＝ 有模型、有生命周期、**必终止**的弧

```
环 = cog-object(Store/Anchor) → cog-func(装载) → cu(弧) → cog-func(记录/算权重) → 可能 cu(概化)
```

**归并**：**沉淀 ＝ 眼动的增量形；眼动 ＝ 沉淀的批形**——同一操作的两个粒度。

### 5. 打断与重组（YZ 修正）

**YZ**：cu 可能被打断（**回看**、**上下文过长**），所以 cu 不是绝对 append，也不全是自然停；可能在**中间停**，停了之后**重新组装成新的 cu**。于是 cu 确实是 append（因为一停，下一次就是一个新 cu），但**这是同一个环，一个环可能是多个 cu**。

```
唤醒（点火）
 └ 环（同一主题）
     ├ cu₁ （cu 内是 append）
     ├ [打断] 回看        → 子 cu → 重组（插入结论）
     ├ [打断] 上下文过长  → 重组（压缩 + 重新取回）
     ├ cu₂ …
     └ 做完 → finish + 沉淀 → 停
主题变了 → 新唤醒 → 新环
```

**关键推论：打断点就是"可以不是 append"的唯一机会。**

| 打断源 | 重组类型 |
|---|---|
| 回看 | **插入型**：把子 cu 结论并进来，再继续 |
| 上下文过长 | **压缩型**：压掉旧 material + 重新取回（**环内微版眼动**） |

所以"上下文过长"不是坏事——它是**压缩的强制入口**；没有它，环内会一直 append 到爆。

**"打断 → 重组" 就是 "存 → 取"**：中断时把弧的状态存下来（目标、做过的选择、后果、未闭合处），重组时取回重建 material。于是**不需要两套机制**——环内重组、跨环、跨唤醒，是同一对动作，只是 scope 不同。这也让"取回"的地位更重：**它是环内重组的前提**。

**环的身份靠什么保持**：同一个目标/主题 + 同一个未闭合状态。这两件正是经历轴记录的形态 `(处境, 选择, 后果, 闭合位)`：

> **同一套记录格式，三种 scope。**
> cu 内 → 不需要（append 就够）；环内重组 → 要；跨唤醒 → 要。

**判据（接 §19）**：

```
主题没变 → 同环的新 cu（重组继续）
主题变了 → 新的点火 → 新环
```

**终止保证要说两层**：

```
cu 保证：不空转【一轮】（不调工具就停 / 被中断）
环 保证：不空转【一圈】（做完 → finish + 沉淀 → 停）
```

后者不能靠模型自己想起来，**得由机制在环的收尾处兜住**。

## 四、未定 / 待办

1. **`finish` 的具体形态**：产出什么字段（声称的结果？未闭合处？下一步？）——它同时是"预测"，字段设计直接影响意外的可算性。
2. **`MAX_TOOL_ROUNDS` 换成什么**：预算怎么给（时间？代价？回看判据？）。
3. **环内重组的压缩策略**：什么该压、什么必须留（未闭合的不能丢）。
4. **权重的构造式**：关注点四类怎么合成一个权重、衰减率、归一化（仍是上游旋钮）。
5. **装载的代价**：取回要不要用模型（相似度）？还是先机械、只在不济时调模型。
6. **真空的判定**：发呆判定"无内容"用哪个信号（未闭合计数？张力？）。
