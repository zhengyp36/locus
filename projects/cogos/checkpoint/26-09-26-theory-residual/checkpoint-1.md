## 一、已澄清结论

### 1. "多环境"不存在，撤掉

- **结论**：不存在多个环境，只有**一个世界、多种来源**。
- **论证**：多环境只有两种读法，都不成立——
  1. 多世界多实例（一环境一个我）→ 撞 §1 唯一性（槽唯一／经历轴唯一／signature 唯一 → 不会长成两个我），**已被裁决**；
  2. 多世界一实例（同一个它轮流待各处）→ 按定义即"一个世界多种来源"，**不是多环境**。
  → 原第 5 项（单 vs 多环境）**自溶解**，不必待讨论。
- **正确切分轴 = 来源，不是环境**：
  - 人（飞书群／邮箱 = 同一来源域的两个通道）——后果软：回应／沉默，带关系；
  - 物（仓库：代码／文档）——后果硬：工具结果，可判定、可反复。
- **理论已如此处理**：§5 段有 `来源`（**开放词汇**）；§8 机制不预设来源种类。"人 vs 物"只能作**标签**，硬编进结构即违规（机制替模型做分类判断）。
- **直面整个世界无问题**；代价只是**槽唯一 → 需装载裁决**（= §4 事件入口，产物是"装载＋续或切"），非新概念。
- **连带修正**：§14 第 4 项措辞 "单 vs 多环境" → 应改为"**一个世界、多种来源、多个参与者**"（是否改文档待定）。

## 四、动手纪律（本次新增 · 已同意）

**每一步动手前，先回到整体架构定位。**

- **形式（三问）**：
  1. **落点**：外圈还是内圈？哪一段／哪根箭／哪个字段？
  2. **接口**：读谁的输出、写给谁？
  3. **差别**：动完，环上哪一处从"不转／空转"变成"转"（＝可观察判据，§9／§12-①）。
  → 三问答不全 = 这一步其实是"搭最小／另起炉灶"，警号。
- **为什么**：零件**循环依赖**（取回→权重→后果→整理→重演→活跃度→取回），"最小"已作废（#18），**无自然动工顺序**；顺序只能从**依赖图**读出，而依赖图＝外圈／内圈环图。回到架构＝回图上找"当前唯一能动的零件"（§9 三纪律）。
- **两条限制**：
  - "回到架构"是**钉到环上**，不是逐条通读 §0~§14 的仪式；
  - 架构本身也在长（§9 只增不改／§10 消解矛盾／§12 填缺口）→ **先定位再动手；定位不上，先停下问"是不是架构错了"**，不拿过期图硬套。
- **示例**：当前"怎么动手 ＝ 接后果的读者"，位置＝**外圈输出端与内圈输入端的接缝**（缺失的 `段.后果 → 权重` 那根箭）。

## 六、设计外圈 vs 现状外圈（对照 · 2026-09-17）

### 设计（§0／§2／§4）

```
外部事件 / 到点 / 生念            ← 事件入口独立于感知；感知只是生产者之一
        ▼
入口裁决：装载 ＋ 续或切          ← 产物不是"事件"，是决定
        ▼
装载三节：过去(经历+目的) / 现在(活状态) / 刚刚(事件源)
        ▼
      cu（必有 finish）
        ▼
停：切点＝误差(预测 vs 后果)，超阈才切   ← 不是"有没有事件"
        ▼
沉淀：落成"段"(id/t,host/来源/内容/预测/后果/结/thread/refs)
        ▼
升格：够格的写进锚槽
        ▼
判：还有燃料吗(距离/张力/队列)；无→真空，压力转向朝内
        └──写回／回看──▶ 回到装载
```

硬要求：环＝**机制三段夹一个 cu**（装载→cu→沉淀）；**引用实时记**（`continue_of`／`cut_by`）；段与引用**只增不改**。

### 现状（代码）

```
飞书 p2p 消息 ─┐
              ├─▶ consciousness.on_message ─▶ 追加到 self._context（常驻、无上界）
内部事件队列 ──┘     (app.py:147 / perception.py:14)         │
                                                            ▼
                                        cu：多轮工具，MAX_TOOL_ROUNDS=10
                                             (consciousness.py:83)
                                                            ▼
                              停：finish_reason / interrupt(超轮数)
                                                            ▼
                              沉淀：回复文本 append 回 _context
                                   (工具结果只活在 cu 内部)
                                                            │
                                                            └─ 未 send_msg 则自动回一条
```

### 并列对照

| 环节 | 设计 | 现状 | 差 |
|---|---|---|---|
| 事件入口 | 独立；外部／到点／生念**平级** | 外部(仅 p2p)＋内部事件，不分级，直接喂 cu | 少"裁决层" |
| 入口产物 | **装载＋续或切**的决定 | 直接一次 `on_message` | 少"切" |
| 装载三节 | 过去／现在／刚刚 | **只有"现在"**，且是**常驻 `_context`** | 三节全无；常驻是设计要废的 |
| cu | 必有 `finish` | 有，多轮工具，≤10 轮 | ✓ 基本对齐 |
| 停 | **误差(预测 vs 后果)超阈** | `finish_reason`／超轮数 | 无预测、无误差、无阈值 |
| 沉淀 | **落段**(含预测／后果／结／thread／refs) | **无段**；回复文本进常驻 context | **外圈断点** |
| 升格 | 有 | 无 | 内圈首环 |
| 判 | 燃料判断(距离／张力／队列) | 无，处理完即等下个事件 | 少"要不要继续" |
| 写回／回看 | 回到装载 | 无 | 少回路 |
| 朝外／朝内 | 两种装载源；朝内不占主槽 | 只有朝外 | 无朝内 |
| 三供给 | 草稿空间／后果绑定／停下来的机会 | 草稿空间 ✓；后果绑定 ✗；停 △(超轮数＋锁) | 大体未实现 |
| 引用 | 实时记 `continue_of`／`cut_by` | 无 | — |

### 四点观察

1. 设计的**外圈最小闭合＝装载→cu→沉淀**（§2）；现状**中间 cu 是好的，两头都缺**：装载退化成常驻 context，沉淀没有。
2. **沉淀是断点，也正是"后果"的落点**：`后果` 是段的一个**字段**，段存在才有字段 → "先稳外圈"与"接后果读者"在**沉淀**这一步重叠：**先落段，才有后果可读**。
3. 沉淀一落，就带出两个硬要求：`t,host` 坐标、`refs` 实时记（`continue_of`/`cut_by`）——没有它们段落不准。
4. "先稳外圈"落到三问：**落点**＝外圈中段（沉淀）；**接口**＝读 cu 的 finish／工具结果，写给经历轴（当前不存在，需新建）；**差别**＝每弧稳定产出一条段（可数可看）。

## 七、稳外圈：思路与零件序（2026-09-17）

### 7.1 思路

按**换零件**思路，一步一步靠近目标；**先把外圈稳住**，不必一次讨论过多，外圈稳了再推内圈。理论依据：外圈全落在 §8 **机制层**（可先验定死），内圈落**价值层**（等经历长）——先稳外圈是"能先做的那一层"。

**范围**：本轮只做外圈——入口／装载／cu(已有)／停／沉淀／写回＋续切引用。**升格、判不在本轮**（吃权重／张力，属内圈衔接）。**判据**：外圈"稳"＝它变成一个**可观察、闭合的响应环**，不是"功能齐了"。

### 7.2 外圈零件序（待定）

| 序 | 零件 | 依赖 |
|---|---|---|
| 1 | **沉淀（落段）** ← 第一刀 | — |
| 2 | 写回 ＋ 装载三节（段接回装载，形成回路） | 1 |
| 3 | 续／切引用（`continue_of`／`cut_by` 实时记） | 1 |
| 4 | 停／切点（误差，需"预测"） | 最靠后 |

（判／升格 ＝ 交接内圈，不在外圈。）

**第一刀＝沉淀的理由**：读 cu **已有**产物，不需别人先改；改完**能看出差别**（每弧一条段）；§2 外圈最小闭合＝装载→cu→沉淀，现状**中间好、两头缺**；沉淀同时是"**后果**"的落点。

### 7.3 第一刀细化

- **挂点＝弧结束**（`on_done`），**非**每次工具调用（§5 弧内多轮工具往返不进轴）。
- **新建**最小经历轴 store（append-only），仿 `ScratchStore`（`tools.py:376`）；新增 `agent/experience.py` ＋ `tests/agent/test_experience.py`。
- **改动一处**：`consciousness.on_message`／`on_done` 落段；`on_tool_call`（`consciousness.py:65`）**捕获 calls＋results**（现被丢弃）以写"后果"。
- **段最小字段**：`id / t / 来源 / 内容 / 后果 / 结`；`预测=None`、`refs=[]`、`thread=id` **先占位**。
  - **修正（09-18）**：原写 `t,host`，**`host` 撤回**——位置已定为"不需要／可设计掉"（见 §十）。设计文档 §5 的 schema 里虽有 `host`，但最小落段**不填它**。
- **可观察判据**：① 一消息→恰好一段；② 字段齐全（空值合法）；③ 重启可读回；④ 弧内多轮工具只产一条段。
- **冻结**：`perception`／`phone`／`tools`／`runtime`／`timer`／`terminal`。
- **防膨胀**：坐标只用 `t`（现成的 `time`）；**不引入位置**；`refs` 先空；**不引入**取回／权重／误差。
- **三问**：落点＝外圈中段（沉淀）；接口＝读 cu 的 finish＋工具结果，写给**新建经历轴**；差别＝每弧稳定产出一条段。

### 7.4 通道（想／说／沉默）与稳外圈的关系

- **E0 装配模型**（09-13/14 会话 #12）：**想 ＝ `content`**（私有、进记忆）／**说 ＝ 调 `send_message`**（对外、带回执）／**沉默 ＝ 默认态**；来源靠**结构＋标签**。通道区分**机制层可判**（`content` vs `tool_calls` 两个原生字段）。
- **配套硬事实**：说需要**显式动作**；**行为由后果塑造，不由教学塑造**；想是稀有的"开口前私下盘算"；静默合法。
- **现状违背该模型**：`consciousness.py:96` `if text and ... not sent:` → `content` 有文本即**自动当"说"发出**（把"输出＝回复"这个先验写死了）；与 `config.py:126` 提示词"需要回复时用 send_msg"**自相矛盾**；想／说混在同一 `_context`，机制分不出；沉默**不是**默认态。
- **为什么卡住稳外圈**：段的 `内容`／`后果` 直接依赖通道——**后果只对"说"存在**（回执／沉默），想对外不可见、**无后果**、只该进段／记忆；**沉默要能被机制识别**才能落"后果＝沉默"。→ **通道是沉淀的前置语义，不是新零件。**
- **待聊**：通道的**定义**（想／说／沉默各自算什么、边界）还是**落点**（在 cu 输出上怎么判、怎么进段）。

## 八、与世界交互：分类框架（初版 v2 · 未成结论 · 待讨论）

> 本节为讨论底稿；结论形成后再改写。
> 原则：**抛开已有工具**看需要什么；**不照搬人的交互方式**（agent 与人不同）。

### 8.1 三轴 ＋ 坐标

1. **对象**：**人**（其他 agent 也算人）｜ **环境**（非人）
2. **方向**：**进**（收／读）｜ **出**（发／动）
3. **介质**：文本／图片／音频／文件／二进制……（**不增通道，只决定理解器／生成器**）
- **坐标**（非交互，是"自我在哪"）：**时间**（机制给）／**位置**（待设计）

映射：

| 对象 | 进 | 出 |
|---|---|---|
| **人** | 收（消息、文件） | 发（文本、文件） |
| **环境** | 读（文件／网页／终端状态／远端状态） | 动（写文件／命令／HTTP／远端执行） |

### 8.2 关键简化

- **"看"不是通道，是理解器**：挂在"进"的介质上——文本直接理解／图片调视觉模型／音频调多模态（后续）。人不是按器官（听／说／看）划分，我们也不按。
- **"上网、操作文件、执行命令、登陆某台电脑"不是四类，是同一个 `出·环境`**，只是 **target 不同**（网络／本机文件／本机 shell／远端主机）。
- **"飞书／邮箱"不是两类能力，是同一个 `人` 通道**的不同 target。
- → **原语只剩四个**：**进**／**出**／**坐标**／**理解**（介质→内容，内部、不对外）；其余全是**参数**：对象／target／介质。

### 8.3 现状对照（按新分类）

| 框架位置 | 现状 | 差 |
|---|---|---|
| 进·人 | phone 消息，**仅 p2p、仅文字** | 缺群聊／多人；缺附件（文件、图片） |
| 出·人 | `send_msg` | **无回执、无沉默**（后果断，`tools.py:125`）；无对多人（对群） |
| 进·环境 | `read_file`／`fetch`／`search`／`terminal_observe` | 无"世界自己动了"的订阅；无远端 |
| 出·环境 | `write_file`／`edit_file`／`execute`／`terminal_*` | 无远端（登陆某台电脑） |
| 坐标·时间 | `timer`／`time` 字段 ✓ | — |

## 十、位置：不需要（结论 · 2026-09-18）

- **位置 ＝ "移动"的坐标**；没有移动就没有位置，且它**可以被设计掉**。
- **时间与位置不对等**：时间是**轴**（有内在序、组织经历、不可省）；位置是**标签**（无内在序，不能排序/衰减经历）。
- **三样归位**：
  - **时区** → **时间坐标的解释参数**（不是位置的属性）；机制给初值、经历可调；是节律的输入。**分清**"自己的节律"（自我侧）与"对方的作息"（关系侧）。
  - **资源** → **资源清单**（稳定标识 ＋ 接入方式：终端/图形）＋ **可达性**（探测得来、落段，**不常驻**）；资源身份**不用 IP**。
  - **移动** → **消掉**。
- **移动不必被感知**，只需感知**可达资源的变化**；"移动"是**模型的推断**，机制只给 delta（机制不解释原因）。完全无变化的迁移＝不可观测＝对它不存在。
- 它需要的是**处境感**（来源／关系／目的／当前弧），不是坐标；**困惑**源于"预期失配且无法归因"，不是缺位置标签。告知位置主要对**机制/审计**与**人**有用（机制可记 `host`，不必进模型认知）。
- **连带修正**：§七 7.3 的 `host` 先占位**已撤回**（见该处）。

## 十一、输入 vs 工具（结论 · 2026-09-18）

- **判据是"谁发起"**（推＝注入／拉＝工具），不是信息本身；**同一信息可有两面**（注入面＋获取面），甚至并存（与时区同构：机制给初值＋可主动拉）。
- **"是输入"是把"我们打算怎么实现"当成了"它必须的结构"**——别把设计选择写成它的结构。
- 推论（**倾向**）：**"可用资源集" ≈ "当前可用工具句柄集"**；"资源缺失"与"工具调用失败"是同一件事的两形态。
- 分类主轴改为**对象**（机制自身／人／电脑），"输入 vs 工具"降级为每类的**两面**。

## 十二、工具组织与工具集划分（倾向 · 未定案 · 2026-09-18）

### 12.1 三层分离（实现／概念／呈现）

| 层 | 怎么做 |
|---|---|
| **实现层** | 复用（一个 adapter 接口，多实现） |
| **概念层** | **对象轴**定集合：自身／人／电脑 |
| **呈现层**（给模型） | **按"后果形态／行为差异"分组**，不按实现分 |

### 12.2 集合划分

- **set-2 ≡ set-3**：**同一个"电脑"**；本地沙箱＝机制**预置的实例**（简化、终端接入、权限受限）。它不是"另一类"。
- **参数／标签**（不再开集合）：实例（哪台机）、接入方式（终端／图形）、target、时间性（`sync`／`async`／`timeout`）、有无事件面、权限范围。
- **"工作目录"不是工具**，是本地沙箱的根；**"打开终端"是"电脑"的会话动作**；**"终端／图形"是接入适配器**。
- **通信应从"自身"移到"人"**（按对象分比按实现分稳）。

### 12.3 归属轴（自己的／外部的）＋ 两层接口

- **归属**：**自己的**（随 signature、不失效、迁移＝搬）／**外部的**（随配置、可失效、需账户）。**电脑是唯一横跨这条轴的对象**。
- **硬约束**：**本地沙箱保持机制托管，绝不引入账户／登录**，否则掉到"外部"侧、失去"永不失效"。
- **两层接口**：**动作面**（统一 `MachineAdapter`：`ensure/release`、`read/write/list`、`run`、`session`、`net`、`caps`）＋ **托管面**（`OwnedDirectory`／`ExternalHost`）。**合并发生在动作面，不合并发生在托管面**。
- 保证可搬的三条实现纪律：状态全在 root 内／不泄漏宿主绝对路径／目录里是"纯数据＋可重建"。
- **搬迁由机制/托管层做**（agent 无感）；有感的只剩外部资源可达性与宿主工具链依赖。

### 12.4 呈现分几套

- **由"后果形态"定，不由实现定**；**三套可行**，只要 ①底层复用 ②不按实现分组。
- 本地 vs 远端**该分**（永不失效／即开即用 vs 要登录／会断／有延迟）——合并反而制造困惑。
- 唯一真问题：**重复**（同动作同后果出现在两套 → 无意义二选一）与**边界绑实现**（集合随实现增长）。
  - 注（09-18 续）：**"分几套"已由 §18.1 取代**——改为"功能分包＋按需装配"，无固定套数；上述两个真问题转为"能力不跨包重复"与"包按能力切"。详见 §18。

### 12.5 阻塞／时间性

- **默认不卡**；卡住＝**占住唯一的槽**（比"真空"更严重：真空可转向朝内，卡住连朝内都不行）。
- **三层限制**：单次超时（**已有**：execute 30s／fetch 60s／lm 120s）／**单弧总预算**（**缺**，现只有 `MAX_TOOL_ROUNDS=10`）／**可打断**（**缺**，外部事件只能排队）。
- **超时是"后果"的一种形态**（对应 §4 切点的"该来的没来"）。
- 慢动作优先走**异步形态**（发起→释放槽→结果事件回来，`terminal_*` 已示范）。

## 十三、草稿纸与工作目录分区（讨论中 · 2026-09-18）

> 注（09-18 更新）：下面的 `work_dir`（`fs/`＋`id/`）两分草图已由 §13.1 取代，以 §13.1 为准。

- **重叠是真的**：草稿几乎可以做成"私有根目录 ＋ 文件工具"。
- **草稿价值的精确表述**：**一块不产生误差的私有空间**。修正："后果"不来自"存哪儿／对外影响"，而来自**"会不会被消费"**——工作目录是执行面的工作区（被命令/程序消费 → 有硬反馈/误差）；草稿执行面碰不到（只有自己读 → 无误差）。
- 剩下三条**便利**（非原则）：id 语义／版本归档／免于被执行面连带触及。
- **方案（当前焦点）**：**工作目录分两部分**——`id` 平铺（不用命名）＋ 名字树，**互不可见**（`ls` 只见名字树）。＝把隔离从**物理隔离**换成**命名空间隔离**，一个 root、两种寻址。

```
work_dir/            ← 一个 OwnedDirectory，迁移搬这一次
  fs/                ← 名字树：执行面与文件工具的根
  id/                ← id 平铺：执行面不可达，由专门工具访问
```

- **我的评估：方向认同**。**必须定的三点**：
  1. **执行面与文件工具的根＝`fs/`**，`id/` 是它的**兄弟**（不能是子目录），且只由专门工具访问——隔离靠**工具面**执行，不靠惯例；写在 adapter 层作硬约定。
  2. `id` 区**保留现有草稿语义**（新建返回 id／列／读／改／旧版归档），只是 root 从 `scratch_dir` 换成 `work_dir/id/`。
  3. 补一个**"落盘／导出"动作**（草稿 → 名字树）＝**"想 → 做"**那一步；现在缺。
- **风险**：隔离全靠"根"的纪律，任一处用 `work_dir` 当根即破（未来加远端 adapter 尤其危险）。
- **未答**：**草稿还要不要作为独立工具**（判据＝"要不要一块执行面碰不到的地方"）。

## 十五、安全（讨论整理 · 2026-09-18）

> 来源：由"agent 怎么用电脑／远程登录／密码"引出。

### 15.1 威胁模型（已澄清）

- **外发不可避免**：用 LLM 则内容出本机。链路逐跳：本机磁盘 → 网络/代理 → 厂商网关 → 滥用日志 → 子处理者 → 人工审核 → 法律。
- **信任边界是逐跳的，不是"这台机"**（修正前一版"电脑安全就没事"）。厂商内部那一跳不归你控；ZDR 是合同且有洞（逐组织/逐模型/逐 feature；Anthropic Covered Model 不能跑 ZDR；Bedrock 模型方可否决 `store=false`）。
- **能决定的只有"发什么、发给谁"**。
- **海量数据如何被利用**：全量过廉价过滤（DLP 正则＋T&S 分类器）→ 命中子集**长留＋人工**（OpenAI 滥用日志 30 天；Anthropic flagged 最长 2 年）→ 落盘即可检索，事后捞针。规模不是障碍。
- **泄密实际路径**：内部人/审核、训练记忆化（机器不会忘）、日志被攻破、法律、子处理者、本地侧明文（transcript/日志）、prompt injection。

### 15.2 秘密（归属已澄清 · 防护为倾向）

- **归属**：秘密是 **agent 自己的事**，机制不替它规定"能不能进段"（那是机制替它下价值判断，违 §8）。
- **进段合理**；记忆本就有损，`权重决定谁不许压`（#17）＝"反复记就编码"的机制对应，**不需要凭证子系统**。
- **忘记密码是它自己的后果**（登录失败＝硬后果），提前挡住反剥夺其长记性机会。
- **外发防护＝遗留（后置 · 已定 09-18 续）** [YZ]：整块**暂不实现**（含秘密清单）。设计要件备查于 §15.7／§15.7.1，将来做时起点仍是"**明文不进 context**"。一致性备注：遗留 ⇒ **默认状态下秘密明文外发**；§17.4"秘密住草稿并 `mark` 禁删"只是**存放位置、非防护**，别当防护讲；provisioning 上应避免把真实高危凭据直接给它（同 §15.5"第三方风险＝别接给它"）。
  - （原四小项：① 双向 redact；② 引用 vs 搬运、消费者处解引用；③ 动态秘密注册/标记；④ 残留：本地映射表 honeypot、只挡外发一维。）

### 15.3 注入（已澄清）

- **不是通信截获，也不是厂商内部**——走正常数据通路，发生在模型这一层。
- context **没有"指令 vs 数据"硬边界**；SQLi 有参数化，LLM 无等价物 → 无可靠解。
- **真正入口是间接注入**：`fetch`/`search` 网页、`read_file`、terminal 输出、**飞书消息（任何参与者）**、工具描述/MCP、历史段、图片。
- 攻击者**不用碰任何"截获"**，只需往它必读处放内容。

### 15.4 来源判断（已澄清 · 含轴的修正）

- **轴＝职责归属，不是权威等级**。多人群里所有人平等、**无 principal**；"该不该听"取决于**这件事归不归我负责**，不归可以不听。
- **机制给"来源戳"，经历长"信任判断"**：来源戳是不**可伪造的事实**（否则标签与内容同通道＝锁与钥匙放一起）；信任判断是可生长的价值。
- **前置 bug**：`app.py:147` 把来源抹平成 `source="system"`，现无判断依据。
- **注入重新定义＝被说服**：与人类员工被社会工程同构，是常态非漏洞；防御是判断＋后果，非权威分级。

#### 15.4.1 来源戳：事实标识与确认分层（已定 · 09-18 续）

> 来源：YZ 指出"来源戳本身明确、与工具无关，但风险操作需更强确认"。**归安全线／段 schema，非工具话题。**

- **来源＝具体标识，非分类**：phone 消息来源＝发送者；timer 来源＝"它自己设的"；各类来源各自给**自然标识**（谁／哪个入口）。**不设计统一枚举**，也不填"人／物"这类分类——§8"机制不预设来源种类"由此满足。（"来源戳填哪几个词"故此**溶解**。）
- **来源 ≠ 信任**：戳只保证"**确实来自 X**"，不保证"X 可信"（自己设的 timer 也只保证是它设的）。信任由**经历长**（§15.4）。
- **两种"不可伪造"分层**：
  - **链路级**（机制盖戳）：防**冒充来源**——"是不是它发的"。
  - **授权级**（数字签名／挑战）：防**本人被胁迫／被盗号／说错话**——"是不是它真授权了这件事"。**要求通常来自外部消费者**（银行／系统），不是机制设闸（合"无地板／约束只在 provisioning"）；机制**不做身份担保**，只搬运和呈现对方要的凭据。
- **人 vs agent 的验证不同**：人靠感官启发式（脸／声／几句话）；agent 没有，但靠**密码学（签名／TOTP）＋ 多通道带外交叉 ＋ 经历一致性**——是**能力性验证**而非感官性验证（合 §8.2）。
- **叠加三层**：① 来源戳（事实：谁）→ ② 确认证据（授权：签名／挑战）→ ③ 信任判断（价值：经历长）。日常只用 ①，高风险叠加 ②③，**别把 ① 当 ③ 用**。
- **与秘密的连接**：签名私钥本身是秘密，落 §15.7.1 清单，签名时在消费者处解引用、不进 context。
- **工具边界**：**工具只提供"来源标注"**（在事件/调用上附带来源字段），**不负责**来源判断、信任、确认——那属安全线，不在工具实现时考虑。

### 15.5 约束点（已澄清）

- **无地板**：地板＝机制替它判断"不许做"，违"判断归它"。
- **约束只在 provisioning**：给不给能力；给了终端＝给了那台机一切动作，要么给要么不给。
- **风险自担**：唯一要保证的是**后果回到它身上（环闭合）**；否则**不给/备份**，非设闸。
- **第三方风险**：解法是"别把别人的东西接给它"（或经同意），非动作地板。
- **发育性保留**：模型的"话≠命令"框弱于人类 → "没有谁是命令来源"这个框得它**自己长出来**，是能力不是闸。

### 15.7 redact 的可行边界（讨论整理 · 09-18 续）

> 来源：YZ 提出两种情形——① 真人／provisioning 直接给占位符；② 模型自己判断，问"若不知是密文如何不读"。

- **只有"明文不进 context"能当机制**：登记为秘密后，模型读到的**永远是占位符**，真值只在动作边界由机制填。代价＝需要一份"**秘密清单**"。
- **模型自判不防第一跳**：模型"看见"明文那一刻，明文**已在 context 里**，而 context 每轮外发 ⇒ 自守与否都挡不住出向泄漏；只能减少后续"去取秘密"。能拦外发的只有**机制在出向（context→API）按清单 redact**。
- **问题收敛到"秘密识别／注册"**：占位符、映射表、`SSH_ASKPASS` 都只是其后的搬运细节。
- **"不知道"无可靠解**：文本层面分不清密码与普通串，同构 §15.3（无可信边界）。选项＝注册制（唯一可靠）／启发式 DLP（必有漏）／接受风险（§15.5 风险自担）。
- **与"秘密是 agent 自己的事"一致**：机制提供"**登记即涂黑**"能力，**登记归 agent**（或人在 provisioning 登记）；**模型自判只是行为层缓解**（可生长），不当机制保证。

#### 15.7.1 秘密清单＝独立模块（已定 · 09-18 续 · **整体遗留/暂不实现**，本条仅作设计备查）

> 来源：YZ 提出"清单做成独立模块、使用处按编号查"。**09-18 续：YZ 决定整块外发防护先遗留、暂不实现**；以下为将来落地的设计要件。

- **形态**：独立模块、**per-agent**、**不上 context**；agent 手里只有**编号＋非敏感标签**（如 `#42 = "github 密码"`，标签可进 context、值不行）。所有权归 agent，**保管归机制**。
- **存明文的一份落机制侧（agent 不可见）**——组件落点（`lm-service` 等）**无关**，唯一硬约束是"agent 读不到"；因此**不能放机器根**（终端完全放开）。草稿管理文件同理不可达（非 `scratch_` 前缀、无 list、无路径）。
- **agent 不能"已有明文换编号"**：明文一进 context 就已在出向路径上，此时登记＝**补票**（只保未来，第一次已出）。故登记**必须发生在明文进 context 之前**。
- **两条干净登记路径**：
  1. **机制生成新秘密**：agent 调 `secret_generate(label)`，机制生成、入清单、**只回编号**（它从头到尾没见过明文）。
  2. **提供方在入口登记**：别人给的明文在进 context 前被收进清单，只把编号递进 context。
- **拆分粒度**（账号/密码各一编号、或只编密码）＝登记时的粒度，由**提供方显式标注**，不靠 DLP（同 §15.3）。
- **生成工具须保证返回值只含编号**：明文不进返回值/日志/transcript；否则又漏。代价＝丢了不可恢复（§15.5 风险自担）。
- **推论**：**登记率＝这套防护的实际上限**；使用处"按编号查清单"即 §15.2 的**消费者处解引用**。

## 十六、工具（讨论整理 · 2026-09-18）

> 来源：终端使用 → 远程登录 → 文件读写 → 同步/异步 → 工具总览。

### 16.1 前置：工具是什么

- **工具＝模型调用的一切**。机制的记忆操作**也是模型调用的工具**，区别在 **agent 是否感知**，不在"机制有没有模型参与"（睡眠整理：模型在场、在调工具，但 agent 不感知）。
- **角色决定工具集**：同一模型醒着（主体）／睡着（机制进程）看到不同工具。
- 三层：**实现层**（代码复用，一能力一份实现）／**角色层**（定集合）／**呈现层**（schema 多套、按需提供）。
- 连带：**§11 的"可用工具句柄集"要补一个维度——当前角色**。

### 16.2 终端工具（已收敛）

- **单形态 pty**（**pipe 废弃**）：pipe 的语义（忠实、非交互、分错流）用 shell 重定向即可拿到，且它解决不了密码——严格被支配。
- **动作**：`open / exec / write / observe / cancel / close / list`；`write` 送字节（含密码、`\x03` 等控制字符）。
- **observe ＝ 看屏**：机制跑 VT 模拟器（pyte），给**渲染后的文本屏 ＋ 滚动历史**（可翻阅）；**不给 raw**。
  - 屏是**状态不是流**，天然有界；进度/动画的 `\r` 覆盖被模拟器自然折叠（＝人看到的跳动）。
  - 去控制字符＝**应用影响布局的**（光标移动/CR/清屏）**、丢弃装饰性的**（颜色）。
- **忠实输出不在工具里做**：agent 自己**重定向 ＋ 文件工具**（如同人）；全屏程序的翻阅靠发键，无界输出靠重定向。
- **窗口尺寸**必须显式设定（`TIOCSWINSZ`），改尺寸发 `SIGWINCH`；**没有普适值，是选定一个并保持一致**。
- **非阻塞**：发起即返回；poll（看屏）／event（退出）。
- **密码**：pty ＋ `write`（刚需场景）；备选密钥 / `SSH_ASKPASS`。
- **远程**：ssh 跑在一个 pty 会话里；非交互化（`BatchMode`/`StrictHostKeyChecking`/`ConnectTimeout`）。
- **附带统一**：终端屏（文本屏）与图形（像素屏）是**同一层"看屏＋送输入"抽象**的不同分辨率。
- 未定：event 推送粒度（只推退出？还是也"屏变"）；单弧总预算/可打断（§12.5）；会话跨重启持续性（tmux？）。

### 16.3 文件：私域／世界、本地／远端（收口 · 09-18 续）

- **文件与终端是两个能力**，同挂"电脑"对象，靠 target 区分。
- **`term` 与 `fs` 共用同一 account/target**：一套凭据；term 走 ssh 会话，fs 用同一 ssh 的 **sftp**（同 transport、各自 channel），凭据一次解析、两边通用（§15.2 消费者处解引用）。
- **fs 从 term 衍生、以"会话句柄"为目标（已定 A · 09-18 续）**：成立条件＝**term 会话 ∧ 机器"可同步可达"**；**`term.open` 返回的会话句柄本身可被 `fs.*` 当参数**（一个句柄、两种能力面），**不新增 `get_fs` 工具**；会话关→挂它的 fs 一并失效（对已关会话调 fs＝失败，不重连）。
- **权限＝OS 账户权限**：不存在工具自造的根沙箱，也**没有 symlink 逃逸**概念——能访问则成功、否则失败。安全全压 **provisioning 的账户权限**（§15.5）。
- **不做本地/远端语义分叉**；改为**机器带"可同步可达"属性**（provisioning 给）：
  - 装（可同步可达）→ 有 **`fs.*`**（同步、有大小上限＋超时，超限拒绝）；
  - 不装（远端）→ **无 `fs.*`**，文件走 `term`（源处处理）＋ `transfer`。
- **`fs.*` 只做普通文件**（`read/write/edit`）；**不支持 socket/pipe/fifo/device**（会阻塞）；**无 list/search**（走终端 §17.1）、**无 delete**（走终端）。
- **`fs.*` 的价值**：**忠实的文件内容通道**（终端是渲染屏，忠实内容靠"重定向＋文件工具"§16.2）＋ 结构化免转义、二进制安全 ＋ 结果可挂 id。
- **大文件/部分内容**：不进 `fs`；**在源处切片**（`head`/`tail`/`dd`/`sed`）→ 小文件 → `transfer`；批量/超大走机器间 `scp`/`rsync`。`transfer` **保持整文件**，不加 offset。
- **时间形态按操作性质分**：**取值型**（`now`/`draft.read`/`fs.read`）**同步**（有界）；**后果型**（`term.*`/`transfer`/`phone.send`）**异步**，事件只做短通知、**不带长内容**。

### 16.4 同步/异步：跟角色走（已澄清）

| | agent 面向 | 机制面向 |
|---|---|---|
| 对象 | 世界 | 自己的记忆 |
| agent 感知 | 是 | 否 |
| 返回 | 句柄/ack，**后果走事件** | 值，**当轮就用** |
| 同步性 | **异步不阻塞** | **同步阻塞** |
| 理由 | 在世界出手，新事件随时来，不能独占槽 | 自己的原子过程，它就是在用槽 |

- 落点：**慢动作不占槽**（挂起／续弧／事件）；机制 store 应留本地（它没法异步）。
- **细化（09-18 续）**：同步/异步按**取值型 vs 后果型**分——**取值型**（`now`/`draft.read`/`fs.read`）当轮要值 → **同步**（有界）；**后果型**（`term.*`/`transfer`/`phone.send`）无值 → **异步**。**不按 target 位置分。**
- 注（09-18 续）：上表"agent 面向＝异步不阻塞"是**主形态**；**取值型工具是同步例外**（当轮要值），见 §18.2。

### 16.5 工具完整清单（定稿 · 09-18 续）

> **工具＝agent 发起（拉）；事件＝机制推（注入），不算工具**（§11）。**包＝可一起授予/撤销的工具组**，不向模型宣示（§18.1）；建议包名即命名空间前缀。

**agent 面向·工具**

| 包 | 工具 | 形态／备注 |
|---|---|---|
| `time.*` | `now`、`set_timezone` | 同步（取值） |
| `draft.*` | `read`、`write`、`edit`、`mark`、`unmark`、`list`(仅已标) | 同步（机制侧、保证快）。`write` 无 id→生成、带 id→覆盖；**无 `new`／`delete`／通用 `search`**；`id=0` 保留地址 |
| `timer` | `set`(→句柄)、`cancel`、`list` | 同步返回；后果（到点/错过）走事件 |
| `transfer` | `transfer(src,dst)` | 异步；**只 copy、整文件**；端点 草稿↔机器根 |
| `phone.*` | `send` | 异步（ack；后果走事件）。**`receive` 是事件、非工具** |
| `term.*` | `open`、`exec`、`write`、`observe`、`cancel`、`close`、`list` | 异步；与 `fs` 同 account/target |
| `fs.*` | `read`、`write`、`edit` | 同步、有界；**以 `term` 会话句柄为目标**（fs 从 term 衍生，§16.3）；仅"可同步可达"机器；无 list/search/delete、不支持特殊文件 |

**事件（推，非工具）**：`phone.receive`、`timer.notify`（到点/错过）、`term` 退出/屏变通知（§16.8，默认关显式开）、事件自带**时刻**（机制注入）。

**机制面向（同步、不可见）**：`load`／`retrieve`／`record_segment`／`promote`／`consolidate`／`replay`／`read_segment`／`write_segment`／`mech_scratch_*`。**（暂遗留 · 09-18 续）**

**总规则**：① **取值型同步、后果型异步**；② 后果是事件不是返回值（事件不带长内容）；③ 句柄集角色相关；④ 组合方式＝功能分包＋按需装配（§18.1）。

### 16.6 草稿与三处归属

- **草稿有两个**，此前混为一谈：**机制草稿**（脑内工作区，同步、不可见）＋ **agent 草稿**（随身私域，异步、可见、是工具）。
- **三处归属**（真正的轴；"电脑不与 agent 绑定"切开后两处）：

| 归属 | 随什么 | 谁可见 | 误差 |
|---|---|---|---|
| 机制根 | 随机制 | agent 不可见 | — |
| agent 私域 | 随 **signature**、迁移＝搬 | agent 可见 | 无（无人消费） |
| 世界（电脑） | 随那台机 | 执行面可达 | 有 |

- **agent 私域 ≠ 记忆**：记忆＝机制自动、联想取回、参与压缩、有损；私域＝它**自己写、精确取回、不参与压缩**（随身笔记本，人写便条同理）。**秘密天然住这里**（接 §15.2）。
- **隔离＝三根目录**（机制根／agent 私域根／`fs` 执行根，后两者是执行面兄弟）；执行面碰不到私域→无误差；导出到 `fs` 才进入"做"。
  - 注（09-18 更新）：此"三根"表述已由 §13.1 目录组织取代，以 §13.1 为准。
  - 注（09-18 续）：**agent 私域现只剩草稿**（档案已删，见 §17.2）；本表第三行"agent 私域"读作"草稿"。
- **跨根直传＝`transfer`（§16.10）**：原分 export＝提升（私域→世界，进"做"、可被消费、有误差）与 import＝吸收（世界→私域，变"自己的"、精确、不进压缩、无消费）两个方向，现由**一个底层原语**统一，方向差异落参数/钩子。要求**不经 context** 的理由：无直传则"世界→私域"只能让模型复述，有损且二进制/大文件不可行，执行面又碰不到私域。场景：fetch/终端产出落到 `fs` 的文件、别人给的资料、想留一份原始副本。

### 16.8 pty 通知：显式开启 ＋ 保留标记（已定 · 2026-09-18）

> 来源：由"终端命令能否走事件通知、如何避免轮询"引出。**结论出自本轮讨论**。

- **不做通用 pty 事件**：命令完成/屏变/等待输入的**语义推断**不值得做（需 shell 集成或 prompt 启发式，脆弱；pty 只给字节流与顶层进程生死）。改为**让发信者自己声明**。
- **定位**：notify 是**唤醒提示**，**不是指令、不带权威**；真相以 `observe` 看屏为准。伪造/误触发的后果＝"agent 多看一眼"，**有界**。
- **默认关、显式开**：`open pty` 默认**不通知**；由 agent **显式开启**（机制不主动过滤，符合"别替它决定"）。开启＝**会话级开关**，`exec` 可随命令带（一次性）。机制**只对开启的会话跑 matcher**，默认不扫。
- **载体＝带内，走 pty 流**。理由：pty 是流，ssh 按构造转发远端输出——**本地/远程同一套，无需 `-R`/端口/认证**；机制本就在读流（喂模拟器＋`observe`），加一分支即可。
- **格式＝保留 OSC 外壳（固定）＋ agent 给的随机 token（变量）**。外壳保证不与真实 OSC 语义撞；只有 token 是变量，**匹配边界明确**。**不让 agent 自定义整串**（否则退化成屏上文本模式匹配，误触发/注入复现）。
- **token 来源＝agent 在开启时给**，机制不生成、只记"该会话在等此 token"。远端由 agent 把 token 编进命令（`cmd; printf '\033]cogos;<token>\007'`）或经远端 helper 发。
- **防什么**：保留外壳 → **无意碰撞**≈0；随机 token → 挡**被动内容伪造**（文件/网页/日志里没有刚定的 token）；**同通道挡不住主动恶意程序**（§15.4 标签与内容同通道；真不可伪造需异通道＋provisioning）。
- **远端配合**：命令在远端执行，信令**在远端产生**（一行 `printf` 即可，helper 只是方便）；信号混在终端输出里过 ssh 回本地，机制读流时**剥离**（不污染 `observe`）并投事件。带外 `ssh -R` 不更省（远端同样要配合，且要配置/认证/管生命周期）。
- **生命周期**：开启可关/一次性到命令结束；机制随会话/命令**回收**（资源管理，非价值判断）。
- **同源**：`timer`（时钟发信）、`phone_receive`（人发信）、此 notify（任意进程发信）都是"**外部信令 → agent 事件**"同一原语的实例；它也是**事件注册模型的最小可用版**（开关＝注册、token＝暗号、事件＝敲门）。

### 16.9 agent 私域寻址（已定 · 2026-09-18）

> 来源：本轮讨论，附一条边界备注。
> 注（09-18 续）：**"两套并存"已被 §17.2/§17.3 改写**——档案去掉、草稿保留，"命名目录（档案）"一套取消，私域寻址收成 **id 平铺 ＋ id=0**。

- **agent 私域寻址＝两套并存**：`id` 平铺＝**草稿**（机器给号、精确取回、无误差）；名字目录＝**档案**（命名、可整理）。二者同属私域、同经工具访问，不混为一种。
  - 备注：要紧的是**归属唯一**——一物归其一，草稿→档案＝一个"归档/提升"动作（命名并纳入名字树），否则检索要两处都扫、语义漂。另需区分**私域名字树**与**世界 `fs` 名字树**，两者不是一回事。

### 16.10 transfer：跨根转移统一原语（已定 · 2026-09-18）

> 来源：本轮讨论（统一为 transfer）。
> 注（09-18 续）：**端点去掉"档案根"**（档案已删，§17.2），保留 **草稿 ↔ 机器根**；"草稿→档案归档"方向消失。

- **一个底层原语**：`transfer(src, dst)`，**根间任意向**：草稿 ↔ 档案 ↔ 机器目录（含**草稿 → 机器直传**，不必先归档）。**机制根不在内**（agent 不可见）。
- **必须显式调用**：机制不自动归档/提升（符合"别替它决定"）。
- **只做 copy，不做 move**：移动＝`transfer`（copy）＋ 删源；底层无 `mode`。
- **取代**：私域↔世界两个方向（导出／吸收）＋"草稿→档案归档"三个动作用同一底层实现；呈现层保留**方向化命名**（工具命名区分、底层复用）。
- **方向差异用参数/钩子，不用两套实现**：import 侧附**来源戳**（接 §15.4，吸收不可信输入）；大文件/二进制**只回 id、不经 context**；跨机走 sftp、慢则**异步**（后果走事件，接 §16.4）。
- **注意**：同一原语 ≠ 完全对称——吸收侧多一层"不可信输入"语义。

### 16.11 timer 与事件时间戳（已定 · 2026-09-18）

> 来源：本轮讨论（timer 到点/错过是否带 now、算不算坐标）。

- **timer 事件带时刻**：到点或**错过**时发事件，事件带 `now`；并区分 **due（预定时刻）** 与 **送达时刻**——两者之差＝"按时/迟到"的后果信息。
- **时间戳是通用事件字段**：机制给坐标（§8.1），所有事件都应带发生时刻，非 timer 专属。
- **timer 归类＝信令/动作**，与 `phone_send`／notify／`phone_receive` 同源（§16.8"外部信令→事件"）；它产出的**时间戳归坐标数据**。
- **"算不算坐标"消解**：坐标是**数据性质**、timer 是**动作性质**，不该同组；归类判据回到 §12.1 呈现层"**按后果形态分组**"——`timer`（设定未来→回事件）与 `now`（当轮取值）后果形态不同，自然不同组。

## 十七、工具的简化与草稿（讨论整理 · 2026-09-18 · 续 §16）

> 来源：由"列目录/搜索归属"起，收敛到"档案去掉、草稿保留"，再细化草稿的索引与淘汰。标注 **[YZ]**＝YZ 表态；**[AI]**＝AI 建议；**[未定]**＝未裁决。**以本节为准，覆盖 §16.6/§16.7/§16.9/§16.10 与 §13.1 中被点名的条目。**

### 17.1 列目录/搜索归属（已定）

- **归属判据＝可达性**：世界侧执行面够得到 → 列/搜交**终端**（`ls`/`find`/`grep`）；私域执行面够不到 → **只能自带**。
- **`fs_*` 去掉呈现层 `list`/`search`**：世界侧列/搜走终端，结果形态因此是"渲染屏 ＋（必要时）重定向"（§16.2），不是返回值——这正是与私域工具的实际差别。
- **机制侧无必要性** [AI]：机制角色对象是记忆、不是文件；`MachineAdapter.list` 属**实现层原语**，不呈现、不是工具。
- **不提供"只给文件、不给终端"的机器** [YZ]：给就一台正常电脑，agent 可自己写代码完成列/搜。
- 推论：**私域无通用 list/search**（见 17.3）。

### 17.2 简化：档案去掉、草稿保留（已定）

- **私域唯一不可替代的性质＝"无误差"**（执行面碰不到，§13）；其余（随身、精确取回、命名、住秘密）在普通电脑 fs 上都能复现。故 **档案（可被电脑替代）去掉，草稿（无误差、工具面极小）保留**。 [YZ＋AI]
- **迁移** [YZ]：记忆在机制侧、自动随行 ⇒ "自我/经历"**不依赖打包**；电脑文件由 agent 用**背包**（选子集 ＋ 机制运）迁移，从"机制搬、agent 无感"变为"agent 打包、机制运、忘则丢"。
- **机器按归属分私有/公有** [YZ 框架，AI 表述]：隔离从"对私域的全局保证"变为"**对公有机器的保证**"；秘密住私有、不接公有（接 §15.2、§15.5），自己电脑上执行面可达＝风险自担（人的类比成立）。

### 17.3 草稿（已定部分）

- **id=0 保留地址** [YZ]：始终可读；**不存在时自动创建空文并返回空**；**覆写为空**即重置（无 delete 动作，可达性删不掉）。这是**机制对草稿唯一的自动写**（与 §11"机制给初值"同构）。设长度上限（例 1MB）。
- **工具面**：`read`／`write`／`edit`；`mark`/`unmark`；`list`（**仅已标**、有界）。**无 `new`**（`write` 无 id→生成 id、带 id→覆盖）；**无通用 list/search**；**无 `delete`**（淘汰机制覆盖删除需求，[YZ]）。
- **淘汰＝默认可删、标记禁删** [YZ]：未标记自动淘汰；`mark` 附 ≤256 字摘要，`list` 返回 id＋摘要（导航）。容量为 provisioning 参数（例：0# 1MB；禁删 20 条 & 10MB；总量 30MB）。
- **策略＝最近访问列表·只在内存（已定 · 09-18 续）** [YZ]：≤100 条 id，热区 LRU（列表末位先淘）＋冷区随机；**重启即清空**（此后既有项皆为冷区随机淘汰；禁删项不受影响）。
- **mark 注册＝独立 `marked_list.json`（已定 · 09-18 续）** [YZ]：记已标 id ＋ ≤256 字摘要，`list` 只读这一个文件。草稿文件命名 `scratch_<id>.<ext>`，**后缀原样保留**（可拷入任意文件）；非 `scratch_` 前缀者（含该 json）自然排除。
- **超容与淘汰触发（已定 · 09-18 续）** [YZ]：手动 `write`/`edit` **不允许超上限（＝总量配额，超出直接失败）**；只有 `transfer` 拷入允许**临时超上限**，**绝对 500MB 不可超**，不满足直接失败。每次写后检查容量，超了立即淘汰、**超大文件优先**；刚 transfer 进来的这份**本轮豁免**（下一次写再清，对上"下次写即淘汰"）。大文件只能在电脑上。⇒ 峰值预留 ≈ 总量 ＋ 500MB（总量是**软目标**）。
- **id=0 与配额（已定 · 09-18 续）** [YZ]：**单独配额**（例 1MB）、**不进总配额**、永不淘汰。

## 十八、工具组织收口：分包与时间形态（已定 · 2026-09-18 · 续 §17）

> 来源：由"呈现分几套"起，YZ 提出**按功能分包＋按需装配**，并划清"工具层 vs 组装 cu 层"的边界。**以本节为准**，取代 §12.4 的"三套"说法与 §16.7／§17.4 的呈现待定项。

### 18.1 分包与装配（取代"呈现分几套"）

- **工具按功能分包**：如 `draft.*`／`term.*`／`fs.*`／`phone.*`／`time.*`／`timer`／`transfer`；每包含一个或多个工具调用（**包名即命名空间前缀**）。
- **装配时按需把多个包装进去**，装入的并集＝该角色/情境看到的工具集。**没有预先固定的"几套"**——套数由装配决定，不预先枚举。
- **装配归机制**（角色/情境定）；模型只看到装入的并集，包是**机制侧装配单位**，不向模型宣示。
- 边界：
  - **包按"能力/后果形态"切，不按 adapter 实现切**（否则"边界绑实现"：加一个远端 adapter 就多一个包）。
  - **一个能力不跨包重复**（列/搜归终端包，不归文件包，§17.1）。
  - **`transfer` 单独归包（已定 · 09-18 续）** [YZ]：它跨"草稿根 ↔ 机器根"，**不并入**草稿包或电脑包，自成包。

### 18.2 时间形态：工具自身的属性，由工具层保证

- **每个工具声明其时间形态**（同步阻塞／异步事件）；组装层只决定"用哪种形态"，前提是**工具已提供**。
- **判据＝取值型 vs 后果型（修正 · 09-18 续）**：**取值型**（当轮要用的值）→ 同步；**后果型**（只在世界发生、无值）→ 异步。**不按 target 位置分。**
  - **取值型**：`now`／`set_timezone`／`draft.*`／`timer.set`(返回句柄)／**`fs.*`（就近本地）** → **同步**。
  - **后果型**：`term.*`／`transfer`／`phone.send` → **异步**；事件只做短通知、**不带长内容**。
- **`fs.*` 仅"可同步可达"机器**（§16.3）；**远端无 `fs`**，故不涉及"异步 fs"。~~远端 sftp 异步~~（此条按位置分，已废）。
- **机制层文件读写保持同步阻塞**（§16.4：机制 store 留本地、它没法异步），不混进 agent 面向。
- 异步非免费：结果成事件 ⇒ 组装层负责续弧与落账（**组装层已遗留**，§18.3）。

### 18.3 边界：工具层 vs 组装 cu 层

- **工具层**：包清单、装配规则、能力不跨包重复、每工具的时间形态。承诺"**没有会长时间占住槽的能力**"。
- **组装 cu 层**（不在工具讨论收口）：单弧总预算、可打断、安全点、**未完成弧的落账与续**。
- **状态（09-18 续）** [YZ]：组装 cu 这批**也先遗留**（与工具无关）；本轮只讨论工具。
- 接口干净：工具只保证"**发起即返回 ＋ 结果成事件**"；**何时用、事件回来怎么续**归组装。

## 十九、工具实现：分层与范围（讨论整理 · 2026-09-18 · 续 §16~§18）

> 来源：由"工具实现怎么开始"起。**先做实现层（A）**，契约层（B）／装配层（C）后续。

### 19.1 分层边界（已定 · 09-18 续）[YZ＋AI]

- **实现层（A）**：能力本体，普通签名，**不懂** LLM／schema／包名／`time_form`／role。能脱离 cu 直接单测＝干净判据。
- **契约层（B）**：声明表 `ToolDef(name, params_schema, time_form, impl_ref)`，**只引用 A、不实现 A**；name／schema／time_form 的**单一来源**。§18.2"工具层保证时间形态"由 B 的绑定兑现。
- **装配层（C）**：`assemble(role/context) -> toolset`；**包（授权单位）属这层，不在 A 也不在 impl**。registry／白名单／system prompt 全从 C 派生，收掉现三处硬编码。

### 19.2 实现层（A）的单位＝能力对象（已定）

| A 对象 | 覆盖工具 | 共享资源 |
|---|---|---|
| `Clock` | `time.*` | 时区状态 |
| `DraftStore` | `draft.*` | 草稿根＋淘汰策略 |
| `TimerService` | `timer.*` | 调度＋`timers.json` |
| `PhoneCapability` | `phone.send` | 现有 `cogos.phone` |
| `ComputerSession` | `term.*`＋`fs.*` | 一个会话、两种能力面 |
| `TransferEngine` | `transfer` | 两个根端点 |

- **A 内实现顺序**：`Clock` → `DraftStore` → `TimerService` → `ComputerSession`(term pty) → 会话 fs 面 → `TransferEngine` → `phone` ack。
- **`ComputerSession`**：单对象持 pty / VT 屏(pyte) / winsize / state /（可选）fs channel；`observe` 返回**渲染屏**（**丢掉现 `buffer`/`cursor`**）；fs 是否存在由"可同步可达"属性定（远端无 fs）；fs 的"同步"是 **B 的对外保证**，A 该 async 就 async（sftp 是网络 I/O）。notify 读流时**剥离 OSC token 再喂 pyte**，产出原始信号。
- **`TransferEngine`**：端点抽象 `Endpoint`（草稿根 id ／ 机器根 path → 流），只做**整文件 copy**、不 move、不加 offset；容量豁免/500MB 上限在此判。
- **A 规则**：无 schema／包名／`time_form`／role；返回普通值或抛**类型化异常**（`{"ok":..}` 信封属 B）；`cancel`/`close`/`list`/`observe`/timeout **内建**（可控可观测）；**信号类型独立**——拆掉现 `terminal.py`/`timer.py` 对 `AgentEvent` 的反向依赖，接线层再映射成事件。

## 二十五、批次 3 开工前口径裁决（2026-09-19 · 已定）

> 来源：`handoff-tools-03.md` 第一步重审。主体自洽；两处口径经 YZ 裁决如下。

### 25.1 机器端通道 × 远端无 fs（原待定 1）→ 定案

- **通道存在性 ≠ 工具暴露**：远端 term **也提供 fs 通道供 `transfer` 使用**，但**禁止暴露给 agent 工具**。
- 理由（YZ）：不希望 agent 被 fs 阻塞；远端场景 agent 走 `transfer` → 草稿 → 再读写。
- 落地口径：
  - `session.fs` 只要传输层能提供文件访问就**存在**（本机 FS / 远端 sftp）；`fs` 从会话衍生不变。
  - `sync_reachable` 退为 **C 层「是否装配 `fs.*` 工具」的暴露闸门**，不再决定 `session.fs` 是否存在。
  - design §6「成立条件＝term 会话 ∧ 可同步可达」「不可同步可达时＝None」的**字面须改**（由 YZ 确认后改权威分册）。

### 25.2 `sync_reachable` 归属/配置（原待定 2）→ 定案

- **取决于机器**，作**机器属性**，由装配层注入（A 不读配置，合 plan §1）。
- 关键在**如何给 agent 配置电脑**：在电脑的配置参数中给该属性（如 `agent.json` 「电脑」段每台 `{ssh, sync_reachable, machine_root, …}`，一台电脑一个 `ComputerManager`）。
- **本刀（批次 3）不接配置**：A 构造参数 `ComputerManager(sync_reachable=…)` 已就位；配置解析/注入归 C（批次 4）。
- **不绑定 local/远端**（YZ 补充）：**纯由配置时决定**——局域网可视为同步可达；网络好时远端也可置 `sync_reachable=True`，此时该远端同样暴露 `fs.*`（走 sftp）。`sync_reachable` 与"本机/远端"正交。
