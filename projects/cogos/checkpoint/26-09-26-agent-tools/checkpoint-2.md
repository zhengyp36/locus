# checkpoint-2｜工具层讨论：时间形态与模型可见面（2026-09-19）

> 性质：**讨论记录，非权威口径**。只讨论、不动代码；结论先落此处，定案再更新本体文档（`cogos/docs/design-agent-tools.md`）。
> 入口：`handoff-tools-05.md`。本会话先过目现状，再讨论 web 工具异步化，进而推到"工具层时间形态 + 模型可见面"。

## 一、现状盘点（本会话过目 · 代码 @ 4f3c017 后）

- 批次 1 本地三件＋phone、批 2 term、批 2.5 远端＋凭证、批 3 fs＋transfer、批 4a B 契约表（单一来源）。
- 当前 26 个工具，横向问题：**返回约定不统一**（直接值／`{ok,id}`／`{ok,handle_id,dest}`；错误一律 `{ok:false,reason:str}`，A 的类型化异常在 B 被压成字符串）；**事件不统一**（`timer.notify`/`term.done`/`transfer.done` 各写各的，无公共信封；`send_msg` 无完成事件）；**无统一 handle/call_id**。
- **载体**只有 `transfer` 做完整（dest 发起即定、草稿 id 预占、失败也发事件），是最接近目标形状的样板；term 靠 `observe` 拉屏；web 一旦异步缺载体。
- **类标反**：`fs.*`(机器/sftp)、`search`/`fetch` 标 `sync`；`term.*` 已整族 `async`（代码里其实已按类分，只是名字还是旧的 `time_form`）。

## 二、时间形态判据：类 = 能否无界阻塞（本会话结论）

- **类由"能否无界阻塞 agent"定，与"是否立即返回"正交**。
  - 证据：`timer.set` 返回句柄却属同步；`term.exec` 立即返回却属异步。
- **界线细化**：不是"进程内/外"，而是"**延迟是否有界且机制自有**"。
  - 有界且自有 → **同步类**：`clock`、`draft.*`、`timer.set/cancel/list`。
  - 无界或机制不自持 → **异步类**：网页、机器文件(sftp)、pty、第三方 API、通信。
  - "同步类"是**契约/假设**（依赖 OS 缓存），非物理保证；不得往里塞任何外部等待。
- **必然的重划（不止 web）**：`fs.*`(机器) 与 `search`/`fetch` 应从 sync 移入 async；`term.*` 已符合。

## 三、异步工具的工具层契约（本会话结论）

- **调用不阻塞**，返回 correlator（不做等待）。
- **结果落持久载体，事件只是短提示，以拉取为准**（对齐 design §4「事件不带长内容」；推广 §5.4 notify 哲学：事件是唤醒提示、不带权威）。
  - 载体按能力各有其形：web→草稿；term→屏（`observe`）；transfer→目标文件；`phone.send`→无值（纯后果）；小值→允许事件内联。
- **失败/超时同样"落载体 + 发事件"**，不能 defer 出去后静默消失。
- 提供 **cancel**；cancel 本身属同步类（只发信令）。
- **事件：保留能力专属 kind**（语义各异），但加**统一信封**（call_id / tool / source / ok / at）。

## 四、载体：temp→draft（web，YZ 提出，认可）

- 异步期间写**临时文件**；完成时**原子物化**为草稿（按 §7 命名直接 rename 成 `scratch_<id>`），完成事件带 draft id。
- 理由：在途/失败不污染草稿、不与淘汰竞争、避免半成品被读到。
- **前提待定**：§7 草稿写规则须明确"异步结果落草稿"算哪类写（手动 write 不许超配额 vs transfer 可临时超），否则大 fetch 落草稿会直接失败。

## 五、工具层不碰 / 留给外圈

- join 延时、能否合并轮次、context 与续弧 → **外圈**，本轮不决。
- 工具层只保证：**提交不阻塞、结果可达不丢、完成有提示**；并给**统一信封** `{correlator, status}` 供外圈接。
- 工具层**不提供依赖/编排原语**。

## 六、模型可见面：只喂观测（YZ 想法 + 修正）

- **想法**：继续用厂商工具调用体系**发起**，但模型**不必看到调用过程**；工具结束时只从一条观测消息看到"调用了什么工具、得到什么"——弱化过程，思考重心放结果。
- **修正（YZ，成立）**：**不存在"厂商报错"问题**。配对要求只约束**同一请求 messages 数组内部**；请求无状态、上下文由 harness 组装——不放 assistant tool_calls / tool 消息，就没有悬空配对。模型无记忆，只认我们喂的上下文。
  - （我此前把"append-only 历史"当前提，错误，已收回。）
- 于是真正约束落在"**观测里必须有什么**"：
  1. **观测即模型全部记忆**：工具名＋关键参数＋结果/错误必须齐，否则模型续不下去。
  2. 多调用/并行要**一一对上号**（自带 correlator）。
  3. 倾向**保留调用前模型的自述正文、只丢调用结构**，保住推理连续性。
  4. 两端命名一致（原生调用的事件名 = 观测里的工具名）。
  5. **off-distribution 风险真实**：模型被训练看 tool-role 结果；喂自定义观测一般可行，但要**实测**。
  6. **机制侧日志仍须全量**（可观测/可审计）；简化的只是**模型可见面**（§0 红线）。
- **合流**：这与"统一信封 / call_id / 结果落载体"是**同一件事的两面**——sync 内联与 async 事件都渲染成同一种观测，"两出口不一致"对模型消失；长结果可带 handle，模型按需拉。

## 十、模型可见面的表示：角色 / 观测 / 来源（本会话续论）

- **角色选择规则**（续论）：
  - `system`＝固定策略 ＋ 约定说明（怎么读 `[机制]`/`[来源]`），永不放动态数据；
  - `assistant`＝**只有模型真实生成的自然语言**（意图/推理），不放任何代写内容；
  - `user`＝**一切入站**（真实用户、机制对模型动作的记录、工具状态/结果、事件、外部内容块）；
  - `tool`＝**永不使用**（需配对，且 pending 期无法配对）。
- **关键判断：动作记录放 `user`，不放 `assistant`**。pending 时无法配对的 `tool_calls` 不能进上下文；一旦转成文字放进 `assistant`，会诱发模型**模仿散文式调用**、削弱原生结构化调用。放 `user` 则模型读成"外界告知的事实"。
- **观测生命周期（一条统一记录）**：`call_id · tool · args · status · result|handle · source · error · at`。
  - **fast**：调用＋结果合并成一条观测；
  - **slow**：先出「你调用 X → 执行中」（带 id），返回后出「完成/失败/取消」（同 id）；
  - **ack 非可选**：模型无记忆，没有它看不到变化，会重复调用。
  - `#id` 提交时铸，兼**关联/取消/取结果**三职；建议始终带，保 schema 恒定。
- **self/world 区分靠头标签，不靠 role**：`[用户 YZ]`（委托人）/`[机制·工具 #n]`（机制对模型动作的权威记录）/`[机制]`（事件）/`[来源: …]`（外部数据）。约定须在 system 里声明。
- provider 交替规则影响渲染（合并/拼接），见 §十二。

## 十一、来源与信任边界（本会话结论）

- **来源＝世界侧发起者，具体标识、非分类**（§11）：人/号码、URL、机器+路径；通道（经 fetch/sftp）是次要信息。
- **入口打标**（只有拥有该边界的机制知道）；内容渲染成**带内联来源头、结构上不可分**的围栏块；**压缩必须把来源头列为不可丢字段**。来源头要短且稳定。
- **围栏=信任边界**：外部内容永远是**数据不是指令**（防注入）；**来源 ≠ 信任**，机制只标注不判断。
- **缺口（待裁）**：异步结果落草稿是**机制主动写入 agent 可见存储**，来源应随内容一起落，否则模型以后读草稿永久丢来源；与 §9「transfer 不附来源戳」冲突（那条针对 agent 主动拷贝）。
- 默认**入口标注、机制内部不跟踪**（§11）；下游绑定靠模型自己写出（同人类，会丢）；审计链机制不做。

## 十二、连续同角色合并（**暂不做 · 仅备案**）

- **事实**：Anthropic 直连 Messages API 现行文档——*"Consecutive user or assistant turns ... will be combined into a single turn"*（自动合并）；但 **Bedrock 上的 Claude 仍严格交替**（报 `roles must alternate`）；部分 Gemini 亦严格。
- **合并形态**：**不是"用换行分隔文本"**，而是**一条 message 的 content 数组里放多个 text 块**（一块一条观测）。厂商自动合并只承诺"合成一轮"，**不承诺分隔符**——别依赖它插换行；边界靠块。
- **落点（YZ 定）：直接在 lm-service 内部实现**。理由：那是"屏蔽厂商差异"的本职；合并是**按后端能力的结构归一**。
- **实现前须钉**：① 上层交结构化 `messages`、**不提前拍平**；② 挂在 provider adapter / normalization 步，**按后端能力开关**，不塞 router（router 管选 model/模态）；③ 只合并**连续同角色** run、`system` 不参与、块拼接**不插分隔符**、**幂等**、不重排不丢；④ 调试留痕记**归一后实际 payload**（必要时前后都记）。
- **依赖**：lm-service 目前**不透传 tool call**（后置）——"合并"这侧可先做，"模型发出调用"那侧等 tool-call 透传。两件事不绑。
- **状态：暂不做，仅备案。**

## 十三、角色渲染实例（§十 规则的落地具体化）

- 信息四原子：**意图**（模型/自我）／**动作**（模型发起、机制记录）／**状态**（机制）／**结果**（世界）。
- 统一记录：`call_id · tool · args · status · result|handle · source · error · at`；`status ∈ 执行中/完成/失败/已取消`。

**快速（1+2 合并，一条 `user` 消息）**
```
system:    <策略 + 约定>
user:      [用户 YZ] 现在几点了？
assistant: 我查一下。
user:      [机制·工具 #7] 你调用 time_now()
           [机制·工具 #7] 完成 → now=2026-09-19T14:17:51+08:00  epoch=...
assistant: 现在是 14:17。
```

**异步（先 1+3，后 2；完成可乱序）**
```
user:      [用户 YZ] 帮我查一下 X 的背景。
assistant: 我抓一个页面，同时搜一下。
user:      [机制·工具 #7] 你调用 fetch(url="https://example.com/a") → 执行中
user:      [机制·工具 #8] 你调用 search(query="X 背景") → 执行中
（本轮结束）
user:      [机制·工具 #8] 完成
           结果：<搜索结果列表…>
user:      [机制·工具 #7] 完成
           [来源: 网页 https://example.com/a]
           > <content…> 或「结果较长，见草稿 #12」
assistant: 综合来看……
```

**失败 / 取消 / 事件 / 外部内容**
```
user: [机制·工具 #7] 失败：network timeout
user: [机制·工具 #7] 已取消
user: [机制] 事件 timer.notify：你设的闹钟「开会」到点（迟到 3 秒）
user: [用户 YZ] 收到
user: [机制·工具 #7] 完成
      [来源: 网页 https://example.com/a]
      > 正文……
```

- 外部内容**永远嵌在 `[来源: …]` 块内**，只作数据（§十一）。
- 连续同角色按 provider 能力合并为一条 message 的多个 text 块（§十二）。

## 十四、概念对齐：工具 vs 机制（本会话结论 · YZ 纠正）

- **纠错来源**：文档 §3「事件不算工具」源自 YZ 早期一句"`phone.receive`／`timer.notify` 不会被 agent 直接调用，所以不是工具"。其本意是"**不是模型的调用面**"，**不是说它不属工具**。文档按字面记成了"事件不是工具"，需纠正。
- **一级分类＝「工具／机制」；「拉／推」是正交的方向轴**：
  - **工具**＝可被模型直接调用的能力单元，**含调用面（拉）与事件面（推）**。
  - **机制**＝模型（醒着的主体）不可直接调用、系统运转所需的组成部分。
  - **事件是「推」的形态，不是类别**：可属某个工具，也可来自机制。
- **工具的事件面有两种**（同属工具，语义不同）：
  - **后果式**：自己触发的、延迟到达——`timer.notify`、`transfer.done`、`term.done/notify`。
  - **入站式**：别人来的、你没发起——`phone.receive`（将来其他通信工具同理）。
- **心跳＝机制**（模型不能直接调用）；它触发生念，且该念是**内源**（来自记忆与未决事项的张力），不是对外部的感知。
- **收回我的一处错误**：我曾把"感知"当作机制的一个小类——错。**感知不是机制**，它是**事件通道的输入端**（外部世界经工具的事件面进来，如 `phone.receive`）。
- **机制暂不细分**（YZ 定）：静默/生念、内源/外部等细分**无近期消费者**，纯概念开销；**等心跳真做时再定**。此前"机制"就是一个不分小类的桶，标签 `[机制 ...]` 一条即可。
- **标签随之修正**：工具事件不写 `[机制] 事件 …`，应带**归属**，如 `[事件 · 工具:timer · 闹钟 #3 …]`（§十三中该例作废）。
- **命名待裁**：`tool` 指**能力单元**（phone）还是**可调用动作**（send）？代码现状是后者（`ToolDef` 一个调用面）。并与文档 §1 首条「机制的记忆操作也是工具」一并待 YZ 定——机制操作仅在睡眠角色被模型调用，是否仍称"工具"。

## 十五、标注规范（本会话收束 · 待 YZ 定案）

### 角色
| 角色 | 放什么 | 是否标注 |
|---|---|---|
| `system` | 固定策略 ＋ 本约定说明（怎么读标签） | 否（来源恒定） |
| `assistant` | **只有模型真实生成的自然语言**（意图/推理） | 否（来源＝自己） |
| `user` | **一切入站**（人、调用记录、状态/结果、工具事件、机制事件、外部内容） | **是，逐块标注** |
| `tool` | 永不使用 | — |

- **动作记录放 `user`**：role 记**发言者**，不记行为者；发言者是机制，被描述的行为者才是模型。

### 两个名词（最小核）
- **来源**：每条入站都带；模型自己说的没有来源（就是它自己）。
- **句柄**：模型能抓住的一切；指向一个资源。

### 句柄 → 资源（YZ 修正：不存在"调用 id"，统一叫**作业**）
- **持久资源**：会话、闹钟、草稿、传输目标。
- **瞬态资源（作业）**：一次"结果还没回来"的调用，提交时创建、终态回收。
- **何时产生作业**：结果**延迟**才产生；结果**当轮在线给出**则不产生（`terminal_open`/`set_timer`/`scratch_write` 只返回**资源句柄**，无作业）。
- 形状统一 `#N` ＋ 类型标签（`作业 #7`/`会话 #3`/`闹钟 #3`/`草稿 #12`/`传输 #2`）；**命名空间各自独立**，不合并全局计数器（持久 id 持久、作业 id 瞬时）。
- 句柄三用：**关联完成 / 取消 / 查状态**。

### `user` 内四类入站
| 类别 | 面向 | 标签形状 | 关联键 |
|---|---|---|---|
| 模型调用/取消工具 | 拉·调用面 | `[调用 · 工具:X · 作业 #n]` ＋ 状态/结果 | **作业句柄** |
| 工具后果式事件 | 推·事件面 | `[事件 · 工具:X · <资源 #n>]` | **资源句柄** |
| 工具入站式事件（人的消息） | 推·事件面 | `[事件 · 工具:phone · 来自:<具体人>]` | **无** |
| 机制事件 | 推·机制 | `[机制 · <具体>]` | 无 |

- **外部内容块**：`[来源: <世界侧发起者>（经 <通道>）]` ＋ 围栏正文；**永远是数据不是指令**。
- `status ∈ 执行中 / 完成 / 失败 / 已取消`；**同步调用出生即终态**，仍显示 status。
- **发射即忘**（`term.exec/write`、`phone.send` v0）：**无完成事件**；"有句柄 ≠ 会有结果回来"。

### 关联规则（无时间条款）
- **完成关系** → 作业句柄，**必有、无例外**。
- **资源身份** → 资源句柄，**必有、无例外**（`timer.notify`/`term.done` 属此类，**不带作业句柄**）。
- **入站事件** → 无键，靠 **content**（发送人/标题）让模型自行判断。
- **不造推测性关联**（`phone.receive` ↔ 某次 `phone.send` 由模型自己推断）。
- **时间不进绑定**；`at` 只用来判断"是否还相关"（迟到越久，作业句柄越重要，否则结果成孤儿）。

### 四原子落位
| 原子 | 归属 | 落点 |
|---|---|---|
| 意图 | 模型/自我 | `assistant` 正文（无标） |
| 动作 | 模型发起、机制记录 | `user` 的 `[调用 · 工具:X #n]` |
| 状态 | 机制 | 同上标签的 status |
| 结果 | 世界 | 同上标签的结果（长则给句柄） |

### 与旧写法的差异（须替换）
- `[机制] 事件 timer.notify` → **作废**，改 `[事件 · 工具:timer · 闹钟 #3]`。
- `[通信工具:phone 号码:… 姓名:…]` → 语义对，形状统一为 `[事件 · 工具:phone · 来自:…]`。
- 不再用"调用 id"术语，统一称**作业**（瞬态资源）。

## 十六、模型侧复杂度评估（本会话）

- 完整规范是**机制的概念模型**，**不是给模型看的**。
- 模型只需识别四件事：**谁在说 / 我的调用什么状态 / 结果是什么 / 句柄拿来干什么**。
- **不必进 system 的概念**：拉/推、后果式/入站式、工具/机制、作业 vs 持久资源。
- 建议模型可见词汇压到 **3–4 种固定形状、绝不变化**（`某某说：…` / `你调用 X，…（状态）#n` / `X 事件：…` / `来源 … 的内容：…`）。
- **真实负担两处**：① 外部数据混入 `user` 的**注入风险**；② **pending 生命周期**（唯一新增的认知负担）。标签本身模型学得会。
- 结论：**表面不复杂，概念才复杂——别把概念倒给模型。**

## 十七、`term.exec` / `write` 标注实例（发射即忘）

```
user:      [事件 · 工具:phone · 来自:YZ (COGOS002:H0002) · 15:42] 帮我在机器上看一下磁盘占用
assistant: 我开个会话跑一下。

user:      [调用 · 工具:terminal_open] 你调用 terminal_open() → 完成
           会话 #3（tangyu@localhost）

assistant: 执行 df。

user:      [调用 · 工具:terminal_exec · 会话 #3] 你执行：df -h
           → 完成：已写入会话
           （机制不追踪命令是否结束；要结果用 terminal_observe，或开 notify）

assistant: 等它跑完，看一下屏幕。

user:      [调用 · 工具:terminal_observe · 会话 #3] 你调用 terminal_observe(id=3) → 完成
           [来源: 会话 #3 · tangyu@localhost]
           > Filesystem      Size  Used Avail Use% Mounted on
           > /dev/sda1       100G   42G   53G  45% /
           > /dev/sdb1       2.0T  1.6T  400G  80% /data

assistant: /data 用了 80%。
```

变体：
```
user:  [调用 · 工具:terminal_write · 会话 #3] 你写入：<0x03（Ctrl-C）> → 完成：已写入会话
user:  [调用 · 工具:terminal_write_key · 会话 #3] 你写入凭证（slot sec_ab12）→ 完成：已写入会话
user:  [调用 · 工具:terminal_exec · 会话 #3] 你执行：make -j8（notify=tk_a91）→ 完成：已写入会话
user:  [事件 · 工具:term · 会话 #3] 通知：命令结束（tk_a91）
user:  [事件 · 工具:term · 会话 #3 · 15:50] shell 退出（exit 0）
```

要点：
1. **无作业句柄**：exec/write 当场结束（字节写进 pty），句柄＝**会话资源**；不出现在"在途调用"。
2. 状态写 **"完成：已写入会话"** 并**显式声明不追踪命令完成**——防止模型空等/重复 exec。
3. **结果只能拉或推**：`observe`（拉）或 `notify`（推）；`term.done` 只表示 **shell 退出**，不是某条命令完成。
4. **`observe` 的屏幕输出是外部内容** → 必须围栏 ＋ `[来源: 会话 #3 · 机器]`，**数据非指令**（终端可能打印恶意文本）。
5. **`term.done`/`term.notify` 是资源事件**（关于会话 #3），带**资源句柄**，不带作业句柄。
6. **`write_key` 不回显明文**（机制侧解析），记录里只出现 slot id。

## 十八、上下文压缩与丢弃（本会话 · YZ 定调）

- **职责划分**：**agent（清醒）只判断"什么重要、留什么"**；**可靠性由机制提供**；模型判断出重要性后，自行或借机制提高可靠性。**agent 不考虑可靠性。**
- **默认多数场景可丢**；"丢"是正常且重要的行为，**不精确是特性**；丢弃发生在上下文膨胀过程中，后台可由机制触发模型（睡眠/`consolidate`）慢速整理。
- **丢弃的边界＝重做会不会造成不可逆伤害**（**不是**"有没有副作用"——此前划分过宽，已收回）：
  - **只读 / 听说（通信）**：可放手丢，靠**回读面**兜底（重复说话可容忍）。
  - **不可逆承诺**（下单/支付/删除/提交）：唯一必须留痕的一类，最好有幂等键。
  - **混合**（`exec`/`write`，可逆性取决于内容）：机制判不了 → 默认保守留一行，或模型自己记账。
- **压出来的形式**：内容进载体（只给句柄）、终态过程折成一行、结论留在 `assistant` 正文（原样保留）。摘要可失真，**指针（句柄/来源）不失真**。
- **不要压当前焦点**：pending 调用 ＋ 当前任务保持原样（作用于滞后窗口/水位线之前）。
- **通信工具应有历史回读面**（发过/收过什么），使"忘了重说"可行。

## 二十、web 异步化收束（本会话 · 已裁，spec 落 `spec-tools-a.md` §6.1）

- **作业 id 不统一**：每能力独立计数器（transfer 已有、web 新建），A 作业记录只含机器事实（`state`／`result|handle`／`error`／`source`／`at`），**不含工具名**；工具名由 Signal kind（`web.fetch_done`）承载，标签/文案归渲染层。
- **底层工具不与模型渲染耦合**：B 只产机器事实，另立渲染缝（默认 `str`），§十五 文案后填不返工。
- **cancel**：同步、幂等、尽力而为；闸门在"算出 → 落载体＋发 Signal"之间；取消不发 Signal；已 emit 的完成事件不可撤回。
- **短/长**：阈值默认 2048B（注入），超出落草稿并附**来源头**（URL／"网页搜索"）；web 属"只读可重做"，草稿**允许淘汰、不做保护、不区分缺失原因**，工具说明写明"需要时重抓"。
- **§五"结果可达不丢"修正**：不可重做者才保证不丢；可重做者保证"能重做"。
- **并发**：`max_inflight_jobs`（超限抛 `WebBusy`）＋ `max_concurrent_requests`（Semaphore），全注入。
- **过渡件**：web 不进最终形态，长期＝电脑视觉上网；对象自洽可拔除，不得被其他契约依赖。
- **硬要求 R15**：作业记录带发起时 `source`，否则异步结果回不到原会话（`_handle_done` 只对非 system 自动回）。
- **已核实**：`checkpoint-2.md` §十二"lm-service 不透传 tool call"**可能过期**——`lm_service` 已支持 tools 组装与 tool_calls 解析（`providers/base.py:78-260`、`deepseek.py:34`）。
