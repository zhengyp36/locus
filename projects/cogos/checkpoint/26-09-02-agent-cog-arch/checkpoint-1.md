# checkpoint-1 — 认知节奏：先粗后细 / 想与说并行 / cu-thread-元层架构

> 纯设计讨论（09-01 下午），无代码改动。原始问题：不用 thinking 模式会损失什么、能否用 in-context 思考替代。讨论后收敛出一套独立于 thinking 的认知机制。

## 当前问题

让 agent 的思考像人一样「先粗后细、边想边说、可中途纠偏」，而非一次性完整输出。

## 关键结论 / 决策

1. **动机澄清（非省 token）**：先粗后细是为了「控制思考的交流节奏」——先说初步想法、听对方反应、再细化，可中途纠偏。不是省 token、不是模拟人。

2. **认知科学依据**：人「粗到细」是被工作记忆小容量（~4 槽）逼出来的分层策略；模型「一次性」是被对齐训练塑造（无此生理压力）。要复现，需外部强制分层节奏。

3. **想与说并行**：人「说粗时脑子已备好细的」靠两个独立通道（隐藏工作空间 + 外化通道）。LLM 无 thinking 时想=说；有 thinking 时想和说是串行两段。但用多 cu 多流拆分，把「想」「说」「输入」分成职责不同的并行流——这是真并行，不是逼近。

4. **架构收敛（YZ 拍板）**：
   - cu 加 `oneshot=True`：不管有无工具调用只走一轮；有工具就执行完结束（不续轮）。cu 回归「单次 LLM 调用」。
   - 新增 thread 概念：thread = cu1 -> cu2 -> cu3... 序列。元层是一个 thread，推理流是一个 thread。
   - 元层职责：接收用户消息，决策三问「对方说了什么 / 我想到什么 / 要不要先说思路、细节让推理流再想」。
   - 元层调度落在 cu 的停顿点（轮次边界），协作式而非抢占式打断。
   - 命名冲突忽略：通信层与认知层相互独立。

5. **cu 产出从「消息数组」改为「一条结论」**：
   - 不保留消息原始形态，每次 cu 输出一条结论（含前因后果）。
   - 工具调用另起一个 cu 总结（不在原 cu 内完成，保持 oneshot）。
   - 总结规范化：不是摘要，是文档式——去不重要的过程细节、保留重要信息/因果链。
   - 效果：每次 cu 后总得到一条想要的消息，不是消息数组。

6. **折叠/展开**：粗 = 结论（折叠态），细 = 展开。内容一长就折叠。暂不考虑 token。

7. **「为什么短」的答案**：短 = 密集停顿点 = 密集调度机会（可调度粒度）。
