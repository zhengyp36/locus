# checkpoint-7 — 对象化认知 + 生命周期 / 记忆与遗忘机制（视觉功能讨论延伸）

本文件记录视觉功能讨论延伸出的"对象化 / 生命周期 / 记忆-遗忘"独立内容，与意图方案（checkpoint-6）并列，为 cog-func / cog-actor 落地做铺垫。

## 当前问题

用对象（IntentObj / ImageObj / agent）组织工具与上下文是否只是"做复杂了"，其好处、生命周期、以及记忆/遗忘机制如何设计。

## 关键结论 / 决策

### 1. 对象化：函数式轻对象，非 OOP 重对象

- 与 checkpoint-3"未来 = cog-actor 函数式轻对象（不可变状态 + 行为组合）"吻合。**不是"像不像 OOP"，而是"一份状态值不值得被赋予身份"**。
- **对象化判据**：一份状态是否 ① 跨多次调用被共享、② 有记忆/缓存价值、③ 行为绑定在这份状态上。满足才对象化。
- **对象谱系**：IntentObj（被动记录/值对象，对象化为异步可找回 + 时间线节点）/ ImageObj（真轻对象：可变状态 + 行为组合）/ agent（主体对象 cog-actor）。
- 一次性无状态流程（ImageTool 入口解析/路由/校验）**不对象化**，保持纯函数。
- 用 **composition（行为组合）非 inheritance（继承/多态）**——cogos 轻对象不需要 OOP 重语法。

### 2. 对象化好处（解决"上螺丝吃力"的根）

- **记忆/缓存**：对象缓存内容，主 LLM 多次画图不重复全程重看（省 token + 快）。= 视觉暂存。呼应 vision 视角"看清靠 crop 不重复全量重看"。
- **状态生命周期清晰**：每个工具 = 独立 LLM 上下文，建/缓存/清由对象管理，作用域明确 = 上下文容器（harness 状态句柄的系统化）。
- **工具隔离 + 可复用**：一个工具集 = 小而专注的对象，主 LLM 面对"能力标签"不陷入选择困难（意图方案目的）。
- **主体性流动载体**：agent 也是对象，对象间传 IntentObj/ImageObj = 主体间协作（cog-actor 雏形）。
- 根因：以前状态无处安放（散在流程变量：循环/槽/阈值），才写得累。

### 3. 统一"边缘信息跟经历走 vs 跟对象走"

- 两层都有，非二选一：**时间线/经历跟主 LLM（IntentObj 串），资源状态跟对象（ImageObj 缓存），经引用链接**。对象是主 LLM 经历中可复用的持续资源，边缘信息指回它。
- 边缘信息保留但不进主上下文（checkpoint-5 遗留-1）在此有落点——内容在对象，主 LLM 拿锚，要看才加载。

### 4. 信息组织 = 图（非树）

- 对象可复用（同一图/文件被多次意图引用）⇒ 是**有向图（含共享、可能含环）**，不是纯时间线单链的树。
- 后果：未来清理走**可达性 / 引用计数**，而非时间线剪枝。

### 5. 记忆 / 遗忘机制（非被动垃圾回收）

- 遗忘是**主动、带价值评估、持续的精简压缩**，人脑类比：近清晰远模糊 = 被持续整理压薄，留下重要的。
- **两个维度分开**：信息层遗忘（时间线/经历薄化）vs 对象层回收（实体删除）。
- 串成链：**边缘信息薄化（摘要化）→ 高价值锚保留 → 对象无高价值锚引用则回收**。遗忘是主循环，回收是下游。
- 整理三件事：时间性衰减 + 价值权重修正（防"关键决策被压糊"）+ 增量分层压缩（= checkpoint-3 compaction 的持续化/带价值升级）。
- **价值评估归属语义层**：主 LLM 周期整理时判断"这段经历重不重要、留多细"；机制层只提供框架（锚保留/摘要化/引用计数）。机制层准、语义层转。
- 检索歧义的解法=常驻整理（一直压薄），非等累积。

### 6. 对象三级寿命

驻留（热）/ **淘汰可重载**（冷，盘上，要用读回）/ 回收（无高价值锚，真删）。

- **两个正交信号**：淘汰 = 时间维度（最近是否访问，LRU，**机制层规则自动**）；遗忘 = 价值维度（重不重要，**语义层主 LLM 判断**）。
- 工作集大小 = 机制层可配置的"驻留对象上限"，超限按访问时间淘汰（把 locate 图池 N1/N2 从图推广到所有对象）。

### 7. 淘汰 / 重载一致性

- **淘汰不是清空，是"对象状态落盘迁移"**；重载恢复**对象当时状态**（工作拷贝/缓存/上下文快照），非重头打开/重读——否则未保存改动丢。对象身份/记忆连续。
- **保存双语义**：显式保存（LLM 说保存 → 即时 flush）/ 兜底 flush（淘汰时把未保存工作拷贝写回，不丢改动）。
- **md5 指纹一致性**：对象内存态基于某版本原文件内容 + 记该版本 md5 指纹。① 显式保存 → flush + 更新 md5；② 淘汰 → 兜底 flush + 更新 md5；③ 访问/重载 → 校验原文件 md5：= 指纹则缓存有效，≠ 则缓存失效、通知主 LLM 重看/重读。
- **md5 触发点校准**：不只"重载时"，应在**主 LLM 每次真正用对象状态做决策时**校验（访问时）——驻留期间外部改也能及时检出。单文件 md5 毫秒级，成本可接受；冷对象自然少校验。可加 dirty/version 标记控制频率。
- **md5 变化 = 失效信号，不自动处理**：交主 LLM 决定（重看/重读/以外部为准），不机制层自动合并覆盖。

### 8. 对象分类

- **可写对象（文件）**：工作拷贝 + 保存/兜底 flush + md5。
- **只读对象（图）**：无工作拷贝，**不涉及 flush**，只有"缓存失效 + 重看"。图简单。
