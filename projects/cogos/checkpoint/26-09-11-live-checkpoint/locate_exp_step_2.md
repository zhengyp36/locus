# locate_exp step_2 — 对话式定位（第 2 次）

> 承接 `locate_exp.md`（方法说明 + 工具 + 素材）。本次为「对话式定位」第 2 次试验。
> 目标：测主 LLM 在对话引导下，能否用 img_tool 定位目标，并暴露真实策略行为。

## 试验流程（真实轨迹）

1. **信息与环境**（`locate_exp.md` 已记录）：原图 `/tmp/kilo/vision/locate_exp/detail.jpg`（4000×3000），全景 `pano_800.png`（800×600，scale 0.2）。
2. **全景第一印象**（仅凭 800 全景，未调用工具）：描述为"青绿渐黄背景 + 细网格线；散布大量 Python 关键字标签（vision/ctype/data/range/django/clone/self/HELLO 等）+ 一串数字（12345/5.938/0.656 等）+ 大量相似空心小矩形"。**第一眼无突出目标**，仅"中部偏右矩形稍密"的注意力倾向。
3. **被问"中心偏右两矩形纠缠、其一近正方形，能否看到"** → **调用 extract 放大该区域**（`--region 0.45,0.35,0.35,0.4`, 得 800×686, scale 0.571）确认：中央确实有一对纠缠矩形（小正方叠大竖长），左上有 `range`、右下 `detail`。全景归一化约 (0.52–0.56, 0.36–0.42)。
4. **被问"为何调用工具"** → 自省：① 全景尺度下那对矩形仅二三十像素，无法确证形状/关系（信息量问题）；② **更关键——把"再细看同一张全景"外包给了工具**，倾向"有取图工具就调"这种更低成本验证路径，而非先穷尽手头 800 图。→ 划分出"感知失败 vs 策略失败"两类。
5. **框定目标**（draw）：`--rect 0.578,0.47,0.055,0.09` → `boxed_target.png`（800×600, scale 1.0）。红框罩住纠缠对，略偏左。

## 结果

- 单次对话式定位**成功**：位置与真值（归一化 ~0.596, 0.513）一致，框基本准。
- **但暴露真实策略**：定位不是"看全景直接判断"，而是**"先有模糊印象 → 调用 extract 放大 → 再报坐标"**。对话引导（中心偏右锚）给了明确起点，规避了旧循环"初始定位错一跳"的薄弱点（locate_issue 发现 3）。
- 待验证：多次是否稳定；无对话锚（不给"中心偏右"提示）时，起点跳变是否重现。

## 关键观察（本轮）

- **对话锚 = 免费的先验**：目标提示"中心偏右"直接消解了"先聚焦再看"的执行缺口，这是旧循环靠机制硬做、这次靠人给提示做到的。
- **工具调用行为可自省**：LLM 能区分"信息量不足"与"策略偷懒"，这一层是坐标推断给不出的。
