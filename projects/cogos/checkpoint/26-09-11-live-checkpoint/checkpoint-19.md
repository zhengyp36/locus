# checkpoint-19 — 定位不稳的归因：capability / ambiguity / no-adjudication + TODO

接 locate_exp（对话式诊断 13 测）+ 稳定性 5 测（t8-1~5）。本文件固化"定位不稳到底能得出什么结论"的收敛，重点是把结论**切在两段制的缝上**，并登记一组待逐一讨论的议题。

## 现状数据（不重复，见 locate_exp.md）

- 13 测（t0.2×3 + t0.7×10）全部定位到 "range" 附近中心略偏右区域，**无一框到别的相似矩形**。
- 偏移分布：多数 1~5px，尾部 run4(+16px) / run2(+11px) / t7 run4(+20px)。
- 目标是一对约 35~50px 的矩形 → 16~20px 偏移 ≈ **半个目标以上**，对精定位是真实失误，非"贴得不够漂亮"。

## 结论收紧（比"细节处理不好"更准）

模型**"该看哪里(coarse)"稳定**，但**"边界回归 + 够不够好的裁决(fine)"不稳定、且无收敛判据**。

## 不稳定 = 三件事叠加（逐一待讨论）

### A. capability：语言回归到顶（YZ 点1，成立但要收紧）

不是"用整张图"这个动作，而是末端三层叠加的精度地板：
1. **last-mile 边界回归精度地板**：目标只占全图 ~5% 宽，要在一张 800×600 上把框中心定到 1~5px = 在全图视角回归极小目标，在视觉精度边缘。
2. **嵌套坐标换算算术误差**：模型先定在 crop、再乘 region 偏移链回原图，是 `(offset×局部归一化)` 算术，误差逐层累积（那些 0.578→0.58→0.576 的来回改多是算术噪声，非感知错）。
3. **用"语言描述边缘在哪"而非"逐像素回归"**：框继承视觉语言量化误差（约 crop 5~10%），5~10px 是表达机制固有噪声。

→ 结论：不是"要不要用原图"，而是"**用语言回归边界"这个动作本身到顶**。

### B. ambiguity：目标定义模糊（YZ 点2，最大混杂，比预想更狠）

1. **输出规格没定死**：单框套整对 / 双框各自标 / union？run 内已分裂（t8-1 单框，其余双框）——这是**任务定义模糊**，不是模型失败。
2. **"纠缠的 pair"本身仁者见仁**：图里散布几十个矩形，哪两个才算"那对"没有客观唯一答案。
3. 我们的真值 (0.596,0.513) 只是**某次人手标的模糊对的框** → 比出来的"不稳定"里混着一半是**参考本身不唯一**。

→ 最重要：**在目标定义钉死之前谈"模型不稳定"很危险**，一部分"偏离"其实是任务允许的不同合理解。

### C. no-adjudication：自校验缺失（YZ 未提，run2 实证，最能指向下一步）

模型在所有缩放级都描述正确、坐标也算到准值(1~2px)，最后却犹豫不决、弃用精确值、停在"感觉偏"。**不是看不清/噪声大，是没法裁决"够不够好、要不要重画"**。自己给的置信度(90%)是生成物、不可靠。

→ 真正锁死它的不是感知精度，而是**没有独立的"判定已收敛"机制**。

## 落地方向（不是继续调模型，而是把不确定性从设计上拿掉）

1. **两段制**：coarse（定位到区域，已证稳）给模型；fine（精确边界）在"目标填满画面"的局部 crop 里回归 → 缩小参考系、抬高有效分辨率（治 A）。
2. **边界回归 → 离散判定**：最后问"目标在不在这个格子/是否呈现"——点击/区域命中(cheap、抗噪声)而非连续 bbox(易受算术误差)（治 A 天花板）。
3. **裁决给机制层**：几何收敛阈值 + 坐标台账独立判定"够不够好"（治 C）。
4. **先钉死任务定义**：单框/双框/union？哪个 pair？（先定义、再谈稳定）。

## T1 已定（YZ 拍板，2026-09-06）

**两段制 = 先粗后精，粗框宁可大、不能漏。**

- 第一步(coarse)：在整图上圈一个**确定包含目标、可以大、可以框不准、唯一硬约束是不能把目标漏在框外**的粗框。只负责"框住"，不负责"框准"。
- 第二步(fine)：只在这个粗框里精修。因为粗框已把范围缩到极小，目标占比自然变大（从占全图 ~5% 升到占局部 1/3），精修才容易。
- 本质 = **换坐标参考系**：粗段全图坐标、细段局部 crop 坐标；坐标换算归机制层，模型永远只在当前帧参考系说话（杀 offset 链算术误差）。
- 关键分工（YZ 认可）：**模型给语义方向，机制层管坐标/帧管理/换算/兜底**；"保证框住"的判权在**机制层技术基线**（分辨率/目标占比/候选清扫），**不在模型自称**。
- **方法论修正（YZ，重要，推翻"coarse 后全图消失"的设想）**：全图与局部图**必须同时在上下文**，且模型**必须知道两者关系**（局部=全图哪个区域、从哪切出）。以人的视角，全图**始终在场**，局部是"从全图切出、又能指回全图"的同一认知体，不是两张无关的图；**不能先看全图再丢弃全图只看局部**。**最终目标 = 给模型工具，让它自己组织出这些关系**——关系不是靠"同时在场+文本记忆"自动成立，而是要靠**带 region 参数的工具调用把它显式化**（模型调一次 `extract(full, region)`，关系即落进上下文："我从全图 (x,y,w,h) 切出这块"），从而能在"全图↔局部"间自由往返、核对、修正。**因此"两段式"坐标轴 = 同一全图下的多视图关系操作（粗框锁定的是"关系中的一块"，而非"一个新输入的孤立局部图"）。**
- 尚未展开（T2/T3，先记下）：放大治"看不清"但**治不了"犹豫不敢定"**（需 T3 机制层裁决）；进精修前**先钉死"目标是谁"**（T2）；"保证框住"只能靠机制层兜、不能靠模型自证。
- **验证缺口（已闭合）**：coarse 自身稳定性未知——若粗框本身不稳（会漏框），则 fine 的局部占比前提全塌，后面空谈。故先做 coarse-only 实验：只让模型"框住不漏、不要求精确"，看稳定性。**结果看下节，5/5 框住不漏 → coarse 稳，fine 地基成立。**

## T1.5 coarse-only 实验结果（2026-09-06，稳）

**任务**：只做一件事——用 draw 框住那对纠缠矩形，宁可大、不能漏，不要求精确。图 `pano_800.png`（t=0.7，5 测，各清 history）。产物在 locate_exp/coarse_1..5。

**真值对（边缘检测实测）**：(0.579, 0.487, 0.034, 0.060)，中心 (0.596, 0.517)。

| run | 粗框 (x,y,w,h) | 目标覆盖 | 框面积/目标面积 |
|---|---|---|---|
| 1 | (0.525,0.480,0.110,0.120) | 100% | 6.5x |
| 2 | (0.530,0.470,0.130,0.120) | 100% | 7.7x |
| 3 | (0.555,0.460,0.075,0.115) | 100% | 4.3x |
| 4 | (0.560,0.470,0.090,0.110) | 100% | 4.9x |
| 5 | (0.575,0.475,0.065,0.090) | 100% | 2.9x |

**结论：coarse 稳定**——5/5 全部框住不漏，框都偏大（2.9~7.7x），正符合"宁可大、不能漏"；目标占比从全图 ~5% 提到粗框内 ~12%~34%。多数一次 draw 成功；仅 run3 画 2 次（先小后大自扩，非卡死）。**未复现 run2 式纠结**。→ fine 的局部占比前提成立，两段制地基稳固。
（注：此前基于粗 GT(0.570,…) 判断 run5 MISS 是**误判**，边缘检测修正真值后反转——下结论前必须拿实测坐标核对，不能凭粗估计。）

## T1.6 身份/桥接 probe（H1/H2，2026-09-06）⚠️ 含验证偏差，待重做

**先验修正**：最初"coarse 身份稳定"是位置假象（目标附近无相似物）。但本 probe **有人为制造陷阱**，结论需打折，见下。

**probe 与偏差（YZ 指出，重要）**：`window_with_decoy.png` 里的左下角 decoy 对是**人工画上的，全图 pano_800 里不存在**。这造成矛盾：任务说"窗口是全图切出"，但窗口多了全图没有的目标 → 全图与窗口不一致。用此测"全图锚能否防跑偏"**不公平**（我人为制造了自相矛盾 + 相似干扰，两个变量纠缠）。

**暂定结果（含偏差）**：5/5 框到 decoy，未框真实目标。但这最多说明"并置相似目标会带走模型"，**不能**干净证明"全图锚无效"或"位置变化致混淆"。

**待重做（YZ 拍板方向）**：回到 YZ 原始朴素问题——**同一真实目标，相对位置平移后模型能否跟住**（无需虚构 decoy）：用全图真实目标（"range"旁那对）切一个**只含该真实目标**的窗口，任务说清"窗口是目标局部、请框出"，看模型会不会因位置变化而定位错/跟丢。这样全图与窗口一致、无矛盾。

## 一句话

**你看到的是"细节层不稳"，但它是 capability（语言回归到顶）+ ambiguity（任务定义模糊）+ no-adjudication（自校验缺失）三件事叠加，后两件尤其被低估。三者会分别用 local-frame 回归 + 钉死定义 + 机制层裁决去解，而不是调提示词。**
