## 机制口径：触发 / 对账（2026-09-10，YZ 提出并收敛）

**问题**：提示词只能"请求"、不能"约束"；环节边界在模型内部，外部看不见也控不住 → 不能建在"它会听话停在某步"上。

**收敛口径**：
1. **停 = 触发**；触发后 handler **统一**（对账）。正常停→进下一步；延后停→问为何超步、重估；提前停→拿计划核实后续。**同一动作（对账）的不同分支**，不是三种机制。
2. **流程本质 = 一组「带可核验证据的条件」清单 + 周期性对账器**；**顺序是结果，不是约束**——"提前做了"不再是问题，按规则标记即可（对应文档 §四看门狗形状）。
3. **对账 = 把「验证→分析→裁决」三环，从"结果 vs 参照"平移到"进度 vs 计划"**：验证=实际进度 vs 冻结计划的差异（早/晚/偏）；分析=为何；裁决=advance / 质问超步 / 复核后续。**分类是裁决的输出，不是触发的输入**，故"停"无需分类。
4. **两条不可省**：
   - **保证至少停一次**：否则没有对账机会、仍会漂 → budget cap 作**唯一带保证**的触发（§四第三段 p=1）；它从"限流"变成"点火"。
   - **对账必须有证据**：清单项写成"带可核验产物的条件"，不是勾选框；否则复现假自评（"按规则标记不出错"仅在规则要求证据时成立）。
5. **副作用**：不再需要"按步开工具/限定上下文"来堵"提前溜步"——统一对账已消解该伪问题。
6. **预算分层（2026-09-10，YZ）**：防"无限续期"靠**任务预算**，不是 agent 自设。
   - **任务预算**：由**指派方（任务提供方）**给定，**硬**；超出 → 强停，只能**总结过程 + 提交结果（附过程）**，不得自行续期（否则 = 自我授权，无限续期未解）。符合 §五"参照不受自己控制"。
   - **分段 `N`**：模型自估的**软**预算，每个 cap/对账点可据过程**重估 `N′`**；但 `ΣN ≤ 任务预算`。
   - **对账输出显式化**：`advance | extend(N′, 理由+证据) | redo | abort`；剩余任务预算不足 → 强制转 `abort/submit`。
   - **打断点须落在"有可核验产物"处**（否则对账空转）。
   - **强停后的产出**要能分辨三种收束：部分成功（部分 pass + 残余不确定）｜未完成（fail/undetermined + 过程）｜已失败 → 故**过程证据全程留痕**。
   - **单位/缺失**：单位（轮/步/时/token）先定；指派方未给 → agent **事前澄清**要一个，不默认无限。

**触发器集合**（需覆盖）：正常停 / 超预算 / 提前停 / 停滞 /（可选）随机。

**待定**：Step 2 的最小实现 —— 任务预算的**单位与数值**（YZ 指派方给）、`N′` 重估的上下限、`--max-inner` 到 cap 的收尾（默认：停 → 立即对账）。

## 暂停实验 / 冻结（2026-09-10）

- **状态：实验暂停、冻结在 S3 门槛前。** 会话与快照原样保留，不再跑新实验；先讨论并定案**显式化机制**。

- **暂停原因**（YZ 判断，AI 认同）——模型的"验证/裁决"是**模糊的整体判断**，不是可复核的对表：
  1. 输出是"对齐良好 / 自检通过"这类**整体感觉**，**两端都模糊**：它给不出可复核证据，我们也只能"看着还行"。
  2. **恰好通过无法证伪**：一次"看着对"，分不清是"真对"还是"模糊判断碰巧过" → 结论：**无论结果好或坏，都该补机制**。
  3. 它已**自认完成、请求提交**（#74）→ "自评"这个出口本身不可信；继续测"它会不会自发真验证"，是在反复确认一个已判定**不可依赖**的东西。
  4. 故 **Step 3（S3 触发式验证）旧形态作废**——结果必然模糊，测不出稳定结论。

- **对已知结论的修正**：Step 2 中"判 PASS 全无『框 vs 文字』"应**收窄为"收尾自检（#74）里没有"**——执行阶段（#50）它其实做过"标注中心 vs 放大图量出的文字中点"的数值比对。真正缺的是：**收尾不会回到计划里的真验证步**，且**判断无处落成可复核产物**。

- **冻结边界**：S1 会话（75 条）＋快照 `_snapshots/s1_after-step2-reconcile/` 原样保留；本文件只追加、不删旧结论。
