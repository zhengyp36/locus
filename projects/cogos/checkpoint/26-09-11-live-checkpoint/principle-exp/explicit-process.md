## 一、对象：整个流程，不是单点证据

- **病根**：模型凭感觉走——动前不知道自己在哪一步，动后没有"这步算不算完"的结构；于是"感觉走到了"就算完。
- **显式化对象 = S1–S8 的整个流程状态**，让模型运行时**时刻知道自己处在哪一步**。

## 二、形态：流程看板

```
步骤           状态           产物/证据           判定
T  触发        done           任务 + 预算          —
S1 规划        done(★)        C / V / B（冻结）    确认
S2 执行        in_progress    结果 + 轨迹          —
S3 验证        pending        证据 E               —
S4 裁决        pending        verdict              —
S5 决策        pending        继续 / 强停          —
S6 分析        pending        类别 + 形态          —
S7 规划(修订)  pending        动作                 —
S8 提交        pending        出口 + 证据 + 残余    —
```

- **动前**：`current = Sk`——声明这是哪一步、这步的"完"长什么样。
- **动后**：`done`(✓) / `blocked`（有问题 → 分析） / `failed`(✗)。
- 状态取值：`pending | in_progress | done | blocked | failed`。

## 三、关键原则：没有角色，勾由产物推出

- **主体**：勾**就是模型自己打**——不存在"谁来打勾"。
  - 依据：实验五（视角/角色/上下文都不是变量，`draft §一`）；§一 口径更新（"视角/角色"退场，缺口只剩 `触发`+`通道`）。
- **有效性**：勾算不算数，**不由谁打决定，由"勾有没有挂在结构化产物上"决定**。
- 故：**不是"不能自己打勾"，而是"勾要挂在结构化产物上"**——`✓` 是**产物的函数**，不是自报。有产物 → 勾成立；无产物 → 空 ✓（空转）。
- 三件东西，**没有第四方、没有角色**：**触发**（走到这一步）+ **结构化产物**（这一步凭什么算完）+ **状态由产物推出**。
- 这正是 §5.3「把意愿问题转成结构性闸门」的落地：闸门要求"必须产出结构化产物"，不是"换个人来判"。

## 四、两层分工

| 层 | 解决什么 | 缺了会怎样 |
|---|---|---|
| **流程显式**（骨架＝看板） | 知道自己在哪一步 | 凭感觉走、早停 |
| **产物显式**（载荷＝证据） | 这一步凭什么算完 | 空 ✓、出口偏乐观 |

两者合起来才叫显式化。

## 五、内容如何定：派生规则

**核心命题**：内容不用"填"，是**刨出来的**——每格产物由上一格产物按派生规则唯一（或强约束）推出。**主体性不重要是结果（规则确定），不是前提。**

```
G（目标）
 └─▶ C（判据，带阈值 + 参照来源）   ← 内容之根
      ├─▶ V（验证计划）
      ├─▶ E（证据：C 的逐条展开）
      │     └─▶ verdict（C 条 × E 行，机械函数）
      │            └─▶ 分析（E 的形态 → 类别）
      │                   └─▶ 动作（类别 → 策略）
```

**schema 固定、值实例化**：字段/形态由通用契约固定（任务无关）；值由任务层从 C/G 实例化。

**逐步派生规则表**：

| 步 | 产物 schema | 从什么派生 | 确定度 |
|---|---|---|---|
| S1 | `C[] / V / B` | G → 可观察属性（每条带阈值 + 参照来源） | 中 |
| S2 | 结果 + 轨迹 | 按 V 执行 | — |
| S3 | `E[]` 逐条 | **C 每一条 → 一行测量**（机械展开） | **高** |
| S4 | `verdict{}` | **C 条 × E 行 → pass/fail/undetermined**（机械） | **高** |
| S5 | 继续 / 强停 | 预算 + 是否"无解" | 高 |
| S6 | 类别 + 形态 | E 形态 → 类别（**类别集固定**，半机械） | 中 |
| S7 | 动作 | 类别 → 策略（调参 / 重规划 / 回炉判据） | 低（开放） |
| S8 | 出口 + 证据 + 残余 | 汇总 S4/S6 | 高 |

**派生规则 v0**：

- **R0（外部输入清单）**：显式列出需**指派方**供给的格：任务 G、**预算初值**、参照来源选择……并标注 `谁给 / 初值 / 可否续 / 续的触发点`。
- **R1（S1）**：每条 C 必须实例化为 `{可观察量, 阈值, 参照来源}`；不可测的判据不许进 C（或标为待澄清）。
- **R2（S3）**：`E = μ(C)`：对每条 C 按"参照来源"取值，产出 `{条目, 测量值, 参照值, Δ, 尺度}`；无参照 → 该条 `E=∅`。
- **R3（S4）**：`verdict = f(C, E)`：逐条判定；某条 `E=∅` → `undetermined`；全 pass → pass。
- **R4（S6）**：`类别 = g(E 形态)`，类别集固定。
- **R5（S7）**：`动作 = h(类别)`。

**预算 = 协商产物（不是单向输入）· 动态（2026-09-10 YZ）**：

- **初值靠协商**（不是指派方单方给）：
  1. 指派方问模型："完成这个任务你估计要多少预算（轮/步）+ 依据"；
  2. 模型**提方案**（数值 + 依据 = 可证伪的承诺，非裸数字）；
  3. 指派方评审是否符合预期 → 接受 / 还价 / 封顶；
  4. 双方**定格**一个值，写死。
  → 本质是一次**事前对齐**（§5.4「先提方案、请求确认」）；**预算协商 = open 闸的实例**。
- **信息分工**：模型握"任务难度"（近端）；指派方握"期望 / 成本"（远端）。协商 = 把两端对齐。
- **对账点再走一遍**：模型 `申请续期(N′, 理由+证据)` → 指派方 `批准 / 终止`；续 = 在已有基础上追加，停 = 按当时状态收束。
- **硬约束**：模型只能**提方案**，不能**批预算**；定格值模型不得单方更改，否则 = 自我授权。
- **无指派方时**（全自动）：模型自估即定格（自提交 + 冻结，§5.5 低信息增益）。
- **续 / 停都要有对账证据**（进度 vs 计划），不凭感觉。
- 看板：S1 的 `B` 记「协商过程 + 定格值」；S5 分两侧 `advance | 申请续期 | redo | abort` / `批准 | 终止`。**不引入角色**——指派方是外部参照提供者（§5.5）。
- **本实验的取值（2026-09-10）**：目标 = 让模型完成任务、验证理论 → **预算给宽（相对长）**。须标记：**宽预算下"完成" ≠ "模型省着花"的证据**；预算紧张下的行为另设实验。

## 六、四条边界 / 风险

1. **确定度分层**：S3/S4 可唯一派生，S6 靠固定类别集半机械，S7 最开放。强行全机械 = 假精确。
2. **C 必须完备**：C 漏测的，E 就漏，判定抓不到。兜底：C 未覆盖的可疑项 → `undetermined`，必要时**回炉 C**。
3. **参照来源是规则的一部分**：E 能否生成取决于"参照从哪来"（工具测量 / 人给 / 自承诺，§5.5）。须在 S1 定 C 时写死。
4. **防空壳**：机械的是"证据与判定"；保留的是"归因与修正"（S6/S7 受控开放），否则模型只填表不思考。

## 九、经验层（积淀）：留接口，暂不实现（2026-09-10 YZ）

- **性质**：这是**经验层（记忆自长）**，不属于流程机制；机制只需**留接口**，防以后回头改机制。
- **两处接口**（都挂在流程上，天然的位置）：
  1. **S1 预估**：预算 / 工作量提案可引用"**相似任务历史档案**"作锚（有则用，无则纯协商）。
  2. **S8 提交**：落一条**任务档案**（任务签名 / 规模 / 实际花费 / 结果 / 预估偏差），供未来召回。
- **三条边界**：
  - 历史是**参考 / 锚，不是决定**——防"用历史替代当次判断"。
  - **冷启动退化**：无历史 → 纯协商，不假装有。
  - **"相似"要有判据**（任务签名 / 标签），否则召回是噪声，还会让预估"看起来有依据"。
- **归属**：与 `plan.md`「通路 vs 经验」一致——**预估变准属经验缺位，机制不背锅**。亦呼应题眼：**自驱**（自启动）+ **积淀**（跨任务）都是"整体"的属性；机制负责回路，经验负责长大。
