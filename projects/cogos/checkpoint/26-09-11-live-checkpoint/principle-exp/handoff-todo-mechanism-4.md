## 本会话已定论

### 1. (a) 修 V1 两漏点
- **rule 4 补 `coord`**：改为"一轮只做一个动作——一次观察（see 或 coord），或一次标注（mark/adjust_mark/unmark）"。
- **宿主加"续推"**：`--strict` 下模型纯文字无工具时不立即结束。**必须限制为"首轮且尚未用任何工具"**——初版在任务完成后误触发、把任务整个重跑污染结果，已修。

### 4. 隔离实验 A/B（回应"user 事件有用"的质疑）

| 条件 | 给模型的是什么 | 结果 |
|---|---|---|
| **A** 规则只在 **user 消息**（无反馈） | user 通道、泛化、任务前 | **0/5** |
| **B** 中性拒绝 `操作未执行。`（无指令） | 纯失败反馈 | **0/5（5/5 原样重试同一 see）** |
| **C** 拒绝 + 具体指令（`demo_manual2`） | 失败反馈 + 决策点具体指令 | **1/1** |

**结论**：通道（system vs user）不是变量；失败反馈本身不产生遵从（只会重试）；**唯一起作用的是紧贴决策点、具体到下一句生成的那条纠正指令**。→ **不存在"主动遵从"证据。**

### 5. 机制路线的重新定位
- 老机制 `--mech` 在**计划边界其实有效**（`build_plan` 把计划变成工具调用，V3 2/2）；它失效点：触发条件（撞线/超预算/连续K轮）**全在动作之后**、注入是**菜单式选项**、且**不覆盖"一轮动作数"**。
- 因此"机制固化"= 把人工在决策点的 `drop+注入` 自动化，且**触发与内容都要对准动作边界**，不能只对预算。

## 关键结论（本会话最重要）

1. **"提示词压不住过程边界"的准确含义**：模型理解字面，失败在生成动作时；规则只能移动概率，不能作为保证。边界分两类——**"让出控制权"类**（计划→动作/收尾门）最难（0/4、0/15）；**"只拆分限流"类**（一轮一动作）较易但不稳（1/4）。
2. **原因是模型/协议接口层面的**：ReAct"想法+动作同消息"先验、协议"纯文字=一轮结束"、以及"计数单位（轮）与生成单位（消息）对不上"。**越靠近"让出控制权"，prompt 越无效。**
3. **续轮是宿主行为，不是模型能力**：模型不调工具只能让"这条消息结束"；是否继续由宿主决定，且宿主必须**区分"暂停"与"结束"**（按位置/显式信号/工具相位）。
4. **不存在主动遵从**：静态规则（谁说的都一样）失败；反馈只会触发重试；唯一有效是"决策点的具体纠正指令"。**能依赖的只有结构强制。**
5. **准确性 ← 自驱闭环 ←（可验证反馈 + 自纠）**；本任务恰好缺 Kilo 五要素④——模型每步都拿到回灌标注图，却从不核验、一律"已对准"。

## 单步调试器 `todo_debug.py`（已建成）

- 执行前暂停；`step>` 命令：回车/n 放行 · `a` 自动 · `d` 掐断 · `x` 中性拒绝（`操作未执行。`，无指令） · `say <文本>` 掐断+注入 · `s` 状态 · `q` 退出。
- 模型不调工具时进 `pause>`：回车继续 / 直接输入要发给它的话 / `q`。
- **人工干预机制（B 法 `drop_tools`）**：push assistant → 为每个 tool_call 回 `{"ok":false,"text":"用户打断…作废"}` → 注入 user 文本。
- **已观测**：`say 先只把计划写完，这一轮不要调用任何工具` → 模型当场收手、输出纯计划等指示；再给"开始执行第 1 步" → 按"当前第 1 步"格式恢复。**拉回成立，但一次性**。
- **已知缺陷**：`q` 退出时最后一条 assistant 消息未落盘（B 组 raw 被截断，故 B 结论取自 `.log`）。**待修**。
