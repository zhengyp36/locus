## 二、设计要点（逐条，均已定）

### 1. 两类上下文 + 区分
- **视野区（视觉工作区）**：看图的操作空间。**打开时**（agent 调 `open_view`）才出现、打印到屏幕；**收起**（`collapse`）清窗留索引。
- **会话区**：人说的话 + 模型说的话。**图只出现在视野区，会话历史天然无图，只有 `viewfield0-#N` 引用**。
- 区分靠**三件套**（非 role 单维）：①区块头 `──视觉区──` / `──会话──`；②视野区**固定模板**（工具生成，结构化语言为零）；③命名空间（`viewfield*` vs "我/LLM"）。
- 含义：**视野区=工具生成的客观事实锚（可指、可引用）；会话区=人+模型的主观语料（可回应、可追问）**。两者形态和主体不同，不易混。

### 2. 视野区（类人）
- 一个视野区挂一张**源原图**（数据源）+ 一层**全景图**（整幅缩略，远看用）。
- **打开后消息三块**：①原始图完整信息（路径/尺寸）；②图1（全景图）信息；③全景图本体（初始注入）。
- **图编号全局唯一**（带视野区前缀，如 `vf0-#2`，或全局递增）——否则跨视野区 `#1` 相撞，归属失效。
- **归属显式化**：打开时在消息里写一条"视野区 → 原图 → 图编号"映射；工具内部维护**反查表**（`图编号 → {原图, center/radius/focal, viewfield}`）。
- **滑动窗（容量）**：一个视野区常驻图 ≤ 容量（初值如 全景1+焦点2）。**旧图被挤出常驻窗 → 降为"可查区"只留 `编号+注解` 占位**；需要时 `look_ref` 按编号重注。
- 图可配**文字注解**（轨迹/坐标/焦距/look_step），但**由工具自动生成**，模型无编辑权（保证"客观所见"可信）。

### 3. 工具集（schema 摘要，非代码）
- `open_view(viewfield_id, 原图)`：打开视野区；写归属记录；注入全景图。
- `view(viewfield_id, center, radius, focal)`：在对应原图上，以 `center` 为中心、`radius` 为半宽、`focal` 为清晰档裁剪；产出 `图#N` + 注解，**替换当前窗**。
- `look_ref(viewfield_id, item=N)`：按编号重看已看过的一帧；工具把编号**反查换算**回它当时的 `center`，重新裁。
- `collapse(viewfield_id)`：收起当前窗（清图留索引）——"我看完这块了"的信号。
- `answer(center, ...)`：对外给的结论（收口）。
- **远看近看映射**：`focal` 低（如 1）→ 命中**全景图**（远看全/结构）；`focal` 高（如 3）→ 命中**高清原图局部**（近看清/细节）。

### 4. 坐标与注解约定
- **一律用"当前视野区所在原图的全局归一化坐标"**（`view` 的 center、注解里的坐标都是全局）——避免跨帧局部/全局混用而漂移。
- 注解 = `编号 + center + radius + focal + look_step + 轨迹`，工具自动生成。

### 5. 时间 = 序位（非时间戳）
- `look_step` 递增 + 轨迹箭头链（`步3->步4: (…)->(…)`）表达先后与因果；**不用墙钟时间戳**（§13 结论）。
- "为什么看这里"是**模型主观动机**，写在它**说的话**里（对话流），不是工具注解，也不是 hidden thinking。

### 6. 直接对话、thinking 不开
- 去掉"对内思考/对外说话"二分：模型每轮输出 = **它说的话（打印给我们）+ 它调的工具（view/look_ref/collapse/answer）**，动机自然落在"话 + 看哪"里。
- **厂商 thinking 模式开关**：默认**不开**——思考链通常不回传（反而看不到动机）、拖慢图像多轮；动机靠"它边说 + 人追问"补齐。

### 7. 先思路后执行、平等共同摸索
- 流程：人说明任务 → 模型**先谈思路**（怎么找：远看扫→近看核对→退远对照→确认）→ 人可讨论/插话 → **逐步执行**。
- **人与模型平等**：一起讨论一个思路，走一遍，保证过程能通。**人只讨论思路，不递坐标答案**（问"该退远看整体吗"可以，说"直接看 0.6,0.5"不行）——否则方法论变成人的。
- 收口与**人确认**（不要求模型独自下结论）——绕开"会看不会收口"这个未解堵点。

### 8. 操作记录 + 先验证基本功能
- 每条操作写日志：`look_step / 工具 / 参数 / 命中档(全景|高清) / 产出图 / 注解`，落盘便于回放"第几步看了哪、远看还是近看、说了什么"。
- **先交互验证基本功能**（远看近看等）→ 通过后再上正式任务。

### 9. 终止 + 失败兜底
- 交互式长驻循环**无法事件叫停**，终止靠：**工具层步数上限**（view/look_step 上限，自我保护防无限循环）+ **手动 ctrl+C**。
- 失败兜底：**能力/预算探测在打开时做**（`open_view` 一次定生死，原图开不起来就拒绝，模型知道别往里探）；`view` 里"范围裁不出/太偏"属**参数无效**，返回错误态让模型改 `center/radius` 重试（非"打开后失败"）。

### 10. 防混/边界原则（防再踩坑）
- 引用索引 ≠ 图在眼前：要用某帧**内容**必须 `view`/`look_ref`（未在眼前的图只有语言记忆，可能有偏差）。
- 图只在视野区；历史无图只引用。
- 坐标统一全局归一化。
- 打开时探测拒绝；view 参数无效回错误态。

## 四、实现思路（模块 / 结构，本会话不写代码）

### 形态
- 推荐**交互式 REPL**（`input()` 循环、长驻），匹配"对话、逐步、插话、一起摸"。备选：diagnose 式（msg.txt + 跑一次）。
  > **唯一待 YZ 确认项**：交互式 REPL vs diagnose 式。两版本共享下面的 ViewTool/消息协议/记录，只是主循环不同，不阻塞骨架搭建。

### 组件
| 组件 | 职责 |
|---|---|
| `ViewTool` | 视野区状态（滑窗图数组、可查区索引、反查表、look_step、轨迹）；`do_view`/`do_look_ref`/`do_collapse`/`do_open`；产出图 + 注解；focal→全景/高清映射；失败兜底 |
| `ContextBuilder` | 每轮组装 `messages`：system 协议说明 + 视野区块（三块消息）+ 会话历史（文字+引用） |
| `OpLogger` | 每条操作写日志（look_step/工具/参数/命中档/产出图/注解）；history jsonl 落盘 |
| `REPL 主循环` | 读用户输入 → 组装 → `chat` → 解析动作（view/look_ref/collapse/answer/纯文字）→ 执行 → 记录 → 更新视野区 → 回显 |

### 消息协议（每轮）
```
[system]
  协议说明：两类内容（视野区 / 会话）；view 才能看图；时间=look_step 步序非时间戳；
  图只在视野区、历史只留引用；动作：view/look_ref/collapse/answer。
[user]
  ── 视觉区 ──
  [viewfield 0] 原图=detail.jpg(4000×3000,全局归一化)   ← 归属记录
      #0 原始图 [base64]                        ← 常驻背景
      #1 焦点 center(…) r… f… [base64]  ← 当前
      (可查) #2 焦点 center(…) r… f…
      轨迹 步1->步2
  [viewfield 1] 目标(参考) 原图=target.jpg
      #0 原始图 [base64]
  ── 会话 ──
  我: <人说的话>  /  我(模型): <模型说的话>
```

### 主循环伪逻辑
1. 读用户输入 → `ContextBuilder` 组装 `messages`（system + 当前视觉区 + 会话历史）。
2. `client.chat(messages)` 得输出。
3. 解析输出：`view`/`look_ref`/`collapse`/`answer` → 执行对应工具；纯文字 → 直接作为模型的话回显。
4. 执行工具 → 更新视野区（替换窗/降级可查区/推进 look_step/写注解）→ `OpLogger` 写日志 → 记录 `(role, content)` 进 history 与上下文。
5. 回显给用户（模型的话 + 工具调用）；人可插话；达 view 上限或 ctrl+C 终止。
6. 全程把 `messages` 写回 history jsonl，产图按 `look_step` 命名。

### 工具执行要点
- `view`：按 `viewfield_id` 定位原图 + 坐标空间；`focal` 低→全景图、高→原图高清局部；裁不出/越界返回错误态。
- `look_ref`：经反查表得原帧 center，重新裁并重注入。
- `open_view`：一次能力探测（`do_info` 尺寸+预算），不行则拒绝打开。
- 图 base64 只在视觉区块内联；历史只存文字（含 `vf#N` 引用）+ 工具注解。

## 五、验证思路（简要）

- **先交互验证基本功能**：人让它远看（`focal=1`→全景）/ 近看（`focal=3`→高清局部），确认工具通路。
- **再上任务**（pano 找目标），场景难度递增：T1 基础（含A/B）；T2 强干扰相近（不吸 B）；T3 目标跨区域绑定（会退远看全貌，不因凑近切对象）；T4 需全局对照（不满足于单点确认）。
- **指标**（沿回放 + 工具序列分析）：行为（最终 answer 的 dA）；有机性（radius 是否退远、有无原地重复扫）；收口（是否收敛、步数、终止原因）；上下文（token 是否随轮有界）；可诊断（人能否凭"话+view序列"复述其动机、追问能否纠正）。
- **判定**（成败观）：分成**可证伪判据**（到达A、radius 有机、上下文封顶——明确过/不过）与**定论性探索**（会不会收口——哪怕"不收敛"也是有效产出，关键是定位卡在哪一步）。对话式方案**能可观测地定位"它为什么这样"即成立**，不要求逼它成功。
