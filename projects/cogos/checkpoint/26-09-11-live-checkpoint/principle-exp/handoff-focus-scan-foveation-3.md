## 一、本会话做了什么（三件事）

### 1. 跑了"降采样档测"（方向 A）→ 方法纠偏为主
- 探针 `probe_downsample_tiers.py`（新建）+ 结果 `obj_exp/downsample_tiers/`（6 档 × 3 次）。
- 数据：锁 A 率 512/384=0/3、320/256/192=各1/3、128=0/3（128 时模型直接说"没有这种形状"）。
- **纠偏（重要，已写进 `result-downsample-tiers.md`，定位为"方法论教训"而非实验价值）**：
  - **以像素量级划档，方法论不成立**——它假设有普适像素门限，但判据其实是"该目标此刻还能不能被模型分辨"，是**对象相关、自适应**的。
  - 唯一结构性残留（非数值）："目标从感知整个蒸发（答'没有'）"与"挑错（gist 吸附）"是**两类不同的失败**，要分开治。
  - 结论：**省像素只能靠任务驱动的选择性采样（判据=目标可辨性），不能靠固定降采档**。此路线作废。

### 2. 重划"模型 vs 程序"的界线（你拍板的方向）
- **模型管"怎么看"（规划）**：读图 → 判断场景该怎么看 → 决定看哪、凑近/退远、隔离哪个候选来核实。
- **我们管"能看多清"（机制/哑原语），只给极薄一套**：弄清、看全（扩 range=远）、凑近（缩 range=近）、隔离（让候选单独占满）。
- **关键立场**：不写状态机、不写策略循环、不硬编码"网格→凑近"单向步进。之前卡壳（自扫吸附 B 簇）是因为①给了它"找相似候选"这种压迫 gist 的框定 ②没给它"隔离/凑近"可调的动作——**现在反过来：把镜筒交给模型，让它自己用。**

### 3. 方法纠偏：撤销"模型自报不可靠"的旧归因
- 此前（exp-1/exp-2）判"模型自报相似度 5 却抓 B/自报看清却错"，**是全在"没镜筒、只有一张图、只能单遍看"的语境下测的**。
- **这是"没工具时被迫单遍"的后果，不是"模型自报本质不可靠"。**
- 关键重构：**"注视=检验"**——策略是"这块像目标 → 移过去调焦距放大"→ **看的结果（更清晰没、更完整没、与周边关系）就是反馈**。误差不是外部给的，是**下一次注视的感知后状态内生**的。这是"学会用"的反馈来源，也是功能成长（程序性经验）的入口。

## 二、机制：镜筒（已收敛，勿再翻案）

**底层看图能力 = 一杆镜筒 `look(center, radius, focal)`：**
- `center`：注视中心。移动它 = 扫描。
- `radius`：视野范围。放大 = 退远看全（整体/结构/绑定），缩小 = 凑近看细。
- `focal`：清晰度档。对应"对象占总画面比例"。

**三个自由度刚好覆盖"扫描/看全/看细/隔离"全部动作**。等价于中央凹标准参数化。

**关键理解（为什么要"退远"）**：
- 人看大物体 = 站远看全（看整体/部件关系/跨区域绑定）；看小细节 = 凑近。
- "对象是跨区域绑定体，格切不开"（第 3 轮内核）⇒ **凑近会切掉对象一部分，违背绑定**。真正对上"对象是绑定体"性质的是**退远看全貌**，不是凑近。所以缩放必须是**双向**的，不再是单向放大。
- 第 2 轮"清晰度主要来自收窄视野让对象填满、不是放大像素"仍成立，落在 focal 档上。

**还差什么（快速验证的最小集合，见下）**。

## 三、下一步：镜筒快速验证（本次要动手的动作）

**目的**：首次把"看"的自主权交给模型，验证"机制给够 + 模型用"成不成立。**不写任何策略**（无网格/贴边/IoU/预设比例/决策层）。

**判据**：
- 模型能不能**自主**通过"移动 + 调焦"走到 A，而不是被左侧 B 簇吸住；
- 中间"看"的动作是否**有机**（该退远退远、该凑近凑近、该对照对照），不是瞎试。

**搭法（最小改动，复用现有 cogos 视觉）**：
1. `look(cx, cy, radius, focal)` 原语：**复用 `img-tool extract` 裁剪管线**，把"半径（视野范围）/焦距档"参数化——现在 extract 只做"凑近到原生最大分辨率"这一半，缺"退远/任意半径/任意清晰档"。
2. **坐标换算**：模型大概率报"当前裁剪图内归一化坐标"，需换算回原图。（现有 extract 有 region_echo，补"裁剪图内→原图"换算即可。快速版也可让模型按原图坐标报，但 exp 里有"目标偏左"滑移，局部坐标+换算更稳。）
3. **任务 + 工具说明 prompt**：讲"你有这杆镜筒、能用来看"，**绝不剧透策略**（不讲"该怎么看"）。这直接决定验证测的是"模型会用"还是"被提示词教了"。
4. 初始视野：整幅全景（或一个起点中格）。最终输出坐标 → 对 GT A(0.595,0.512) 打分（仿 `probe_window_verify` 的 ext 解析）。

**已具备（不用补）**：连续调用（tool call 结果回传续轮）、裁剪图作为下一轮输入、lm-service 视觉路由。

### 已跑结果（本会话后半，探针在 `/tmp/kilo/vision/order_probe/probe_look_telescope.py`）
- 用"模型每轮输出 JSON 决策（look/answer）+ 脚本执行 look"的**轻量循环**（未接 cog-runtime 工具链），并**瘦历史**（每轮只留 目标图+最新画面）防 base64 请求体过大（首版因 messages 膨胀报 `invalid json body`，已修）。
- 1 轮 8 步观察到：**模型确实主动"移动中心 + 调半径/焦距"**，且**未复现被 B 簇吸附**（扫点覆盖右/中/上多处，没到左下方 B 区）——这印证"给镜筒、模型会用"方向成立。
- **但收敛不了**：8 步耗尽也无 `answer`，一直在扫（扫到 (0.55,0.32) 已近 A(0.595,0.512) 却不停下定夺）。
- ⇒ 结论：**"会用镜筒 + 摆脱吸附"两个预期基本成立；新缺口 = 模型会看但不会"何时收口给结论"**。这对应开放问题 #3（工作内存/收口），是策略层未长出的自然结果，非 bug。
- 只跑了 1 轮，**"不收敛"是否为稳定现象需扩 3 轮确认**；且此结果不应与"cogos 仓库能否提交"相混（本次会话未改 cogos 代码）。

## 附：本会话辨清的三条界线（防再混）

- **网格 ≠ 隔离**。网格只做"发现/定哪"，允许切对象（它是侦察）；真正隔离靠"凑近让对象占满"。之前"网格隔离"说只对一半。
- **蒸发 ≠ 挑错**。蒸发=对象从感知消失（物理性，靠选择性高清治）；挑错=gist 吸附（靠隔离/退远治）。分开对待，别混。
- **凑近 ≠ 放大像素**。放大像素不新增信息；有效分辨率来自"收窄/调整视野让对象合理占满"（focal 档的本质）。
