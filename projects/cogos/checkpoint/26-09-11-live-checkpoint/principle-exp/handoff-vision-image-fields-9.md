## 本会话讨论结论（新会话别推翻）

### 1. 坐标教学必要性 → 改口径
- 坐标规则不是"可教可不教"，是**表述精度**问题。不写 `COORD_TEACH` 那种"坐标规则：center 分轴…size 宽对宽高对高…"的规则型 system blurb。
- **表述三件套**让参考系自明（不破坏"短+固定序"）：
  1. 标签即语义：`@窗口`=当前窗口相对、`@全图`=全图地图、位图尺寸=实际下发。
  2. 锚自含：`F:id | 原图宽×高 | @全图 地图 | → 位图 宽×高`（参考盒就在这行）。
  3. 一句话话术点破：`center/size 都相对这个参考盒`——贴着动作的那句，不是独立规则。

### 2. 示例（推荐形态）
```
SYSTEM: 你是看图助手。图中 F:… 说明行由程序生成，是非图像内容的参考。
模型看到: 当前窗口 F:1001（原图 1357×764）· 它相对全图的 c(0.276,0.098) s(0.332,0.196) · 已渲染位图 451×150
任务: 请以"当前窗口 F:1001 本身"为参考盒再开一个窗，让『工具(T)』落到新窗中心。给出 center/size（都相对这个参考盒）。
模型回: {"view":{"ref":"F:1001","center":[0.156,0.133],"size":[0.100,0.050]}}
程序换算: view(F:1001, [0.156,0.133], [0.100,0.050]) → 参考盒左上 + @窗口×参考盒尺寸 → 新窗 @全图 c(0.164,0.037) s(0.055,0.013)
```
（模型只给"相对当前窗口"的数值，换算全在程序侧。）

### 3. 测量方法论（YZ 本轮提出 + 我们收敛）
- **懂 ≠ 用**：模型能复述规则 ≠ 会按规则产出坐标（LLM 很会"表演理解"）。`被你口头复述的理解` 与 `程序化的应用` 脱节。
- **直接问 = 聚光灯下的理解**：单独问"这句话你咋理解"时注意力集中在这句话上 → **会高估**；任务里注意力被稀释，可能打折扣。
- **对反了的作用**：若一个表述**只能在聚光灯下被理解**、放到任务里就崩 → 说明它不够自明、靠模型额外花注意力解读 → 该做的是**把话写得更自明**，不是怪注意力。
- **两层协议**：
  - A（直接问，作措辞筛查，不过关）：单独问"这句话你咋理解？用自己话复述 + 给个例子坐标"。便宜，只抓措辞粗歧义。
  - B（任务内，作通过标准）：放回真实看图任务（taskE 式 zoom 循环），量最终中心到目标像素的距离。
  - 判据：**A 懂 + B 崩 → 表述"注意力脆弱"，需写得更自明**；**B 过 → 表述成立**（A 仅供参考）。

## 关键决定（已定，新会话别推翻）

1. 坐标语义写进"表述"（锚自含 + 一句话点破），**不写 system 规则型 blurb**；模型不换算。
2. 测量"理解"用**任务内性能（B）**当通过标准；单独问（A）只做措辞筛查。
3. 坐标基准不是难点；难点 = 模型视觉定位精度（上限）+ 窗口退化。
4. P1/P2/P3/P4 边界、坐标基准统一（宽对宽/高对高）、`@窗口≡@全图`（全图 ref）等上游定案不变。
