## 已定结论（新会话别推翻）

1. **坐标语义进"表述/注解"，不进 system 规则**。模型只在 `@窗口` 动作、程序负责换算（handoff-9 定案，只强化表述）。
2. **不分首见/复用**：同图任何时候读到的都是同一段。理由——
   - 模型侧无坏处：零状态、零判断，且**每句独立自含**（即使早期上下文被裁剪，仍完整成立），比"复用版依赖记住首次"更鲁棒。
   - token 无谓：完整 vs 紧凑差 ~53 词/次，一长会话 30 图轮也就 ~1.6k，≈1.2%，可忽略；且累积本就是**通用层**职责（长会话文字压缩），非图背锅。
   - 复杂度省：无 per-figure 状态、无分支。
3. **分隔符用 `|`**（回退，不用散文标点 / `·`）：
   - `|` 是机器/字段分隔、固定序、可预测（契合设计 §6 "统一分隔符 + 不做对齐"），与 `meta_annotation` 现实现一致。
   - 散文/`·` 会弱化"字段化可预测"、且与代码不一致；除非全走散文并重写 `meta_annotation`（已否）。
4. **参考系文字说破**：`相对原图：窗口中心/尺寸…归一化到0~1（相对原图宽高）`——这是关键自明句，模型零推断。
5. **`图幅` = 本图实际像素尺寸**（解决"尺寸：451×150"歧义：那其实是被发现的**位图**尺寸，非窗口像素）。窗口大小用 0~1 归一，图幅用像素，两者不混。
6. **累积的持久化文字**是通用上下文问题（长会话文字压缩/老化），**不归图**；图只管"注解自明 + 忠实可重载 + 控制同时多少图/是否重发"。

## 图说明最终定格（示例：F:1001，真实值 windows.png 1357×764）

```
图 F:1001 | 原图 /tmp/windows.png（1357×764）| 相对原图：窗口中心 (0.276,0.098)、窗口尺寸 (0.332,0.196)，归一化到0~1（相对原图宽高）| 矩形 | 图幅 451×150
```

**字段语义（`|` 分隔，顺序固定）：**
1. `图 F:1001` —— 图编号（引用/重载 token）
2. `原图 /tmp/windows.png（1357×764）` —— 源自哪张原图（坐标基准就是它；缺图可 `PATH:` 重载）
3. `相对原图：窗口中心/尺寸 … 归一化到0~1（相对原图宽高）` —— 本图在原图里的窗口（关键自明句，区分"相对谁"）
4. `矩形` —— 窗口形状
5. `图幅 451×150` —— 本图自身实际像素（机器给模型看的那张多大）

---

## 为什么这么写（简要）

- **图注口吻**：模型拿到的是"一张图 + 一段关于它的说明"。说明应是**中性、第三人称、描述这张图**（哪张、源自哪、在图里哪、多大），而不是"系统投喂记录"（如"实际发给我的图…"把收发说破，像汇报流程）。
- **不靠规则**：参考系由字面直接给出（0.276 相对原图宽高 0~1），模型不用套坐标规则、不用换算。
- **可预测 + 自明兼得**：字段序和 `|` 不变（机器解析稳），关键语义用文字（模型读得懂）。
