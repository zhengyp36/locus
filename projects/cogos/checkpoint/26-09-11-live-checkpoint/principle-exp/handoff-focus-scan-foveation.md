## 一句话状态 + 结论

**核心转向**：模型单遍在杂乱 pano 抓 B、出不去 A 的根因不是判别力，而是**缺少串行、状态化的聚焦机制**。人眼可靠是因为**默认逐个注视（中央凹）+ 模糊外周**，天然已分区；这靠的是**机制/架构**，不是"判断难不难"。**业界共识解法 = 状态化串行中央凹循环**（低分辨率外周定哪 → 高分辨率中央凹取证据 → 跨注视累积 → 抑制返回推进），且因冻结 VLM 是单遍的，**必须由 agent 从外部强加状态机**（不能指望裁剪窗口自带串行）。

**已判定**：不依赖通用几何检测器（`cands_from_scan` 是线稿特例）；模型自扫会被显著簇吸附；纯单遍判断不可靠。

> **⚠️ 最新修正（2026-09-07，见附 录 A）**：模型"判别失败"有一半是**问法太严**——`有无/一致`这种二元严格提问会让模型保守否定；换成**"找最像目标的对象 + 相似度 1-5"**（最佳匹配+评分），模型在含 A 的 0.333 窗口里**单窗即锁定 A（dA≈0.004~0.10）**。所以**判别没坏，坏的是问法**；且**瘦硬件（无 GPU、3.6Gi）方案完全可行**。

## 本轮实验结论（按它喂出的判断，逐条）

### 1. 无目标判断"信息量/难易" —— 失败，证明难点是目标驱动的
- 探针 `probe_info_density.py`（只给场景图，无目标）。
- pano 判"一眼可分"5/6、"有一堆难分"1/6。模型依据全是"分布稀疏、彼此独立、不重叠 → 一眼可分"。
- **含义**：无目标时"难分"没有意义——模型测的是"场景好不好数清"，不是"给定目标能否唯一锁定"。难点是**目标/任务相关**的。

### 2. 目标驱动"唯一锁定"探针 —— 在 3 张图上区分度清晰（分区门控的直接依据）
- 探针 `probe_ambiguity_target.py`（目标图 + 场景图；判据：数"与目标相似"的候选 → 能否唯一锁定）。
- 结果：
  | 图 | 判定 | 说明 |
  |---|---|---|
  | pano_800 | 6/6 **B_无法唯一锁定** | 触发区分 ✓ |
  | p_AB_only | 6/6 **A_可唯一锁定** | 不触发 ✓ |
  | p_3obj_only | 2/6 A、4/6 B | **边界**，门控偏保守 |
- **边界案例规律**（3 对象 5 轮）：数到 **3** 个 → 一律"几乎不能"→ B；数到 **2** 个 → "很勉强/能"（从不"几乎不能"），但结论 2/3 A、1/3 B。
- **A/B 真正分界 = 模型有没有抓到"判别锚"**：
  - 判 A 的（n4/n6）：抓住"目标=纵向重叠"，右侧匹配 → 锁定 A。
  - 判 B 的（n1/n3/n5）：没隔离出判别特征（或者数到 3），把候选都当干扰。
- **结论**：门控读的是"**一眼能否抓到判别锚**"，不是稳定判据；杂乱图铁定抓不到（6/6 B），干净 2 对象能抓到（6/6 A），3 对象时抓时不抓（灰区）。

### 3. 盲"逐框→标号→再框" —— 卡死，粒度不对
- 探针 `probe_box_annotate.py`（无目标，框"一个未标注对象"，画红圈编号，再喂回去）。
- 结果：只框到 1 个小矩形（`(0.03,0.26,0.02x0.03)`），下一轮 IoU>0.5 重复 → 停。
- **原因**：密集相似场景"框一个对象"定义不清——模型框到任意**小矩形/碎块**而不是有意义的复合对象；相邻相似小框导致重复。**盲枚举在密集图不适用**。

### 4. 目标驱动"逐框→标号→再框" —— 被 B 簇吸附，出不去
- 探针 `probe_box_annotate_target.py`（目标图 + 场景图，框"一个与目标相似且未标注"的候选）。
- 结果：框到 2 个，全在**左侧 B 一侧**（n1 dB=0.153，n2 dB=0.009=基本是 B），n3 重复 → 停。**全程从未框到 A**（dA≈0.54~0.58）。
- **原因**：模型"找相似候选"的扫描**被左边密集相似簇吸附**，标号后"找下一个"仍在本簇内（必然靠很近、易 dup），永远逃不出簇去看见更远的 A。**不是系统覆盖全图，是被最显著簇牵引。**

### 5. 核心结论（本轮最重要）
- 模型自己的**单遍/自驱扫描会被显著簇吸附**（B 一侧）；"让 A 被看见"不能交给模型注意力，应交给**系统覆盖/裁剪**（此前"方案C 候选裁剪窗口已证可召回 A"）。
- **人眼"隔离"是默认机制**（中央凹 + 模糊外周），不是要主动执行的动作。所以正确设计 = **"低分辨率外周定哪 + 强制小平窗高分辨率判什么"**，且**不要给模型单张全图细节**（会触发整体印象匹配→抓 B）。

## 业界调研（6 篇，逐篇：做了什么 + 对我们的意义）

| # | 论文 | 做了什么 | 对我们的意义 |
|---|---|---|---|
| ① | **Why We Look Where We Look** (2605.17823) | 模拟中央凹代理，以"最大化场景理解"为目标训练 → 长出类人注视顺序；换成"搜索/分类"目标或外周更好/更差，反而偏离人类 | **任务取向决定扫描走向**。agent 别用锐利"找目标"引导注视，更适合"理解场景"取向，否则会朝目标冲、被显著簇吸附 |
| ② | **Matched Outcomes, Divergent Gaze** (2608.16514) | 逐注视点喂人类匹配中央凹图（COCO-Search18）；模型在"目标存在/首跳命中"上超过人类，但注视轨迹低熵、自洽、**单遍非串行** | **头号警告**：光给中央凹化/裁剪输入买不来"串行"。**串行+状态化必须 agent 从外部强加** |
| ③ | **Foveated Reasoner** (2604.21079) | 自回归 VLM，把 foveation 与推理放进同一解码轨迹：低分辨率开始、按需触发放大、取高分辨率证据**回注轨迹**；RL 训练，**惩罚"看全图"** | **最接近我们**：循环骨架"低分辨率定哪 + 放大取证据 + 状态累积"；强调**只喂裁剪图、不喂全图**逼选择性聚焦 |
| ④ | **PLOS FOD** (Akbas & Eckstein 2017，github.com/eakbas/FoveatedObjectDetector) | 视网膜特异模板 + **MAP 规则引导眼动** + **跨注视证据累加进一张图** + **抑制返回**（已注视降权、逼探索、防复访）+ **非极大值抑制**；≈全分辨率精度、约 1/2 算力 | **最完整可抄骨架**。抑制返回=我们的编号/推进；证据累积图=agent 工作内存；点名**复访是扫描的死敌**（对应我们"框到 B 停"的病根） |
| ⑤ | **Set-of-Mark (SoM)** (som-gpt4v.github.io) | 往对象叠**编号**，模型按编号引用 → 激活 grounding；配 GroundingDINO/SAM 生成编号 | **直接支撑我们的"框+编号"**：编号=定位锚+已选/+清单/计数 |
| ⑥ | **CropVLM** (2511.19820) | 模型无关 RL 裁剪模块，自动学"往哪放大"，无需人工 bbox、不改 VLM | "该裁剪哪"的现成低成本组件；证明局部放大对细粒度感知提升巨大 |

> 其中 **②③④ 与我们最相关**：②=必须状态化串行的警告；③=循环骨架；④=可抄完整算法。

## 下一步：如何借鉴（我的评估 / 思路）

**核心判断**：那些论文在**训练模型**（RL 学 foveation 策略），我们是**设计 agent**（冻结 VLM API + 提示词 + 工具 + agent 侧状态）。**复用它们的"循环架构"，而非训练方法**——架构组件可以无训练地手搭出来：

| 机制组件 | 论文（训练学） | 我们（agent，不用训练） |
|---|---|---|
| 外周定哪（低分辨率） | MAP 学出注视点 | 提示词让模型在低分辨率图上"列候选/定哪" |
| 中央凹取证据（放大） | 学出裁剪位置 | 工具裁剪放大 + 提示词 |
| 状态化跨注视累积 | 证据图/解码轨迹回注 | **agent 工作内存**（自己维护候选+证据表） |
| 抑制返回 / 不重复 | RL policy | **编号标注(SoM)** 或提示词排除 |
| 惩罚"看全图" | RL 奖励项 | **我们只喂裁剪图，不给全图** |

**要搭的 agent 状态机（对照 PLOS FOD / Foveated Reasoner）**：
1. **外周层**：低分辨率全图 → 让模型列"多个可能像目标的粗区域"（**必须列多个，防被一簇吸附**），取代几何检测器。
2. **中央凹层**：对每个粗区域**裁剪放大成小窗**，逐个问"里面是否有与目标相似的对象、是哪个"。
3. **状态累积**：agent 侧维护每候选一个证据表（相似度、判别锚、位置），跨步骤累积，不靠单遍下结论。
4. **抑制返回**：给已判/已选对象打**编号标注**（SoM），避免复访、逼模型探索别处 → 才能跳出 B 簇、到达 A。
5. **去重**：候选间 IoU>0.5 视为重复（NMS），过滤。

**关键原则（吸取本轮教训）**：
- 不要给模型**单张全图**做细节判断（触发 gist→抓 B）；用**低分辨率外周 + 小高清窗**双层。
- 外围层**列多个**候选（防被显著簇牵引）；模型自扫会吸附，覆盖要交给系统性/提示词强制。
- **串行与状态化由 agent 强加**（温故 ②的警告），不能只靠裁剪窗口。
- 任务取向用"**理解场景**"而非"找目标"（温故 ①）。

**验证收口**：仍在 `pano_800.png`，判据 = 该状态机能否在杂乱全景里**找对 A**（而非 B/其他同构对）。对照臂：干净 2/3 对象（判别未坏基线）。

## 附录 A｜瘦硬件可行性实测（最新，重点看这块）

> 本机：**无 GPU、无 torch、3.6Gi 内存（可用 ~1.5Gi）**、pano 800×600。重组件（Grounded SAM / SAM2 / fovi）**跑不了**。

### A1. 关键转折：问法决定成败（最重要）
- 同一"含 A 的 0.333 窗口"，对 VLM：
  - **`有无/一致`严格问法**（"有没有与目标形状相似的对象？有给坐标、无输出无"）→ **3/3 都答"无"**（尽管 A 就清楚在窗里）。
  - **`最佳匹配+相似度`问法**（"找出与目标最相似的对象，给中心 + 相似度 1-5 + 依据"）→ **3/3 全部锁定 A**：global=(0.595,0.516) dA=0.004 / (0.577,0.52) dA=0.02 / (0.628,0.415) dA=0.102。
- **结论**：模型**判别没坏**，坏在"二元严格提问"会让它保守否定（与手稿"一致被否、相似召回"同源）。**凡是让模型判"是不是/有没有"，都要换成"找最优/给分/相对排序"。**

### A2. 硬件可行性：✅
- 方案只需 **PIL（本地）+ 冻结 VLM 远程服务**。无需 torch/SAM/fovi；也**不需要它们**。

### A3. 各组件实测
| 组件 | 结果 |
|---|---|
| PIL 网格/裁剪/放大/编号 | 可行（纯 PIL，零负担）|
| 网格覆盖（"哪看"）| 模型自己就切成 3×3 铺满全图 → 网格是自然策略；**本地确定性切块更可控** |
| 验证环节（"是什么"）| **严格"有无"→ 3/3 答无；"最佳匹配+相似度"→ 3/3 锁定 A** |
| 低分辨率外周"列多候选" | **不可靠**（倾向退化成 3×3 网格或脑补一条顶部横带，run1/run2=3×3、run3=顶部 21 框）→ **别依赖它定位**，改用确定性网格 |

### A4. 因此可行的完整 agent 方案（全在瘦硬件）
1. **本地确定性网格切块**（PIL）保证覆盖全图（模型自己也是这么切的 3×3）。
2. 每窗对 VLM 用**"找最像目标的对象 + 相似度 1-5"**问法 → 得候选点 + 分数。
3. **跨窗累积 + 去重**：同一对象会出现在多个重叠窗 → 用 IoU 合并只记一票。
4. **编号抑制返回**：对已高分候选打标（SoM/自绘编号），避免复访、逼探索别处。
5. 最后按**累积分数选唯一候选 = A**（并给判别锚依据）。

### A5. 诚实的遗留
- 轻微抖动（run3 dA=0.102 vs run1 0.004），但都指向 A 区域；**跨窗多票累积 + IoU 去重**可稳住。
- 重叠窗重复计数要处理好（同一对象多窗命中 -> 合并）。
- 网格粒度 0.333 即可（最佳匹配问法已锁定 A），**不需过细**，否则调用数暴涨。
- 本机无 GPU 但 VLM 远程服务可跑；调用数 = 网格数（3×3=9 窗，可行）。

### A6. 方向修正小结
- 之前"模型被 B 簇吸附、判不了"的判断——**一半是问法太严**；用"最佳匹配+评分"后单窗即可定位 A。
- 真正**仍待解**：跨窗如何把 A 从"最佳匹配"里**唯一挑出并排除 B**（判别锚）。"最佳匹配"会在每个窗都给出一个最像者，需要跨窗累积 + 判别锚来定 A、排除 B。
