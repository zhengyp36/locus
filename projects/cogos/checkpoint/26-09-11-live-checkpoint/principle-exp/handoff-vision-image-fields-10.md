### 关键设计结论（已定，新会话别推翻）

1. **断循环靠"视角切换"，与主体性无关**；但**自我评审**让元认知内化成"agent 自己的能力"（vs 外部评审=外来功能，用完就撤）。
2. **评审负责"何时停"，不负责"像素准"。** 评审标准是"可辨即停"（定性/语义），once `done` 就放行到模型主张，精度=主张噪声。这是"我认对了、该停就停"，不是"精确到像素"。
3. **坐标系：模型只在 `@窗口` 动作、程序换算到全图**（handoff-9 定案）。**实验证明这条必须明确写进表述**——taskLoop 前面版本模型给"全图语义坐标"被当@窗口换算，收口偏到 62.3px；写死"pos 相对参考盒 F:<id>"后又恢复对。
4. **功能导向表述 + "二选一收口"约束 = 收敛点**：没有它模型会无限 zoom（taskM/taskConf 病）；加上"看清就不要再 view、本轮二选一"后，模型肯给主张了。
5. **视角切换可只靠语言、无需物理剥历史**（taskSwitch/taskMeta 证实；早期 taskReview 剥历史是过度手段）。

## 点击命中标准（已落地成代码，是 metric）

- 目标『工具(T)』真值 @全图（windows.png 1357×764）：`[0.188, 0.042]` → 像素 `(255.1, 32.1)`。
- **菜单块列投影定位**（y∈[14,34) 共 7 块，按序）：
  `文件(F)[16,52] 编辑(E)[69,110] 查看(V)[123,161] 命令(C)[178,216] 工具(T)[234,270] 窗口(W)[287,329] 帮助(H)[347,385]`
- **『工具(T)』文字块 = x∈[234,270]，中心 ≈252**（与真值 255 吻合）。
- **可点归属带（不偏邻居）**：取左右相邻的文字块空隙中点 = `x∈[(216+234)/2, (270+287)/2]=[225,278]`；菜单行高 `y∈[12,38]`。
- **命中判定**：收口坐标转屏幕 px，`225≤x≤278 且 12≤y≤38` 则命中；否则按"偏左(命令C)/偏右(窗口W)/y偏出菜单行"报告。已在 `taskLoop.py` `hit()` 实现。

## 闭环结构（taskLoop.py，主力探针）

```
[执行] 面对当前图（含上轮"我的修正方向"）→ 二选一：给 pos(相对参考盒 F:<id>) 或 调一次 view
         先 parse pos，抓到即记"定位主张"（即使绕带工具调用）；没抓到才走 view
[自省] 注入第一人称+方法论判据 → {done, reason, hint}
         done=true → 收口（主张换算@全图 → 命中判定）
         done=false → 把 hint 作为"我的修正方向"回填；hint 无变化 / 连续超 MAX_GIVEUP → 放弃收口
[上限] 自省次数 MAX_META 耗尽 → 强制收口（最近主张）
```

关键提示词：
- 执行者表述：`请找到顶部菜单栏的『工具(T)』，使鼠标能**点击中它**（落在这个菜单项区域内、不要偏到相邻的『命令(C)』或『窗口(W)』）… pos 是【相对当前参考盒 F:<id>】的 @窗口 坐标… **本轮只能二选一：直接给 pos，或调用一次 view**。如果你已经能在当前图看清『工具(T)』的位置，请直接给 pos，不要再调用 view。`
- 自省（第一人称 + 方法论判据）：`…用『我』的口吻重新审视…对照准则自我检查：1)目标是否已清晰可辨、能说出相对位置(可辨即停)；2)是否仍在做重复/无新信息动作；3)是否已达分辨率极限；4)若找不到就该诚实放弃。已定位到位回 {"done":true,...}，否则 {"done":false,"hint":"我的修正方向"}。`

## 下一个攻坚点（目标 100%）：疑似根因已定位

**未命中的共同特征：模型在"子窗参考盒(如 F:1001)"时，给的 pos 像是"全图语义坐标"，被程序当成@窗口换算 → 收口 x 偏左。**

对比数据：
- 命中样本：`[0.185,0.044]` 相对 **F1000(全图)** → 换算后 x=251 ✓；`[0.195,0.044]` 相对 F1000 → 265 ✓。
- 未命中样本：`[0.19,0.045]` 相对 **F1001(子窗)** → 被当@窗口换算 → 216 ✗。若它是全图语义(≈0.188)，本应对，但被@窗口换算错。

**推断**：模型有时给"@窗口坐标"、有时给"全图语义坐标"，不稳定，取决于它当前参考盒的理解。**子窗时它倾向报它"脑子里记得的全图位置"，而非相对当前子窗的@窗口**——因为任务强调"点击中目标"它直接按全图报。这导致换算错。

### 100% 的候选方向（新会话从这里接）

1. **彻底锁定坐标基准**（最可能的关键）：把"pos 相对参考盒"的约束再压死，尤其**子窗时**。可考虑：在自省/执行提示里明确"pos 的 '0.5' 指参考盒正中心，不是全图"；或当参考盒≠全图时，强制模型先报"目标在全图的位置"再由**程序**换算（而不是让模型换算或混用）。
2. **收口方式重选**：要么统一"模型永远给 @窗口"（严格换算）；要么**收口坐标直接用"模型对该目标在全图的判断"+ 程序锚定**，避免"子窗内报全图值"的两义。
3. **低置信兜底**：若自省判"目标边缘模糊/位置不明确"→ 判 `not_ok`，强迫再补一拍一锤定 x，而不是模糊时放行。
4. 校验命中带边界：带是 [225,278]，文字块 [234,270]；可微调带中心/带宽，但**根因是坐标基准不是带宽**。

## 遗留确认（09-09 已核实为"非遗留"）

**窗口极小退化（原 handoff-9 记为"真 bug 待修"）→ 已澄清，不再当遗留。** 结论：
- `clamp_rect`（`view.py`）对 0 面积/完全出界落 2×2 位图是**预期行为**（保证返回非空位图），不是 bug。
- 极小窗口（1×1/2×2）**渲染与 API 均不报错**（实测 0.001/0.0001/0.02 三种 size 正常返回 Block）。
- `_pixel_diag` 会给出中性事实提示`> 当前窗口位图 W×H，像素过少（可能无法辨认）`（min<16 时触发），机制不拒绝缩小、无放大兜底——符合"只陈述事实、判断交给模型"。
- 真正的"无限 zoom"根因在**模型基于上下文自决**（评审/自省），不在 clamp 机制层。
