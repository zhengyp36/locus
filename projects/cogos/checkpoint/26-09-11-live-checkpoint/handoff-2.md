## 方法转向（本次核心，框架性）

### 1. 推翻"coarse 后全图消失"（YZ 纠正，重要）

全图与局部**必须同时在场**，且模型**必须知道它们的关系**（局部=全图哪个区域、从哪切出）。人以"全图一直在 + 局部是指回全图的一块"理解，不是两张无关图。**不能先看全图再丢全图只看局部。**

### 2. 关系由工具显式组织，不是靠文本记忆

最终目标 = **给模型带 region 参数的 extract 工具**，让它"选全图一块→切出局部→『局部↔全图』映射靠工具调用落进上下文→自由往返核对"。关系是**机制层维护的数据结构**，模型用**句柄/语义**引用，**不做坐标算术**（run2 崩在语言心算坐标）。→ 即"两段式"= 同一全图下的**多视图关系操作**，粗框=关系中的一块，非孤立局部图。

### 3. 矛盾：文字锚 vs 坐标 vs 图（本轮正在收敛）

- **文字组织关系 = 否**（YZ）：谁来组织文字？只能是模型，而模型自己组织的描述会漂（T1.6 已证它自造"range旁"这类不可靠锚）。
- **坐标 = 否**（前几轮已定）：0~1 归一化坐标模型辨识度低，run2 在 1~2px 反复漂。坐标给机制层算几何判据，不交给模型指认。
- **图组织关系 = 可能是**（YZ 直觉，人的直觉，**模型侧未证**）：用"图"表达关系比语言更清晰，但这只是人类直觉，**模型是否如此仍需 probe 验证**。

### 4. 关系的一种图表示：挖空 → 描框（逐步澄清，当前收敛点）

YZ 提出"3 张图：全图 / 同尺寸但目标区挖空 / 空位细节高清图"，关系靠图像结构、无需坐标。随后多轮澄清与修正：

- **多图可在一条消息**：content 是数组，可含多个 `text` + 多个 `image_url`（deepseek 官方文档形态）。所以"关系描述 + 多图"能在一条 user 消息里**内聚**，不必拆多轮。
- **关键未证点**：模型能否理解消息里多图的**顺序/对应关系**？靠文字解释，但**如何用文字把图序与对应讲到模型懂**，是能力问题、必须实测。
- **挖空有工学缺点**（YZ）：动图、缺块可能要画两条清晰边线、对图有干扰；若给未编辑原图更清晰。
- **框的职责 = 位置关系，只能画在原比例画布上**（YZ 纠正我的错误）：框表达"裁剪图在全图的位置"，画在放大裁剪图上就只剩"内容级"标注、失去位置关系。故"位置锚(全图+框)"与"内容细节(高清裁剪图)"**角色不同、不可合一**。
- **双边框采纳**（YZ，我无异议）：黑+白光晕，任意背景可见，不依赖图内容色；机制层坐标已知、画零成本。
- **框边缘压到图里已有边框会混淆** —— 见下节原则。

### 5. 收敛原则（YZ，重要，回应当前"设计完美框"的纠结）

**不要设计一个"解决所有场景"的框——做不到、也无必要。** 设计"解决多数常见场景"的形态（如：双边框光晕，通用即可，不为"框边缘恰压到已有边框"这极端情况过度设计）；"确认自己错了"的能力放**机制层 + 工具**（几何阈值/候选清扫/跨视图核对/回退），这与"人出错→用经验/工具补救"一致。

- 人本身有错觉、也有感知边界，**人不追求看所有图不错，而是错时能察觉、能补救**。agent 同理。
- 但**"人的错觉 ≠ 模型错觉"**：错觉域不同。人易在深度/透视/双关图错；模型（T1.6 证）易在目标占比小/相似目标多/坐标系切换错，且是"**自信聚焦错目标而不自知**"——比人更隐蔽。
- → **"哪些算常见、哪些算少数"不能用人的直觉定，要用模型自己的失败分布（累计 probe）定**。我们前面所有探针本质上就是在**摸模型自己的"错觉域"**。
