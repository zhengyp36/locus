# checkpoint-15 — ImageTool 功能与命名的再次收敛：看/记忆二分 + 意图=任务（子任务划分）

接 checkpoint-14（ImageObj 定稿）。本文件修正并深化 ImageObj 的方法集与入口形态。参与：修改 checkpoint-14 的"方法=open/focus/取子图"。

## 当前问题

取子图是否是纯"看"动作；命名轴怎么定；主 LLM 意图如何分离到具体动作。

## 关键结论 / 决策

### 1. 命名轴 = 瞬态视角 vs 持久对象（非"产不产一张图"）

模型拿到的图是**结果**，不是命名依据；命名要锚定动作**目的**。把 focus 和取子图都看成"给模型一张图"来比较会撞车，但那是产物表象。区分在本质意图。

### 2. focus 不分 pan/zoom（Z）

- 对外**单一 focus**："把视线对准 X 看清"。主 LLM 只给语义意图，不承担"我在移动还是缩放"的底层决策（信息隔离，checkpoint-12）。
- 内部分 center/range 正交，一次 focus 可同时调移动+缩放；技术清晰度基线（checkpoint-4/9 收益上限）属机制层内部，不暴露。
- 理由：拆开违背信息隔离 + 使用高度伴随（"看清那红东西"要 pan+zoom）+ 人眼 foveated 本就瞄准+聚焦一体。拆开徒增往返。

### 3. 取子图漂移 → 被掰成两维（Z 指出）

取子图混杂两种不同性质的事：

- "排除干扰/剥离目标" = **看**任务 → `isolate`（视图引擎）
- "记录/固化/加旁注/整理" = **记忆写入**，与看无关 → `seal` / `annotate`（记忆容器）

故 checkpoint-14 的"方法 = open/focus/取子图"**作废**，拆成两个维度的方法集。

### 4. ImageObj 两个不相干本职

| 角色 | 动作 | 产物 |
|---|---|---|
| 视图引擎（看） | `open` / `focus` / `isolate` | 瞬态视图+摘要（看完即弃） |
| 记忆容器（写） | `annotate` / `seal` | 持久节点（可复用、可整理） |

（英文名为拟名，待 YZ 拍板。）

### 5. focus 与 isolate 正交甚至相反

- focus：center+range，变清晰，倾向"**尽量多带周边上下文**"（checkpoint-12 §7）。
- isolate：收敛到 target bbox，排除干扰，"只要目标、剔除周边"。

张力：focus 带上下文，isolate 排除上下文——**相反意图**，故是独立能力。机制层边界：isolate 的"哪个是目标"归主 LLM（语义），落目标 bbox 归 locate。

### 6. isolate 伴随触发（Z 拍板）

- 触发条件改为：**意图中出现了可辨识的具体目标 → 就附加 isolate**，而非"主 LLM 主动要排除干扰"的独立意图。
- 工具适当多做：locate 定位目标已得 bbox → isolate=crop(bbox) **零边际**（同摘要，checkpoint-8）。结果包 = focus 视图 + isolate 目标 + 摘要。
- 边界：目标模糊 → 降级只给 focus，或标注"目标边界不确定/未完全剥离"。
- 通用准则：**工具被内容丰富度驱动，非只用动词触发**；意图内容变丰富，工具就做得多。

### 7. 意图=任务，工具集=任务执行器（子任务划分，Z 升华）

- 入口不是"选工具"，是"**用工具完成任务**"——一个意图可调多个工具（open/focus/isolate），相当于**子任务划分**。
- 结构分层（呼应 checkpoint-3 原语/功能层）：

```
意图（任务）          ← 主 LLM 只发这个
  │
功能层（任务执行器）   ← 读懂任务 → 拆子任务 → 编排/迭代
  │                    （"有目标→open+focus+isolate"、"看清→反复 locate/focus"）
原语层（方法集）       ← open / focus / isolate（视图引擎）· annotate / seal（记忆）
  │
img_tool + cog_runtime ← 机械执行
```

- "拆子任务"是**功能层**的事，非主 LLM 的事。
- 计划来源：初版 = 预设"意图→计划"映射（确定性模板，校验层兜底，checkpoint-6 "宁可拒绝不瞎猜"）；生长 = 动态/LLM 计划（记录规则自长，checkpoint-3）。
- 一个意图可循环：看→聚焦→看→换方向（checkpoint-9 停权/放弃出口）。
- 推论：别把视图引擎当"方法菜单"，当一个能完成"看图"任务的可执行体；方法集只是内部原语。

### 8. 意图分派器（意图→结构化 {动作,目标,参数}）

- **状态先缩圈**：无对象 → open；有对象+当前视野 → focus/isolate。
- **语义细分**：无 region → open；"更清/接近/移那边" → focus；"只要/单独/背景乱" → isolate；判不出 → 默认 focus 或澄清。
- **可靠性**：LLM 语义粗判（鲁棒）+ 机制层兜底（不瞎猜，宁可拒绝/澄清，checkpoint-6）；允许不确定（输出"是否可结构化"信号），模糊就降级。
- 不违背信息隔离：读懂意图→定动作是定位的一部分（checkpoint-8/9），主 LLM 看不到。

## 遗留 / 开放

- 方法集形态（看=open/focus/isolate、写=annotate/seal）——命名待 YZ 拍板。
- 分派器归属：独立 cog-func 还是并入 locate（意图→动作 与 动作→region 坐标 可能是同一连续 LLM 循环）。
- 主 LLM 意图要不要半结构化（function call args 带"想要什么"自然语言 vs 再给粗 schema）。
- 关系树 vs 全图坐标（checkpoint-12）仍未拍板。
- isolate 依赖"到目标边界"的 locate 精确度；annotate/seal 细节、图池/缓存/生命周期（checkpoint-7/8）后置。
