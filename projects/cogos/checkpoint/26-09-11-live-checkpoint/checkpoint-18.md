# checkpoint-18 — 视觉引擎架构再收敛：主 LLM 自己看 + 工具按需加载

接 checkpoint-16（三接口）/ checkpoint-17（可行性实验）。checkpoint-17 走通 open 后，讨论发生重大转折：从"ImageTool 替主 LLM 看 + 摘要"整个反转到"主 LLM 自己看 + 工具按需加载"。本文件固化结论，修正 checkpoint-16 的三接口定义。

## 实验实证（checkpoint-17 补充）

- open 机械 + 摘要两层已通（`p062.jpg`/`detail.jpg` 全景 → LLM 摘要准确）。
- **内容描述必失真**：主 LLM 用"内容描述"指认目标必错（人眼描述"X形框+image"错；模型定位 bbox 落到 "12345" 也错，且它声称"找到了"）。**坐标准确**。
- 结论：机械层缺"定位/指认"，而让主 LLM 用内容描述补位也补不住——locate 依赖 LLM 这条路本身有偏（checkpoint-11 定位偏）。

## 关键结论

### 1. 信息边界修正（YZ 纠正）

"open 不需要看清、抓语义锚"表述不准。采样后全景在**整图尺度上已清晰**，再加分辨率只是像素变多、无新信息。真边界 = **整图尺度可辨识**（open 覆盖）vs **区域尺度才可辨识**（小字/精确值，需 crop 那个 region 看原生分辨率）。接 checkpoint-4/11。

### 2. 主 LLM 有视觉，自己看

识图通道已通（read 直接读图文件当附件；主 LLM 按内容路由到 vision）。所以"看"是**主 LLM 自己看**，不是 ImageTool 替它看（checkpoint-12 的"信息隔离/替主 LLM 看"前提作废——它本基于"主 LLM 无视觉"，而 checkpoint-8 已闭合"主 LLM 有视觉"）。

### 3. 摘要作废

主 LLM 自己看图 + 上下文原样在，摘要（把"看"压成文字）是**失真通道**，失去意义。纯"看"输出 = **图本身**，主 LLM 直接读图。摘要只在确有无视觉消费者时作可选窄路径，不默认内嵌。

### 4. open/focus/isolate 三合一

机械上三者全是 `extract(region, max_dim)`：open=全图、focus=center/range、isolate=目标 bbox。**差异只在 region 语义**，而 region 由主 LLM 意图+迭代决定，**不是工具选择**。→ "看"维度只有一个取图工具。checkpoint-16 的三接口定义**收敛为一个工具 + 主 LLM 意图决定 region**。

### 5. 坐标约定躲不掉，但承认暴露工具

主 LLM 若必须输出位置，就必须学坐标约定（坐标就是"指"）。**承认：只要有工具，就绕不开暴露用法**；意图翻译层又必失真。所以放弃"用意图翻译来藏工具"。

### 6. 最终形态：工具按需加载 + 痕迹擦除

```
主 LLM ──"加载看图工具"──→ 加载器（原"意图工具"，只做 fetch，不翻译）
   ↓ 工具注入上下文（出现在它要用的附近）
主 LLM 直连工具（坐标照给，精准）——每次工具调用 = 意图执行
   ↓ 调用后机制层擦痕迹（不留坐标/过程，只剩意图+结果）
闲置 N 轮未用 → 工具从上下文摘除（小工作集）
```

- **意图不消失**：不是独立翻译层，是嵌入在每次工具调用里。
- **精准发生在调用时**（直连工具、坐标精确），**干净发生在调用后**（擦痕迹）。
- **最终上下文形态 = 意图 + 结果**（过程不留痕），看起来就是原意图模型，但达成方式是**事后擦除**而非**事前翻译**。
- 接 checkpoint-6（消息合并=意图+结果一条、过程边缘化）、checkpoint-7（对象 LRU：工具加载≈对象实例化、闲置摘除≈淘汰可重载）。

### 7. 两个清理动作（不同，勿混）

| 动作 | 清什么 | 触发 |
|---|---|---|
| 工具摘除 | 工具 schema | 连续 N 轮未用 |
| 痕迹擦除 | 调用过程细节（坐标/参数/中间序列） | 调用完成后即时 |
