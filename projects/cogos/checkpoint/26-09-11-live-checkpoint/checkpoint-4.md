# checkpoint-4 — vision 模型视角：识图内部机制对 locate/look_at 的印证（讨论）

## 当前问题

换用带视觉输入能力的模型（deepseek-v4-flash-vision-exp）重新审视识图方案。区别于之前用的纯推理模型 v4 pro（只能透过工具拿文本结果，隔一层），本模型能直接"感知"图，对图像任务有第一直觉——用此视角校验 locate / look_at 的关键设计。

## 关键结论 / 决策

### vision 视角的内部直觉（本会话核心）

1. **封顶机制是根因**：整图进模型前被 resize 到固定 token 上限再切 patch（封顶常量）。超过上限的细节在进模型那一刻就**丢了**——不是"看不清"，是根本没进上下文。→ 看清只能靠 crop 缩 range，"永不放大"由机制依据。印证方案/本体 §4/§6 结论。
2. **VLM 对"看不见"无感**：它能输出置信度很高的坐标/结论，但不知道什么细节被丢弃。→ "糊了该凑近"不能指望 LLM 自己发现，必须机制层用分辨率预算/能力探测兜底。印证方案"软硬阈值机制层、LLM 只管语义"。
3. **坐标漂移是结构性的**：patch 网格切块后跨 patch 连续性弱，感知映射绝对坐标有系统性偏差，局部计数易错。→ locate 让 LLM 只报相对当前图坐标、机制层做 region 链换算正确；LLM 做多层嵌套换算是灾难。
4. **crop 的有效分辨率收益有上限**：region 缩到很小时像素本身成瓶颈，收益消失甚至有损（过度缩放）。→ 对"focus 能凑多远 / 何时该放弃转第一人称"是实感边界，实现阈值可参考。
5. **聚焦区注意力天然强**：模型对"看局部"的倾向自然，聚焦注意力强。→ locate 用"focus 优先、draw 校准、final 收束"的退化设计贴合模型能力。

### 待进入草案的延后点（vision 视角初稿，实现时定）

- focus 最大深度、draw 起点策略、失败阈值方向——基于上述直觉给出第一版草案。

## 遗留 / 坑

- 本模型为 flash 档：更轻省 token、迭代快；深度多跳推理弱于 pro。识图理解来自 vision 输入能力，非推理扎实度。
- 以上为直觉层面，未与 v4 pro 对照实验；供实现时校验，非定论。
