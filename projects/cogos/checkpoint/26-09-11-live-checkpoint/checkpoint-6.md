# checkpoint-6 — 意图（intent）方案（独立内容，视觉功能讨论沉淀）

本文件独立记录"意图"方案。视觉功能用意图工具做入口，但意图机制本身独立、可复用（图/文件/terminal/搜索等工具集共用）。

## 当前问题

主 LLM 如何从机械工具中解放、只通过"意图"调用工具集；意图结果如何返回；意图方案整体设计。

## 关键结论 / 决策

### 1. 意图入口：主 LLM 只面对一个意图工具

- 主 LLM 不面对一堆工具，面对"能力意图"——它看到若干工具集标签 + 一个意图工具，用意图调用，不关心工具内部（像人不关心手怎么动/眼睛怎么看）。
- **意图 = 工具集标签（枚举）+ 意图内容（自然语言）**。"我想看图"→ 指向 ImageTool + 一句自然语言。
- 走**厂商 function calling**（注册单一 intent 工具）：买的不是字段对错，而是**控制流可靠**（正确触发 / 等待回传 / 续轮）+ 结构化约束。复用 lm-service/providers 成熟 tools 链路，不重造。
- 修正：**不要退到 `json_object`**（只保证合法、不保证字段/枚举对）；若真要 JSON 路线，至少用 structured output / `json_schema` 强制字段 + 锁死工具集枚举。厂商 function calling 最稳。

### 2. 意图结果 = 对象，工具过程边缘化

- 工具集返回结果封装成**对象**：图 / 文件 / terminal 是对象（有身份、可复用、带状态）；上网搜索是**值**（一次性查询），非对象，直接返回结果。
- 打开对象返回"对象本身 + 简要描述"（首次加载对齐），主 LLM 看完表达明确意图后再局部聚焦；拿不到返回明确错误（如图不存在）。
- **对象 id（暴露给主 LLM 的索引）可弃**：对象描述（路径）即唯一主键，主 LLM 用自然语言/路径引用，工具集理解，程序保证对象准确。
- **意图 id（机制层内部）必须留**：异步关联锚 + 边缘信息主键，机制层自建、不占用主 LLM 注意力。**区别**：可弃的是"对象索引 id"，保留的是"机制层内部意图 id"——两个不同的 id，勿混。

### 3. 消息合并：意图 + 结果合并成一条

- 主上下文里只有"我想看图 → 我看到了这个"，没有"我调用了 extract 200ms"。把打开图的过程边缘化。
- 本质：不走厂商 tool_result 通道，把结果伪装成普通上下文消息（带意图标签）追加。cogos 手动续轮（cog-runtime cu 循环）不依赖 tool_call/tool_result 配对，可裁掉工具调用痕迹。
- 保留**弱意图标签**（区分"这是看图结果"还是"文件内容"/来自哪个工具集），别清成裸文本。
- 两个边界：a) 合并只对**对外结果呈现层**；内部多步迭代状态（locate 的 draw→focus→final 链）须封装进 cog-func 自持、不合并。b) 错误诊断靠 raw trace 旁路，不靠主上下文。

### 4. 对象准点护栏（代替格式结构）

- **结构不是被放弃，是被移到工具集校验层**：存在性 / 覆盖保护 / 权限 / 歧义拒答。
- 主 LLM 意图自由，但"破坏性动作"关键语义须显式（覆盖 / 新增 / 追加）；工具集**宁可拒绝、绝不瞎猜**；错误传回主 LLM（"哦这文件重名了"），负反馈教会主 LLM 说清关键语义。
- 数据驱动放开：哪个环节 LLM 反复说不清，再兜进机制层，不拍脑袋。

### 5. 意图内容 = 自然语言，结构下沉到工具集入口

- 意图内容主形态 = **自然语言**，不硬造 JSON。入口解析靠 cog-func（=工具集）内部 LLM 理解语义。
- 真正的设计难点在**工具集入口把自然语言稳定解析成确定性动作**（又一个 LLM 环节，会出错、可能不收敛），守"可拒绝、不瞎猜"底线。
- 与 locate 的 `draw/focus/final` 同构：外层一句话自然语言，内部结构化三选一。两层都有，结构位置在内层、不在主 LLM。
- 路径等关键引用不需要单独结构字段：LLM 擅长从自然语言提实体，入口提取 + 存在性校验即可。

### 6. 路由

- 每个工具集有意图入口；路由纯软件，找入口把意图内容交接过去。

### 7. 同步 / 异步

- **阻塞/非阻塞作工具集契约属性**（看图默认阻塞、搜索默认非阻塞），主 LLM 不显式填、每次不用操心。
- 主 LLM 可**盖过默认**（通常异步搜索，但这次要先看结果就改同步）。既有默认不烦人，又不剥夺控制。
- 意图 id 作异步落点：异步回调带 id → 找到原意图 + 上下文背景，主 LLM 不突兀。

### 8. 边缘信息体系（跟主 LLM 经历走，非跟对象走）

- 边缘信息 = **主 LLM 的连贯性/时间线**。产生意图时主 LLM 不关心，但回想此段经历时信息完整。对象只是这条经历里的内容。
- 写入分工：程序在每次产生意图时**低频写时间线锚**（含意图 id）；主 LLM **周期性整理压缩**（折叠进背景区 = context engineering 的 compaction/note-taking），自然让上下文不长。机制层准写、语义层该转。
- **边缘信息要在主上下文里但"降注意力"存在——这才是真正形态**。理由：彻底清理会让主 LLM 失忆死锁——没有低注意力背景钩子，它根本不知道自己"搜索过"，也就不会去回顾。低注意力锚 = "我知道我有记忆"的钩子（人：边缘信息我不关心，但我知道它在那）。
- "降注意力"不可使模型真降权重，只能靠三样近似：① 形态压缩（背景/备忘被动语气，非待办/过程）② 措辞（一行薄锚）③ 位置（归入背景区）。
- 落地形态 = **可折叠薄锚**：主上下文一行摘要/标签（低 token），脚注/详情外置；主 LLM 想看某脚注 → 展开进上下文；完全展开 → 锚消失、部分展开 → 锚保留（内容多不全部展开），像回忆逐渐的。
- 边界：低注意力≠零成本。锚要"薄到不干扰、厚到能被记住"，粒度让机制+主 LLM 整理时自适应、不预设；守**必须可折叠**底线（薄锚 + 脚注外置，看才展开）。

### 9. 语义总结（契合）

- "主 LLM 的世界里只有『我想看图 → 我看到了这个』，没有『我调用了 extract 200ms』。"
- 意图结果 = 对象（有状态、可复用）；非对象（搜索）= 一次性值。意图机制与 cog-func 分层、主体性流动咬合。

## 遗留 / 开放

- **多意图 / 并行**：异步非阻塞天然允许多意图并行（一次发多个意图等待）；当前"意图=单一动作"未覆盖。待深化（独立讨论题）。
- 边缘信息召回/回顾触发：谁触发、注入形态——挂 checkpoint-5 遗留-1；回顾式召回是合理触发维度，机制层应提供"请求回顾"入口。
- 实现细节后置：意图 id 具体形态、错误反馈 loop 格式、工具集枚举扩展方式、意图入口解析与校验收敛。
- 意图未落 ImageTool 具体；有了意图机制，ImageTool 才有落点（打开图返回全景 + 简要描述）。
