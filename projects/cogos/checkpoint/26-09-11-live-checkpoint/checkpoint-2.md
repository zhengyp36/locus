# checkpoint-2 — look_at 方法论 + cog-func 实现一般法（讨论，未完全收敛）

## 当前问题

look_at（cog-func 第一步落地）怎么实现：cog-func 的一般实现方法，以及 look_at 的「看图/定位」方法论怎么定。

## 已读代码要点

- `cogos/img_tool/core.py`：`do_info`（尺寸+预算）/ `do_extract`（crop + `pick_scale`≤1.0 永不放大）/ `parse_region` 归一化→像素 clamp / `mem_budget` 每次读 `MemAvailable×0.6`。
- `cogos/img_tool/stub.py`：async `info`/`extract`；`extract` 返回 `{ok, data, width, height, scale, format}`。
- `cogos/img_tool/cli.py`：`img-cli`，`info`/`extract` 子命令，flock 计数信号量 `acquire_slot`。
- 实测 p062.jpg：`info` 返回 3468×4624，est_peak 105.5MB < budget 800MB。

## 关键结论 / 决策

### cog-func 一般实现方法（范式操作化）

- cog-func = 自然语言方法论 + 底层原语集，复用主 cu 循环，无新引擎/进程/服务。
- 组成：方法论（策略层）+ 原语集（机制层）+ 状态句柄（缓存，机制层维护）+ raw trace（旁路）。
- 方法论分两层：契约（下界稳定，怎么做算对）+ 经验（上界可长，什么情况用什么招），都条目化非散文。
- 稳定执行三手法：条目化 + checklist 自检 + 状态锚定（每步输出结构化中间状态写句柄）。
- 稳定性来源二分：能写成硬约束→下沉机制层（代码保证，下限）；必须靠判断→条目化+自检+锚定（上限）。
- 方法论↔程序是连续轴非硬边界：下沉判据 = 验证稳定性 × 失败模式代价；程序演化慢于方法论（成本高），不是禁令。
- 原语「多一点」的判据 = 是否补偿 LLM 固有局限（必要，如 VLM 报坐标漂移/计数差）；策略性选择（如画法）不预装、机制层自动定。

### look_at 功能定义

- 让主 LLM 像人眼看东西一样看清一张图：全景背景 + 局部凑近，看完出结论，图不留上下文。
- 三条核心语义：看清=缩 region 凑近（非放大）；看不清→extract 更小 region；能力不足→第一人称转述，不降级。
- 原语：`info`（探尺寸+预算）+ `extract`（crop 局部，region 归一化 0~1，scale 自动推≤1.0 永不放大）。

### 定位方案演进（本会话重点）

1. **网格 4×4 编号**（§14 原方案）：编号画图上，LLM 报离散格子，机制层映射 region。缺点：污染内容、粒度固定。
   - 网格画法：反色有坑（中性灰失效 + 高频纹理碎），勾边（深线+浅描边）更稳；编号放角落。
2. **自由估**：报坐标偏大包住，迭代逼近。缺点：VLM 报连续坐标漂移 + 计数差，容错救不回。
3. **画线自校验**（本会话关键收敛）：给 LLM 配画线工具，估坐标→画线→看图看线落哪→修正，二分逼近。**把「报坐标」弱项转成「看图」强项**，是定标探针的主动升级版。
   - 定位倾向：起步 = 画线自校验（准确优先），网格 = 后续生长出的省费技巧（批量预置线）。
   - 原语集倾向：`info` / `extract` / `annotate`（画线），封闭在 look_at 内。

### 费用 / 上下文组织

- DeepSeek prompt cache 前缀匹配：msg-1 功能描述 + msg-2 全景图固定在前，迭代只追加 msg-3 坐标 + msg-4 画线图，边际成本低（前缀命中缓存）。
- 「改上下文」= 尾部裁剪、前缀保稳：删旧迭代消息（画线图历史），不碰 msg-1/2 前缀（删前缀=缓存失效）。
- 缓存是机制层自动发生，LLM 不必理解；只需按契约组织上下文（功能描述+全景图在前、迭代追加、看清后整段退场）。

## 恢复后讨论收敛（09-04）：locate 方案

定位问题从"画线工具形态"升华为「locate 独立 cog-func」。上述遗留大部分已解决，收敛如下：

### locate 形态

- 独立 cog-func（函数式嵌套，look_at 调用）：入参（背景 / 任务 / path），出参（坐标，相对全景）。对外 async 函数，内部循环驱动多个 cu。
- **oneshot 不续轮**：每次迭代 = 一次独立 `cu(完整 material)`，无工具调用，LLM 只回答一个问题。JSON 输出（`response_format: json_object`），不注册 function calling。
- 上下文组织：msg-0 方法论 + msg-1 背景 + msg-2 任务 + msg-3 图像信息 + msg-4 迭代状态（**固定槽，每次重写，不追加**）。前缀 msg-0~3 稳定命中 prompt cache。

### 答案三选一

- `draw` 画线 / `focus` 凑近看局部（原 zoom_in）/ `final` 最终坐标。
- 坐标归一化 0~1，**相对当前图**；focus 后新图成当前图，继续同一循环（如法炮制）。
- `focus` 语义 = 缩 region 凑近（非放大），避开 zoom 放大误导；参数是 region 坐标，不是倍数。

### 坐标链换算（机制层）

- 机制层维护 region 链（局部图逐层嵌套），final 时把相对当前图坐标换算回全景坐标。LLM 全程只报相对当前图坐标，绝不做嵌套换算（VLM 报坐标漂，多层组合是灾难）。

### 图池管理

- 图池 + 编号（层号，全景=0 禁删），LLM 决定删留。
- 软阈值 N1 提醒（每 +N 张，默认 3）+ 硬阈值 N2 强制删或放弃（默认 5）。阈值机制层、删哪些语义层。
- 删图审视 = 独立 cog-func（判断权在 LLM），倾向实现为「主循环管理轮」（切换提问，非重建上下文）。

### 失败两分类

- 格式/参数错 → 机械判定重试，超限放弃；迭代不收敛（一直 draw 不 final）→ 达上限换评估。
- "放弃"返回失败给 look_at → 第一人称转述（与"能力不足"同一出口）。

### 缓存澄清

- DeepSeek prompt cache = 内容前缀哈希匹配，跨请求命中，不靠会话/请求 id。成本优化而非正确性前提，设计不依赖它。
