## 1. 感知

**真实判据**：`真实 = 不是它自己写的 + 会自己变 + 能反驳它`。按这条，它现在关于自己的一切都不是感知、是断言——`config.py:96` 的 `render_system_prompt` 把名字/手机号/时间快照/通讯录/工具清单一口气告诉它。断言的毛病：不会变、不能被反驳、也就可以随便装。

**感知 ≠ 经历**：感知给"处境"；经历 = 处境 + 选择 + 后果。感知正是**后果的载体**（execute 失败、文件写坏、验收变红都从感知进来），所以"接感知"与"接世界后果接口"是同一件事的两面，不用分两次做。

**它的"身体"只有两处**——跑它的机器、接入的电话网：

| 感官 | 真实来源 |
|---|---|
| 身份 | signature |
| 所在 | 主机（可变） |
| 时间 | 系统时钟 |
| 听/触 | 飞书消息、timer 到点、terminal 退出 |
| 看 | （缺）屏幕或外部图源 |

**提供感知的四个件**：
- **处境快照（situation）**：每次唤醒现算、不常驻，几行 `[处境] 我 <signature> 在 <host> | 现在 <time> | 自上次醒来：<新消息/新后果>`。替换 `loop.py:530` 那种"只给当前 item"的 material 头部，等价于 §3 的"锚常驻"。关键是**每次重算**——会变才可能出乎它意料。
- **拉**：一个 `perceive` / `where_am_i` 工具，让它能主动问"我在哪、世界什么样"。这是"可寻址"的来源：处境能被查，经历才可能按处境取回。
- **推**：复用 `event_queue`（`app.py:147` `_consume_events`）。但 `events.py:20` 的 `render_event` 连时间都没有，且只送它自己请求的后果（timer/terminal），**缺"世界自己动了"**（文件变了、消息到了、进程退了）。
- **坐标而非正文**：时间与位置当每条记录的两列，不当一句话塞进上下文；否则"昨天/上午"检索不到。

## 2. 身份锚：signature

```
身份（不变）:  signature
处境（会变）:  (host, time, 目录内容, 到达的事件, 后果)
```

- 主机也可变（可以换机器跑），**只有 signature 不变**；所以"我在哪"是处境的一列，不是身份。
- **不感知目录**：它改不了目录，目录是处境（世界），不是位置。
- **经历只能挂 signature**，不能挂主机或进程——否则换机器/换进程过去就丢。
- 先例同形状：bot_id 不可变 / name 可变（`README.md`）；`entries/2026-09-03-cogos-cogfunc-paradigm.md`："agent = 对外的 cog-actor 实例，有 signature / 身份"。
- 实现约束：**别把 host 写进身份**。signature 放 profile/code（不可变），host 每次运行记成处境的一列；"先不考虑主机变"因此零成本（它是常量列，将来换机器只是这列变了）。

## 3. 运行组织：事件驱动

**架构只有一条：事件驱动**——`Agent` + `Consciousness` + `event_queue` + `perception`。消息、`timer_fired`、`terminal_done` 都 funnel 进 `consciousness.on_message`。

`loop.py` 是**实验台**，不是第二个架构：它借同一个 `Agent` body，在事件系统之外**离线单独验证**"推进 → 验收 → 写回 → 停/问"这套机制能否跑。`for step`、独立 `material`、7 工具清单都是实验台的控制流与数据，**不是设计决定**（`cogos-s2/docs/design-selfdrive-loop-s1.md` §6"需加只读访问器暴露 registry/runtime/phone，不扩 consciousness"正因此）。

实验台里真正的架构价值——**验收作独立第二判官、verdict 守卫、后果绑定**——待机制验证后**折回事件驱动主体**；壳与重复清单丢弃。

## 4. tick：内部事件

架构里跑**两类不同**的输入：

| | 来源 | 内容 | 作用 |
|---|---|---|---|
| **外部事件** | 世界（消息 / terminal / 文件变了 / timer） | 带世界内容 | 感知：能出乎意料，提供 ground |
| **tick** | 机制（节律 / 时钟） | 无**世界**内容 | 生念的时机：给"现在" |

- 这解开 scaffold §3 的回声疑虑：念头不从上下文开始，是因为**起点是一拍，而不是一个上下文窗口**。
- 与 scaffold §6.2 对上：**节律是机制给的中性件**，生念内容才是进口的。
- tick 与 §7.3 缺的"时间感"是同一件事：一个离散的拍子既是时钟、又是生念的时机。

## 5. 生念：一个选择器机制

**生念不空拍。** 空拍缺的正是"选什么"和"从哪看"，所以内部事件带 `(事项, 角度)`——**无世界内容，有机制内容**。

**念 = 事项 × 角度**：
- **选事项**：从"未完成事项池"张力加权、**概率**抽取。
- **选角度**：给这件事配一个视角。**不直接加载事项**——直接加载 = 提醒 = 同一方向 → 回声；加角度才是新念。

**张力 = 未闭合的环**（后果未落定）。这补上 scaffold §6.5 的悬问：后果能闭合 → 张力可算 → 生念有源。用概率而非优先级：避免高张力项独吞注意力（反刍），留缝给低张力项（意外 / 交叉）。

**中性守则**：机制只做**抽样与簿记**（中性）；**张力从后果来、角度从经历来**（非中性，进口）。张力不能是手写表，否则"选谁"是我们在提线——它必须是可观测量的函数（未绑定后果数、目标-状态差、最近失败、recency）。

**角度必须来自事项之外**（最硬一步）：从变化的后果、相关经历、目标的其他侧面来；若从事项自身推得，就没有变化的方向。此步与 §6.5"处境 / 相似怎么算"同一口子。

```
tick      → 该想了
选择器    → (想什么, 从哪看)      ← 张力概率 + 角度
模型+目标+经历 → 念的内容与转向
```

**接口**：agenda 池 = 未完成事项池雏形；`pick_next` 从"确定性挑"升级为"**张力加权抽样 + 选角度**"，S1 七格里的"触发"格即**生念**——不是加新机制，是把退化的 tick（agenda 扫描，拍子里硬塞 item）换成"真 tick + 选择器"。
