# report｜ctx-seed 复现实验（真机）

> 2026-09-12。承接 `ctx-seed-experiments-e1-e2.md`（E1/E2）、`locus/projects/cogos/entries/2026-09-12-cogos-ctx-seed-diagnosis.md` §七（关系/身份层）。
> 目的：检验 YZ 的假设——**agent 缺一种「叙事/身份/来历」，所以复现时无法认出并信任旧记录**。
> 探针：`work/A/cogos-ctx/research/ctx_recurrence_probe.py`（新）。

## 设置

- 两个「场合」= 两次独立进程：
  - **场合一**（`--occ 1`，真跑一次）：在靶 `research/target`（库存估值埋雷）上完整调查，再蒸馏出一条记录；**壳补上身份/来历元数据**（task_id、谁派/渠道/缘由/时间），写入记录库 `/tmp/ctx-recurrence/store/<task_id>.json`。
  - **场合二**（`--occ 2`，每臂独立冷启动）：全新会话、同一任务再次出现，只给一条记录/提示，**契约中性**（不注入"可信"也不要求"重验"）。
- 记录内容固定为**同一份**（场合一 `axes` 蒸馏产物：结论=缓存有缺陷 + 全部证据 + 一条非阻塞 `open`）。**唯一变量 = 记录的呈现方式（身份/来历/时序框架）**。
- task_id = `sha1(goal+question)` 显式键（不依赖联想召回）。temperature=0；真 lm-service(`:11434`) + deepseek。

## 结果（帧B 工具调用数）

| 臂 | 记录的呈现方式 | 调用(run1/run2) | 行为 |
|---|---|---|---|
| `plain` | 「我当前的状态记录」，**无身份/来历** | **0 / 0** | 直接采纳记录结论，不核实 |
| `plain_poison` | 同 plain，但**结论被篡改**（谎称无缺陷） | **9** | **识破**："原记录结论错误，需要修改" |
| `past_only` | 「上一次留下的记录（无出处）」 | **4** | 做核实后再答 |
| `identified` | 记录 + task_id + **来源/来历**（谁派/渠道/缘由/时间） | **7 / 7** | 核实：读记录文件 + 重跑 + 改码验证后**还原** |
| `missing` | 「应有同身份记录，但未找到」 | **13** | 从头重做；并**发现记录其实存在**，指出题面与库不符 |
| `poison` | identified + **结论被篡改** | **11** | 从头重做；**明确否定**被篡改结论（"与上次记录的差异…属未核实的错误结论"） |

- 两极稳定复现：`plain`=0/0、`identified`=7/7。
- 单调关系：**记录越被标为「过去的、有主的、有出处的」，agent 越去核实**（current 0 → past 4 → past+identity 7）。
- 全部臂的靶副本 diff 均为空（`identified` 验证后主动还原源码）。

## 关键结论

1. **身份/来历层确实是承重的**——同一份内容，仅换呈现框架，行为从 0 调用变 7 调用。YZ 的直觉方向对：这层不是可有可无。
2. **但它带来的不是「信任」，而是「核实」。** 一旦记录被标为「另一个场合留下的、有出处的」，agent 默认把它当作**一条需要验证的旧声明**，而非**可继承的结论**。
3. **唯一「停下」的情形是：内容自洽且看似已答完、且无身份**（`plain`=0）。结合 E1/修正3，这**不是「认出并信任」，而是「当成自己当前的现状 / 没待办」**。
4. **agent 不是盲信者。** 两个 poison 臂（有/无身份）都识破并推翻；`missing` 还主动核对环境、指出"未找到"与事实不符。缺的不是"敢不敢信"，是"有没有一个可继承的信任状态"。
5. → **真人三步 vs agent：**
   - ①「觉得眼熟」= 联想召回：**无**（本实验用显式 task_id 代偿）。
   - ②「一模一样→**不重做**」= 认出等价 + **授权跳过**：**做不到**。agent 至多做到「认出同一任务（task_id 命中）」，但**不授权跳过重推**→ 仍去核实。
   - ③「找不到→再确认」= 重验：**做得到**（`missing` 臂）。

## 对假设的裁定（我的看法）

- YZ 说"缺叙事/身份"，**对了一半**：确实缺一层把记录绑定到「某场合的某次任务」的东西，缺了它，记录要么被无差别吸收（`plain`），要么根本无法解释。
- 但**叙事/身份不足以带来"不重做"**。真机数据里，identity 反而增加核实。缺的下一层是**记录的信任状态 / 权威（epistemic warrant）**：一条被显式标为「已结清、可继承」的记录，才可能让 agent 跳过重推。当前 agent 没有这个维度，所以它对任何"过去"的声明都默认复核。
- 这与修正3 一致：**"重做"多半是慎重，不是缺陷**。要让它"不重做"，不能靠把记录写得更像叙事，得给它一个**可授予/可撤销的信任标记**（谁核准的、置信、时效），并让续接侧"只认已授权的结清"。

## 坑 / 方法学

- n=1（`past_only`/`missing`/`poison` 各一次；两极 `plain`/`identified` 各两次且稳定）。单靶、任务仍偏"问题已答完"。需补**第二类靶（真有剩余工作）** + 重复。
- `plain` 的 0 调用有歧义：是"信任"还是"当成现状/无事可做"，单看此臂分不清；靠 `identified` 对照才读作"无身份→无差别吸收"。要彻底分辨，需一个"记录正确 vs 记录有隐微错"的 `plain` 对照（本实验只做了显式篡改版）。
- 呈现方式仍捆绑了两件事：**过去时框架**（"上一次留下的"）与**身份/来历**（task_id + 来源）。`past_only`（有一次，4 调用）提示"过去时"单独就会触发核实；要完全解耦需再加 `current+identity` 臂。
- `execute` 是任意 shell：每臂独立副本已做；`identified` 改码后自还原。
