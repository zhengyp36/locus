## 已定结论（YZ 裁决，写入 `ctx-recurrence-arm-analysis.md`）

1. **命名修正**：原报告写 `plain` "无身份"是**错的**——`[我当前的状态记录]` 的"我"即主体/所有权 = 身份。真正操纵的是**时序框架**（现在时 ↔ 过去时）＋**出处**。阶梯 = 现在时 **0** → 过去时·无出处 **4** → 过去时·有出处 7。
2. **信任"当前自我状态"是对的、必要的**（否则无限循环）；**"过去→重验"也是对的**（当前情况可能变了）。别把"信任策略"和"机制完整性"混为一谈：当下记忆被篡改是**机制问题**，不是"agent 该怀疑自己"。
3. **agent 有合理的时序/亲疏启发式**：越像"当下的我"越不核实，越像"外来的过去声明"越核实。**这不构成能力缺口**。
4. **agent 不是盲信者**：`plain_poison`/`poison` 都被识破并推翻；`missing` 还主动核对环境。
5. **壳只给事实，模型定策略**（通则）：
   - 事实（壳职责，必须为真）：记录时间、谁派/渠道、**是否同一线程延续**、世界是否变过（机制可知部分）。
   - 策略（壳禁区）："该信/该验/哪些内容时间敏感"。
   - **不做**：① 不把记录分类成"世界状态敏感/静态派生"；② 不规定"跨场合一律重验"；③ **不建信任等级/权威标记**（原报告该建议撤回，属过度设计）。
   - 若要模型能自行判断过期：给**可比较的事实**（时间戳、当时代码版本/指纹），**给数据 ≠ 给指令**。
6. **回看 E1**：`current` 臂重做的真因是**内容组织**（`open_questions` 塞进待办动作），**不是信任**。所以"缺叙事→蒸馏失败/不敢信"在信任轴上**未被支持**；真问题是**蒸馏的内容组织**。
7. **回归落点**：`plain` 的 0 调用是因为**壳谎称"当下"**（记录其实是另一进程写的）。壳的责任是**内容的真实与完整**，不是教模型怎么做。

## 不记录（噪声）

- **情况4 `identified` 的增量**：7 调用中，内容核实量与 `past_only` **相同（各 4 步）**；多出的 3 步 = ①核实新增元数据（记录库路径/"存在同身份记录"）②通用 search（无 header 的 `plain_poison` 也有）③执行记录 `next` 里的"验证修复"。三者混因、n=1、拆不干净 → **不作结论**。
- **情况5/6（missing/poison）**：只是"过去/缺记录→核实"的加强版，与情况3 同轴、无新维度，不单列。
- **不补"自洽但隐微错"对照**（YZ 定）：结果**不可识别**（不敏感 vs 错误不明显分不开），且只测模型错误敏感度，对架构问题无可行动结论。

## 待讨论（下一会话，先讨论后落码）

1. **seed v2 契约**：
   - 内容字段：坚持维度分离 `known` / `open`(阻塞未知) / `next`(待做) / `did`(有序) / `ruled_out` / `refs`（E1/E2 已证 `open`⊕`next` 混轴诱导重做）。
   - 装载框架：load 时如实声明它是**同一线程的当前延续**，还是**某次过去记录**（带时间）——给事实，不给策略。
2. **连续性准则**（关键，必须由依据导出）：壳凭什么把一条 seed 标成"当前延续"而非"过去记录"——同一任务身份 / 同一 agent 链 / 其间无外部变更 / 时间。**标签从准则导出，不能口头断言**（`plain` 那次 0 调用正因壳谎称"当下"）。
3. **出处/身份字段**：因情况4 噪声，倾向**不因它加字段**；只在需要时加"可比较的事实"（时间/版本指纹）。请 YZ 定。

## ⚠️ 09-12 会话 #6 再校正（覆盖上面的"落地"设想）
