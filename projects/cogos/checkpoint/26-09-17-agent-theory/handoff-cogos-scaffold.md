## 3. 生念（YZ 提出的核心问题）

- **区别**：AI 的处理是"上下文整理一次、始终不离视线"；YZ 是"**围绕目标展开，上下文按需唤醒；念头不从上下文开始**"。
- **风险**：若总从已有上下文出发，**念会退化成"对上下文的续写"，方向无法从外部来 → 回声**。这也解释了为什么我的总结会流水账——**全量常驻 = 一切平权 = 无主次**。这是我的病，也是 agent 的病。
- **架构约束（这是全节最硬的一条）**：**目标常驻、上下文非常驻**。三样分开——锚（目标+粗状态，常驻）/ 场景（世界输入）/ 经历（可寻址、按需加载）。
- **加载是惰性还是全量 = 生念与续写的分界线。**

## 4. 业界调研（2026-09，自驱/自进化）

- **两条主线**：**自进化**（改自己结构提性能）与 **自驱**（外部触发找活干）——**是两回事**。
- **综述**：
  - Gao《Self-Evolving Agents》2507.21046（what/when/how/where：改 模型/上下文/工具/架构）。
  - Ren《Self-Improvements in Modern Agentic Systems》2607.13104（**FM improvement（改权重，慢）vs Scaffold improvement（改 prompt/记忆/工具/控制，快）**）。
  - Luo《From Storage to Experience》2605.06716（**Storage → Reflection → Experience**）。
- **代表系统**：DGM、AlphaEvolve、SICA、Voyager、Reflexion、Mem0、A-Mem、MemGen、Memento、Memory-R1。
- **自驱在业界＝调度层**：heartbeat / cron / event-driven（OpenClaw、Paperclip、Temporal ambient agents、Claude Code routines）；Anthropic《Measuring AI agent autonomy in practice》(2026-02)：autonomy 是**被逐步授予的关系**，不是内在动因。
- **内在动机线最弱**：RL curiosity（奖励塑形）；open-ended/autotelic（2510.14548）；Musolesi《On the Creativity of AI Agents》2604.13242 列出三个缺口——**缺内在动机、缺基于经历的持续学习、缺意向性与人格**（与我们的三个议题一一对应）。
- **反方（重要）**：Zenil《On the Limits of Self-Improving in LLMs》2601.05280——递归自训练若外部 grounded 信号 αₜ→0，**熵衰减+方差放大，必然退化**。→ **自驱 ≠ 自给自足，必须持续锚在外部世界**（支持我们的"非中性来自世界"）。CMU《Limits of Prompt-Based Self-Improvement》2026-07：ACE 式自适应无稳定收益。
- **对照结论**：业界做的是"自进化（改结构）"和"自调度（外部触发）"；**"生念"没人正面回答，"中性+可塑经历"没有**。我们做的是"自驱的动因与自我如何从经历里长出来"——接近空白。

## 5. 困境诊断：无法整合

**一句话**：**理论在等一个还不存在的最小运行体，实验在等一个还没冻结的理论——两边互卡。**

四个卡点：
1. **实验和理论不在同一层**：探针是离线/单发/手喂后果，测的是"倾向"；理论讲的是"跑起来的环"。互不相认。
2. **部件都挖出来了，但从未接线**："整合"恰恰就是接线，而接线这道工序**还没开始**。
3. **层级一直没冻结**：机制 vs 内容、形式 vs 目标、上下文 vs 念头——每次都在重划这条线。
4. **目标和判据没定**：要"好用"又要"自驱"、判据未定案 → **没有"完成"的定义**。

**深层原因（方法）**：一直在做**垂直深化**（一个概念挖到底，每次开新问题），缺的是**水平接线**。越深越散。

## 6. 框架修正（本次核心）——不是"中性机制"，是"沉淀机制"

### 6.1 我先给错了一版（YZ 不认同，我也不认同了）
我给的"中性机制（四件事：record/load/anchor/gate + 两个不许）"：
- 是**负定义**（只说不做什么）→ 没形状、抓不住；
- 把非中性放错了位置（说"经历库=中性存储"）→ **答不出非中性从哪来**；
- 跟 append-context 没差别。
（YZ 的原话："非中性难道不是用中性的机制调用非中性的模型及经历与内容，才产生了非中性的经历吗？"——**这句是准的**。）

### 6.2 修正后的框架

**谁中性、谁非中性：**

| 层 | 中性？ | 内容 | 谁给的 |
|---|---|---|---|
| 机制（存 / 取 / 时间轴） | **中性** | 只提供"被调用"的能力，不加值 | 我们 |
| 模型 | 非中性（**冻的**） | 先验、判断算子 | 训练 |
| 世界 | 非中性（**活的**） | 后果 | 环境 / 人 |
| 经历 | 非中性（**沉积的**） | 带后果的事件 | 由上面两者沉积 |

**关键：非中性来自模型和世界，机制只把它们调用起来。机制不生产非中性——它让非中性集中、留下、能再被取回。**
→ 所以不是"中性机制 + 可变内容"，是 **中性的调用接口 + 非中性的模型与经历**。

**经历是什么（对 agent）：**
```
经历 = 离散事件 (时间, 处境, 选择) + 后果
```
- **离散**：agent 只在被唤醒时"活着"，两次之间没有体验（不是连续流，是一串点）。→ 所以"能不能回忆昨天/上午"取决于**机制给了时间轴、且 recall 是可能动作**。
- **时间索引**：能问"昨天/上午"的前提。
- **后果绑定**：**没后果的只是日志，有后果的才叫经历**；非中性就挂在后果上。

**两个动作——非中性进入的唯一入口：**

| 动作 | 机制提供 | 标准来自（非中性） |
|---|---|---|
| **存**（留下什么） | 写入能力 | 后果（世界）——有后果的才留 |
| **取**（调回什么） | 检索能力 | 目标 + 当下处境——相关才取 |

**这两次选择就是"我"的雏形。自我 = 存/取长期偏好的沉淀**（机制不存自我，让自我沉淀）。

**与 append-context 的差异（缺一条就退化）：**

| | append-context | 本框架 |
|---|---|---|
| 过去的位置 | 常驻窗口 | **可寻址**（取才来） |
| 过去的权重 | 全部平权 | **后果绑定** |
| 时间 | 无 | **有** |

**两条约束（是约束，不是身份）**：① 机制不自己加值；② 过去不常驻。
**时间轴**：clock/节律给离散的"天"；节律是身体自带（机制给），排班是它的（机制不给）。

### 6.3 环
```
唤醒 → 取(目标+处境) → 模型读(先验 + 取回的经历) → 选择
     → 世界 → 后果 → 存(绑定到这次选择)  ↺  沉淀 → 方向
```
第一个可观测：**下一次的选择是否被取回的后果改变**。

### 6.4 为什么这次能解释"非中性内容从哪来"
非中性是**进口**的（模型带一份、世界每次给一份）。机制不生产它，只让它**集中、留下、能再被取回**。若世界不给真后果，任何框架都产不出（= Zenil 的 αₜ→0）。

### 6.5 未定口子
1. **处境 / "相似"怎么算**：决定"取"能否取到相关。
2. **后果落定谁判**：决定"未闭合的环"是否存在、生念有无源头。
3. **目标和动因从哪来**：本框架里"目标"是常驻取用键，但**它自己的来源仍是悬的**（饿/驱动那摊）。

## 7. YZ 的下一步计划 与 我的回应

### 7.1 YZ 的计划
**先搭"中性架子" → 让 agent 真正接触外部世界（视觉、上网、用电脑）→ 再让它有经历、有时间感。**

### 7.2 事实纠正：能力基本已经有了
- **上网**：`agent/webtools.py` 的 `search`(Brave) + `fetch`(Jina)，已在 `TASK_TOOLSET`（`loop.py:33`）。
- **用电脑**：`read_file / write_file / edit_file / execute`（`tools.py`），沙箱在 `work_dir`。
- **视觉**：`cogos/image_ctx/`、`cogos/img_tool/` 有零散件。
- **沟通**：`send_msg` + `perception.py`（飞书 p2p）。

### 7.3 真正缺的三样（这才是架子）
1. **没有跨唤醒/跨 item 的记忆**：`loop.py:530` 的 `material` 每个 item 重建；`runs.jsonl` **只写、从不读回给 agent** → 每跑完一件事就失忆。
2. **没有时间索引**：`perception.py:19` 抓了 `time`，但没有地方把它当结构用。
3. **没有后果绑定**：`acceptance` 的 red/green 算得干净（loop.py 的 `check`），但**没绑到"它这次的选择"、没留给下次**。

### 7.4 我的回应要点
- **顺序要反**：不是"能力 → 经历/时间"，而是 **经历/时间先接上，新能力才有落点**。加感知只增加**输入**=更多 append；**感知不等于经历**（经历=带后果的事件）。
- **世界已经够用**：`execute` 会失败、文件会写错、网页会变、验收会红。缺的是把推回来的东西**留下并绑上**。
- **时间最先**（不是最后）：它是每条记录的一列；没它则经历无法索引、后果无法排序。
- **视觉最后**：对文本世界 agent ROI 最低；除非有"必须看才能行动"的场景（如操作 GUI）。
- **检验标准（防又变成加部件）**：每个想加的东西，必须能产出"**可被记录并绑定到选择**的后果"，否则不加。
- **结论**：架子 = **存 / 取 / 时间 + 世界后果接口**，不是更多传感器。

### 7.5 最小落点（接现有 loop，不加新部件）
- **写**：每轮结束把 `(时间, 处境, 选择, 后果)` 追进 store（后果现成：`check`/工具返回/报错）。
- **读**：开跑前按 `目标+处境` 取回相关记录，塞进 `material` 头部（替换"只给当前 item"）。
- **时间**：每条记录打戳；把 `perception` 的 `time` 接上。
- **触发**：`timer.py` 给节律，让它不只被 agenda 叫醒。

### 7.6 更正：`loop.py` 是实验台，不是第二个主体
- **架构只有一条：事件驱动**（`Agent` + `Consciousness` + `event_queue` + `perception`）。飞书上的它是唯一主体。
- `loop.py` 是借同一 `Agent` body 做的**离线实验台**：在事件系统之外单独验证"推进→验收→写回→停/问"这套机制。`for step`、独立 `material`、7 工具清单都是实验台的一部分，**不是架构选择**（`design-selfdrive-loop-s1.md` §6"不扩 consciousness"正因此）。
- 实验台里真正的架构价值——**验收作独立第二判官、verdict 守卫、后果绑定**——待机制验证后**折回事件驱动主体**；壳与重复清单丢弃。
- 据此，**经历挂 signature（唯一主体）**，不存在"挂哪个它"的问题。（原"两个它"说法为误读。）
