- **自驱** = 议程更新函数 `f`（`A_{n+1}=f(A_n,结果)`）；静态议程不驱动，ΔA 才驱动；自主度 = agent 在 f 里的占比。

## 二、方向候选（供 YZ 选）

排序按"源外移"阶梯，风险低→高。

### 候选 1｜真靶 dogfood（把已验证机制放到真活上）
- **是什么**：拿一个真 ISSUES 的"**加能力**"类项（基线须绿）跑两相，不用极小靶。
- **为什么**：机制在真活上可能有歧义；顺带看 agent 自产判据的合理性分布。
- **前提**：从 `locus/projects/cogos/ISSUES.md` 挑项，或先造一个可验收的小切片。
- **风险**：低。**验证**：真机跑出 `done` + 人复核判据合理。
- **注意**：本机制不适用"修既有 bug"（基线红）项。

### 候选 2｜议程源外移（L3，分水岭）
- **是什么**：议程为空时，agent 自己长出值得做的议题（不自停）。
- **为什么**：这是 L3 的门槛；`f` 由 agent 写 = 真正的"自驱"。
- **前提（关键）**：先有**安全件——生成权 / 终结权 / 丢弃权**，否则议程爆炸/自我扩权。
- **风险**：高。**验证**：议程空 → agent 提出合理议题且能终止/丢弃；人只复核。
- **形态**：不是一个 demo，而是"**安全件 + 议程外移**"一对，建议先设计安全件。

### 候选 3｜触发进阶（L2 完整）
- **是什么**：现在只是"人启动一次跑一条"；让 agent 自己醒来（常驻/定时）。
- **前提/依赖**：B 的 task-7（Kilo 常驻 + 事件唤醒 + 多通道）是探路，看其结果。
- **风险**：中（工位隔离缺口 `COGOS_HOME` + 服务单例是阻塞项）。
