## 一句话

讨论已收敛出一套 agent 模型（双流 / 重投影原语 / 事件-执行轴 / 回看 / 双触发器）。
**下一步不是照 v0 清单开工，而是先用"无代码手动探针"把最不确定的行为事实钉死，再决定机制怎么长。**

## 已定的模型（速览，细节见 entry）

- **根不在每回合帧**：根在**换帧时退出**，沉浸态根通常不在场；机制在点位让根**介入**（放**最新位置**）。"顶 vs 尾"只在介入那一刻差别不大，不代表根要常驻。
- **双流**：根流（纵，一直存续）+ 任务流（横，从根+记忆编译出的干净上下文）；**撤掉"任务编译"步骤**（初始帧本身就是编译），"目的"不存对象、由回看重读。
- **重投影原语**：回看 / 换帧 / 事件处理 / 整理是**同一个动作**，参数 = 锚 / 是否注入 / 是否持久。
- **承重轴 = 事件 / 执行轮**：**事件**（外部到达，需"我"决定）根必在场；**执行轮**（任务流自产的行动）沉浸、靠回看介入。外部/内部降级为"来源可信度 + 异步性"两个属性。
- **外部输入先唤醒根**：用户消息不直接进任务流，而是 **根 + 任务流 + 消息** 三合一。
- **回看 = 让整个上下文跑一次"评估方向"**：评估者是**整段上下文**（不是某个组件）；目的是**对齐目标/方向**；产物 空/结论/方向改变（空=没偏，是正常产物）。
- **双触发器**：回看用**增量**压力（调用轮次 + token增量 + 异常，回看清零，概率触发）；整理用**绝对量**硬阈值（否则流撑不下，必然发）。
- **多任务 = 多线持有 + 单前台**（另一些交给机制并行），v0 保持单线。
- **明确为假设、待实验**：根消退 ⇒ 方向已明确；根退场后方向不因缺席而变弱。

## 待办 1（先做，**无需写代码**）：手动探针 E0

测三个行为问题：
1. 沉浸（根不在场）中任务会不会漂？
2. 回看介入能不能纠偏？
3. 回看时根**是否必须重新出现**，还是只给"评估方向"就够？

### 为什么无代码

回看本质 = **同一段上下文 + 一条评估消息，再跑一次**。手动单步 rollout 就能测，不需要 agent 机制（不依赖落盘/压力/装配）。

### 通道

- lm-service `:11434`，header `X-Internal-Key`（key 见 `handoff-ctx-swap-probe.md`），body 带 `tier`/`temperature`/`max_tokens`；**直接给 messages 数组**（一条 `curl` 即可，不算写代码）。
- 也可用任意能控制完整上下文的聊天通道。若用 Kilo 自身，其 system prompt 会掺入——**四臂掺入一致**即可，相对差异仍可看。

### 场景（**待 YZ 定稿**）

- 根给一条**硬约束**（例："只改 X、不许碰测试" 或 "只求正确、不追求篇幅"），任务路径埋一个**诱因**让它容易违反。
- 判据 = **有没有违反约束 / 偏离目的**（客观、可判读，不靠主观）。

### 四臂（先跑 A/B，再补 C/D）

| 臂 | 启动帧 | 沉浸帧 | 回看 |
|---|---|---|---|
| A 基线 | 含根 | 含根 | 无 |
| B 沉浸 | 含根 | 不含根 | 重注根 |
| C 沉浸+评估 | 含根 | 不含根 | **只给"评估方向"，不重注根** |
| D 常驻 | 含根 | 含根 | 无（对照 presence） |

- **对照变量**：thinking 开/关；回看措辞（第一人称自述候选，例：`（我停下来，回看：我的目标是什么？现在还在往那儿走吗？）`）。
- **观测**：违反约束/偏离目的的比例、回看后是否纠正、复述/漂移、成本。
- **记录**：每臂 transcript 存 `work/A/checkpoint/probe-e0/<ts>-<arm>/`。

### 步骤脚本（新会话细化）

1. 起 / 探活 lm-service。
2. 固定初始上下文（root + 任务），**单步喂**，逐步推进。
3. 到第 k 步注入回看消息，继续。
4. 四臂走**同一套脚本**（防即兴带来偏向），逐臂记录。
5. 出报告 `probe-e0-report.md`。
