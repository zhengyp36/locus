## 1. 先把"最小"的定义立住

> **最小 ＝ 环闭 ＋ 三条不变量成立。**

- **环**：唤醒 → 取 → 选择 → 世界 → 后果 → 存 → 沉淀 → 方向
- **三条不变量**（总纲 §一）：过去可寻址 / 后果绑定 / 单一归属

**检验方式**：把任何一件删掉，环还闭吗？还闭就不在最小里。

## 2. 最小核

```
单槽                 （已有：consciousness）
+ 经历轴              ← 新增，骨架
     时间戳 ＋ 处境 ＋ 选择 ＋ 后果 ＋ 闭合位
+ 取回                ← 新增，唯一真正的结构改动
+ 目标锚              （已有，但目标很弱：只有 profile / system prompt）
+ 验收判据            （在 loop.py 实验台里，待折回；最小可先用最弱形）
+ 世界接口            （已有：tools / webtools / feishu / terminal）
```

**明确不在最小里**：睡/醒、`P整理`/`P节律`/`T`、生念节律、回看、眼动、压缩、权重、迸发。

## 3. 经历轴：是骨架，不是模块

**记录形态（最小）**：平的、有序、带戳、带闭合位的序列。

```
一条 = (时间戳, 处境, 选择, 后果, 闭合位)
```

**区间树 / 嵌套 / 多分辨率是后面长出来的**（`runtime-flows` §19/§20）——最小只要"轴"，不要树。

**为什么必须最先**：它是唯一一个**后续所有机制都要读**的东西。

```
P整理 ← 未整理的经历量
T     ← 未闭合的项
取回   ← 带后果的过去
眼动   ← 年龄 / 量 / 后果
迸发   ← 目标 + 取回的材料
```

→ 它要立成**轴**（有序、带戳、可寻址），**不能立成"记忆库"**——库是个箱子，后面每个机制都得返工。

## 4. 取回替代常驻：唯一真正的结构改动

现在 `consciousness` 的 `_context` 是**一直追加**的——那本身就是 append-context，**不变量①当场就破**。

所以最小 agent 的这一步**不是加东西，是替换**：

```
现在：material ＝ 上一次的 _context（常驻、追加）
最小：material ＝ 锚 ＋ 取回的经历 ＋ 当前事件（每次重建）
```

这是最小 agent 里唯一需要动既有代码的地方。

## 6. 生长判据与顺序

> **每个新长出来的东西，只读已有的量，不引入新的底层。**

满足这条才叫"长出来"；不满足就是在搭第二个骨架。

```
1  经历轴（先有量）
2  取回（先立不变量①）
3  睡/醒 ＋ P整理        ← 只读"未整理量"
4  生念 / 回看            ← 只读"未闭合"和"验收距离"
5  眼动（压缩 / 权重）    ← 只读 年龄 / 量 / 后果
6  迸发                  ← 只读 目标 + 取回
```

## 7. 不要先做的两件事

- **睡/醒、迸发**：依赖前面的量。没有"未整理量"就算不出 `P整理`；没有"未闭合"就没有朝向。先做只能空跑。
- **B 支的价值**（`flow-direction` §4）：那是**目的层**，不是结构层；塞进来会让目的冒充结构输入。

## 8. 那个洞的位置

`flow-direction` 未闭合的"**一条新流的方向从哪来**"，在最小 agent 里的对应物就是**经历轴上的"闭合位"**。

所以它**不是靠讨论填的，是靠先有地方放它**——轴立起来之前，那个问题无法被回答。

## 9. 待讨论 / 未定（本文件的主要用途）

1. **经历轴的落盘格式**：一行一条 JSONL 够不够？`闭合位` 用布尔，还是要有更细的状态？
2. **取回的键**：`目标 + 处境` 具体怎么算相似？最小可退化成什么（最近 N 条？关键词？），退化到什么程度就失去意义？
3. **处境怎么表示**：现在只有飞书消息的文本；"处境"要不要归一化（来源 / 事件类型 / 时间）？
4. **目标锚怎么给**：现在 system prompt 只有身份，没有目标。最小要给到什么程度（一句话目标？一个目标列表？）。
5. **验收判据要不要进最小**：进，就要把 `loop.py` 的 acceptance 折回来（一次不小的搬迁）；不进，最小就少了"机械可判的距离"，回看那一层也就没有依据。**这是本文件最需要定的一个口子。**
6. **单槽的边界**：`_context` 换成"锚+取回"后，一次事件处理里的多轮工具调用还算同一个槽，这部分不用改，但**"一次事件"的边界**（= 一次 cut）要定。
7. **后果从哪来**：工具返回 / 报错 / 验收红绿，哪些算后果、哪些只是日志？最小先收哪几种？
8. **落地位置**：改 `agent/`，还是先另起一个目录做纯机制（`handoff-cogos-scaffold.md` 的那个问题）。**仍未定。**
