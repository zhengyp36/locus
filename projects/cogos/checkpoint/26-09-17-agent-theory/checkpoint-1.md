## 一、回路七格逐格拆解

回路 = `议程 → 触发 → 执行 → 验证 → 写回 → 通知 → 停/问`。
纪律视角：每格要同时回答"机制怎么实现"和"人不在时谁来做"（后者 = 安全件 + 自主度分阶的锚）。

### 1. 议程（Agenda）
- **作用**：回答"下一步从哪来"；要可拉取的候选项，而非等人临时开口。
- **现状**：只有人写的 `ISSUES.md` / `tasks/` / `ROADMAP.md`——散文，agent 读不进、不知优先级、不知"什么算做完"。
- **缺口**：**机器可读议程**。每项至少结构化出 `id / 目标 / 验收判据 / 自包含度 / 状态`。
- **最小形态**：把现有 `ISSUES.md` 候选整理成结构化清单（YAML/JSON），"列表 → 取一条"。不新建组件。
- **安全件**：议程是**候选**不是命令——拉到一条也要有"不做/先问"的出口。

### 2. 触发（Trigger）
- **作用**：回答"何时启动/续跑"。
- **现状**：有外部触发——`perception.py`（p2p 消息）、`timer.py`（`timers.json` 恢复 + `timer_fired`）、`events.py`/`app.py`（事件队列 + consumer）。
- **缺口**：**自触发**——无消息、无到点事件时自己从议程拉一条推进、做完续下一条。**这是 L1→L2 门槛**。
- **最小形态**：S2 先由人手动触发跑通后面格子；S3 换"启动时自动拉一条"。
- **安全件**：停止/预算——跑多久、最多几轮、何时收手。

### 3. 执行（Execution）
- **作用**：推进一小步——调模型、调工具、改文件/跑命令。
- **现状**：**已齐**。`lm_service` + `cog_runtime`（cu 多轮/并发/父子通知）+ `tools.py` + `terminal.py` + `consciousness.py`（循环体）。
- **缺口**：无（唯一满的格）。
- **最小形态**：直接复用 `consciousness.on_message`。
- **安全件**：`MAX_TOOL_ROUNDS=10`（`consciousness.py:14`）已有，但它是"单轮对话"上限，不是"一条议程项"上限；后者要在回路层再包一层。

### 4. 验证（Verification）
- **作用**：回答"这一步成没成"。**agent 内自验证，不是人验收**。
- **现状**：**❌ 无**。能力已在（能跑测试/重读/交叉验证），缺**触发 + 通道**。
- **缺口**：定"什么算验证动作"（跑 pytest？重读产物？对照验收判据？）；不通过时怎么办（重做/记不确定/上报）。
- **最小形态**：每推进一小步，用该议程项的"验收判据"自检一次，结果作结构化 observation 回喂（候选 1 有现成测试，天然可验）。
- **安全件**：**"不确定就问"**——给不出确定结论时不许硬编"我成功了"（对治"模型为自洽编造且不自知"）。

### 5. 写回（Write-back / 记忆）
- **作用**：记下结果/状态/教训，让下一轮乃至跨会话知道"进展到哪、剩什么"。
- **现状**：进程内 `_context`（`consciousness.py:50`，重启即失）+ `scratch` + `timers.json`；locus 是 dev 侧外部记忆，非运行时。
- **缺口**：**跨会话持久**；能写回**议程本身**（做完的项标 done，续跑不重做）。
- **最小形态**：先落文件——议程清单的"状态"字段 + 一份运行日志（本轮做了什么、验没验过）。
- **安全件**：幂等/可追溯（记 id + 依据），防重跑污染议程或被"自己写的幻觉"带偏。

### 6. 通知（Notify）
- **作用**：结果外送给人（回路的人机界面那一半）。
- **现状**：`feishu/` + `send_msg` + `_handle_done` 兜底发送（`:95`）。
- **缺口**：现是"每轮对话结尾发一句"，缺**按回路语义**的通知（做完一条发什么 / 卡住发什么 / 只推进一步发不发）。
- **最小形态**：两类事件通知——**已完成该议程项**、**需要人介入**；中间过程不刷屏。
- **安全件**：通知是**上报**不是**求许可**（L2 目标 = 人只事后复核）。

### 7. 停/问（Stop / Ask）
- **作用**：回路的出口与闸门——"何时停、何时必须问人"，所有自主度里最关键的安全件。
- **现状**：仅 `CuResultInterrupted`（超轮打断）+ 错误日志（`:99–106`）。
- **缺口**：**"不做"的判据**——验收判据不清 / 需人裁决方向 / 风险动作 / 试 N 次无进展 → 停 + 问。
- **最小形态**：S2 在"YZ 不在"约束下，把所有"人做了决定"的时刻记成清单；停的条件先写死几条。
- **安全件**：没有可靠的停/问，就不该放开下一格的人工依赖。

### 穿线示例（候选 1：load_bot 分层错位）
议程读结构化清单取候选 1 → 触发（S2 人工"开始"）→ 执行复用 consciousness 改代码 → 验证跑现有测试 → 写回更新议程状态 + 日志 → 通知飞书"已修、测试过" → 停/问无异常收工，涉及公共接口则问 YZ。

**格子状态**：议程/触发/验证 = 红；执行 = 绿；写回/停问 = 黄。

## 二、来源区分（本轮新增的推进）

起点：简化回路没考虑"信息来源区分"。人问：议程读文件 = 内部信息？飞书对话 = 外部信息？

### 结论
- "内/外"二分**太粗**。LLM 眼里只有 context token，飞书消息 / 议程文件 / 系统事件 / 自己上轮输出最终都被渲染成 token，从脑内看同质。
- 分界不是"脑内/脑外"，而是**模型层 vs 机制层**：
  - **模型层**：同质。来源顶多是它**读到的文字标注**（可能忽略、可能编造）。
  - **机制层**：异质。来源是**可执行的结构**——谁可抢断、谁要复核、往哪路由、何时失效。
- 来源不是"位置标签"，是**信封（envelope）**。议程文件 = 人写的、外存内取（作者 external，载体 mem，取用走机制），既非纯内也非飞书那种一次性外源。
- **双写结构**：同一来源信息，模型层编码成**内容**（帮它推理），机制层编码成**结构**（帮系统路由/抢占/校验）。
- 推论：**机制不能依赖模型尊重来源语义**——抢占/优先级/校验须机制**结构性强制**；同时把来源标注作**内容**喂模型，两边都要，各管一头。
- 纪律归位：路由/抢占/校验属"机制"（允许）；替模型决定"这条议程该不该做"属"策略"（禁止）。

### 旧 vs 新（避免重复记录）
- **旧（已存在，不重记）**：来源四标签 `external/self/sys/mem`、来源标注分工、来源标注进对象层 + 心智时间留元层、模型驱动环境哑。
  出处：`locus/projects/cogos/entries/2026-09-02-cogos-agent-cog-arch.md:19,37`；`plan.md` 纪律。
- **新（本轮增量）**：
  1. "脑内" = **agent 内**不是模型内；同质/异质分界 = **模型层 vs 机制层**。
  2. **双写**：模型层=内容、机制层=结构；机制不依赖模型尊重来源语义。
  3. **抢占**是当前回路真没考虑的一格（`consciousness.py:56` 单 `asyncio.Lock` 串行 → 人喊停只能排队，无打断/优先级）。
  4. 落地形态 = 统一**来源信封** `{来源类别, 内容, 担保级别, 版本/时间, 引用}` + 两条规则（抢占权、`self` 产出进"事实"前是否验）。
