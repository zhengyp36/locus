## B. 本会话新增／仍未定

| 项 | 说明 | 为什么要紧 |
|---|---|---|
| **权重构造式** | 怎么合成、怎么衰减归一（含"强度"） | 关键路径：没有它，**升格不工作**，自驱不成立 |
| **`T` 与活跃度的具体公式** | 分工已定：共享"权重"底座；`T` 多带模型的重要/紧急判断，活跃度多带近因 | 不打通，两套词会混用 |
| **升格规则** | 目的槽／方法槽：阈值、取多少、被处理过怎么降权 | 决定"会动"能不能跨到"自驱" |
| **抽样预算** | 每次重演几段、多频繁；加权抽样而非 top-N | 防反刍、防自嗨 |
| **睡／醒 与整理的接线** | `P整理` 何时触发整理（＝重演） | 朝内那半没有触发条件 |
| **感知通道接哪些** | 纪律：**能绑后果才加**（坐标型除外）。候选：世界自己动了／看 | 决定后果的来源面 |
| **验收判据是否折回主体** | 折回就得在主体**新写最弱形**（`loop.py` 是实验台，无现成代码可搬） | 决定"意外"这套能不能算 |
| **一次事件＝一次 cut 的边界** | 一次事件的边界要定 | 决定段怎么切 |
| **落地位置** | 改 `agent/` 还是先另起一个纯机制目录 | #15 起的老问题 |

## C. 裁决记录（#18 已拍）

1. 本会话五处修正**全部追认**：经历树→后压 ／ 切点＝误差 ／ 拓扑后判 ／ 机制可雇 cu ／ 感知坐标型（此条经查 `#17 §1` 本已如此，非例外）。
2. `T/P整理` 与 `活跃度` **分工，不合并**（合并会破"机制不许走价值判断"）。
3. "流"专指**主槽流／后台流**；存储那个统一叫**经历轴**。
