## 一、自驱的语义（本轮收敛）

起点：S3 跑通了，但 YZ 觉得"它本来就该通"——为什么没有成就感？

- **回路机制本身只是 harness**（拉一条 → 调模型 → 跑验收 → 写状态 → 通知），"跑通"是确定能做到的事，**是自动，不是自驱**，边际信息量低。
- **自驱的定义**：驱动力 = **议程的更新函数** `A_{n+1} = f(A_n, 本轮结果)`。静态议程不驱动，**ΔA 才驱动**。
  - f 由人写 → 被驱；f 由环境触发 → 被动响应；f 由 agent 写（写回时自己发现"还缺 X"）→ 自驱。
  - 自主度 = agent 在 f 里的占比。
- **三源外移框架**：回路每格都有一个"源"，终点两类——落**壳**（机制、确定）= 自动；落 **agent**（认知、会错）= 自驱。
  - 现状账：执行（→agent，早已）、触发（→壳，S3）= 已挪；议程/验证判据/记忆仍在人或壳。
  - 已发生的外移终点**全是壳**，所以还是自动。
- **分水岭判据**：议程为空时——停（现 `no_work`）= 自动；自己长出值得做的议题 = L3 自驱。
- **自驱度** = 人被需要的频率 × 深度，随时间下降（S2 那张"人在哪被需要"清单即基线）。
- **无限循环要分清**：转圈（ΔA=0，空转）vs 生长（ΔA≠0）。生成权、终结权、丢弃权同等重要，否则**议程爆炸/自我扩权**。
- **最小自驱 demo**：给一个只有标题、无红测试的 issue，agent **自产判据（红测试）+ 实现 + 自判完成**，且人复核认为判据合理。跑通这个才第一次出现"自"。

## 二、时间分配原则（本轮收敛）

原则：**时间按"信息增量"分配，不按"流程完整性"分配**；每轮只为本轮新增的信息付钱。

| 类型 | 现在花在哪 | 对策 |
|---|---|---|
| 固定（每次启动） | 起 lm-service / feishu / work_dir 隔离 / 环境偶发 | 常驻复用、热环境（候选 1 的时间价值） |
| 边际（每轮） | 全量 pytest ~67s + 模型往返 ~90s | 验收分时机；工具调用批量、少续轮；模型分级用在真思考点 |
| 人的介入（最贵） | 写议程/判据、等候 | agent 自产判据（候选 3）+ 异步续跑（候选 2） |

- **pytest 正解不是"少跑"，是"分时机"**：轮内目标/增量；宣布 done 前全量跑一次当硬门；终局看**红→绿证据**（防空转）。
- **快的真实价值**：让 agent 每单位人的注意力多试几个假设（花在 ΔA），不是多转几圈。
- **"等 YZ"不是延迟问题，是阻塞问题**：把等待做成一等状态（`needs_human` + 通知 + 停放 + 可续跑），慢就无害。候选 2 的意义 = **等待非阻塞**。
- **通知要省**（保住人的低频）：只在真需裁决/高风险时报 → 候选 4 的真实价值。
- **先改明确、同时埋点**：phase 计时（model/acceptance/setup/notify）随改动一起落，作为"时间花在哪"的事实基线。
