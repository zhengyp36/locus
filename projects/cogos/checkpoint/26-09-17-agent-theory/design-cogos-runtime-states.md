## 1. 一句话

agent 的运行 = **两层状态机**（睡/醒 × 子态），由**三类驱动源**推动，而睡/醒的判决由"**未完成张力 vs 睡眠压力**"决定。

## 2. 状态：两层，不是栈

```
睡                      醒
├ 眼动（整理记忆，必做）  ├ 运行（念驱动：思考 + 调工具）
└ 深睡（空白，无活动）    └ 暂停（念与念之间的空隙，无活动）
```

- **唤醒 = 一次完整的状态迁移**，不是"临时起来一下再落回"。被叫醒就是醒了。
- **继续睡 = 一次选择**，不是自动回落。
- **生念是醒的属性**（运行中、或念之间的空隙都可能起念）；睡里没有念。
- **深睡不是必须的，眼动是必须的**：深睡只是"压力≈0 时的睡"。
- "暂停"与"深睡"都是无活动，区别就在此处：暂停属于醒，会被 tick 起念；深睡不会。这也是"睡"唯一的行为学意义——**停止产生新念头 + 把已有经历整理掉**。

## 3. 驱动源：三类（+ 生念）

| 源 | 性质 | 作用 |
|---|---|---|
| 外部事件 | 世界推来、不可预知、**带世界后果** | 打断 / 唤醒（飞书消息等） |
| 预约事件 | agent 自己设的闹钟：**过去的自己递给现在的自己** | 唤醒（睡眠中的张力显式化） |
| 节律 | 内部、周期、可预知 | 撑起时间结构（到点、睡/醒节拍） |
| 生念 | 内部、非周期（tick + 概率） | 无外部输入也进入运行 |

**预约事件为什么不并入"外部事件"**：闹钟的**内容来自过去的自己**，且**不带来世界后果**。若把它算作世界，会直接糊掉"经历必须绑后果"这条线（响应了闹钟却没有后果）。外部的定义应严格是"世界给的、带真后果的"。

## 4. 睡 / 醒 的判决

三个量：

| 量 | 来源 | 作用 | 谁消减 |
|---|---|---|---|
| `P整理` | **经历的量与混乱度**（一天太多、可能乱了） | 驱动睡 | 眼动（归纳/压缩/写偏好） |
| `P节律` | 到点 | 驱动睡（弱、有界） | 时间过 |
| `T` | **对未完成事项"重要 + 紧急"的判断** | 对抗睡 | 做完，**或重判为不重要** |

```
P睡 = P整理 + P节律
T   = 未闭合 × (重要/紧急判断)

醒 —— T > P睡 ——→ 保持醒
   —— T < P睡 ——→ 入睡
```

- **"强制睡"不是一条特例规则**，而是 `P整理` **无上界**的极限：`T` 再大也有限，`P整理` 总会超过它。能对抗，但只到某个时刻为止。
- **入睡落点**：`P整理 > 0` → 眼动（必做）；`P整理 ≈ 0` → 深睡。
- **醒来** = `(整理完成) AND (到点)`；或由 外部事件 / 自设闹钟 直接唤醒。
- **眼动被中断 → `P整理` 没清 → 下一轮睡更早到**（压力只能被实际整理进展消减，不能靠"进入睡眠"清零）。

## 5. 三个量的性质（要点）

- `P整理` 与待办**无关**，纯粹是经历太多/太乱。眼动做的是**整理**（归纳、压缩、给存/取写偏好），不是清 `T`。→ 正好对上 §4 的 `Storage → Reflection → Experience`，也是 §6 里"**自我沉淀**"唯一发生的地方：**眼动是自我长出来的车间**。
- `T` 的乘数"重要/紧急"是**判断**，不是事实。所以：
  - 一条都没做完，`T` 照样能掉到 0（重判了）。
  - 睡/醒的判决根本不是"事做完没有"，而是"**还觉不觉得该醒着**"。
  - 判断那一半是**非中性的、模型给的那半**。对比算子本身中性——正好是 §6.2 的形态（**中性机制调用非中性的内容**），不违反 §2②（机制不能"想要"：这里的"想要"在 `T` 里，不在规则里）。
- "紧急"带时间维度（越近 deadline 越急），可能是 `T` 中唯一会随时间**自己涨**的分量。

## 6. 生念的硬约束

tick **只给机会**，内容必须来自**取回的经历 + 目标/张力**。所以生念不能写成 `random() < p`——那等于机制在"想要"，直接回到 §2② 被证伪的提线。正确形态：

```
到点 → 用 (目标 + 当下处境) 取回经历 → 模型决定要不要起念
专注度高 = 降低取回/起念权重；未完成事项张力 = 目标锚 + 未闭合的后果
```

**张力在两种状态下有两种表达**（同一来源：未闭合的后果）：
```
醒（暂停）→ 生念 tick
睡         → 自设闹钟（预约事件）
```

## 7. 与现有代码的差距

**已有**（`cogos-s2/cogos/agent/`）：
- `event_queue`：外部事件 + `timer_fired`（`app.py:72`）
- `perception`：飞书，且**只认 p2p**（`perception.py:17`）
- `timer`：**一次性**闹钟（`timer.py`）
- `consciousness`：**无状态**，来什么都直接跑（`app.py:147` 对每个事件都 `on_message`）

**缺**：
状态变量（睡/醒/子态）、节律源、生念 tick 源、运行→暂停的收敛、事件入队/打断策略、出生标记、`P整理`/`P节律`/`T` 三个量、眼动、经历 store、后果的**闭合位**。

→ 现在**既没有暂停态，也没有睡**：每个事件都直接进运行。

## 8. 落地顺序（修正 `handoff-cogos-scaffold.md` §7.5）

原来说"时间最先"，现修正为——`P整理 = f(未整理经历量)`，**没有 store 就算不出压力**，睡眠触发不了：

```
经历落盘 + 时间戳 + 整理水位        ← 最小 store（含"整理到哪"）
        ↓
整理压力 → 入睡/醒来
        ↓
状态机（睡/醒 + 可打断的运行）
        ↓
生念节律（醒时）
        ↓
眼动产出 → 存/取偏好（慢变量）
```
