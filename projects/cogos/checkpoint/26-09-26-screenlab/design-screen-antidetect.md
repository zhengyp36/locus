# design｜"像真人、不被检测" 分析稿（2026-09-25 与 YZ 讨论）

> **性质**：方案/判据层工作稿（非目标）。目标唯一约束 = `spec-screen-1.md` §0.0。
> **定位**：坐实 §0.0 "仍未闭合"里的 **反检测强度** 一条；横跨 Goal 1（Xvfb）与 Goal 2/3a（attach），不属单一线。
> **状态**：方向已与 YZ 讨论确定（2026-09-25）；未回写权威分册（分册只在定案后更新）。
> **一句话**：图形路线只买下"自动化协议层"这一层；在**同一台机**上 Xvfb 与 attach 的检测面几乎塌缩为同一份，剩余欠账只有**注入输入缺人类特征**这一簇。

## 0. 问题来源

- §0.0 把 **"像真人、不被检测"定为图形路线成立的前提**（动机：文本/无头 HTTP 易被反自动化拦），并把它列为 **"仍未闭合"**：对谁隐蔽（普通站点 / 风控 / 定向检测）、隐蔽到什么程度。
- 本条不定，则"是否必须用真 GPU / 真显示器"无从判断 → 本稿把问题拆细并给出可判据的收敛形式。

## 1. 收敛：近期场景 = 浏览器上网

- 目前真正会扣分的场景是 **浏览器访问网站**（Cloudflare / Akamai / DataDome 这类）。
- 相邻但不占主流：带遥测/反作弊的原生桌面应用（较少）；**移动端另算**（Accessibility Service 本身可枚举、Play Integrity 是另一套，图形路线在移动端**不**解决检测——别把桌面 web 的结论平移）。

## 2. 拆层：检测是什么，谁负责

| 层 | 检测什么 | 图形路线（XTEST + 真浏览器）能否解决 |
|---|---|---|
| 1 自动化协议 | `navigator.webdriver`、CDP/Selenium/Playwright 痕迹、headless 标记 | ✅ **核心杀招**：不碰 CDP，事件 `isTrusted=true`，真浏览器 |
| 2 环境指纹 | webgl/canvas/audio、GPU、字体、locale、屏参、显示器/音频设备 | ⚠️/✅ **取决于配置**（见 §4），与"是否用 XTEST"无关 |
| 3 传输指纹 | IP/ASN、JA3/JA4、HTTP2、TCP | ❌ 与输入方式正交；**机器决定** |
| 4 行为与账号 | 指针轨迹、事件时序、按键节奏、账号/IP 关联、设备复用 | ❌ 只有"输入像不像人"这一小块归我们，大头是账号与出口 |

**结论**：图形路线只保证第 1 层；其余层是环境/身份/运营的事，需显式分离，不算本工具欠账。

## 3. 三条路对比（关键结论）

| 层 | 真人用 VBox 上网 | 3a attach（驱动真人 :0） | Goal 1 Xvfb（同机 headless） |
|---|---|---|---|
| 1 协议 | 真浏览器 | ✅ 一致（XTEST，`isTrusted`） | ✅ 一致 |
| 2 环境 | llvmpipe / VM / 真显示器 / profile | ✅ 同一个 box，天然对齐 | ⚠️ 同机时经配置可对齐（见 §4）；异机则分叉 |
| 3 传输 | 家宽出口 | ✅ 同 guest 同 IP | ✅ **同机时同 guest 同 IP** |
| 4 行为 | 人类轨迹/时序、真人账号 | ❌ 合成输入（唯一差异） | ❌ 合成输入（同一份差异） |

- **同机情形**：IP/ASN/TZ/locale/硬件/字体/音频/codecs 全部系统级共享；`human` 与 agent 账户**都是空 profile**，新鲜度对等；VBox 是 VM 这点对两边也相等。→ 这些层**无差别**。
- **塌缩结论**：**同一台机上，对"上网"检测而言 Xvfb ≈ attach**；真正的基准是"真人自己浏览"，系统性 delta 只剩**注入输入缺人类特征**一簇，且为两条路共享。
- **异机情形**（Xvfb 跑在数据中心/独立服务器）：第 3 层（datacenter ASN）与第 2 层（无显示器、新 profile、TZ 错位）分叉 → 那才是"服务器伪装桌面"的典型高风险画像。此时**图形路线不足以弥补，需另配干净出口 + 预热 profile**。

## 4. 环境 parity 的前提（配置项，均可消除）

Xvfb 相对 `:0` **可能新增**的破绽，都属配置、非形态：

- **GL/GPU 暴露**：`:0` 是 VBox llvmpipe；Xvfb **若没开 GLX / Chrome 带 `--disable-gpu` / `--headless` → `webgl=null`**，这才是经典 headless 破绽（比指针跳变更致命，属"身份级"）。开同样 GLX/swrast 后即 parity。
  - 注意：`webgl renderer=llvmpipe` **本身不是破绽**——真人 VBox 不开 3D 也是 llvmpipe（§0.0 已纠正）。
- **WM**：无 WM 时 `act` 不可靠且渲染异常 → 起 openbox（Goal 1 形态已含）。
- **启动参数**：不带 headless / automation flag；保真 chrome。
- **屏参/显示器**：屏参差异是弱信号（站点无法跨桌面核对；常见分辨率反而不反常）。

## 5. 判据（可测）

- **判据 = parity，不是绝对真**：与**同一环境里的真用户不可区分**即达标；不追求"消除 VM 痕迹"（真人 VBox 本来就有）。
- **测试方法（合"地面真值"纪律）**：在真人那台 XFCE/VBox 上，用同一浏览器，比较 **真人操作 vs agent 驱动** 对站点可见的指纹与事件流差异；差异为空即达标。

## 6. 剩余欠账：输入行为簇（唯一系统性差异）

`act` 目前是**瞬移落点**。浏览器 JS 可测、而真人不可测的特征包括：

- 指针轨迹（弧线 / 变速 / 过冲修正）
- 事件时序（间隔、停顿节奏）
- 按键时长与键间节奏
- 悬停 / 静止时的微动

指针跳变只是最显眼的症状。**补法**：把注入做成有人类特征的输入（样条 + 变速移动、按键 hold、人味延迟）。按 §0.0，这是本工具**该提供的"能力"**，选择权留给 agent（不由工具规定"必须像人"）。

**边界澄清**：在 attach 与 Xvfb 之间，输入行为欠账是**同一份**，与"用不用图形界面"无关。

## 7. 战略含义

- **Xvfb vs attach 的选择依据 = 可用性 / 规模 / consent，不是反检测**（同机场景下两者检测面几乎等价）。
- attach 的价值：寄生真人真实环境与身份（账号是真的、有真人在场），但需真人在场、不可规模化。
- Xvfb 的价值：常驻、可规模化，但**异机部署时**需要一整套身份栈（住宅出口 + 预热 profile + TZ 对齐）才谈得上隐蔽。
- **近期投入优先级**：第 1 层（已具备，靠图形路线）→ 环境 parity（配置核对，可测）→ 输入人类化（工具能力，唯一真欠账）。**不追**第 3/4 层的对抗。

## 8. 待 YZ 裁（仍开）

- **威胁模型**：对谁隐蔽（普通站点 / 风控 / 定向检测）、隐蔽到什么程度——决定第 2/4 层是否值得继续投入。**倾向**：近期只对"普通站点 + 通用风控"负责，做法 = 第 1 层 + 环境 parity，不追第 3/4 层对抗。
