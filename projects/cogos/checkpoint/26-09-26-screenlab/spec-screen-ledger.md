## 1. `[目标]` 本步用到的条文（引自 §5.1，编号一致）

1. 每 agent 有若干账户（归属单位），可 ssh 使用。
2. 账户有一块**可操作的图形界面**，发动作能读回结果（闭环）。
4. 默认**不抢物理屏**；需要时人能看到、能介入。
5. 三种关系：自用 / 授权他 agent（显式可收回）/ 与人双向。
6. 一账户同一时刻一块界面；"要"是**幂等**的。
7. agent **只面对客户端**，不面对平台细节。

## 2. `[目标]` → 推导链（每条挂账）

- **L1** "一账户同一时刻一块界面" ⇒ 账本的**边界就是"一台电脑 / 一个账户"**；**不需要中心**。← 目标 6
- **L2** 服务跑在这个账户下 ⇒ **本账户连入即 `owned`**（装配事实，不协商）；非本账户连入一律走凭证。← 目标 1 + 5
- **L3** "授权显式、可收回" ⇒ 授权 = **在目标服务的账本上登记一张凭证**；授权方可能是人（在人的机上）或 agent（在它自己的机上）。← 目标 5
- **L4** 收回要"随时可收回" ⇒ 吊销必须**本地立即生效**，并**连带断掉由该凭证派生的通道**。← 目标 5
- **L5** 授权是**临时**的 ⇒ 账本状态**放内存**，重启即失效（安全默认）。← 目标 5
- **L6** "任一时刻至多一个有效操作者" ⇒ 账本维护**输入持有者唯一**这一不变量。← 目标 5
- **L7** 幂等 ⇒ 界面存在性由**一把锁**保护：并发"要"只开一次。← 目标 6
- **L8** 账本不关心**传输**（只接受"一条已建立、已认证的流"）。← §5.2·E；目标 7

## 3. `[方案]` 三张表

| 表 | 键 → 值 | 挂账 |
|---|---|---|
| **界面表** | 账户 → `{是否已开, 尺寸, 世代, 输入持有者?}` | L1/L2/L6/L7 |
| **凭证表** | 凭证串 → `{位, 作用域, 有效期?, 一次性?, 状态}` | L3/L4/L5 |
| **通道表** | 通道 → `{凭证, 位, 接入方标识, 存活}` | L3/L4/L6 |

- **位**只有两位：`看` / `操作`（与 `spec-screen-client-api.md` §3 一致）。
- **作用域**起步 = 账户级（"整台电脑"）；更细（会话 / 窗口）不是本步，见 §8。

## 4. `[方案]` 状态与判定

### 4.1 凭证状态（三种"不可用"是同一件事）

```
状态 ∈ { 未兑换 fresh, 已兑换 redeemed, 已吊销 revoked, 已过期 expired }
```

- **判定点唯一**：`可用(凭证) = (状态 == fresh) 且 (未过期)`。
- **一次性**、**有效期**、**可吊销** ⇒ 只是**三种转态方式**，同一个终点；所以只需一条记录，不需要两种凭证类型。
- **有效期同时界定通道寿命**：到点即不能再兑换，**并断掉其派生通道**。不做"凭证一个 TTL、通道另一个 TTL"。
- **一次性在"兑换通道时"转态**（不是每次操作）：兑换一次后不能再兑换，**已建立的通道继续存活**；要重连就重新申请一张。
- 任何使凭证不可用的转态，**一律连带断掉派生通道**（L4）——这是"立刻踢掉接入者"的落点。

### 4.2 通道

- 一条通道 = 一次接入；**一个账户可同时有多条通道**（owner / 被授权 agent / 观察者），每条带自己的位。
- `owned` 通道（本账户连入）由装配事实给出，不需要凭证。
- 只读通道（`位 = 看`）**永远不成为输入持有者**，与 L6 天然相容。

### 4.3 界面与世代

- `open`：查界面表；未开则加锁开，已开则直接返回现状 —— **幂等**（L7）。
- **世代**由服务端维护（单调号 / 帧哈希），`capture` 返回它，`act` 必须带上它（`spec-screen-client-api.md` §2·D11）；世代不符即拒。
- **输入持有者**：写入界面表；`act` 前校验（位 + 是否持有输入权）。被拒时不改状态，只返回失败。

### 4.4 不变量（账本必须一直成立）

1. **至多一个输入持有者**（同一账户）。
2. **任何通道的位 ⊆ 其凭证的位**。
3. **不可用凭证不得再兑换通道**；已断通道不得再收 `act` / `capture`。

## 5. `[方案]` 明确不做

- **无中心**：没有全局视图 / 全局账户表。← L1
- **不跨重启持久化**：凭证表内存。← L5
- **无心跳 / 协商 / 优先级抢夺**（协调在语言层）。← §5.2·C
- **不管传输**：不认网络、不认 NAT。← L8
- **不做多账户共享服务**。← L1
- **不做授权粒度细分**（会话 / 窗口级）。← §8

## 6. 判据自检：四场景能否只用三张表 + 一把锁表达

| 关系 | 账本上的动作 |
|---|---|
| ① 自用 | 界面表加锁开户；通道 = `owned`（无凭证） |
| ② 授权他 agent | 写一条凭证（位 / 有效期 / 一次性）→ 对方兑换出通道 → 吊销 = 转态 + 断通道 |
| ③b 人看 agent 机 | 同上，凭证位 = `看`；该通道**不进**输入持有者 |
| ③a agent 接入人的机 | 在**那台机**的账本上登记凭证（同机制，只是授权方是人） |

结论：四场景只用三张表 + 一把锁，且"吊销立即生效""`open` 幂等"都能自证。

## 7. 事后对照已有素材（仅核对，**不作前提**）

- 已有 `authority ∈ {owned, granted}`（机器级、装配注入）↔ 本稿 L2 + `owned` 通道。**一致**。
- 已有 `grant = {capture, input}`（运行时两位）↔ 本稿凭证/通道的"位"。**一致**（本稿把它落到账本：位挂在凭证与通道上）。
- 已有"单操作者"不变量 ↔ L6。**一致**。
- **差异**：已有把认证与装配划在协议外（`§1.4`），本稿把它落成**凭证表 + 通道表**——即"划在协议外"并不等于"没有机制"，而是**机制在服务端账本里**。属补充，非冲突。

## 8. 遗留（不影响开工）

1. **授权粒度**：起步账户级；"某会话 / 某窗口"级留待有需求时补（目标 §0.0 曾把这条列为未闭合）。
2. **`owned` 与真人的关系**：真人在自己机上的"物理输入优先"依赖平台侧事件（真机实现），账本只需**可被外部置空 / 交还输入持有者**。
3. **世代的具体生成方式**（单调号 vs 帧哈希）留到落码时按候选实现定。
