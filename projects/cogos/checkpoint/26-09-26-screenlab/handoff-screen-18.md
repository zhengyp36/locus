## 二、必须先"一起"定的分叉（互相牵动，单独定没意义）

1. **界面的形态**：全桌面（mutter / gnome-shell headless）↔ 最小 X（`Xvfb + openbox + chrome`，原型那条）↔ 别的？

2. **反检测落在哪一层**：落在**机器形态**（真 GPU / 真显示器 / 真机）还是**软件痕迹**（浏览器 flag / profile 一致性 / 输入时序 / humanization）？
   - 牵动：要不要换机、机器长什么样 → 直接决定第 1 条选哪种形态。
   - 已知当前形态**必然不合格**：`webgl=null`（无 3D）、surfaceless 渲染、虚拟显示器 —— 都是指纹。
3. **操作权怎么实现**：token / grant 放**协议层**还是**语言层**？`grant = {capture, input}` 两个位够不够？**收回**怎么落地（真人输入事件 = 立即抢占？）
   - 牵动：关系②③ 全部，以及 `screen/1` 要不要加动词 / 字段。
4. **共屏怎么实现**：**物理同屏**（同 seat / 切 VT）↔ **投流给人**（把 agent 桌面推过去）↔ 人在 agent 机上开 viewer？
   - 牵动：关系③b、"不抢屏"的边界、与"单操作者"的交互。
5. **装配与寻址**：空账户 → 可用图形界面（装机脚本 / 镜像 / 模板）；client 怎么找到"某账户的界面"（账户名约定？注册表？）。
6. **三者联立**：**谁点亮屏、谁拿输入、谁只读** —— "不抢屏 / 单操作者 / 共屏"必须放在一起定。

# 第五轮定稿：目标重导方案（2026-09-22）

## 五、双栏结构与纪律

### 5.0 读法与记录纪律（**开发时同样遵守**）

> 污染的形状：上下文里的方案 / 结论以**事实口吻**存着，读时会被自动升格成约束。
> 本轮已实际偏三次（`Xvfb` 起步 / 共屏 = 热订阅 / "界面形态"作为待选项）——**三次都不是从目标推出来的，都是从上下文抄来的**。

1. **双栏**：每条陈述标 `[目标]` 或 `[方案]`；**只有 `[目标]` 有否决权**。
2. **目标段禁实现名词**（后端 / 协议 / 工具 / 服务 / 具体程序名），出现即降格为方案。
3. **方案段必须挂账**："满足目标哪一条 + 代价 / 缺口"；写不出 = 走偏。
4. **方案不继承，只重导**：旧方案降为 `[候选实现]`，不进推导前提。
5. **反证句自检**：凡说"因为已验 / 已定案 / 以前这么做"→ 暂停；正确句式是"目标要求 X，候选 Y 满足 X"。
6. **作废即删名**：判定不属于目标的词列入作废名单，后续禁止借用。

### 5.1 `[目标]`（唯一约束 · 纯净版）

1. 每个 agent 有若干电脑账户（账户是归属单位，非物理机），可 ssh 使用。
2. 账户除文本外还有一块**可操作的图形界面**，发动作能读回结果（闭环）。
3. 操作要像真人、不被检测；**可逐步实现**，方向必须能加固。
4. 默认**不抢物理屏**；需要时人能看到、能介入。
5. 三种关系：agent 自用 / 授权另一 agent（显式、可收回）/ 人与 agent 双向。
6. **一个账户同一时刻只有一块界面，"要"是幂等的。**
7. agent 只面对客户端，不面对平台细节。

### 5.2 `[方案·可换]` 由目标逼出的分解（每条带挂账）

- **A. 界面 = 账户的一个可开启能力，按"开一个程序"模型** ← 目标 6/7。落地为「账户 → 界面句柄」映射 + 首次懒启动。
- **B. 三根独立通路：跑东西 / 出画面 / 收操作**
  - 输出独立 ← 目标 4（"不抢屏"= 输出不必接物理屏；"能被看见"= 输出可分离、可多路取走）
  - 输入独立 + **权限与身份分离** ← 目标 5（"可收回"要求服务端随时可判决权限，故权限 ≠ 登录身份）
  - 计算独立 ← 目标 2；状态延续由**账户级磁盘 profile** 承担，与通路无关
- **C. 长期身份 ≠ 接入凭证** ← 目标 5。谁的机器谁持长期身份；**外来主体一律临时凭证**（限作用域、可过期、可立即收回）。
- **D. 界面是资源，操作权是租约** ← 目标 6 + 5。授权 = 带位租约；收回 = 服务端撤销。
- **E. 传输不入方案** ← 纪律（防耦合，2026-09-22 YZ）。方案只假定"**有一条能通的字节流**"；网络（同机 / 局域网 / 隧道 / tailscale / NAT）由外部提供，**不进目标也不进方案**。
- **F. 主人侧 = 服务 + 长期身份；客侧 = 客户端 + 临时凭证** ← 目标 1/5a。谁拥有那台机谁装服务、持长期身份；接入方只用客户端 + 临时凭证。装配可能由 agent 代劳（如经 ssh）⇒ **装配须可远程、无交互**。与 E 一致：服务在目标机 ⇒ 吊销本地立即生效。

### 5.3 六条分叉的答案

1. **形态**：不选"全桌面 vs 最小"。目标 3+4 逼出的是「**有真实渲染能力、且输出可分离**的图形会话」；具体实现是候选，不是约束。
2. **反检**：分档——起步"适当"、底线**"不留硬指纹"**，加固主项 = 渲染落真 GPU。只定"能往上走"，不定形态。
3. **操作权**：服务端按凭证判权；租约 + 可撤；授权两位（看 / 操作）；收回 = 服务端立即撤销（人一动手即夺回输入）。**补（2026-09-22 YZ）：协调在语言层，机制只保下限** —— 凭证 = 有效期（授权方设）+ 可吊销 + 目标机本地判决（服务在目标机 ⇒ 吊销立即断掉接入者）；**不做**心跳 / 协商 / 状态机 / 抢占协议。第一版凭证就是一串字符，在对话里递。
4. **共屏**：**两件不同的事** —— ① 观察口（只读，喂给要看的主体）；② 临时接入（外来主体带临时凭证进来）。都由 B 支撑，均**不需重开会话**。
5. **寻址**：两套 —— 账户 → 界面（自用）；端点 + 临时凭证（接入）。
6. **联立**：**屏可多人看，输入同一时刻一人，权按凭证判。**

### 5.4 `[候选实现]` 素材降格（可用可换，不作前提）

- **图形会话**：已验证那套（headless 合成器 + Xwayland + XTEST 注入 + portal 取帧）=「B 的现成实现之一」，起步用它；其 X11/Wayland 指纹记入加固清单。
- **协议动词集**：是"三通路 + 权限"的一种编码，**服从 5.2，非相反**。
- **原型 `cogos/screenlab/`**：候选实现 + 已验 / 未验标注。
- **加固清单**：`webgl=null`、surfaceless 等。

## 七、第 3 步结果（本机验证）· 2026-09-22

### 7.1 落点与形态

- 本机两个测试账户：`agent1`（uid 1003）、`agent2`（uid 1004，作为"客"）。账户由 `checkpoint/setup-test-account.sh` 建。

### 7.3 验证证据

- **自用闭环**：`open`（连续两次 → 幂等）→ `state` → `capture`（1920×1080）→ `act pointer`（归一化 0.25,0.35 → 像素 480,378）→ `act type` → `state`。全过。
- **凭证语义 e2e（13/13 PASS）**：只读凭证可看不可动（`no_input_bit`）；读写凭证可动；单操作者（`input_taken`）；**owner 抢占**；`revoke` → `credential_revoked`；一次性 → 第二次 `credential_redeemed` 且**已建通道仍活**；`ttl` → `credential_expired`；客侧不能 `grant`（`not_owner`）。
- **跨账户**：agent2 经 **ssh streamlocal 隧道**（`ssh -L 9911:/run/user/1003/screenlab.sock`）+ **临时凭证**接到 agent1 的屏（不经账户密码）；agent1 在它连着时 `revoke` → `killed_channels` 命中该通道 → 客侧下一次调用 `no_channel`。即目标关系②。
- **装配可远程无交互**：agent2 → `ssh agent1` 跑 `session-start.sh`，会话与服务自起。

### 7.4 过程中发现并修掉的问题

1. **Pillow 的 `ImageGrab` 在 Xwayland root 上 `X get_image failed`** → 换 `gst ximagesrc`（`gst-launch-1.0 ximagesrc ! pngenc`），写成可探测的 capture 后端。
2. **由 root 启动会话时没带 `HOME / XDG_RUNTIME_DIR / USER`** → gnome-shell 用 root 的 home → **X server 假死**（能连上但永不回应）。装配脚本补齐 env 后正常。**这是本轮最大的坑。**
3. **`set -e` + `pipefail` 下 `ls` 缺 auth 文件会直接退出**（rc=2）→ 加 `|| true`，并把"等 auth 文件"改成"等 display 应答"。
4. **`xdotool` 在假死 display 上无限阻塞**（`timeout` 都不易杀掉）→ 探活一律 `timeout -s KILL 3`。
5. **停会话后遗留 stale X socket / auth 文件**会毒害下一次启动 → `session-stop --session` 一并清理；`session-start --restart` 先停后起。
