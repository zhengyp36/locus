> **从目标（`spec-screen-1.md` §0.0）推导，usage-first。** 本稿取代 #63 中间那版"机制/本体汇总"（不另记，避免冗余）。
> 工具机制与已定 1–16 见 `design-vision-scripting.md`；平台实验见 `screen-change-detect.md`；规则见 `screenlab-rules.md`。
> 定位：先把"agent 如何看屏并操作"用到的那点东西定下来；机制（几何 / 帧 / 传输 / 平台）全部内化。

## 0. 从目标出发

§0.0：agent 拥有**一台自己用的电脑**（账户级）；**图形面是与 `term`/`fs` 并列的一项能力**；要有**"能操作 + 有反馈"的闭环**。并明确：**服务端只做 mechanical，唯一智能主体在 agent 侧，图不转文字**。

→ 直接导出：**工具面只暴露"模型用得上的动作 + 反馈"；机制全部内化。** 这与 usage-first 是同一件事，不是两套说法。

## 1. 第一原则（教训）

#61 的坐标打偏，本质不是"坐标算错"，而是**模型"看到的那张图"与 act 作用的坐标系没有绑定**。

> **工具必须保证：模型作用在它看到的那张图上。**（闭环反馈也要求 act 回那张图。）

这条统领整个模型面接口。

## 2. 模型的真实循环

以"打开设置 → 关掉无障碍"为例：

看屏 →（在图上）认目标 → 在图上指个位置 → 点 → 再看 → 确认。
中途：点不准 → 放大那块 → 再点；跨几步要重新定位（v1 靠再看一次；跨帧 mark 复用后置）。

## 3. 模型面接口（由能力边界导出）

模型**可靠**：认内容、在图上大致指位置、比两张图、跟指令走。
模型**不可靠**：精确坐标、坐标换算、长程记 id、判断屏幕在不在过渡中。

→ 模型面只要：

- `look` → 一张能看的图（附件）；内部设"当前视图"。
- `zoom(区域)` → 在所示图上放大某块 → 新图（点不准时用）。
- `act(位置)` → 作用在**"模型刚看到的那张图"**上；回**整屏 + 落点标记**（一次往返同时完成"点"与"确认"）。
- `mark(区域)` → 在所示图上叠加标记、回同图；**可选**，只在"动手前怕点错、想先看一眼"时用。
- **settle 不暴露**：act 内部先**短时**（数百 ms ~ 1s）试稳；稳了无感直接点；稳不住 → 回报"仍不稳"，让模型选 再等 / 冒险 / 放弃。**不单设 wait 动词**（模型自身慢，再 `look` 一次自然覆盖加载）。

## 4. 内化（对模型不可见）

**图 id（内容）/ 帧 id（观测）——都在传输层，模型看不到**；revision、pull / 采样 / 传输、判稳默认行为、平台差异。

## 5. 内部模型（实现用；跨帧定位）

- **内容**：**图 id**（内容寻址、去重，一张图一个）；**帧 id**（一次观测 =（图, 时间），**与图 id 不同**）。两者都只服务传输 / 缓存。
- **定位**（统一帧坐标空间）：**窗口**（viewport）、**mark**（位置标注）。
  - v1：mark 只作**即时视觉自查 / act 落点确认**，临时、不跨步 → 不背"跨帧 mark 有效性"。
  - 待将来要"跨步复用位置"时，再启用跨帧语义与有效性判据。
- **settle**（事实层 revision + 脏区）：目标区域静默 T → 管**能不能动**。
- **act**：定格当前视图对应的帧、在该帧作用、返回**整屏 + 落点标记**。
- **传输返回**：capture 图恒为**整屏**；服务端每图一个图 id，已推过 → 只回 id 不重推，客户端可再要图；`zoom` 的放大图是 **render 派生裁图**（已定 10），走同一套 id / 去重。**模型不感知这些。**

## 6. 平台差异隔离（结合 62a/b/c）

- 差异只有两处：**怎么抓原始像素**、**怎么拿变化**（Android 无原生脏区 → 自算分块 diff）。
- **seam = 一层后端**：`capture_raw` + `change_hint`(可选) + `bind`。上层只认 `(revision, dirty, raw_frame)` **语义**；原生 damage 只是快路径。
- **平台顺序（2026-09-26 锁）**：**视觉 / 坐标闭环先 X11**（迭代快、无物理同意、可无人值守）；**Android 第二**（逼通用兜底 + 修 #61 坐标链）；Windows 第三。设计上"最难先做"仍只适用于**传输 / 兜底**那条线。
- **三平台共用同一验收判据**（capture 对地面真值 / settle / mark-coord-act 往返）。
- **风险**：别让"原生脏区一定精确"假设漏到上层。

## 7. 与已定 13/15/16 的关系

- 承接：capture 整屏原生（13）、看/动坐标闭合、脏区只作信号不做像素重建、机制不做语义判断（16）。
- **精化 15**：把"推变化事件"降为**"事实层可查"**（供判稳），不再需要真的推。

## 8. 后置封存

环形缓冲（变化自带脏区像素）· push 实时画面 · 两级 / 自适应 / 注意力采样 · 观测时间对齐 · **动作不全**（tap 之外：drag / 滑动、type、key / 导航）· 跨帧 mark 复用。

## 9. 开工顺序

> 具体工作单与当前进度见 `screenlab-work.md`（任务态落文件）。

1. **一个平台上把"看 / 指 / 放大 / 点 / 确认"做成模型可用的最小闭环**——先能用，不是先搭机制。
2. 融合适配：computer tool 包 `cogos/image_ctx`（模型面只此一个入口）。
3. 平台增量：X11 / Windows 换后端。

## 10. 第一刀（开工实施 · 待 YZ 讨论）

**范围**：Android 上打通"模型看图 → 指位置 → 落点正确"，地面真值验收。

- 先探 `cogos/image_ctx` 实际 API（`see/mark/coord`、`Domain` save/load）——唯一未知，属探索。
- `../checkpoint/tools/` 建薄 CLI 适配（import `image_ctx`）：`look`（现成 `ScreenClient.capture` → **内容寻址落盘** → image_ctx 渲染 → 出 PNG 路径）/ `zoom` / `mark` / `coord` / `act`（coord → 设备坐标 → `ScreenClient.act`；回整屏 + 落点标记）。
- 验收（不用自写 e2e，用地面真值）：kilo 以 agent 身份用 CLI 定位已知元素 → tap → `adb screencap` 差分 / app log（`inject tap x,y -> true`）核对。
- **不依赖**传输改造（`daemon.py:296` 等）；第一刀用现成 app 侧 capture/act。

**明确不做**：settle / change_hint、传输改造、非 tap 动作、push / 采样、X11 / Windows、接进真正的 `computer` 工具（v2）。
