# checkpoint-7 — 上网访问的三种方式 + 真实身份访问（终极后置）

## 当前问题

上网能力（WebTool）的访问方式收口为三种，按「身份层级」递进；明确「真实身份访问」为终极形态但后置。

## 三种访问方式（身份层级递进，非技术替换）

1. **直抓 HTTP**（自己共享 IP）：无身份，最低端，会被拉黑。→ 兜底。
2. **匿名抓取接口**（Jina/Brave 等）：借服务商高信誉身份，覆盖「网络身份(IP) + 客户端身份(指纹)」，但**无账号身份**（无 cookie/登录态/实名），只适用公开无需登录 URL。→ 阶段 1 主力。
3. **真实身份访问**（agent 自己的账号/cookie/登录态 + 本地浏览器）：带账号信誉层，覆盖全部四层信号，看到和真人一样的网络世界。→ 终极，后置。

## 关键结论（YZ）

- 接口层 = 「匿名高信誉抓取」，卖的是信誉不是身份；隔的一层恰恰是「身份」本身。
- agent 要以独立个体身份访问（登录/个性化/订阅/互动），必须绕过第三方、以真实身份 + 本地浏览器操作。
- 真正融入世界的 agent 需要第三种访问——看到真人看到的网络世界（登录后内容/个性化）。
- 即浏览器 DOM 自动化 / 视觉上网(GUI agent)那条路，后续考虑。

## 与信号四层的关系（checkpoint-5）

| 信号层 | 直抓 | 接口层 | 真实身份 |
|---|---|---|---|
| 网络身份 IP | 共享✗ | 服务商✓ | 自己✓ |
| 客户端身份 | curl✗ | 无头浏览器✓ | 本地浏览器✓ |
| 行为信号 | ✗ | 规整~ | 真人✓ |
| 账号信誉 | ✗ | ✗ | ✓ |

## Jina Reader 政策核实（08-27）

- 免费：无 key 20 RPM（按 IP）；免费 key 含 1000 万 token、Reader 500 RPM / Search 100 RPM；Reader 按输出 token 计费，Search 每请求 ~1 万 token 起；5 分钟服务端缓存。
- **关键修正**：Jina 官方明确「不主动绕过反爬，被拦就尊重」。它的价值 = 免自己维护无头浏览器 + HTML→Markdown + SPA/PDF/图片 caption，**不是**「高信誉身份过反爬」。遇到拉黑 Jina 出口 IP 的站点照样失败。
- 对接口层的定性修正：接口层分两类——**官方数据/搜索 API**（Brave，本身是数据源，无拉黑问题）vs **抓取即服务**（Jina，只外包渲染清洗，不解决拉黑）。此前把两者混为「借服务商高信誉身份」不准确。
- kilo 接入：可作 `proxy-fetch` 增强后端（`r.jina.ai/<url>`），解决 SPA/PDF 抓取，不作拉黑解药。
- 计费（有 key 档）：按输出 token 计费 ~$0.02/M（社区报 $0.02~0.05，以 dashboard 为准）；新 key 10M 免费 token；单页 2k~5k token ≈ $0.0001 内；10M 免费 ≈ 2000~5000 页，kilo 低频用可撑数月。坑：ReaderLM-v2 3x token、Search 每请求 ~1 万 token、5 分钟缓存命中不重复计费。
