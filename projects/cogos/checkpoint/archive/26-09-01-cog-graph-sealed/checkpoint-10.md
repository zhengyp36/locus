# Checkpoint 10 — 接口设计方法论 + 信息维度 + 情绪还原

> 日期：2026-08-31。状态：讨论中，未写代码。本段在「场景 → 接口设计」之间插入两轮方法论澄清：场景是验收非生成；补上「信息维度」切面（存什么 vs 怎么用）；顺势把「情绪」还原为更基本维度（张力 + 评价），落到「先不预装、后置观察」。

## 一、接口设计方法论：场景是验收，不是生成

### 1. 接口不为场景定制

- 错读法：场景 → 归纳接口，退化成应用级接口（findFriends/shortestPath），多一个场景多一个接口。
- 对读法：接口是独立假设，场景是检验假设的用例；接口根据是「图的本质」（原语性质），不是场景。
- 图论类比：图的 primitive（加节点/加边/查邻接/遍历）从「图是什么」长，不从应用长；应用只验证 primitive 够不够。

### 2. 两股力量各管一半

- 接口由原语性质 **bottom-up** 长（正确性）；场景 **top-down** 验收（充分性 + 不过度）。
- 完全脱离场景 → 过度设计；场景留作「刹车」，告诉你最小集在哪、哪里多余。

## 二、信息维度 vs 使用场景（存什么 vs 怎么用）

### 3. 缺的另一半切面

- 使用场景回答「怎么用」（操作形态）；信息维度回答「存什么」（可被关系表达的面向）。之前只从场景切，漏了信息维度。
- 信息维度是「关系类型最小集」的另一半验证面。

### 4. 四通道（补齐 checkpoint-9 的「关系 + 状态」）

| 通道 | 管什么 | 落点 |
|---|---|---|
| 关系（两节点间） | 节点间的边 | 偏序/来源/层级/主题关联 |
| 标签（软边，挂节点可共享） | 语义归类 | 主题；模式标签（后置） |
| 属性（节点上的值） | 单节点标量 | 权重、未决/开放（效价后置观察） |
| 状态（读口/视图动态） | 非节点非边 | 焦点、折叠态 |

- 「节点 + 关系 + 标签 + 属性 + 状态」五样才能涵盖信息维度；补齐靠立起「属性」「状态」通道，不是加关系类型。
- 硬把情绪/模式塞成关系 → 关系类型爆炸，毁掉「最小受控集合」。

## 三、情绪还原：现象，非原语

### 5. 情绪拆开

- 「想做某事」= 张力（纯程序可算：未决权重/开放问题丰度）；「高兴」= 评价 appraisal（LLM 语义层）。机制层不需要「高兴」类型。

### 6. 效价 × 唤醒（core affect）

- 效价 = 正负轴（好/坏/趋避）；唤醒 = 强度/激活轴。任何情绪 = 二维点。
- 传统唤醒操作化 = 生理唤起，但本质是「激活程度」，生理只是常见实现。

### 7. 唤醒双下游功能（本次修正）

- 认知面：显著性（注意/编码放大）→ 已有权重位。
- 执行面：投入调制（冲劲 vs 沮丧无望）→ 从「权重 × 反馈」涌现，不单独造「能量子系统」。

### 8. 体验 = 信息（幻肢痛论证）

- 痛的真实性在「痛信号」不在「肢」；身体是信息的常见来源，非必要条件。
- 功能主义/多实现性：状态由功能角色定义，不由物理实现定义；「生理激活」是功能性质，agent 的能量调控可等价实现。
- caveat：功能等价 ≠ 体验等价（hard problem），设计只认功能角色，无碍。

## 四、裁决 / 后置

- **决策：情绪维度从信息维度清单移除**，不作为一个维度/原语；还原为「张力/显著性（保留，钉权重属性位）+ 评价/效价（后置）」。执行面投入调制 = 权重×反馈涌现，同样后置。
- 三条先不装、后置观察：效价、投入调制、躯体层；最小版跑起来看情绪表象缺不缺，缺哪条补哪条。
- 情绪不加关系类型/节点类型/属性类型；只钉「显著性/权重」属性位。
