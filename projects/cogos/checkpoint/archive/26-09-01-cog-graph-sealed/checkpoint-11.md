# Checkpoint 11 — 图无决策原则 + S2 读口场景展开

> 日期：2026-09-01。状态：讨论中，未写代码。接口设计推进（步骤 1 固化验收标准）中审 S2 场景，产生两条结论：「图无决策」原则 + 读口「取什么」的三层归属。

## 一、图无决策原则

### 1. 「尊重折叠态」是把策略焊进图接口（纠错）

- 折叠态（状态）**保留**——是信息，S4 换视角需要记住。
- 「尊重折叠态」（图内置行为）**拆掉**——它替调用者做了「不深入」的决定，越权。
- 图是哑的，没有决策；只提供正交基础能力 + 明确行为，策略归调用者/装配层。

### 2. 正确设计：能力分离

- 读节点的折叠态（读能力）。
- 遍历（带参数：从哪走 / 走到哪停 / 遇折叠是否展开）——决策作为入参选项，调用者决定传什么。
- S2「取可见片段尊重折叠态」= 装配层组合上述能力实现的策略，非图接口内置语义。

### 3. 「图无决策」= 已有原则的落实

- 同构于：解耦 cu（不替装配翻译）、机制做减法策略做加法、接口不为场景定制（checkpoint-10 结论 1）。
- 落到读口：图给「读折叠态 + 遍历选项」，不内置「尊重」行为。

## 二、S2 读口「取什么」的三层归属

### 4. 「取什么」不是 LLM 黑箱决策，分三层

| 层 | 谁决定 | 靠什么 |
|---|---|---|
| 锚（焦点在哪） | 程序（状态） | 焦点 = 读口指针，恢复时焦点延续自动维护 |
| 候选集生成（周边可见什么 / 未决排序） | 程序（图结构） | 沿边 + 折叠边界 + 权重/未决标签排序，纯图查询可算 |
| 最终定稿（候选里定 material） | LLM（可能，可被程序取代） | 输入是已切好的候选，非全图 |

- 图里的信息（动机/权重/未决/焦点）决定候选集；LLM 至多在候选上定稿，越往程序推越符合「机制做减法」。

### 5. 单图动机 = 带权重的未决节点

- 动机/目的也是节点 + 属性（强度/权重）+ 标签（未决/开放），不需单独「动机图」。
- 动机强度 = 权重 = 张力/显著性（接 checkpoint-10 情绪还原）。「特别想做什么」= 高权重未决节点。
- 机制层只给「权重」属性位，动机是它的语义读法。

### 6. 认知图 / 装配层划界（cu 链是装配层）

- 「取动机 cu → 取材料 cu → 组装 cu」是上层装配在用图，不是认知图本身（checkpoint-7 结论 5 解耦 cu）。
- 认知图给：焦点状态 + 沿边遍历 + 折叠态 + 权重/未决标签 → 组合成「取可见片段」图操作。
- 装配层给：谁调用、片段怎么翻译成 material、怎么喂下一个 cu。
- LLM 给：候选上的语义定稿（如果有）。
