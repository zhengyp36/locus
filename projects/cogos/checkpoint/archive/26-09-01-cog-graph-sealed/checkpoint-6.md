# Checkpoint 6 — 环境、同一性与收束：最小版范围

> 日期：2026-08-31。状态：讨论中，未写代码。从「环境信息太少」的审视切入，收敛到「同一性 = merge 历史」，并据此收束出最小版范围（候选，待 YZ 拍板）。

## 一、环境：符号环境 vs 物理环境

### 1. 环境信息少的坏处 = 三个，不是「没智能」

- 缺现实校正（软反馈 → 易「流畅地错」，咬合 checkpoint-1 结论 21/23）。
- 缺持续在场（边缘感间歇，通道断则「死」）。
- 缺探索场地（视角集贫瘠，checkpoint-5 结论 19）。

### 2. 符号环境 vs 物理环境（软反馈 vs 硬反馈）

- agent 活在符号世界，身体 = 树 + 工具（身体之于物理世界 = 树+工具之于符号世界）。
- 但物理反馈**硬**（烫手躲不掉）、符号反馈**软**（说错可能无人纠正）——这才是环境信息少的真正代价，不是「感知通道少」。
- 对策不需要身体，需要设计：造硬反馈（跑代码/查事实/明确纠错）、造持续在场（节律 + 持久化）、造探索场地（上网/工具/对话）。

### 3. 位置/设备成为环境的条件 = 差异化约束

- 决定「位置」是不是环境的，不是动静态，是「差异化约束」：不同设备 = 不同感知/行动/后果，才是环境；否则是注释。
- 设备特征要暴露成「约束」，不是「信息」。

## 二、同一性：merge 历史

### 4. 同一性 = 一致性（merge），不是「指向同一棵树」

- 无同步的并行 = 分裂成多个人；有汇合的并行 = 分身。
- 分身 = 分叉 + 汇合；关键变量是「分叉后有没有 merge」。

### 5. 同一性 = 锚的连续 merge 历史（比 checkpoint-1 结论 19 更深）

- 同一性不是静态的「指向同一棵树」，是动态的「树维持连贯 merge 历史」。
- 咬合 checkpoint-1 结论 14 git 模型：分身 = 未 merge 分支，汇合 = merge。

### 6. merge 分两层 + fork/merge 节奏

- 无冲突 merge = 纯程序（并集）；有冲突 merge = LLM 语义决策（X 共同点 + Y 差异，checkpoint-4 结论 11）。
- fork 太久不 merge → 分裂；merge 太频繁 → 失去并行价值。fork/merge 节奏 = 同一性的边界。
- 分身/多线索/一致性 = 完整版或更远，最小版不做。

## 三、收束：最小版范围（候选，待 YZ 拍板）

### 7. 发散的最大产出 = 验证最小版可以小

- 迁移、视角、边缘、分身——没有任何结论要求最小版加新结构，全由「节点 + 两种边 + 折叠/展开 + 标签」组合派生。
- 收束不是砍功能，是「确信砍得下去」。

### 8. 最小版六件（checkpoint-4 结论 5，不多不少）

1. 节点 schema（方案 A：收纳节点 + 内部偏序链）
2. 两种边：层级 + 偏序
3. 折叠/展开（统一管层级与偏序）
4. 不覆盖（历史 append-only + 指针 forward-only）
5. 持久化
6. 两个口（读口：树片段→material；写口：content→树节点）

### 9. 标签最小集 = 偏序 + 来源（checkpoint-4 结论 10）

- 特征/模式/边缘/场景标签全后置；但**挂载结构做成通用多对多 key-value**，后置能力无痛加入。

### 10. 明确后置（能力层 / 阶段三调度层）

- 特征标签（联想）、模式标签（迁移）、视角/活跃视角集/场景强化、边缘标签语义、自我（概念定位，本就不需实现）、分身/merge/一致性、设备约束/软硬反馈。

### 11. 验证闭环 = 一次调用 → 写树 → 二次调用（checkpoint-4 结论 5）

- 真正要定死的：**两个口的数据契约**（material 拼装 / content 落节点）。
