# Checkpoint 4 — 认知树设计转向：从认知单元发散到结构收敛

> 日期：2026-08-31。状态：讨论中，未写代码；本轮从「认知单元」发散切入，逐步转向认知树的设计收敛。

## 一、从认知单元（cu）切入的发散

### 1. cu 的本质 = 一次「启动→停」的完整闭合循环

- LLM 一次推理会自己停，停点概率但大致可控（不是完全随机）——这就是一次认知单元的边界。
- 人的念头一念一念断续冒出，同构；差异只在停的驱动：LLM 靠「任务闭合」停，人靠「动机转移」停。动机是续上下一念的机制，没有动机人也会像 LLM 一样停（发呆/空转）。

### 2. 势垒/势阱：把「停」具象化

- 势垒（potential barrier）= 能量图上的凸起（墙），势阱（potential well）= 凹陷（坑），是同一个标量场的两种曲率符号，一体两面、天然成对。阱对「待在里面」稳定，对「离开」就是垒。
- 几何形状 = 代价结构 + 演化倾向的编码：低处待得住、高处挡人、系统沿最省力路径滑到局部极小（= 最小作用量）。
- 语义对应：**势阱 = 意义的吸引子（锚）**，**势垒 = 概念间迁移的阻力（需要动机/复杂度/外部刺激翻越）**，整张曲面 = 认知的地形。
- 自指：珠子滑行的地形是珠子自己以前滑出来的——认知塑造自己的势能面，又在面上演化。

### 3. 语义 = 对象 + 关系；几何/树把关系从抽象变具象

- 讨论缺一个「对象」，语义就是对象，语义在描述关系。几何形状/树 = 把关系从抽象变具象。
- 树：节点 = 语义对象（结论/概念），边 = 语义关系（依赖/脉络/归属）。LLM 输出的 token 把关系压平成一维（日志流的问题），树把关系重新立体化。

## 二、突破口：cu=操作、树=内容、两个口对接

### 4. 散材料串不起来 → 突破口是「两个口」

- 散的原因：哲学发散与工程对象混在一起。公约数 = **cu=操作（已实现）、树=内容（未实现）、中间靠两个口对接**。
- 两个口（= checkpoint-1 结论 3，本会话拎出来当主线）：
  - 读口：树片段 → `material`（cu 输入）
  - 写口：`content`（cu 输出）→ 树节点
- cu 是纯执行壳（`material` 进、`content` 出、`_finish` 后 pop，会死、不留状态），它已经抽象完；唯一待定的是「这个会死的壳，内容从哪来、到哪去」= 树。

### 5. 分层：本阶段认知树 = 纯程序数据层

- 关于线索/点亮暗化/差异粒度/版本/流整合/势垒 → 都是「调度层怎么用树」（阶段三），不是树本身。
- 本阶段只做：最小节点 schema + CRUD + 折叠/展开 + 持久化 + 两个口，用最小闭环验证（一次调用→写树→二次调用）。
- 真正要定的只有一件事：**两个口的数据契约**（material 怎么拼、content 怎么落节点）。

## 三、壳与内容解耦 + 机制递归

### 6. 壳与内容解耦 = 统一本质

- cu = 推理的壳：不管「怎么推理、推出什么」，只推进「调用 LLM→拿结果→结束→死」。
- 树 = 存储的壳：不管「存的内容是什么」，只推进「存/取/折叠/展开/持久化」。
- 共同本质：**程序管「动作的推进」，LLM 管「内容的语义」**。认知单元的「单元」是动作切出来的，不是内容切出来的。

### 7. 折叠/展开拆两半：执行（纯程序）vs 决策（语义）

- 执行（折叠这个动作）= 改标记、切视图、隐藏子树，不碰语义不改内容，展开即回，纯程序（如 git checkout）。
- 决策（该折叠哪个）= 语义活，LLM 做，发生在树外部（可注入算子，后置）。
- **折叠 ≠ 摘要**：折叠是视图切换（不丢内容），摘要有损压缩（需 LLM 生成内容）。树本体是纯程序，语义由策略层注入。

### 8. 机制是递归的；智能 = 机制的组织状态

- 我们设计的机制、LLM 的机制、训练 LLM 的机制——全是机制。智能不在任何一层机制「里」，是机制的一种**组织状态**。
- 两层机制栈：第一层 LLM = 训练出来的语义变换器（无状态，会停会忘会无方向）；第二层 cu+树+两个口 = 手工设计的组织器（补持续性/记忆/方向）。
- 边界在移动：策略（方法论）可自长，设计者越退越少，最后手里只剩一样——**目的（根节点）**。

## 四、认知树结构收敛

### 9. 折叠/展开 + 标签 + 不覆盖 = 表达变化的三件套

- 变化要成立需三件：**折叠/展开（空间）+ 标签偏序（时间）+ 不覆盖（append-only，内容）**。
- 光有标签回不到过去：标签是指针，指向的东西必须没被销毁。不覆盖 = 历史 append-only + 指针 forward-only（checkpoint-1 结论 14 git 模型）。
- 呼应 checkpoint-2 两轴模型：折叠/展开=内容轴（截面），标签=脉络轴（流程）。本会话把这翻译成可落地 schema。

### 10. 版本是派生的视图，不是存储的副本

- 不是「一棵树装不下多历史版本」，恰恰是一棵树就够：存粒度 + 标签，版本 = 用不同标签切出的视图（checkpoint-1 结论 15）。
- 最小标签只要两个：**偏序（先后）+ 来源（哪次 cu 写的）**。清晰度/权重/置信度先不做。

## 五、差异粒度模型（对 append 的纠偏）

### 11. 存 X（共同点）+ Y（差异点），不存 A、B

- A→B，不是同时存 A 和 B，是找共同点 X + 差异点 Y，存 X、Y。没有覆盖，也没有 append（不复制）。
- append 是差异粒度的退化：存 A、B 快照 = X 存了两次 + Y 一次（冗余）；差异粒度把 X 提出来存一次。append 无损但冗余，差异有损但节能。
- **咬合**：差异粒度 = 「折叠/展开 + 标签」的另一个名字——X=骨架（不变量），Y=标签（差异），A/B=按标签组合的视图。树节点不是快照，是「一个不变量锚 + 一串差异标签」。

## 六、有损 vs 无损（关键定论）

### 12. 有损是智能的特征，不是缺陷

- 有损 = 变异 = 进化。无损就难有变化，进化靠变异，有损才带来改变。不追求无损。
- 动机同构：动机不准确、是大方向；若变成确定终点，智能退化。锚保证方向，有损保证变异空间，两者缺一不可。

### 13. raw trace = 观测旁路，不是给 agent 的

- raw trace 是给**开发人员**分析过程、找原理用的，不在 agent 认知回路内。
- 对应 checkpoint-2 §五三层：认知树（agent，有损）／干净日志（人回顾）／原始日志（开发审计）。之前的「无损兜底」是把 raw trace 错放进了智能层。
- 设计边界：**认知线（agent，全有损）vs 观测线（人，可无损，默认可丢，不回流）**。把 raw trace 喂回 agent = 污染有损回路 = 退化成数据库查询。

### 14. 准确靠外部介质，但介质到不了「内在思考的全部」

- 现实中追求准确靠外部介质（纸/硬盘/录音），因为内在记忆有损。agent 同理：可借助外部介质（raw trace/日志）实现**产物级**的准确记录。
- 但外部介质记录不了内在思考的全部——LLM 内在的激活、被丢弃的候选分支、潜意识的语义运算，就像人看不见自己全部想法，意识只看见浮现结果的冰山一角（咬合「浮现对意识不可见」）。
- 所以「无损」有上限：即使对开发者的观测，也只到「外显产物」（token/动作/输出）这一层，永远到不了「全部内在思考」。这为观测线（结论 13）再划一条边界。

### 15. 收口：智能 = 带着方向的有损再生成

- 树不需要保存真相，只需足够骨架 + 差异标签，让智能每次长出一个大致对、且可能带点新东西的现场。
- **树是给变异一个不失控的锚，不是给历史一个精确的档案。**

## 七、两种边 + 方案 A（偏序链收纳）

### 16. 树里两种边：层级边（树）+ 偏序边（链）

- 同一批节点挂两种边：**层级边**（父子，空间/逻辑；折叠沿它向上看父、展开沿它向下看子）+ **偏序边**（先后，时间/变化；A→B→C 链）。
- 层级 = 共时截面（节点），偏序 = 历时轨迹（线索），对应 checkpoint-1 结论 20 两轴。
- 「展开」这一动作有两种取值：按逻辑子分解（层级）或按时间演变（偏序）。

### 17. 方案 A（YZ 拍板）：一个节点收纳一个偏序链

- 版本不是树上并列节点（方案 B 弃），而是**一个节点内部挂历史链**：收纳节点 = 父，偏序链 = 子，链内各版本 = 兄弟。
- 核心好处：层级和偏序共用同一个折叠/展开动作——沿层级折叠（子主题收进父）与沿偏序折叠（历史版本收进当前节点）是同一种操作。
- 折叠释放认知消耗：咬合 checkpoint-1 结论 16/17（潜意识减负/节能）+ checkpoint-2 §七（折叠两驱动）。折叠不是树的附属功能，是树节能的本质——纯链（日志流）无折叠能力，只能线性堆积。
- 与结论 11 咬合：收纳节点 = 骨架 X/锚（当前版本+骨架），偏序链 = 差异 Y/标签。折叠态只留锚省消耗，展开态看历史链 = 「现场组合再生」落地。

## 八、系统定位：LLM 是操作者，cu/树是被操作的机制

### 18. 三层图景：语义（动力）→ 机制（被操作）→ 上下文工作区（有限）

- **LLM = 真正操作者，动力 = 语义**。它操作两个机制：cu 控制「现在的工作区装什么」，树控制「工作区之外沉淀什么」。
- **cu = 上下文控制工具**：cu 输入端就是上下文，LLM 可通过一个工具替换 material / 起新 cu 代替当前 cu，实现自我上下文控制。这把 checkpoint-1 结论 7 的「方式1/方式2」（换现场壳策略）从实现细节升级为「LLM 可主动调用的工具」。
- **认知树 = 上下文工作区的记忆扩展**：上下文窗口有限（= 人脑工作区有限），需要外部记忆。树的定位不是「更大的上下文」，是工作区的补给站（读）+ 沉淀池（写），不参与当前思考，只提供可检索的过去。
- 呼应 checkpoint-2 §六：主体不是 agent，是「认知树 + LLM + 信息」构成的语义场，agent 只是临时活化形态。

### 19. 由此推出认知树设计三要点

- 操作接口 = 意图：LLM 产生意图，系统消费执行，下轮看到结果看不到意图本身（checkpoint-2 §七）。树不自己动。
- 两个口 = 树与工作区的唯一接口：读口（树片段→material，补给）+ 写口（content→节点，沉淀），是「有限工作区」与「无限记忆」之间唯一闸门。
- 树本体纯程序（执行 CRUD/折叠/持久化），但「操作什么」是语义（LLM 决策）。设计树 = 设计「LLM 能高效存取」的接口，不是程序自动维护的数据库。

### 20. 修正：单一重心 = 树；上下文 = 树的活跃片段（局部）

- 结论 18 的图景有两个重心（LLM + 上下文），「上下文」这个重心是错的倾向。
- 上下文不是独立于树的另一极，是**树的活跃片段**（局部）：当前动机+焦点下被点亮的加权视图，= 每次 cu 的 material（当前帧）。
- 咬合 checkpoint-1 结论 2（上下文=树的活跃片段会反写树）/ 结论 9（点亮/暗化）/ 结论 10（material=加权视图当前帧）+ checkpoint-2 §七（视图≠树本身）。
- 「上下文编辑树」= 树的自我变迁：活跃片段是变迁现场，编辑动作推进树的演变。树是持续演化的整体，上下文是它此刻活着的部分。
- 收口：唯一实体 = 树。cu = 动作，上下文 = 树的活跃局部，两个口 = 局部与整体之间的通道。系统 = 「LLM 操作一棵自我演化的树」。
