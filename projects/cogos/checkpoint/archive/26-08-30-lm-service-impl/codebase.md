## lm-service（新模块，cogos.lm_service）

- `cogos/cogos/lm_service/config.py`：`Config(base_dir=None)` 类，管理 `~/.cogos/lm-service/` 下三 yaml（config 0644 / secrets 0600 / state 0644），`load()` 建目录+补默认；`_atomic_write` 走 tmp+`os.replace`。方法：`list_api_keys` / `add_api_key`(append api_keys, 校验 account) / `delete_api_key`(active ik 守卫) / `list_internal_keys` / `add_internal_key`(ik_+token_urlsafe) / `delete_internal_key`(revoke) / `resolve_internal_key`(返回 provider/account/group/api_key[0]/base_url/max_concurrent/max_rpm/models 清单)
- `cogos/cogos/lm_service/providers/base.py`：`ErrorCategory`(StrEnum: retryable/auth/quota/content/semantic/invalid_request) + `ProviderError(category, message, raw=None, status_code=None)` + `ProviderBase.chat_completion(body, model, api_key, base_url)`
- `cogos/cogos/lm_service/providers/base.py`（轮4 共享函数）：`status_to_category(status)`（400/422→invalid_request, 401/403→auth, 402→quota, 429→retryable, 5xx→retryable, 其他→semantic）；`post_json(url, headers, body)`（传输错误/空body/非json→retryable，不设 status_code）；`parse_response(status, raw)`（非200→status_to_category 且 status_code=原状态；200 非dict→retryable；choices 空→semantic；content_filter→content；insufficient_system_resource→retryable；content None→""；reasoning=msg.reasoning_content）
- `cogos/cogos/lm_service/providers/deepseek.py`：adapter。thinking enabled 发 `thinking.type`、disabled 发 temperature/top_p；归一 reasoning_content→reasoning
- `cogos/cogos/lm_service/providers/openai.py`：adapter。thinking enabled 发 `reasoning_effort=budget_tokens`；reasoning 恒 None
- `cogos/cogos/lm_service/admin.py`：argparse 嵌套 subparsers（`admin`→`api-key`/`internal-key`→`add`/`list`/`delete`），`set_defaults(func=...)` 分发、无子命令 print_help 退出；`build_parser(subparsers)` 供顶层 cli.py 复用、`main(argv=None)` 供 `python -m` 直跑；list 输出 json。api-key 只写 secrets、internal-key 只写 state，chmod 由 config.save_secrets 负责
- `cogos/cogos/lm_service/router.py`：`select_model(models, messages, tier=None, must=False)` → `{model, tier, degraded}`。`infer_modalities` 只推断非 text 模态（image，看 content[] 的 `type=="image_url"`）。`_TIER_RANK` cheap=0/expensive=1，`degraded = rank(actual) < rank(requested)`。模态不满足/ must=true 无匹配 → `ProviderError(invalid_request)`。tie-break = 注册顺序第一个。
- `cogos/cogos/lm_service/handler.py`：`ALLOWED_REQUEST_FIELDS` = messages/temperature/max_tokens/thinking/top_p/tier/must/trace_id；必填 messages+温度+max_tokens，unknown→invalid_request。`_error_response` category→HTTP（auth 401/quota 402/invalid_request 400/content 400/semantic 502/retryable 503）。`X-Internal-Key` header → `resolve_internal_key` 只查 active。错误响应格式 `{"error":{"category","message"}}`。
- `cogos/cogos/lm_service/scheduler.py`：蓝本 AccountScheduler(semaphore+RPM 软约束)+Scheduler 池化原样；`PROVIDER_REGISTRY={deepseek:DeepSeekProvider(), openai:OpenAIProvider()}`；`Scheduler.submit` 调 `select_model` 选 model → 拼进 resolved → provider 结果加 `routed={tier, degraded}`；`ProviderError(category, msg)` 位置参数。
- `cogos/cogos/lm_service/server.py`：`create_app(base_dir=None)` 组装 Config+Scheduler+app dict，`--config` 语义 = base dir（非旧 json 文件）；`web.run_app(print=lambda _: None)` 静默。
- `cogos/cogos/lm_service/recorder.py`：`now_iso()` / `build_entry(**kw)`（16 字段固定顺序，status 必填）/ `CallRecorder.append`（mkdir + 单行 json append，`default=str`）/ `read_calls`（逐行 parse，坏行跳过）
- `cogos/cogos/lm_service/config.py`：`calls_path` property = `_dir / "calls.jsonl"`（调试记录落 config 同目录）
- `cogos/cogos/lm_service/scheduler.py`（轮5）：`Scheduler.__init__` 建 `CallRecorder(config.calls_path)`；`submit` 包 try/except 落盘（成功 status=ok / ProviderError error_category=str(category) / 兜底 semantic）后 re-raise；`_record(started, ik_id, body, ...)` 抽公共字段
- `cogos/cogos/lm_service/admin.py`（轮5）：`calls` 子命令（`--from/--to` ISO+epoch / `--limit/--offset` / `--fields` 投影 / `--filter key=value` 可重复 / `--count` / `--out`）；`_parse_ts` 先 float 后 fromisoformat；`_match` 布尔用 `str(v).lower()==expected.lower()`；`--count` 在分页前统计；输出 JSON 数组 indent=2
- `cogos/cogos/lm_service/client.py`（轮6）：`LmServiceError(category, message)` + `LmClient(internal_key, base_url=None)`；`chat(messages, *, temperature=0, max_tokens=1000, top_p/thinking/tier/must/trace_id)` keyword-only，optional 字段 None/False 不发；POST `/v1/chat/completions` + `X-Internal-Key` header；非 200 解析 `error.category` 抛 LmServiceError，传输错误/空body/非json→retryable，2xx 返回归一响应原样。`base_url` 默认 `http://{LM_SERVICE_HOST|127.0.0.1}:{LM_SERVICE_PORT|11434}`。`__init__.py` 导出 `LmClient, LmServiceError`。
- `cogos/cogos/lm_service/cli.py`（轮7）：顶层 `cogos-lm-service` CLI，`build_parser()` 注册 server/call/admin 三子命令（`set_defaults(func=...)`，无子命令 print_help exit 0）。`call` 复用 LmClient：读 stdin/`--file` JSON → 校验 messages + `_CHAT_FIELDS` 白名单（未知字段 SystemExit）→ `asyncio.run(_run_chat)` → 打印 content 或 `--raw` 全量；`LmServiceError` 打印 `Error [category]: message` exit 1。`--host/--port` 显式拼 base_url 否则用 LmClient 默认。`_cmd_server` 调 `server.run`。
- `cogos/cogos/lm_service/server.py`（轮7）：`create_app` 改**同步**（原 async 无 await，main 传 coroutine 给 run_app 是 latent bug）；抽 `run(config, host, port)`，`server.main()` 与 cli `_cmd_server` 共用。AccountScheduler 的 Semaphore/Queue 在首次 submit 时于运行 loop 惰性创建，故 create_app 同步化安全。
- `pyproject.toml`（轮7）：`[project.scripts]` 新增 `cogos-lm-service = "cogos.lm_service.cli:main"`（已有 cogos-feishu/cogos-phone）。
- 环境：`pip show cogos` editable 指向 `work/A/cogos`（工位 A，无 lm_service）。工位 B 跑 gate/pytest 需 `cd work/B/cogos` + `PYTHONPATH=work/B/cogos`（或 `python3.11 -m pytest` 借 cwd 进 sys.path）。
- `tests/lm_service/test_router.py`（轮8）：mock 走 `monkeypatch.setitem(scheduler.PROVIDER_REGISTRY, "deepseek", MockProvider)` 后经 `Scheduler.submit` 全链路测路由；`env` fixture 用 tmp base_dir 写 config.yaml 再 `Config.load()` + `add_api_key`/`add_internal_key`；降级用例用 `models=[TEXT_CHEAP]` 单 model 构造无 expensive 匹配；断言 `exc.value.category` 非 message。pytest `asyncio_mode=auto`（pyproject）故 async 测试函数免装饰器。
- `tests/lm_service/test_errors.py`（轮9）：错误归类全表直测纯函数（`status_to_category`/`parse_response`）+ 客户端 `LmClient.chat` 错误解析，无需走 Scheduler 全链路。`mock_http` fixture 用 `MagicMock`+`AsyncMock` 拼 `aiohttp.ClientSession` 双 `async with` 链（session_ctx→session→resp_ctx→resp），transport_error 走 `session.post.side_effect`；服务端 `post_json` / 客户端 `chat` 共用。StrEnum 比较：client 抛的 category 是 body 纯字符串 `"auth"`，`== ErrorCategory.AUTH` 成立。轮10 归一/调试记录测试可复用该 fixture 模式。
- `cogos/lm_service/router.py:5-6`（轮10 改名）：`TIERS=("basic","advanced")`、`_TIER_RANK={basic:0,advanced:1}`。tier 语义 = 推理能力档位（非价格），视觉是正交模态由 modalities 声明；视觉模型归 basic 档。
- `tests/lm_service/test_normalization.py`（轮10）：两 adapter 端到端归一，monkeypatch 各 adapter 模块的 `post_json`（`monkeypatch.setattr(module, "post_json", fake)`，因 adapter 是 `from .base import post_json` 模块级名字）。
- `tests/lm_service/test_recording.py`（轮10）：submit 后读 `config.calls_path` 断言 16 字段齐全；admin calls 测试 monkeypatch `admin.Config` 为 lambda 返回 tmp cfg（`_cmd_calls` 内 `Config()`+`load()` 幂等）。
- 真实 deepseek model（轮10 查证）：`deepseek-v4-flash`（basic 文本）/ `deepseek-v4-pro`（advanced 文本）/ `deepseek-v4-flash-vision-exp`（basic + image 实验性）。spec 占位名 `deepseek-v4-vision` 替换为后者。
- 真实行为坑（轮10，轮11 已修正）：deepseek thinking 原默认 enabled 致 reasoning 吃掉 max_tokens（content 空 + finish_reason=length）。**已拍板默认关闭**：`deepseek.py` `thinking.get("enabled", False)`，cogos 内部不用厂商 thinking（agent 思考由上层承担），仅保留 thinking 参数用于效果对比。openai 本默认不发 reasoning_effort（`if thinking.get("enabled")` 才发）。视觉模型 latency 高（识别 11s）。admin CLI 写三文件后运行中 server 内存不刷新（config load 一次），加 key/ik 需重启 server。
- `tests/lm_service/test_normalization.py`（轮11 增 TestThinkingDefault 4 用例）：deepseek 默认发 `thinking.type=disabled` + temperature、显式 enabled 发 `type=enabled` 且不发 temperature；openai 默认不发 reasoning_effort、显式 enabled 发 `reasoning_effort=high`。
