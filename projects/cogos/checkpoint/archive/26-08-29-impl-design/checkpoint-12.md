# checkpoint-12 — cu 最小契约收敛 + 告知值默认注入 + 短输出不流式

## 当前问题

cog-runtime 雏形已出，收敛 cu 最小契约；顺带定告知值注入方式与流式取舍。

## 关键结论（YZ 拍板）

### cu 最小契约（5 块）

1. **material** = 消息数组（lm-service 定形式，cu 纯透传）：`messages: [{role, content:[{type,...}]}]`。
2. **tier**（原 intent 改名）= cheap|expensive 软倾向、可降级。改名理由：「intent」已被意图子系统占用（意识产生意图），避免术语撞车。意识产生的意图 → 归 material（内容透传）。
3. **结果** = lm-service 归一形式 `{content[], usage, routed}`，非厂商原始响应。cu 对结果「机制字段读、内容字段透传」：读 status（判 done 成败）/ usage（速率反馈）/ routed（降级留痕），content 透传。故 cu 不是严格对称纯函数。
4. **defer** = 纯暂停机制。剔除「求助」（求助是策略层元动作「继续/换路/求助/放弃」，非 cu 机制）。触发方 = 资源控制/上层，cu 不自决定何时 defer。
5. **父子关系** = 照 zio：初始化指定父，或之后设置。约束：**发起（wait/no_wait）前可设、发起后冻结**，避免并发改父子。

契约草案：

```
CogUnit(
    material: 消息数组（lm-service 定形式，纯透传）
    tier:     cheap|expensive（软倾向，可降级）
    parent:   CogUnit | None（发起前可设）
    children: [CogUnit]（发起前可设）
)
cu.wait() / cu.no_wait() → 入 taskq
cu.on_done(cb)           → done 回调（结果=归一形式，内容透传/机制字段可读）
cu.defer()               → 纯暂停机制（触发方=资源控制/上层）
```

### 告知值默认注入（化解「纯透传 vs 填告知值」缝）

- CogRuntime 提供基本配置：**默认自动在 material 注入窗口预算**（工作预算/输出预算，checkpoint-7 告知值）。
- 默认值，上层可显式：不用 / 填其他形式 / 置空。
- 分层：机制层给默认、上层有控制权，与「放权不放资源无限」一致。

### 短输出不流式 + 单总超时

- 短上下文窗口（物理 64K / 工作预算 16K / 输出 4K 量级）→ 输出短 → 流式无意义（首字节延迟/边收边处理/进度反馈三点都不需要）。
- 与 checkpoint-7 一致：「短输出不需要流式，流式只是长输出的传输优化」。
- lm-service 阶段 1 非流式（蓝本 `stream: False` 保持），流式基本不做。
- 超时简化为**单总超时**（非流式 = 一次请求 → 一次完整响应）；「卡住」触发总超时，归可重试异常走 checkpoint-2 可靠性（退避重试/归一上抛）。
- 作废：流式「首 token / 中途停滞 / 总超时」三层超时细分（非流式不需要）。
- 非流式也会卡：卡法 = 连接活着但不返回完整响应；比流式更盲（看不到 token 动没动，只能干等计时器）。自洽逻辑：**短输出（输入 16K/输出 4K 量级）保证不常卡，单总超时保证卡了能被兜住**（触发超时归可重试异常，退避重试/上抛，非无限干等）。「短输出」才是可不用流式的根本条件，不只是「流式没必要」。
