# checkpoint-10 — 预算归属：ce 不管预算，归资源级元控制

## 当前问题

前面把「预算」写进 ce（checkpoint-7「预算留 CogExecutor」、checkpoint-9「ce=调度…预算/停条件安全阀」），质疑：预算与资源级元控制相关，ce 不该管预算，预算策略只是 ce 与资源控制之间的交互。

## 关键结论（YZ 澄清）

### 「预算」拆两层

| 意思 | 是什么 | 放哪 |
|---|---|---|
| 硬安全阀 | 并发上限 / 循环上限 / 停条件 / 取消 | 留 ce（执行现场），兜底 |
| 预算策略 | 能量分配 / 降级 tier / 延时 / 优先级重排 | 资源级元控制，决策 |

- ce 保留**硬安全阀**（策略失灵也不失控的本能），**预算策略归资源级元控制**，经 hook 注入 ce。
- 修正 checkpoint-7「预算留 CogExecutor」与 checkpoint-9「ce=调度…预算」措辞：应表述为「ce 管硬安全阀 + 反馈速率，预算策略归资源控制」。

### 资源级元控制 = 独立模块，非 ce 一部分

横跨两端：读 lm-service 账本（真实消耗）+ 读 ce 速率（消耗快慢）；塞进 ce 则无法访问账本。呼应 checkpoint-3「账本/速率/决策三分离」。

### 三流

```
调用流：ce ──发起──→ lm-service
反馈流：lm-service ──账本──→ 资源控制
        ce ──速率──→ 资源控制
决策流：资源控制 ──换tier/延时/优先级/暂停──→ ce
        资源控制 ──配额阈值/硬执行──→ lm-service
```

- lm-service：账本 + 硬执行配额上限（不足→错误），无脑。
- ce：执行调度（依赖/并发/优先级）+ 硬安全阀，反馈速率，不制定预算策略。
- 资源控制：合成「账本 + 速率」做决策（强推理换弱 / 延时丢给 lm-service / 昏迷·休眠），下发两端执行。

## 遗留 / 待定

- 资源控制决策策略细节（阈值三级：降速/昏迷/预留整理能量，checkpoint-3）仍后置。
- 硬安全阀 vs 预算策略的 hook 接口形态（ce ↔ 资源控制）待定。
