# checkpoint-13 — 工具调用与 cu 关系收敛：工具标配 + 工作簿抽象 + cu 不决策

## 当前问题

checkpoint-12 遗留：「工具调用与 cu 的关系」。经认知科学类比（大脑工具少、工具在执行层）讨论后收敛。

## 关键结论（YZ 拍板 / 纠正）

### cu 定位：横跨三层 + 不决策不发起

- **两根轴正交**：功能层（认知/元/执行）× 实现（LLM/程序）。人脑一种物质（信号）纯功能分层；cogos 两种实现（LLM=语义 / 程序=规则不懂语义），语义→执行是**硬切面**，无法渐变。
- **cu = 一次 LLM 语义加工封装，不绑认知层**，哪里有语义哪里就有 cu：认知层全语义；元层监控=程序（读 telemetry 标量，红线）、决定涉语义→有 cu；执行层动作内容=语义→有 cu、动作执行=程序。
- **cu 只加工语义，不决策、不发起**（YZ 纠正，收回「cu 决定」表述）。关系链：`agent（元层）决定读写 → cu（认知层）加工语义（产内容/参数）→ 程序（执行层）执行工具`。工具调用是 **agent 整系统**的对外行为，cu 是链上语义环节；机制上借某次 cu 落地（tool_call），语义主体是 agent 非 cu。类比「手写字」。

### 工具调用统一定义

- 有语义 → cu；cu 与外部系统交互 → 工具调用。工具调用 = 语义决策 + 程序执行。
- **自动浮现也是工具**（YZ 纠正「程序不会浮现记忆」）：浮现=语义判断（相关性）→ 要 LLM → 要 cu → 与文件系统交互 → 是工具调用。与主动提取只差触发源（自动/意图），内部同构「语义决策(cu)+程序执行」。

### 工具标配，权限由 profile 静态实例化

- 工具=agent 基本能力，**标配**；无授权配置、无独立沙箱（YZ 否定「授权集合」做法）。
- **权限=实例化参数**：通信=账号；目录=根目录（绝对路径以根为界，chroot 式内建）；电脑=账户。均写入 `profile.md`。
- profile 明文无泄露：agent 读不到 profile，风险前提是「谁能读到」非「是否明文」。
- 沙箱不消失，退化为工具实现内建（根目录映射 / 账号身份），非独立机制。

### 工作簿抽象（YZ 拍板）

- 目录≠电脑目录，从 agent 视角是**自己的纸笔 / 外置工作记忆**。工作记忆 4±1 chunk + 上下文窗口有限 → 草稿纸外置释放上下文。
- 工作簿：名字 + 唯一 ID，`create(name)→id / write(id,content) / read(id) / delete(id) / list()`。多个（日记/草稿/项目）。
- **三介质分工**：工作簿=显式寻址（确定性 IO，无语义召回，读便宜）；记忆=语义召回（浮现，需 cu 判断）；电脑=世界副作用。
- **介质=当前文本**；扩展跟随 LLM 生成模态（能生成什么记什么），写侧对称读侧（读图=读文件+视觉模态；画图=生成图像模态+写文件）。

### 工具清单（三类）

1. **工作簿** — 外置工作记忆，文本，显式寻址。
2. **记忆读写** — 语义召回/浮现，也是工具（自动浮现/主动提取/反写）。
3. **世界交互** — 通信（发消息）+ 电脑（读写文件/执行命令，阶段一后置）。

### LLM API 工具调用机制（知识，映射病根）

- 三环节：工具清单进 prompt（`tools` + JSON Schema）/ 模型只发意图（`tool_calls`，输出格式之一）/ 客户端执行后结果 `role:tool` 回填续轮。
- 三特征=「工具与认知混」的具象：清单常驻 prompt、tool_calls 是输出格式、结果 content 混入。cogos 拆开：清单不进 cu prompt、调用意图是语义产出非输出格式、结果走执行层回流。

### 读图非工具

- 读图=读文件（工具）+ 视觉模态（LLM 能力）。工具只产数据（MediaRef），模态由 lm-service 自动路由（checkpoint-5），cu 不感知。推广为一般原则：工具产数据、模态是 LLM 能力、两者正交。
