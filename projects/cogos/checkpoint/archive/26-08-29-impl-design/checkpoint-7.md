# checkpoint-7 — cog-unit 设计讨论（暂停 lm-service 实施）

## 当前问题

cog-unit 设计尚未想清；讨论确认 lm-service 与 cog-unit 有配合关系，先想清 cog-unit 再实施 lm-service，避免返工。

## 关键结论（YZ 拍板 + 收敛）

### 定位与职责边界

- **编排在上层（cog-func/业务），不在 cu / CogExecutor**。cu 是被编排对象，不是编排者。
- **CogExecutor = cu 的 DAG 调度器**：父子关系表述依赖，有依赖串行、无依赖并发，并发受预算约束（资源级元控制）。同构 lm_service 的 `Scheduler`，调度对象从「API 调用」换成「cu」。
- **资源级元控制 ≠ 编排**：停条件/循环上限/预算/并发上限/取消是本能安全阀（机制层，预装不可自长），必须留在 CogExecutor；「跑什么、为什么跑、拆成什么」才是 cog-func（策略层）。「放权不放资源无限」靠前者落地。
- **cog-unit 必要性 = 边界而非代码量**：lm-service 故意拒绝语义（不装配心智现场/不纠语义错/不编排 prompt/不感知调用间关系），被拒绝的职责由 cu 接住。cu 不是 lm-service 的上层封装，是它让出来的那层。
- **观测单位 ≠ 调用单位**：`trace_id` 串「一次语义运算」下多次底层调用；span/父子由 cu 树维护，lm-service 只透传。
- **量/内容二分**：机制层管「量」（窗口/预算/并发/依赖），上层管「内容」（装什么/卸什么/跑什么）。小窗口、上下文加载/卸载是「内容选择」，涉语义，归上层，cu/ce 不碰。
- **ce 不取素材**：从树取活跃片段 = 「哪些片段活跃」的判断，是语义活，上移到上层/认知树；ce 只接收已准备好的 material，负责分发/依赖/并发/预算。cu 的心智现场装配限定为格式/模板组织（填告知值），不含「选什么」。

### cu 粒度与「独立思考 AI」

- **cu = 一个语义增量**（如「回一句话」），不是「完成一个任务」。增量大小由业务定。
- **连续性在认知树，不在 cu**：cu 无状态（临时心智现场用完即弃），每句从树读活跃片段、说完整理反写树（hooks:17）。
- **自我纠正 = 后面 cu 反写树覆盖前面结论**。区分两种关系：依赖（数据流先后）vs 修订（语义覆盖）；CogExecutor 只认依赖，修订是树的语义。

### 小巧上下文：根本原因

- 不够小巧的根因 = LLM 训练默认「回答者契约」（对单 query 给完整可靠答案），非缺技术手段。
- 「回答者」与「任务型 AI」同一根源；cogos 要的是「思考器官 / 独立思考」，契约/角色要换。

### 意识层（YZ 引入的关键概念）

- **多流并行想很多 → 进入意识层少 → 说出来更少**。小巧是结构本性，不是补丁打出来的。
- **说过的话回流到意识层 → 发现说错 → 纠正**。说 = 写回是同一动作（即时回流），非「说完再整理」两步；这是「边想边说、随时纠正」的结构性来源。
- **流式撤回**：短输出不需要流式，流式只是长输出的传输优化。「边想边说」靠短输出 + 回流，不靠 token 流式。

### 约束：物理截断 vs 主动控制

- **max_tokens 是「截断」不是「约束」**：硬切产生不完整尾巴，不改变思考策略。要的是「主动控制」——LLM 提前知道输出预算，装不下就拆小逐个解决，输出完整。
- **「告知值 < 物理值」模式**：告知 4K（进 prompt，引导主动控制）/ 物理 6K（max_tokens 兜底，lm-service 参数）/ 余量吸收 LLM 模糊控制误差。LLM 看不到物理值（只见 prompt 不见 API 参数）。同构「告警先于不足」（告警线 < 错误线）。
- **三个窗口量（从大到小）**：厂商上下文上限（能力表，lm-service 知）≥ 物理窗口（64K，上层设、lm-service 校验，见 checkpoint-8）> 工作预算/告知值（LLM 感知可用空间，16K 量级，进 prompt，待调）。小巧靠语义层装得少（工作预算），不靠物理窗口小。
- **输出受限 → LLM 主动拆小 = cu 化 / 增量化 / 边想边说的自然动力**，增量不是外部规定而是被约束后主动选择。
- 具体数值（64K / 16K / 4K / 6K / 比例）都是**待调参数，未定**，仅示例思路。
