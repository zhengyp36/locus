# 工具与记忆组织 + 轻机制（10-15 收口）

> 意识层工具视图（就两个）+ 记忆组织（fold/unfold）+ 轻机制信任 LLM。术语＝`glossary.md`（＋意识层工具视图、折叠/展开、轻机制）。轻机制详件＝`2026-10-14-cogos-light-mechanism-principle.md`。
> 收口源（scratch，已删）：`2026-10-13-selfdrive-tools.md`。

## 1. 意识层工具视图（就两个）

- **`intent`**：对外，表达意图；外部能力分几类（computer / communication / vision 等）藏在其背后，意识不可见。
- **`memory`**：对内，整理上下文、组织记忆。

## 2. 锚与记忆存储

- **锚的表示**：索引区条目＝`name + description`；正文引用＝`[[name]]`。
- **记忆存储**：藏在 agent 不可见的目录，agent 只能经 `memory` 工具间接访问；链/索引只在记忆内部，不外溢到外部文件。

## 3. memory 的两个原子操作

- **fold**：把一段思考整理成一个概念（name + description）。
- **unfold**：把一个概念展开成详情。
- **折叠＝意识命名 ＋ 机制收拢（两面）**：意识层折叠只贴名/抽象、不收起内容；机制层看到 name，装载时把其背后内容不装、只留锚（收拢）；一次折叠同时完成"压缩"与"索引构造"。
- **展开 ↔ 折叠互逆，长成概念树**：注意力所在的展开、退到背景的折叠成 name，两者动态平衡；多次折叠长出概念树（树生长式，非 append）。

## 4. 记忆组织的归属

- `memory` 只提供 fold/unfold 两个操作；存、索引、蒸馏、收拢由**机制层**完成。
- 记忆＝意识层命名（fold）的副产品，机制层落地。

## 5. 轻机制 / 信任 LLM

- 机制可以**留白**，前提＝最自然的填法恰好就是设计者要的填法（LLM 语义理解正好填空白）。
- 反例（出生走查里）：对象指称（「张三」「那个陌生人」「刚开的电脑」）本来一句话就是 fold 的应用、机制零新增，却一度被做成"兜底命名、触发条件、代词/锚切换规则"的设计——替 LLM 操心它本来就会的。
- 来源＝Claude Code 记忆机制（`[[name]]` 双链、name+description）；关键差异＝Claude Code 记忆是 agent 可读写的文件，我们藏进机制层、按需装载、不外溢。

## 6. 被否

- 对象指称做"兜底命名/触发/代词切换规则"（→一句话 fold，零新增）。
