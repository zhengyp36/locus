# agent 生命周期与介入机制设计（2026-10-21）

> 状态：**设计已定、部分落码**——第一步骨架（`6563b28`）落了状态机/心跳/事件/介入点 stub；装载/卸载/SEQ/介入判断留后。原 `scratch/2026-10-21-agent-lifecycle-design.md` 收口至此，术语进 glossary。未落码部分标「待实现」。

## §1 图景

agent = 常驻进程，里面只有两样：**记忆**（盘上文件、唯一持久实体）＋**意识**（在记忆上活动的推理流，是过程非部件）。其余是让这两样转起来的机制：**事件**（唯一输入）、**状态机**（意识生命周期）、**心跳**（Monitor，监控＋干预、不做调度）、**介入**（统一入口）。

## §2 核心定义（详见 glossary）

- **事件**：唯一输入，来源只有 body 工具（chat/terminal/web/reminder）；当前阶段**无内部事件、无生念**（永久性待定）。
- **心跳 heartbeat**：状态机 Monitor，三职责＝节律/事件/推理监控；与 tick 各司其职（tick＝无内容信号、不再合成事件）。
- **意识**：推理活动本身（过程），活在**意识上下文**（＝记忆的活跃区）上。
- **助推 boost**：注入一条 user 消息让推理继续（外部事件、元层注入都是助推；工具结果回灌不算）。
- **SEQ**：上下文整理的产物（蒸馏，非日志）；顺序 append 不产生 SEQ，仅「需要整理」时切新 SEQ。
- **介入**：统一入口 `intervene(trigger)`，两调用点 `on_done`/`on_tool_call`；两层判断（程序 gate → LLM 判断）；两操作（注入＋清理）。
- **信号/介入点**：信号＝无内容通知、幂等；介入点＝LLM 返回后安全位置；事件只投信号、不直接开 cu。
- **装载↔卸载对称**：装载＝卸载的逆；出生＝退化特例（统一装载）。

## §3 状态机

四态：`ASLEEP`/`AWAKE`（稳态）＋ `WAKING_UP`/`FALLING_ASLEEP`（暂态、**不可打断**）。转移 trigger 依次 `heartbeat/meta/on_done/meta`。**启动归一化**＝读盘上状态→一律 ASLEEP（快照回滚后置）。两套分层（agent 状态只存内存＋意识标签落盘）留第二步；第一步落 agent 四态单字段。

## §4 生命周期主流程

```
ASLEEP ──(心跳检测事件/节律)── wake_up ──► WAKING_UP ──(装载)──► AWAKE
  ──(SEQ 链推理，on_done/on_tool_call 介入判走向)──►（介入提示该睡→意识调 sleep 工具）──►
  FALLING_ASLEEP ──(整理/蒸馏)──► ASLEEP
```

`main` 非循环：`start_agent()`（归一→起事件→起心跳）后 `await Event().wait()`。AWAKE 内推理自驱，`on_done` 处介入决定走向；`on_done` **不决定睡**（睡由 sleep 工具或心跳强制）。

## §5 元层三形态

同一 LLM 角色的三种出现：**装载流**（WAKING_UP 独立流）／**整理流**（FALLING_ASLEEP 独立流）／**介入**（AWAKE 内部：挂提示→产出→清理＋留痕，非独立流）。「没有一个稳定的元层」指动作层面，非否定角色。

## §被否

- 心跳＝调度系统（否，Monitor 不调度）。
- 事件只靠轮询（AWAKE 时事件走介入点立即处理，仅 ASLEEP 靠心跳轮询）。
- 介入＝on_done 专属（否，统一入口 `intervene`）。
- 意识＝容器/部件（否，过程）。
- 独立稳定的元层流（否，同一 LLM 三形态）。
- 单一固定节拍处理所有监控（不同监控可能需不同频率）。
