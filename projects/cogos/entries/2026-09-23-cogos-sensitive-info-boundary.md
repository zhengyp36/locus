# 讨论｜agent 与敏感信息：边界怎么划 · 2026-09-23

> 性质：讨论记录（会话印象），非结论、非施工稿。起点 = YZ 问"ToDesk 解锁电脑、模型不碰密码怎么做到的"，展开到自主 agent 的敏感信息策略。

## 一、机制事实（从 ToDesk / sudo 推出）
- **ToDesk 解锁**：密码留在被控端。两入口——(a) 实时屏上手输，(b) 登记密码（存被控端，之后不再走网络，本机特权服务直接喂 PAM/凭据提供者）。
- **传输**：链路加密，但**两端进程必然握明文**（要注入登录框）；服务器能否看到取决于是否真 E2E。"模型看不到"是**通道隔离**（输入通道 vs 画面通道 + 安全段遮罩/secure desktop），与加密无关。→ 两把不同的锁：模型看不到 ≠ ToDesk 看不到。
- **sudo 同构**：`NOPASSWD`/polkit/setuid 让 agent **不需要**密码；`SUDO_ASKPASS` + root-only 秘密让 agent 能触发却读不到。前提是**主体分离**（agent 与秘密不同 uid）——同账号下"藏密码"无意义，模型 cat 一下就出来。

## 二、核心区分
- **能力(can) ≠ 知识(know)**：can 不需要 know。**自主 = 在能力封套内自驱**，不是掌有全部凭据（人也是：有通行证，不知主密钥）。
- **agent = 意图层，不是权限层**：L1 意图 / L2 能力 / 权限策略在 agent 之外强制。
- 好处：凭据进上下文会被注入、日志、上下文残留泄露；能力不进上下文，只能被**误用**，由 scope/时限/审批兜住；撤销能力不需轮换秘密。

## 三、"谁脱敏"
- 让 agent 自己脱敏**架构上无效**——看见原文即已泄露；脱敏必须在 agent 上下文之外。
- 流水线重述：`原始 →[策略中介决定视图]→ agent`，不是 `原始 →[脱敏]→ agent`。
- 人只写**策略/规则一次**（O(规则)），不是逐条脱敏（O(记录)）；人出手 = 审批某次披露。
- 结构化数据：字段策略 + tokenization（真值存 vault，agent 只见 token）。
- 非结构化文本：确定性检测器打底 + 独立受限 NER 组件（哑工具、无能力、只标 span）+ 默认拒绝；人只审长尾。

## 四、非规则敏感：分类搞不定，围堵搞得定
- 敏感不是字符串属性，是**关系属性**（谁看 / 流向哪 / 能拿来干什么）→ 靠"识别敏感内容"把关必漏。
- 真正要的是**围堵**，全是确定性的：源侧最小权限 / 边界按**来源标签**（不靠内容推断）/ 动作侧能力收窄 + egress 白名单 + 审批。
- 框架：**致命三元组**（私密数据 + 不可信输入 + 外泄通道）→ **拆三元组**，不识别内容。
- 语义判断不可避免时：模型只当**分诊 / 风险削减**（fail-closed、无能力），**永不当安全边界**。
- **硬限制**：既要"不许它看"、又要"据它判断"的任务 → 这个 agent 干不了，只能靠确定性规则 / 隔离专家组件 / 人。

## 五、对 cogos 的落点
- ledger 的 scope/ttl/revoke/一次性 + daemon 特权中介 = 上述围堵，方向已对。
- 缺的是：**审批（HITL）** + **egress 限域**；敏感分类最多当分诊，不当闸门。
- sudo/解锁若要进动词面：只留意图（`unlock`/动作），凭据由 host daemon 持，**不把 password 塞进 verb**。
- 未定 / 待 YZ：L3 的"解锁 / 登录"是否算进目标 7 条；能力封套的具体边界。
