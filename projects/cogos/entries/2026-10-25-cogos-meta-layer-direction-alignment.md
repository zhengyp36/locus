# 元层方向对齐（2026-10-25）

## 结论（活跃）

在 meta-layer 检视修复两轮收口（`b716a06`/`54b9a7f`，全量 1369 passed）之后、LLM 接线之前，做了一轮**方向对齐**讨论。收敛出五条结论，均为**纯讨论、未落码**（下一步 LLM 接线时落地）。

> ⚠️ **10-28 修订**：第 5 条「方向定/内容长/不让方向自己长出」被 10-28 改为「**初始设定＋流内聚合稳定**」（方向在流内涌现、元层维护不漂）；「目标/方向＝外部锚」被否。见 `2026-10-28-cogos-generic-specialized-boundary.md`。

### 1. 介入决策四元 Proceed/Relay/Switch/Stop

元层介入点控制策略统一为四元，**本质＝下一轮输入从哪来**：

- **Proceed**＝无助推继续，**仅工具介入点**（靠程序回灌工具结果）。
- **Relay**＝有助推继续，任意介入点（**追加**一条消息）。
- **Switch**＝重构上下文继续，任意介入点（**替换** LLM 上下文内容）。
- **Stop**＝停止，任意介入点（去 unload→ASLEEP 或 idle）。

要点：

- **换/不换＝LLM 上下文内容「替换/追加」，不是 cu**；推理结束点原 cu 已 done、必换 cu 是实现约束。故 Switch 与 Relay 在内容层天然互斥。
- **Sleep 不再是决策**，降为 Stop 的一个去向（卸载入睡）；同理"醒"也不是决策，是 Stop(卸载)后被节律/事件再触发＋装载。
- 与「意识即停」公理自洽：只有工具点有程序自动回灌，故 Proceed 只在工具点存在；推理点无回灌，必须元层给输入（Relay/Switch）或停（Stop）。

### 2. 意识内容组织三动作（生命周期闭环）

**组装（从无到有）→ 接续（从有到有）→ 卸载（从无到有）**：

- **组装**＝`load()`：首次醒用**出生模板**（唯一且确定）、其后醒从**经历/记忆取＋结合事件**。出生＝空记忆退化特例，非独立机制。
- **接续**＝Proceed/Relay/Switch 的执行：重构/助推是**怎么组织**，事件/经历/记忆是**内容来源**。
- **卸载**＝把意识内容**整合进记忆/经历**（内容去向）。

**未点明的核心＝动机/方向/目标**（引力）：内容组织＝**管道**（怎么流）、动机/方向/目标＝**引力**（围绕什么、往哪偏），两维正交。

### 3. 日界推进 = full 档整理专属

wake_version 改锚**节律周期号（day）**：

- **只在时间界点（24:00）的睡眠整理（full 档）时推进**，＝整理动作的副产物，不靠时钟独立递增。
- **进程重启/归一化不推进**（重启不整理就不变）——消除"进程生命周期泄漏进意识语义"。
- "今天→昨天"＝full 档整理时的时间投射推进。
- `is_first_wake`＝day==1 且日内首醒（需另配日内醒标记，不混进 day）。
- **日界推进＝full 档整理专属**，light/medium 档不碰。

### 4. 两层关系：同一 LLM 的两种职责

- 元层与意识层＝**同一 LLM 推理的两种职责**，非两个不同 LLM：意识层**前向推理**（怎么达成）、元层**对齐/校准**（偏没偏）。
- LLM 语义方向**非唯一、非完全确定、有概率随机性**（大概率/小概率都可能发生），单层长程会"先偏一点、再偏一点"，两层叠加在介入点交替校准实现稳定。
- 两层**围绕同一核心＝动机/方向/目标**（元层拿它判偏、意识层拿它推进），装进同一份方向背景，装载时总带入。

### 5. 方向来源：持续存在（定）＋环境（长）

动机/方向/目标两来源：

- **持续存在＝基础条件（定）**＝本性/法则＋种子：每天醒睡、能想能动。
- **所处环境＝决定形状（长）**＝人生初课＋根/倾向：人类社会、用工具与世界互动。

**方向定、内容长**：定的是**方向/张力**（持续存在、与人打交道、思考价值），不是**内容/结论**（价值是什么、该怎么活——必须自己长）。**不让方向自己长出**：方向本属种子层，不该长，也想象不出长出机制。

> ⚠️ **10-28 修订**（见 `2026-10-28-cogos-generic-specialized-boundary.md`）：「方向定、内容长」改述为——「持续活着、要想怎么活」只是**初始设定（种子）**，方向**在流内随机涌现、靠连续 stream 聚合稳定**，「不让方向自己长出」不再成立；元层职责＝**维护流内长出的方向不漂**，非「从外部拿方向」。

## 被否 / 未采用

- **Sleep 作为独立介入决策** → 否，降为 Stop 的去向（卸载入睡）。
- **wake_version 锚进程重启/醒次数** → 否，进程生命周期泄漏进意识语义，改锚节律周期号（day）、full 档整理专属。
- **工具回灌与元层注入合并为一个概念** → 否：两者来源不同（程序自动 vs 元层主动），保留 Proceed/Relay 区分；不必为"都有新内容"而统一。
- **方向自己长出** → 10-25 否（方向在种子层本就该定）；**10-28 修订**：方向在流内随机涌现＋连续 stream 聚合稳定，被否的只是「无种子约束的纯流内长出」（破坏持续存在连续性），种子＝初始设定、守这条线。
- **Continue 作为决策名** → 否，撞 Python `continue` 关键字（历史上已为此改过一次 continue→resume），改 Proceed。
- **Relay 换成 Boost/Nudge** → 未采用：Relay 与 Continue/Switch/Stop 同属"怎么继续"这一层、读起来顺；"助推 boost"继续专指"注入消息"这个动作，Relay＝决定"通过助推继续"，层级不混。

## 元观察（收录）

本会话讨论轨迹本身＝一次**"对齐两层"演练**：起点对齐**目标**（下一步＝LLM 接线）→ 被"听不出目标"逼回**架子语义** → 一路退回**动机/方向来源**（持续存在＋环境）。设计 agent 时人在对齐、agent 运行时元层在对齐——同一根轴，印证"对齐"是核心而非拍脑袋加的一层。
