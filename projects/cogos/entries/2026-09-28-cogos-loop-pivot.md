## 3. 怎么确认零件（AI 看法）

- **三种"确认"别混**：① 边界（一段/一根箭，判据＝能写成 `输入→状态/处理→输出`）；② 次序（只在真依赖处，不追全序）；③ 验收（三问第三问：环上哪处从"不转/空转"变"转"）。
- **核心异议：不确认整张零件序**。零件循环依赖（取回→权重→后果→整理→重演→活跃度→取回），§四已定无自然全序、"最小"作废（#18）；排全序＝回到"一次设计完"。只确认 **第一刀 + 直接上游契约 + 直接下游读者**；序靠"走一步看环多转一处"验出。
- 步骤：**Step0** 刷新现状列（09-17 表已逾一周，须按代码重核）→ **Step1** 重画外圈并标"有/无/残缺"（以 §六 表为底，产单页锚）→ **Step2** 只对候选第一刀填三问（答不全→切错或架构要改，停）→ **Step3** 只定其直接上游。
- **第一刀判据修正**：§7.2 选沉淀的理据是工程可行性，§七 又自定"外圈稳＝可观察闭合环"——两者打架（只落段、段无消费者，环**不闭合**）。故沉淀判据须写**代理口径**（每弧稳定产出一条段，可数、可读回），**不得声称"外圈稳"**；紧跟第二刀 **`段→写回→装载`** 回边（最简/占位装载），否则重演"只写不读"。
- **后果读者 A/B**（§二未定）：A 先接占位读者（先让箭存在、可观察，公式边跑边修）／B 先定权重式再接线。**AI 倾向 A**（与"不先做权重"一致）。
- **动手前钉死两个前置语义**：
  1. **通道（想/说/沉默）**：想=`content`／说=send／沉默=默认（E0 定义）。现状 `consciousness.py` 有文本即自动补发 + `config.py` 提示词自相矛盾＝**违背点**；落段按 E0 写 `内容`/`后果`，别把"自动补发"记成"说"。
  2. **后果最小字段**：`on_tool_call` 现丢弃 calls+results。第一刀只填**硬后果**（工具结果），软后果（送达/沉默）留空。段最小字段 `id/t/来源/内容/后果/结`，`预测=None/refs=[]/thread=id` 占位。
- **冻结**：`§7.2` 的续/切引用、停/切点依赖"预测"，本轮不做。

## 4. 当前工具调用机制（已核代码事实）

- **厂商原生 function calling，调用痕迹存在且持久**（非"合成一条、不留痕"）：`cogos/cog_runtime/runtime.py:127-142` 每轮追加 `assistant.tool_calls` + `role:tool`，append 进 `cu.material`，而 `material=self._context`（`agent/consciousness.py:62-68`、`agent/app.py:228-237`）→ **跨轮常驻**。上线转换 `lm_service/providers/base.py:101-174`。
- 被 message 化的**不是**工具调用：常驻总览（`app.py:230`）＋内部事件（S4 渲染）。
- "调用+结果合成一条、不留痕"＝未做的**抹痕**（`entries/2026-09-28-cogos-toolbox-presentation.md:42`、`entries/2026-09-08-cogos-vision-image-fields.md:39`）。
- `on_tool_call`（`consciousness.py:44-55`）拿 results 后只递 cu、不落 store ＝"落段填后果"的**捕获点**；将来抹痕更动捕获点。
- 执行层**无同步异步之分**：`ToolRegistry.call` 一律 `await`（`agent/tools.py:1455-1467`）。"异步"唯一实现＝impl 发起即返回 + 真结果作事件唤醒新弧。
- **`time_form` 是死声明**：只被 `catalog.py:501`（help 印"时间形态"）+ `tools.py:44-49`（校验）用到，runtime/registry/toolbox 都不消费；标注与设计轴不一致（`observe`/`screen`/`vision` 返回值却标 `async`）→ **待清账**（让 cu 消费或删）。
- 事件→唤醒**已通**：`_QueueSink.emit`（`app.py:132-146`）→ `_event_queue` → `_consume_events`（`app.py:337-345`）→ `render_event`。**缺口＝续弧/关联**（无 correlator/join）。

## 5. 抹痕与同步异步归属（YZ 提，AI 细化）

- **抹痕（抹调用痕迹）→ 归 cu/装配层，划出"工具呈现"**：抹痕＝改"历史如何呈现给模型"＝**渲染时的一处选择**，与工具名/描述无关。两落点：**P1（默认，YZ 提）＝append 时就渲染成自己的消息格式（调用+结果，不写厂商 `assistant.tool_calls`/`role:tool`）→ "从未写过痕迹"**，更简单、无配对约束；P2（兜底）＝历史已存厂商协议物时在**装载时投影**。三约束：① **先捕获后抹痕**（`on_tool_call` 现丢弃 calls+results，须先落，同"落段填后果"接缝）；② P2 只能抹过去轮（活轮厂商协议要求配对）；③ 归 agent 装配层（C），别塞进通用 `cog-runtime`。→ **修正早前"只能抹过去轮/装载时投影"的说法：那是 P2；采纳 P1 后默认是渲染时选择。P1 前置＝解"连续同角色"（丢空 assistant 拍会撞厂商交替，`checkpoint-2 §十二` 合并暂不做）。** 详见 `entries/2026-09-28-cogos-intent-view.md`。
- **同步异步拆两半**：事实侧（搬不走）值 vs 后果由 impl 与世界交互性质决定；编排侧（该搬、缺）事件→唤醒→续弧/关联/落账/预算/打断，归 cu/装配。
- **关键**：两者在**落段时会显形**——异步后果落进新弧 ⇒ 原弧段无后果 ⇒ 做沉淀必须先定"**事件属于哪条弧**"的最小关联。AI 建议：做第一刀时同步定「事件→弧」最小关联 + 「捕获→投影」最小切面，其余（join/预算/打断/抹多干净）往后留。
