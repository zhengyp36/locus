# 2026-09-03 cogos cog-func 范式讨论

> 背景：视觉方案"看似收敛但仍有疑虑"，YZ 换角度——不从视觉子系统切入，而从三件套理念（LLM/cog-unit/cog-func）审视，发现只实现了 lm-service + cog-unit，缺 cog-func。讨论从"cog-func 是什么"出发，最终抵达范式层。
> 视觉落地已化解，但讨论主体是「开发范式转变」，越出视觉单点。

## 推进链

1. **主体性**：上下文才是主体 → 进一步"没有主体，信息在流动"（流动是实，聚集是名）。
2. **cog-func 本质**：语义函数（输入=意图，输出=结果）→ 语义层/机制层分离。
3. **视觉 = cog-func 而非子系统**：look_at 只能定义"看"这个动词，"怎么看/看什么"由 LLM 自己组合。
4. **预枚举 vs 组合**（纠正"涌现"用词）：原语预枚举封闭，功能组合开放；种子功能 + 生长功能（extract function）。
5. **范式转变**：函数封装"过程"，cog-func 封装"理解"；正确性从精确过程 → 契约+约束+反馈。
6. **隔离 vs 视角转换**：cog-func 不是隔离上下文，是"一个动词 = 一次焦点转换触发"；机制层真隔离（how 屏蔽），语义层视角转换。
7. **契约 vs 成长**：契约=下界，成长=上界；经验是程序性记忆（绑定 cog-func），不是陈述性记忆（认知树）。
8. **经验如何长**：raw trace 攒批 → 量变总结 → 保底滚动替换；总结模块=程序性记忆整理者（非第二主体）。
9. **记录规则自长**：只给保守种子；开发者被资源化（可邀请/约时/异步汇报）。
10. **主体性流动**：主体=发起调度的能力，在信息流里转移，人与机制等价。

## 层一：具体结论（视觉 + cog-func）

- **视觉不是子系统**：`img-tool 原语 + look_at 种子功能 + 生长功能`。此前"工具 vs 子系统"分叉是伪分叉，正确框架是 cog-func。
- **cog-func 分层**：
  - 原语层（机制层，预枚举封闭）：lm-service.chat / img-tool.info/extract / 程序动作 read·write·edit·execute·search·fetch·terminal·timer / cog-unit 调度。决定「可以怎么做」，预装不可自长、管资源。
  - 功能层（语义层，组合开放）：cog-func = 原语的命名组合。决定「要做什么」，可生长。
- **功能层内两种来源**：种子功能（预装，如 look_at）/ 生长功能（extract，如 zoom_in、verify_readable）。
- **look_at 剖面**：契约 + 能力集 + 数据缓存（图）+ 经验缓存（路径），复用主 cu 循环，不新建进程/服务/引擎。
- **视觉落地清单**：实现 img-tool 两个原语 + 一段看图契约 prompt + 一个缓存句柄结构，复用现有 cu 循环。没有第四件东西。

## 层二：成长机制

- **经验绑定 cog-func**（程序性记忆，调用即生效），不进认知树（陈述性记忆，需检索管理）。认知树=体（事实），cog-func 经验=用（技能）。
- **成长路径**：raw trace 攒批 → 量变触发总结 → 置信度驱动滚动替换（保底兜底）。
- **记录 = 可复现的 raw trace**（LLM 当时看到什么 + 怎么决策 + 什么结果），非摘要、非流水日志；一个 raw trace 两个消费者：总结模块（长经验）+ 开发者（分析成长）。
- **记录规则自长**：只给最保守种子（尽量全记），总结模块在分析中自己发现记什么/不记什么。
- **保底替换**：经验集 A+B → B+C，C 不靠谱由 B 兜底，永不裸奔。
- **不即时沉淀**：即时沉淀开销大 + 单次噪声固化 + 缺跨次对比。

## 层三：范式转变

1. **封装对象变了**：函数封装"过程"（怎么做），cog-func 封装"理解"（要什么 + 有什么能力），过程在运行时由理解者生成。
2. **正确性来源变了**：从"精确的过程"→"契约 + 约束 + 反馈回路"（定标/能力探测/保底都是反馈，不是过程控制）。
3. **复用对象变了**：从"复用代码（函数）"→"复用理解（cog-func）"。
4. **开发者位置变了**：从"园丁/神"（设计一切、干预一切）→"可调度的协作资源 + 研究者"（被邀请讨论、被约时间、异步汇报），调用 phone + timer 现成能力。

主线：**主体性从「固定的我」变成「流动的调度权」**——人和机制都是信息流里能发起调度的节点，等价。

## 命名收敛（cog-actor，09-03 YZ 拍板）

- **本质层 vs 呈现层**：actor = 本质（能行动、能调度的单元）；agent = 呈现（对外、被当主体的那个）。牛菌同构但牛仍是主体——主体不必拆，是呈现层的事实，不是本质层的特权。
- **cog-actor / cog-func / cog-unit 三层** = 谁 / 什么能力 / 什么动作：
  - cog-actor = 单元/主体，能行动、能调度。
  - cog-func = 功能，原语的命名组合。
  - cog-unit = 一次推理请求。
- **agent = 对外的 cog-actor 实例**（有 signature/身份）；总结模块 = 内部 cog-actor（无对外身份）。
- 主体性 = actor 在呈现层的投影。否定的是「主体=神秘自我」（本质层特权），保留的是「主体=对外呈现」（呈现层事实）。
