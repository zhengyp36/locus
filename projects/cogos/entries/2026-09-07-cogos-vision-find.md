# cogos 聚焦-扫描 / 镜筒 落地推进（09-06 晚 ~ 09-07）

> principle-exp 目录（非 cogos 仓库本体），核心文件 `/tmp/kilo/vision/vf6.py`（整合版一次性/REPL）。

## 定位与原则（YZ 反复敲定）

- **对话式观察**：人主导追问、agent 负责看和说，一起把"扫描+聚焦找目标"的过程走通；人不预设任务让 agent 独自完成。目标/思路/收口全在对话里。
- **中性提示词**：只声明工具能做什么（参数/产出契约 + 三层视野客观事实 + 坐标定义），不教"该何时/怎么用"（策略）。写"能怎样"，不写"该怎样"。
- **换算归工具（本会话关键）**：模型报"在哪张图、相对位置"，工具换算回原图；模型不适合作子图→原图坐标换算（算术），手算必偏。

## 落地（vf6.py）

- **视野三层**：全景(default 坐标上下文, open 换图即变、中央凹清空) + 中央凹(view 轨迹, 参数对象不入 images) + 驻留(≤2)。
- **image 坐标系**：`view{"image","center","radius"}`；center/radius 相对指定图（缺省=当前全景），坐标可超[0,1]、出界视线停边界并注明；view 记录 source=换算后的原图 id。
- **`State.map_to_pano(ref,cx,cy,r)`**：沿 view→source 链递归，把任一图坐标系换算到原图（返回 orig_id,ox,oy,or）。
- **轨迹叠加**：`save_trail()` 每次 view/open 后在全景底图画所有 fovea 圆窗（红→蓝→绿→橙），存 `out_dir/trails/overlay_NNN.jpg`；只画在当前全景上的轨迹。
- 素材：`detail.jpg`(4000×3000) + `pano_800.png`(全景缩略) + `p_target_bw_t145.png`(目标 ref)，归一化坐标等比通用。GT A(0.595,0.512)、B(0.044,0.680)。

## 关键实证

- **换算修复**：手算子图点(0.65,0.25)模型报错 (0.63,0.58)；工具 `map_to_pano` 算 (0.593,0.515)≈GT A。误差根源=模型漏按窗径缩放 + y 方向记反。
- **命中**：真实对话 2-3 步 view 收敛，view_2 精确框住双矩形(range/detail 处) ≈GT A。
- **会用相对位置**：被引导"基于局部图移动"时，模型会用 `image=view_N` 子图坐标（换算触发正确）；不引导时默认走全景坐标（择优，非"不知道"）。

## 行为分化（空区域重复 view）

3 次采样同 msg：1 完全重复 / 1 小幅再挪 / 1 干净收尾 → **偶发**。
- 根因：模型面对"空/无细节"时缺**收口**动作，用"再发一个 view（重复或微挪）"确认；明说"没细节"仍补发。与"找到还过度收敛"同源。
- 边界：只重复 1 次就停，不会无限循环。

## 未落（机制层候选，观察阶段不落）

- **注入轻提示**：机制层检测"完全不改坐标连续多次 view" → 注入一条消息"你在同一位置看好几轮了"。属元控制=机制层预装（非教学），**但观察预研阶段会遮蔽自然行为、且无无限重复，先不落**，自动化阶段再说。
