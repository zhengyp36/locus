## 1. cu 的边界：为什么不"纯粹"

- 现状定义（总纲 §2）：cu＝不间断的模型弧、必有 finish。但实际：**不是一次 API 调用**（可多轮工具）；**可随时被打断**（打断即终结，下次新 cu 组织）。
- AI 判读：**下界＝上次重组，上界＝下次重组或模型自停**——边界**由外部决定**（何时必须重组 material），所以"难把握"是正常的，不是缺陷。
- 重定义：**cu ＝ 机制不介入的模型自转区间（append-only）；机制一介入（重组/叫停）→ cu 结束。** 真正稳定单位＝**弧/环**；段＝"一弧一条"。cu 降级为"两次重组之间的实现段"。

## 2. 一弧多 cu 与打断

- **打断点＝"可以不是 append"的唯一机会＝重组入口**（loop-invariants §二.5）。
- 打断源：**回看**（插入型）／**上下文过长**（压缩型，＝压缩的强制入口）；机制叫停手段：**预算**（现 `MAX_TOOL_ROUNDS=10` 是硬常数占位）／**回看判停**／**误差切点**。
- **打断→重组 ＝ 存→取**；与跨弧／跨唤醒是同一对动作，只是 scope 不同（cu 内→不需要，环内→要，跨唤醒→要）→ 不需要两套机制。
- 三个动作要分清：**停**（弧收尾→沉淀）／**打断**（cu 中途叫停→可重组继续）／**自然停**（模型不再调工具）。"中断"＝`cu.interrupt(reason)`→`CuResultInterrupted`，是机制常规手段，非异常。
- 现状缺口：父被打断时子未 done → 父 done、子孤儿、无 join（`_finish` 不等子）→ 即 loop-pivot 的"缺续弧/关联"。

## 3. 父子 cu：只拆不建（已定，待执行）

- **判据：关系 ≠ 属性**。`state/_resp/_tool_calls` 是 cu 的**执行态**（属性，留）；`parent/children` 是"cu 连到谁"（**关系**，属**编排层**）。存进 cu 既弄脏定义，又让打断时关系悬空（孤儿）。
- **事实（已核代码）**：`parent=` **零生产调用**（仅 `tests/cog_runtime/test_parent.py`、`test_unit.py`、`test_lifecycle.py`）；机制只保证"父等子 done"的**顺序**（`_all_children_done`，`runtime.py:68/71`），**不给数据流**——`test_parent.py:61-101` 要绕 `on_done`+`on_ready` 传结果。且 **done 前并不等子**（`_finish` 不查子）。
- **决定：本轮只拆、不建**。拆掉的是**约定**（自动记父子/自动等子），**能力一直在原语里**（`cu()`＋`wait()`/`no_wait()`）；替代形态——**回看＝`on_tool_call` 内 `await` 子 cu**（该回调本就 async，`runtime.py:118`，比 on_ready 绕法更顺）、**fan-in＝编排层 `gather`**——**留到编排真需要时再建**（父子只是概念，建不难）。
- **拆清单**：`unit.py` 删 `parent/children`(17-18)、`add_child/remove_child`(46-51) ＋ docstring；`runtime.py` 删 `cu(parent=)`/`add_child`(25,37-38)、两处 `_all_children_done`(68-69,71-73)、`_all_children_done`(153-154)、`_finish` 唤醒父(172-173)；`tests` 删 `test_parent.py` 整篇、`test_unit.py:30-44`，改 `test_lifecycle.py:43-69`。**不加**编排层示例测试。验收＝`tests/cog_runtime` 全过＋全量回归。

- **被否**：Y（搬到新编排对象）＝为不存在的需求造对象；"现在就把替代能力重建"＝越界（**建**属后面编排阶段）。

## 4. 无名的连续线索（开放）

- YZ 提：cu 被打断换新 cu，但仍是**一条连续线索**；外圈/内圈都靠它承载，它不是外圈/内圈，**也可能是其他**。
- AI 定位（**倾向，未定稿**）：运行时＝**流**（主槽流，唯一）；持久层＝**`thread`＋`refs` 链**。命题：**这条线索的载体不是运行时对象，就是经历轴上由 `thread`/`refs` 串起来的那条链**（cu 只是它的一次次 append 段）。
- 推论：**外圈/内圈不是两条独立线索，是同一主槽流上的两种驱动**（事件驱动 vs 经历驱动）。
- 三层命名建议：**cu**（append 段＋终止）／**编排**（父子、事件、预算、打断）／**线索**（流 / `thread`）。
- **待裁**：总纲 §0"两条链（外圈/内圈）"是否重述为"**一个主槽流 + 两种驱动**"。
- 状态：YZ 说"那条线后面再说"，本轮只定了父子层。
