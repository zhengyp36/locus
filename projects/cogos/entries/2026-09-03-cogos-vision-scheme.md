# 2026-09-03 cogos 视觉方案收敛

视觉子系统方案讨论 + 实测收敛。正文已固化本体 `cogos/docs/vision-system-design.md` §4/§6/§14 + 待拍板。

## 核心模型

人眼视觉 = 模糊全景背景（常驻）+ 清晰局部焦点（移动），与意识层「强焦点 + 弱背景」同构。

## 两个关键修正

1. **无「缩略图」、无「预生成金字塔」**：全景模糊用 JPEG DCT 降采样（draft）动态生成，不碰全图；range 用 crop 动态裁剪。预生成金字塔被否定（弱机摊内存 + draft 已让动态读免费）。
2. **无「放大」，只有「凑近 = 缩 range」**：看细节 = crop 原图更小 range 的原生像素，永不 upscale。放大 = 插值假细节（对比图实证：文字糊成一团）。

## 取图原语

取图 = 原图 + `range`(crop 区域) + `scale`(draft 降采样档 1/1、1/2、1/4、1/8)。scale 语义 = 降采样档，非放大倍数。意识只发 range 意图，scale 由视觉子系统内部自动推（预算内最高分辨率）。

## 实测（弱机 2 vCPU Celeron / 3.6G 内存，4000×3000 JPEG）

| 动作 | 耗时 | 峰值 RSS |
|---|---|---|
| draft 缩略 | ~70ms | 22MB |
| crop 原生 | ~285ms | 67MB |
| crop + 放大 4x（弃用） | ~480ms | 81MB |
| draft 工作图 + crop（弃用：丢细节） | ~150ms | 32MB |

- draft 只省「解码像素缓冲」（全图 47MB → 12MB 固定开销），不省熵解码固定成本。
- JPEG 全局熵编码：crop 局部也要全图解码，Pillow 无法只解局部（crop 显不显式 load 峰值一样 67/73MB）。

## 量力而行（能力探测 + 拒绝）

- 软件普遍适用，能力边界由环境动态决定，**不写死场景魔数**（放弃「够用上限」这种业务取舍）。
- 处理前 `Image.open` 惰性读尺寸，预估峰值 ≈ 宽×高×3 + 压缩字节 + 常数；与运行时探测可用内存（MemAvailable 保守比例）比对。
- 超限 → 视觉工具返回**错误态结果**（非异常）`{ok:false, error:...}` → LLM 第一人称转述用户「这张图太大，当前环境配置能力不足，我看不了」。
- 不降采样兜底（降级丢细节且无感知），超限即拒绝。

## 架构

- 视觉子系统 = 感知侧 io 层，独立 cog-func，不内置 CogUnit。
- **独立进程**：图处理 CPU 密集（Pillow 持 GIL），agent 进程 IO 密集（asyncio），混一起互拖；单 worker 串行。
- 语义理解在意识层调 vision LLM；视觉子系统只做取图/缩放/清晰度检测等 io 原语。
- 演进：libvips 惰性部分解码（crop 只解局部，既全细节又省内存），原生依赖，暂不引入。

## 测量方法坑

`resource.getrusage(RUSAGE_SELF).ru_maxrss` 是进程级历史峰值只增不减，多方法必须在独立进程各测一次，否则峰值被污染。

## 三轮收敛（同日续）：架构定型

正文已固化本体 §14「架构收敛」「精确给 + resize 鲁棒 + 定标」小节 + handoff。

### 主线演进

1. 视觉 = 纯工具（无状态）→ 命名 `img-tool`（短命子进程，非服务，句柄 = path，无 close）。
2. thumb/crop 二分 → 统一 `extract(path, region)`：region 归一化 + scale 自动推到封顶内 = 渐进离散聚焦。
3. 方案1（工具返回文字结论，主 LLM 当盲人听转述）vs 方案2（图进主 LLM 上下文自己看）→ **方案2 胜**。
4. 取景器 LLM / 内部 LLM（第二主体）被否 → 看图需背景知识，背景只在主 LLM 处，唯一主体 = 主 LLM；视觉子系统 = 手眼。

### 关键机制

- **精确给**：自己缩到封顶内，不甩厂商 resize（省 token + 网格不被糊）。
- **resize 鲁棒**：保守给图 + usage 校准（固定文本模板，总 token 封顶 ⟺ 图像封顶）+ 相对定位。厂商无运行时接口，文档声明会漂移（实测 443 vs 文档 384），usage 是锚。
- **定标（自校验探针）**：看新图让 LLM 读四角编号、比对已知答案；全景最危险、定标一次够；分步避免分心。
- **网格定位**：LLM 报离散格子编号（VLM 报连续坐标不可靠、离散可靠），grid 元数据查表换坐标。

### 待验证（新会话继续）

- region 表达细节（网格编号 vs 归一化坐标入参）。
- f(W,H)：图像 token 纯尺寸函数？图内文字额外计 token？
- 纸载体、自下而上显著检测（大图起点）。

## 并发控制（09-03 四轮收敛）

- 「短命进程天然串行」是错的：只对单进程内成立；多 agent 多进程可并发调用 img-cli，弱机会拖垮。
- 控制必须落在 img-tool 自身（跨进程共享点），不能放 look_at——多进程彼此管不住。
- 方案 = 短命子进程 + flock 计数信号量：N 个 slot lockfile 抢任意空闲槽（非阻塞试抢 + jitter sleep），N 可配置（IMGTOOL_CONCURRENCY），N=1 退化互斥。
- flock 内核自动释放，崩溃安全，优于 POSIX 命名信号量（进程崩溃计数泄漏）。
- 不用 hash 分片：`hash(path)%N` 是「同图串行」语义（缓存/写回一致性才需要），与资源限流无关，现在 YAGNI。
